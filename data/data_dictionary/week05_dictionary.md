# week05_dirty_process_data.csv 데이터 설명서

## 목적
결측값·중복값·이상값 등 "지저분한 데이터"를 찾아 정리하는 실습을 위해 **의도적으로 오염시킨** 데이터다.

## 가상 상황
**공정 지도 위치**: 공정 지도 **②~⑤(산화·포토·식각·증착/이온주입) + 세정**의 설비 센서 기록이다.

공장 데이터에 흔히 끼어드는 문제(빈 칸, 같은 기록의 중복 저장, 튀는 값, 잘못된 날짜 형식, 오타 등)를 재현했다.
현실에서는 센서가 잠깐 꺼지거나 통신이 끊겨 빈칸이 생기고, 같은 기록이 두 번 전송돼 중복이 생기며,
센서 고장·단위 실수·입력 실수 또는 실제 설비 문제로 튀는 값이 생긴다. 이 데이터의 오류는 연습을 위해 일부러 넣은 것이라
하나하나의 실제 이유는 없다.

## 행 하나의 의미
한 행 = 1건의 공정 기록(단, 일부는 중복 저장되었거나 값이 잘못 입력됨).

## 정상 범위 (교육용 예시)
온도 295~305℃, 압력 995~1025 Pa, 가스유량 47~53 slm.

## 압력_Pa 값의 한계 (교육용 가상 데이터)

`압력_Pa`는 교육용으로 생성한 가상 값이며 실제 측정값이 아니다. 이번 차시의 실측 범위는 약
996.3~1,033.1 Pa(평균 약 1,013.2 Pa)인데(의도적으로 심은 음수 이상값 2건과 결측값 2건은 제외한
범위다), 이 자릿수는 Pa로 읽은 챔버 압력보다 hPa로 읽었을 때의 자릿수에 가깝다(대기압이 약
1,013 hPa = 101,325 Pa다). **단위 라벨과 값의 자릿수가 서로 맞지 않는다.** 이 값이 실제로 어떤
공정 조건을 나타내는지는 단정할 수 없으므로, 실습에서는 `압력_Pa`의 절대값을 물리적으로
해석하지 않고 **수치 열 하나**로만 다룬다.

**학생이 물어보면**: "교육용으로 만든 가상 값이라 단위와 자릿수가 실제 공정과 맞지 않습니다.
이번 실습에서는 압력의 절대값을 해석하지 않고 값들 사이의 상대적인 차이만 봅니다"라고 답한다.

데이터를 다시 만들면 1~10차시의 실습 결과 수치와 강의 자료가 모두 함께 바뀌므로, 현재 버전은
값을 그대로 두고 이 한계를 여기에 명시하는 쪽을 택했다.

## 의도적으로 포함된 이상 현상(실제 생성 결과)
- 결측값(NaN) 총 10건(온도 3, 압력 2, 가스유량 3, 합격여부 2)
- 완전 중복 행 3건
- 날짜 형식이 다른 `측정시간` 2건
- 500℃ 이상 극단 고온 2건(약 540.3℃, 557.7℃)
- 음수 압력 2건(약 -42.9, -27.0 Pa)
- 비정상 가스유량(음수 또는 200 이상) 2건(-5.0, 250.0 slm)
- 공정명 오타 3건(`중착`, `식각 `(공백 포함), `포토공정`)
- `합격여부` 누락 2건

## 이번 차시 분석 질문
- 결측값은 열별로 몇 개씩 있는가?
- 정리 전후 행 개수와 평균 온도는 어떻게 달라지는가?(실제, 노트북 순서: `dropna()` 113 → 104행 → `drop_duplicates()` 101행 →
  범위 밖 행 제외(온도 ≤ 400, 압력 ≥ 0, 0 ≤ 가스유량 < 200) **95행**. 평균 온도 304.9℃ → 300.6℃로 약 4.3℃ 차이)
- 정리 전 `describe()`: 온도 count 110, mean 304.9, max 557.7 / 압력 min -42.9 / 가스유량 min -5.0, max 250.0. 중복 행 3.
- Orange 실측(`_2_dirty_process_done.ows`): Impute(평균, 합격여부 빈 행 삭제) 113 → 111행 → Select Rows **105행**,
  정리 후 온도 Mean 300.75(Median 300.8, Min 291.3, Max 310.9), 압력 Mean 1013.10, 가스유량 Mean 50.09.
  Impute 설정을 다르게 하면(새 위젯에서 실측, `_workspace/measure_w05_impute.py`): 합격여부 개별 설정을 빠뜨리면 빈 합격여부 2칸이
  최빈값 "1"(합격)로 채워져 113 → **107행**(온도 Mean 300.63), 위쪽 Default Method를 Remove instances로 고르면 104 → **98행**,
  아무것도 고르지 않으면(Don't impute) Select Rows가 조건 열이 빈 8행도 지워 **99행**이 된다.
  파이썬(95행)과 행 수가 다른 것이 정상이다 — 파이썬은 빈칸 행과 중복 행을 지우고, Orange는 빈칸을 평균으로 채우고 중복을 남긴다.
- 이상값 행을 지우기 전에 다른 열과 함께 보면 무엇이 보이는가?(실제: 이상값 6건 모두 합격(1), 그중 4건이 EQ-03 기록.
  오염 위치는 무작위로 정했으므로 이 쏠림은 우연이다. 수업에서는 "확인할 단서"로만 다룬다)
- (5차시 실습 범위 밖) 공정명 오타 3건과 형식이 다른 측정시간 2건은 "입력 오류"의 예로 데이터에 남아 있다.
  5차시에서는 이름만 소개하고 코드로 고치지 않는다.

## 생활 예제 데이터 — week05_easy_class_records.csv

### 목적
반도체 데이터(`week05_dirty_process_data.csv`)를 정리하기 전에, 학급 학생 기록으로 **같은 정리 순서**
(`describe()` → 정리 전 값 기억 → `isna().sum()` → `dropna()` → `duplicated()`·`drop_duplicates()` →
범위 조건으로 튀는 값 찾기·빼기 → 정리 전후 비교)를 먼저 연습하는 **생활 예제용 가상 데이터**다.

### 가상 상황
담임 선생님이 세 반(1반·2반·3반) 학생 14명의 키·몸무게·수학 점수를 표로 옮겨 적다가 실수를 몇 군데 했다.

### 행 하나의 의미
한 행 = 학생 1명의 기록(단, 마지막 행은 같은 학생을 한 번 더 적은 중복이다).

### 열 설명

### 정상 범위 (교육용 예시)
키 140~200cm, 몸무게 35~100kg, 수학 점수 0~100점. 이 범위는 학습용으로 정한 것이다.

### 의도적으로 포함된 패턴(실제 값)
- 크기 15행 x 5열.
- **결측 3칸**: `반` 1칸(조예준), `키_cm` 1칸(최수아), `몸무게_kg` 1칸(장서준). 열마다 15행 중 1칸(6.7%).
- **완전 중복 1행**: 마지막 행(행 번호 14)이 박지호(1반, 171.0, 63.5, 78)를 한 번 더 적은 것이다. `students.duplicated().sum()` = 1.
- **입력 실수 이상값 1개**: 정도윤의 키 `1720.0`(172.0을 소수점 없이 잘못 적음). `students[students["키_cm"] > 250]`로 1건 찾는다.
- 정리 전 `describe()`: 키 count 14, mean 276.6, 50%(중앙값) 166.75, max 1720.0 / 몸무게 mean 56.4 / 수학 점수 mean 83.1.
  평균 키 276.6cm는 이상값 하나 때문에 생긴 값이고, 중앙값 166.75cm는 거의 흔들리지 않는다(튀는 값을 먼저 확인해야 하는 이유. Orange 3.35 Impute에는 중앙값으로 채우는 방법이 없고, 오늘은 평균(Average)으로 채운다).
- 노트북(v3)과 같은 순서로 정리한 실제 결과:
  `dropna()` → 12행(빈칸이 있는 3행 삭제) / `drop_duplicates()` → 11행 / `students[students["키_cm"] <= 250]` → 10행.
- 정리 전후 비교: 행 15 → 10, 평균 키 276.6 → 163.8.

## Orange 워밍업 데이터 — week05_orange_cleanroom_env.csv

### 목적
5차시 PART 2 Orange 워밍업용 데이터다. Feature Statistics로 빈칸·튀는 값을 찾고, Impute(빈칸 채우기)로 빈칸을
평균으로 채웠을 때 **튀는 값이 남아 있으면 채운 값도 엉터리가 되는** 장면을 직접 본다. Orange에서는
`orange/week05_orange_cleanroom_env.tab`을 연다.

### 가상 상황
반도체 공장의 클린룸(먼지를 아주 적게 관리하는 방, 병원 수술실을 떠올리면 된다) 세 구역에서 하루 동안 1시간마다
공기 상태를 기록했다. 센서가 가끔 값을 놓치거나(빈칸), 고장 신호로 99,999 같은 값을 남기기도 한다는 설정이다(99,999는 이 기록에서 쓰는 오류 코드이며 일반 규칙이 아니다).

**공정 지도 위치**: 공정 지도 **②~⑥이 이루어지는 FAB의 클린룸**(① 웨이퍼 제조는 보통 웨이퍼 제조사에서, ⑦⑧도 별도의 청정 공간에서 진행)의 환경 기록이다. 특정 공정 단계가 아니라 그 방의 공기 기록이다.

### 행 하나의 의미
한 행 = 한 구역의 한 시각 기록(3구역 × 24시간 = 72행).

### 의도적으로 포함된 패턴(실제 생성 결과)
- 결측: 파티클 4 · 습도 3 · 차압 2(모두 서로 다른 행, 9행).
