# week03_python_basics_2.csv 데이터 설명서

## 목적
리스트·딕셔너리를 조건문·반복문·함수로 다루는 실습을 위한 데이터다(2차시와 같은 계열,
다른 행으로 따로 생성). 3차시에는 이 CSV를 Pandas로 읽지 않고, 필요한 열(로트번호·설비번호·온도_C·합격여부)을
"딕셔너리의 리스트"로 옮겨 적어 쓴다. CSV를 코드로 읽는 방법은 4차시에 배운다.
개념마다 먼저 보여 주는 쉬운 예제(시험 점수·체온)는 이 CSV와 별개로 코드 안에 적은 설명용 값이다.

## 가상 상황
**공정 지도 위치**: 공정 지도 **②~⑤(산화·포토·식각·증착/이온주입) + 세정**의 설비 기록이다.

여러 로트가 여러 공정을 거치며 남긴 온도 기록이다(2차시보다 행 수가 조금 더 많다).

## 행 하나의 의미
한 행 = 로트 하나가 공정 하나를 거친 기록 1건. 그래서 같은 로트번호가 다른 공정에서 한 번 더 나올 수 있다
(예: LOT-0186은 식각과 증착에서 각각 기록되었다).

## 열 설명

| 열 이름 | 쉬운 설명 | 데이터 형식 | 단위 | 예시 | 결측값 가능 여부 |
| --- | --- | --- | --- | --- | --- |
| 로트번호 | 함께 이동하는 웨이퍼 묶음(상자)의 번호 | 문자열 | - | LOT-0049 | 없음 |
| 공정명 | 이 기록이 나온 작업 종류(산화·포토·식각·증착·세정) | 문자열 | - | 세정 | 없음 |
| 설비번호 | 작업한 기계의 번호 | 문자열 | - | EQ-02 | 없음 |
| 온도_C | 작업할 때 설비 안에서 잰 온도(교육용 가상 값) | 실수 | ℃ | 304.4 | 없음 |
| 합격여부 | 그 뒤 검사에서 나온 실제 결과 | 정수 | - | 1(합격) / -1(불합격) | 없음 |

## 단위 읽는 법

| 표기 | 읽는 법 | 뜻 |
| --- | --- | --- |
| C (온도_C, 기온_C) | 섭씨 몇 도(℃) | Celsius(섭씨)의 첫 글자 |
| ug_m3 (PM10_ug_m3) | 세제곱미터당 마이크로그램 | 공기 1m³ 안에 든 먼지의 무게. 1마이크로그램(µg) = 100만분의 1그램 |
| pct (습도_pct) | 퍼센트 | percent의 줄임 |

## 정상 범위 (교육용 예시)
온도 295~305℃. 1차시부터 쓰는 이 과정의 학습용 기준이며, 실제 공정의 기준이 아니다.

## 의도적으로 포함된 패턴(실제 생성 결과)
- 30행 중 정상 범위(295~305℃)를 벗어나는 온도 값이 **12건**(높은 쪽 > 305: 8건, 낮은 쪽 < 295: 4건). 경계값(정확히 295 또는 305)은 없다.
- `합격여부`는 온도만으로 정해진 값이 아니다. 합격 27건, 불합격 3건이다. **범위 밖 12건 중 실제 불합격은 3건이고 9건은 합격**이다.
  범위 안 18건은 모두 합격이다(이 데이터에서는 범위 안 불합격이 0건).
  그래서 온도 판정 함수(`judge_pass`)의 결과와 실제 검사 결과가 다르다 — "규칙 하나로 합격·불합격이 다 설명되지 않는다".
- 설비별: EQ-01 6건(범위 밖 1) · EQ-02 5건(범위 밖 3, 불합격 1) · EQ-03 11건(범위 안 7 · 밖 4, 불합격 1) · EQ-04 8건(범위 밖 4, 불합격 1).

## 3차시 수업에서 쓰는 값(노트북 실제 출력)
- "반도체 데이터로 확인하기"(노트북 6단계): 설비 **EQ-04** 기록 8건 → 범위 밖 **4건**(314.1·318.4·291.0·307.0), 그중 합격여부 -1은 1건(LOT-0085, 307.0).
- 반도체 데이터 실습(노트북 7단계 = 실습지 문제 1~3)
  - 문제 1: 온도 하나(293.8, LOT-0186·LOT-0195의 값) → `범위 밖입니다.`
  - 문제 2: **EQ-03** 온도 11개 중 정상 범위 **7개**.
  - 문제 3: `judge_pass`로 기록 30건 판정 → "불합격" 판정 **12건**, 그중 실제 불합격(-1) **3건**.
- Orange 실측(`_2_records_done.ows`): Select Rows `온도_C is outside 295, 305` → **12행**, 조건 `합격여부 is -1`을 더하면 **3행**
  (LOT-0186 293.8 · LOT-0195 293.8 · LOT-0085 307.0).

## 이번 차시 분석 질문
- 내가 만든 판정 함수(`judge_pass`)로 걸러낸 불합격(범위 밖) 기록은 몇 건인가? → 12건
- 그중 실제 검사(`합격여부`)에서 불합격(-1)한 기록은 몇 건인가? → 3건

## 실제 현업 데이터와 다른 점
완전한 가상 데이터다. 가상 데이터라 설비와 공정이 무작위로 짝지어져 있다. 실제 공장에서는 설비마다 맡는 공정이 정해져 있다. 온도 값은 공정 구분 없이 300℃ 근처로 만들어 실제 공정 조건과 다르다.
결측값은 아직 넣지 않았다(결측값 처리는 5차시 주제).

## Orange 워밍업 데이터 — week03_orange_air_quality.csv

### 목적
3차시 PART 2 Orange 워밍업용 데이터다. Select Rows(행 고르기)로 "미세먼지가 많은 날"을 조건으로 골라 보고, 고른 날의
`등급`이 사람이 기준 구간으로 붙인 판정이라는 것(오늘 만든 `judge_pass`와 같은 일)을 확인한다.
Orange에서는 `orange/week03_orange_air_quality.tab`을 연다.

### 가상 상황
가상의 우리 동네 측정소가 2024년 4월 한 달 동안 매일 잰 대기환경 기록이다.
공장 기록에서는 온도 295~305℃ 같은 허용 범위(연습용 기준)가 등급 기준과 같은 역할을 한다 — 오늘 반도체 표의 `온도_C`가 이 범위를 벗어난 기록이 '나쁨'인 날처럼 먼저 확인할 대상이 된다.

### 행 하나의 의미
한 행 = 하루의 대기환경 기록(30일 = 30행).

### 열 설명

| 열 이름 | 쉬운 설명 | 데이터 형식 | 단위 | 예시 | 결측값 가능 여부 |
| --- | --- | --- | --- | --- | --- |
| 날짜 | 측정한 날(2024-04-01 ~ 2024-04-30). Orange에서는 표에만 보이는 meta 열 | 날짜 | - | 2024-04-03 | 없음 |
| PM10_ug_m3 | 지름 10마이크로미터 이하 미세먼지 농도 | 정수 | µg/m³ | 161 | 없음 |
| PM2_5_ug_m3 | 지름 2.5마이크로미터 이하 초미세먼지 농도 | 정수 | µg/m³ | 76 | 없음 |
| 기온_C | 그날의 기온 | 실수 | ℃ | 11.3 | 없음 |
| 습도_pct | 공기 중 습기의 정도 | 정수 | % | 54 | 없음 |
| 등급 | PM10 값만으로 붙인 판정: 좋음 0~30 · 보통 31~80 · 나쁨 81~150 · 매우나쁨 151 이상 | 문자열(범주) | - | 매우나쁨 | 없음 |

등급 구간은 우리나라 미세먼지 예보에서 흔히 쓰는 PM10 구간을 빌렸다. 측정값은 교육용 가상 측정값이다.

### 의도적으로 포함된 패턴(실제 생성 결과)
- 등급: 좋음 7 · 보통 15 · 나쁨 6 · 매우나쁨 2. 등급은 생성기의 규칙 함수 `pm10_grade()`가 PM10 값만으로 정한다.
- **PM10 > 80인 날 8일**(나쁨 6 · 매우나쁨 2), 그중 **습도 > 70인 날 3일**(4/4 · 4/14 · 4/16, 모두 나쁨).
- 기온 8.6~22.9℃, PM2.5는 PM10의 약 0.41~0.59배.
- Orange 실측(`_1_air_done.ows`): Select Rows `PM10_ug_m3 is greater than 80` → **8행**, 조건 `습도_pct is greater than 70`을 더하면 **3행**.
  Distributions(등급) 막대: 나쁨 6 · 매우나쁨 2 · 보통 15 · 좋음 7. **막대는 가나다순(나쁨 → 매우나쁨 → 보통 → 좋음)으로 놓이고, 나쁜 정도 순서가 아니다.**
