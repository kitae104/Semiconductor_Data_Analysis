9차시 실습 데이터 설명서

대상 파일: week09_pass_fail_train.csv · week09_new_lots_to_predict.csv

목적

scikit-learn으로 첫 머신러닝 모델(결정트리)을 직접 만들어 보는 실습 데이터다. 학습용 데이터(week09_pass_fail_train.csv)와, 정답 없이 예측만 해볼 신규 로트 데이터 (week09_new_lots_to_predict.csv, 10차시에서 사용)로 구성된다.

가상 상황

공정 지도 위치week09_pass_fail_train.csv = 공정 지도 ②~⑤(산화·포토·식각·증착/이온주입) + 세정의 공정 조건과 그 작업 뒤 검사 결과(공정 중간 검사와 ⑦ EDS(전기 검사) 결과를 모은 교육용 설정). week09_new_lots_to_predict.csv = ②~⑤를 마쳤지만 아직 ⑦ 검사 전인 새 로트(10차시).

여러 공정·설비에서 측정한 공정 조건과 그 작업 뒤 검사 결과를 모아, "공정 조건만으로 합격/불합격을 미리 예측할 수 있을까?"를 실험하는 데이터다. 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록).

행 하나의 의미

한 행 = 공정 작업 기록 1건(어느 공정·어느 설비에서 잰 공정 조건)과 그 작업 뒤 검사 결과(공정 중간 검사 + ⑦ EDS 결과를 모은 교육용 설정). 검사 결과는 행마다 붙어 있고, 같은 로트가 여러 행(여러 공정)에 나올 수 있다(이 파일에는 로트 번호 열이 없다).

부호 — 1~8차시와 같은 표기

합격여부는 1~8차시와 같이 1 = 합격, -1 = 불합격이다. 합격 비율은 (y_test == 1).mean()으로 구한다. (v2 기록 — v3 수업에서는 confusion_matrix 코드를 쓰지 않는다. 강사 참고) scikit-learn의 혼동행렬은 기본으로 숫자가 작은 쪽(-1 = 불합격)을 첫 줄·첫 칸에 두므로, 강의에서는 confusion_matrix(y_test, pred, labels=[1, -1])로 합격을 먼저 놓아 "윗줄 = 실제 합격, 왼쪽 칸 = 합격으로 예측"이 되게 한다.

week09_new_lots_to_predict.csv 열 설명

week09_pass_fail_train.csv와 같은 8개 열(공정명, 설비번호와 공정 조건 6개: 온도_C, 압력_Pa, 가스유량_slm, 두께_nm, 진공도_mTorr, 습도_pct)만 있고 합격여부는 없다. 아직 검사하지 않은 신규 로트 9건이며, 10차시에서 학습된 모델로 이 로트들의 합격/불합격을 예측한다.

압력_Pa 값의 한계 (교육용 가상 데이터)

압력_Pa는 교육용으로 생성한 가상 값이며 실제 측정값이 아니다. 이번 차시의 실측 범위는 학습용 데이터가 약 982.9~1,041.8 Pa(평균 약 1,011.9 Pa), 신규 로트 데이터가 약 989.2~1,031.7 Pa(평균 약 1,013.3 Pa)인데, 이 자릿수는 Pa로 읽은 챔버 압력보다 hPa로 읽었을 때의 자릿수에 가깝다(대기압이 약 1,013 hPa = 101,325 Pa다). 단위 라벨과 값의 자릿수가 서로 맞지 않는다. 같은 행의 진공도_mTorr와도 맞지 않는다. 진공도 평균 약 5.01 mTorr는 약 0.67 Pa인데(1 mTorr ≈ 0.133 Pa) 같은 행의 압력_Pa는 평균 약 1,011.9 Pa여서 약 1,510배 차이가 난다 — 한 챔버가 같은 시각에 두 압력일 수는 없다. 신규 로트 데이터도 같다(진공도 평균 약 4.79 mTorr ≈ 0.64 Pa, 압력 평균 약 1,013.3 Pa, 약 1,590배). 이 값이 실제로 어떤 공정 조건을 나타내는지는 단정할 수 없으므로, 실습에서는 압력_Pa의 절대값을 물리적으로 해석하지 않고 수치 열 하나로만 다룬다.

학생이 물어보면"교육용으로 만든 가상 값이라 단위와 자릿수가 실제 공정과 맞지 않습니다. 이번 실습에서는 압력의 절대값을 해석하지 않고 값들 사이의 상대적인 차이만 봅니다"라고 답한다.

데이터를 다시 만들면 1~10차시의 실습 결과 수치와 강의 자료가 모두 함께 바뀌므로, 현재 버전은 값을 그대로 두고 이 한계를 여기에 명시하는 쪽을 택했다.

이번 차시 핵심 수치(실제 실행 결과, max_depth=4, random_state=42)

(v2 기록이 섞여 있다 — 혼동행렬·특성 중요도·밖/안 비율은 v3 수업에서 코드로 다루지 않는다. 강사 참고. v3 수업 값은 아래 "v3 9·10차시 수업에서 쓰는 값" 절.)

  • 학습/평가 데이터 분할: train_test_split(test_size=0.2, random_state=42, stratify=y) → 588행 / 147행 (모의고사 실제 합격 116건, 불합격 31건)
  • 모델 정확도: 80.3%(147건 중 118건)
  • "무조건 합격으로 예측" 기준선 정확도: 78.9%(116건) (모델과 2건 차이 — 정확도 하나로는 판단하기 어렵다는 것이 이번 차시의 핵심 교훈)
  • 혼동행렬(labels=[1, -1]): [[109, 7], [22, 9]] — 실제 불합격 31건 중 모델이 잡은 것은 9건, 놓친 것은 22건 (모델이 불합격으로 예측한 것은 16건 = 헛경보 7건 + 잡아낸 불량 9건). labels를 빼면 [[9, 22], [7, 109]].
  • 가스유량_slm(비교용 열)을 47~53 slm 범위로 나누면 불합격 비율은 밖 20.3%(241건), 안 21.1%(494건)로 차이가 없다. 그런데도 중요도는 9.2%다(모델이 우연한 패턴도 배울 수 있다).
  • 특성 중요도: 온도_C 48.8%, 진공도_mTorr 21.1%, 압력_Pa 16.7%, 가스유량_slm 9.2%, 두께_nm 4.2%, 습도_pct 0.0%. 중요도는 "모델이 질문에 많이 쓴 열"일 뿐 원인이라는 뜻이 아니다. 가스유량·습도는 합격여부와 관계없게 만든 비교용 열이라 중요도가 0보다 커도 원인 후보로 부르지 않는다. 원인 후보는 아래 밖/안 비교처럼 근거 수치가 있는 열(온도·진공도)에만 쓴다.
  • 트리 위쪽 질문(학습용 588건): "온도 ≤ 293.95℃?" → "온도 ≤ 306.05℃?" → "진공도 ≤ 5.49 mTorr?". 세 질문을 모두 안전한 쪽으로 통과한 406건의 불합격 비율은 9.4%.
  • 온도(295~305℃)×진공도(4.5~5.5 mTorr) 범위별 불합격 비율(735건): 둘 다 안 8.0%, 온도만 밖 33.2%, 진공도만 밖 32.6%, 둘 다 밖 56.5%. 열 하나씩 밖/안으로만 나누면 온도 밖 239건 중 90건 37.7% / 안 496건 12.7%, 진공도 밖 141건 중 57건 40.4% / 안 594건 16.2%(가스유량 밖 241건 20.3% / 안 494건 21.1%와 같은 방식). 원인 후보 문장의 근거 수치는 이 밖/안 값을 쓴다.
  • 같은 분할에서 Feature를 바꾼 결과(max_depth=4, labels=[1, -1], 과제 2·운영안 참고용): 온도·진공도 두 개 80.3% [[110, 6], [23, 8]], 온도 하나만 78.2% [[103, 13], [19, 12]](불합격 12건을 잡지만 헛경보 13건). 모의고사가 147건뿐이라 몇 건 차이는 나누는 방식에 따라 바뀔 수 있다.
  • dropna()를 건너뛰면(750행) 정확도 79.3%(시험용 150개 중 119개 — Orange 기준선 79.3%와 숫자만 우연히 같다).

실제 현업 데이터와 다른 점

완전한 가상 데이터다. 불균형(합격이 불합격보다 훨씬 많음)과 "정확도의 함정"(기준선과 거의 같은 정확도)을 직접 관찰하도록 구성했다. 가스유량·습도는 합격여부와 관계없게 만든 비교용 열이다.

생활 예제 데이터 — week09_easy_outdoor_class.csv

목적

의도적으로 포함된 패턴(실제 값)

  • 크기 120행 x 6열. 결측 4칸(최고기온_C 1, 습도_pct 2, 풍속_m_s 1). dropna() 하면 116행.
  • 정답 분포(116행): 진행(1) 82일, 취소(-1) 34일 → 진행이 70.7%로 한쪽 답이 더 많은 불균형 데이터(원본 120행 기준 진행 84, 취소 36).
  • 조건별 취소(116행, 조건은 서로 겹칠 수 있음): 강수량 5mm 이상 22일 중 21일, 풍속 9m/s 이상 7일 중 7일, 기온 32℃ 이상 7일 중 7일, 약한 비(0~5mm) 10일 중 3일, 아무 조건에도 해당하지 않는 날 75일 중 1일(2024-04-04). 강수량 5mm 미만인데 풍속 9m/s 이상이거나 기온 32℃ 이상인 날은 9일이고 모두 취소했다("비만 보면 놓치는 날", 강의 "왜 여러 Feature" 절).

이번 차시 핵심 수치(실제 실행 결과, max_depth=4, random_state=42)

강의·노트북에서는 반도체 변수와 섞이지 않도록 쉬운 예제 변수 앞에 easy_를 붙인다(반도체 문제는 easy_를 뗀 이름).

  • easy_feature_cols = ["최고기온_C", "습도_pct", "풍속_m_s", "강수량_mm"], easy_y = easy_df["진행여부"].
  • train_test_split(easy_X, easy_y, test_size=0.2, random_state=42, stratify=easy_y) → 92행 / 24행(모의고사 실제 진행 17, 취소 7).
  • 모델 정확도 91.7%(24건 중 22건). "무조건 진행" 기준선 (easy_y_test == 1).mean() = 70.8%(17건). 모델이 기준선보다 5건 더 맞힌다(반도체 데이터는 2건 차이였다).
  • 혼동행렬 confusion_matrix(easy_y_test, easy_pred, labels=[1, -1]) = [[16, 1], [1, 6]]. 실제 진행 17일 중 16일 맞힘, 1일은 취소로 잘못 예측(헛경보: 2024-04-14, 비 12.1mm였지만 진행한 날). 실제 취소 7일 중 6일 잡아냄, 1일 놓침(2024-04-11, 풍속 9.2m/s로 취소한 날). labels를 빼면 [[6, 1], [1, 16]].
  • 특성 중요도: 강수량_mm 69.8%, 최고기온_C 24.8%, 풍속_m_s 5.4%, 습도_pct 0.0%. 중요도는 "모델이 질문에 많이 쓴 열"일 뿐 원인이라는 뜻이 아니다.
  • 트리가 찾은 질문(학습용 92일): "강수량 ≤ 4.75mm?" → 아니면 취소(17일 모두 취소) / "기온 ≤ 31.75℃?" → 아니면 취소(5일) / "풍속 ≤ 9.9m/s?" → 아니면 취소(1일) / "강수량 ≤ 1.0mm?" → 맞으면 진행(61일 중 취소 1일), 아니면(약한 비) 진행으로 예측하지만 8일 중 3일 취소.
  • dropna()를 건너뛰어도 scikit-learn 1.3 이상의 결정트리는 오류 없이 학습한다(결측값을 스스로 처리함). 이때는 120행이 96행 / 24행으로 나뉘고 정확도 83.3%, 기준선 70.8%다. 강의에서는 5차시 복습으로 dropna()를 먼저 한다.

Orange 워밍업 데이터 — week09_orange_wafer_patterns.csv

목적

9차시 PART 1 Orange 워밍업용 데이터다. 웨이퍼 맵의 불량 모양(정상·중심형·가장자리형·스크래치형)을 요약한 숫자 4개로 Tree(결정 트리)가 패턴을 규칙으로 나누는 모습을 Tree Viewer·Test and Score·Confusion Matrix로 본다. Orange에서는 orange/week09_orange_wafer_patterns.tab을 연다(불량패턴이 목표 열, 웨이퍼ID는 meta). 10차시에도 학습 데이터로 다시 쓴다.

가상 상황

공정 지도 위치공정 지도 ⑦ EDS(전기 검사) 웨이퍼 맵의 요약이다. 웨이퍼 240장마다 다이 317개(이 가상 웨이퍼 설정, 지름 300mm — 실제 다이 수는 칩 크기에 따라 다르다) 검사 결과(웨이퍼 다이 합성기)에서 불합격 다이의 개수와 위치 비율을 계산했다.

행 하나의 의미

한 행 = 웨이퍼 1장의 불량 모양 요약(240행).

의도적으로 포함된 패턴(실제 생성 결과)

  • 240행: 정상 120 · 중심형 40 · 가장자리형 40 · 스크래치형 40. 정상 웨이퍼는 불량 다이 3~8개(무작위 위치).
  • 패턴 세기를 웨이퍼마다 다르게 해 일부는 헷갈리게 만들었다(완벽 분류 방지).
  • Orange 실측(_1_patterns_done.ows, Tree 깊이 4, 10겹):
  • Tree Viewer 첫 갈림길: 불량다이수_count ≤ 11(145행) / > 11(95행) — 먼저 불량 개수로 정상을 떼어 내고, 그다음 갈림길에서 모양(비율)으로 패턴을 나눈다. 정보 줄 17 nodes, 9 leaves(상자 17개, 그중 잎 9개). 가장자리 비율 질문(> 35.3)은 불량다이수_count > 11 갈래 안에서만 쓰인다 — 이 가상 웨이퍼는 다이의 37.9%(120/317)가 가장자리 영역이라, 불량이 적게 흩어진 정상 웨이퍼도 가장자리 비율이 평균 36.5%다.
  • Test and Score: Tree CA 0.942(AUC 0.961).
  • Confusion Matrix(Tree, 실제 → 예측): 정상 119 → 정상(1개는 중심형) / 중심형 33 맞힘, 4 → 정상, 3 → 스크래치형 / 가장자리형 40 모두 맞힘 / 스크래치형 34 맞힘, 4 → 정상, 1 → 중심형, 1 → 가장자리형.
