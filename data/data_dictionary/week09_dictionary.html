9차시 실습 데이터 설명서

대상 파일: week09_pass_fail_train.csv · week09_new_lots_to_predict.csv

목적

Orange3 Tree와 scikit-learn으로 첫 머신러닝 모델(결정트리)을 만들고, 그 모델로 새 로트를 예측해 보는 실습 데이터다. 학습용 데이터(week09_pass_fail_train.csv)와, 정답 없이 예측만 해볼 신규 로트 데이터 (week09_new_lots_to_predict.csv, 9차시 Orange Predictions·파이썬 predict()에서 사용)로 구성된다. Orange 워밍업 데이터 week09_orange_wafer_patterns.csv(학습)·week09_orange_new_wafers.csv(예측)는 이 문서 끝에 있다.

가상 상황

공정 지도 위치week09_pass_fail_train.csv = 공정 지도 ②~⑤(산화·포토·식각·증착/이온주입) + 세정의 공정 조건과 그 작업 뒤 검사 결과(공정 중간 검사와 ⑦ EDS(전기 검사) 결과를 모은 교육용 설정). week09_new_lots_to_predict.csv = ②~⑤ + 세정을 마쳤지만 아직 ⑦ 검사 전인 새 로트.

여러 공정·설비에서 측정한 공정 조건과 그 작업 뒤 검사 결과를 모아, "공정 조건만으로 합격/불합격을 미리 예측할 수 있을까?"를 실험하는 데이터다. 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록).

행 하나의 의미

한 행 = 공정 작업 기록 1건(어느 공정·어느 설비에서 잰 공정 조건)과 그 작업 뒤 검사 결과(공정 중간 검사 + ⑦ EDS 결과를 모은 교육용 설정). 검사 결과는 행마다 붙어 있고, 같은 로트가 여러 행(여러 공정)에 나올 수 있다(이 파일에는 로트 번호 열이 없다).

부호 — 1~8차시와 같은 표기

합격여부는 1~8차시와 같이 1 = 합격, -1 = 불합격이다. 합격 비율은 (y_test == 1).mean()으로 구한다.

week09_new_lots_to_predict.csv 열 설명

week09_pass_fail_train.csv와 같은 8개 열(공정명, 설비번호와 공정 조건 6개: 온도_C, 압력_Pa, 가스유량_slm, 두께_nm, 진공도_mTorr, 습도_pct)만 있고 합격여부는 없다. 아직 검사하지 않은 신규 로트 9건이며, 9차시에서 학습한 모델(Orange Tree → Predictions, 파이썬 model.predict(new_lots[features]))로 이 로트들의 합격/불합격을 예측한다. 예측 결과를 담는 예측 열도 합격여부와 같은 규칙(1 = 합격, -1 = 불합격)이다.

압력_Pa 값의 한계 (교육용 가상 데이터)

압력_Pa는 교육용으로 생성한 가상 값이며 실제 측정값이 아니다. 이번 차시의 실측 범위는 학습용 데이터가 약 982.9~1,041.8 Pa(평균 약 1,011.9 Pa), 신규 로트 데이터가 약 989.2~1,031.7 Pa(평균 약 1,013.3 Pa)인데, 이 자릿수는 Pa로 읽은 챔버 압력보다 hPa로 읽었을 때의 자릿수에 가깝다(대기압이 약 1,013 hPa = 101,325 Pa다). 단위 라벨과 값의 자릿수가 서로 맞지 않는다. 같은 행의 진공도_mTorr와도 맞지 않는다. 진공도 평균 약 5.01 mTorr는 약 0.67 Pa인데(1 mTorr ≈ 0.133 Pa) 같은 행의 압력_Pa는 평균 약 1,011.9 Pa여서 약 1,510배 차이가 난다 — 한 챔버가 같은 시각에 두 압력일 수는 없다. 신규 로트 데이터도 같다(진공도 평균 약 4.79 mTorr ≈ 0.64 Pa, 압력 평균 약 1,013.3 Pa, 약 1,590배). 이 값이 실제로 어떤 공정 조건을 나타내는지는 단정할 수 없으므로, 실습에서는 압력_Pa의 절대값을 물리적으로 해석하지 않고 수치 열 하나로만 다룬다.

학생이 물어보면"교육용으로 만든 가상 값이라 단위와 자릿수가 실제 공정과 맞지 않습니다. 이번 실습에서는 압력의 절대값을 해석하지 않고 값들 사이의 상대적인 차이만 봅니다"라고 답한다.

데이터를 다시 만들면 1~9차시의 실습 결과 수치와 강의 자료가 모두 함께 바뀌므로, 현재 버전은 값을 그대로 두고 이 한계를 여기에 명시하는 쪽을 택했다.

이번 차시 수업에서 쓰는 값(노트북·Orange 실제 출력, max_depth=4, random_state=42)

실습지 문제의 답(온도 한 열 정확도, Orange Test and Score·Confusion Matrix·Predictions 값)은 이 설명서에 싣지 않는다. 실습지에서 직접 구한다.

  • 노트북 1단계: (750, 9) → 빈칸 온도_C 1 · 압력_Pa 3 · 가스유량_slm 3 · 습도_pct 8 → dropna() 뒤 (735, 9).
  • 노트북 2단계(6개 열): X (735, 6) · y (735,) → 학습용 588 · 시험용 147(시험용 실제 합격 116건, 불합격 31건).
  • 노트북 3단계: 정확도 80.3%(147건 중 118건). "무조건 합격" 기준선 78.9%(116건) — 모델과 2건 차이라 정확도 하나로는 판단하기 어렵다. 시험용 불합격 31개 중 9개를 잡고 22개를 놓쳤다.
  • 노트북 4단계 model.predict(new_lots[features])(새 로트 9개): 3번째 로트(식각 · EQ-04 · 온도 289.8℃)만 불합격(-1), 나머지 8개 합격(1) → 새 로트 9개 중 불합격 예측 1개.
  • Orange(Orange 3.40, Tree 깊이 4, 750행 전체 — Orange는 빈칸을 스스로 처리해 행을 지우지 않는다):
  • Distributions(합격여부): 1 = 595, -1 = 155 → 기준선 79.3%(595 ÷ 750).
  • Tree Viewer 첫 갈림길: 온도_C ≤ 293.9(80행 중 불합격 44행, 55.0%) / > 293.9(669행). 트리는 기록을 잘 나누는 열을 고를 뿐이라, 온도는 불합격의 원인 후보까지다.
  • 파이썬과 Orange는 학습한 행(588 vs 750)·빈칸 처리·트리 기본 설정·채점 방법이 달라 숫자가 조금씩 다르다.

목적

반도체 데이터(week09_pass_fail_train.csv)로 합격/불합격을 예측하기 전에, 날씨로 "야외 체육 수업을 했는지"를 맞히는 생활 예제로 같은 머신러닝 순서(결측 정리 → Feature/Label 나누기 → train_test_split(stratify=y) → DecisionTreeClassifier(max_depth=4) → 정확도 → "무조건 다수" 기준선 → 혼동행렬 → feature_importances_)를 먼저 연습하는 생활 예제용 가상 데이터다.

가상 상황

어느 학교가 2024-04-01부터 2024-07-29까지 120일 동안, 그날 날씨와 야외 체육 수업을 실제로 했는지(진행/취소)를 적었다. 비가 많이 오거나, 바람이 세거나, 아주 더운 날은 대부분 취소했고, 약한 비가 온 날은 진행과 취소가 반반쯤이었다.

의도적으로 포함된 패턴(실제 값)

  • 크기 120행 x 6열. 결측 4칸(최고기온_C 1, 습도_pct 2, 풍속_m_s 1). dropna() 하면 116행.
  • 정답 분포(116행): 진행(1) 82일, 취소(-1) 34일 → 진행이 70.7%로 한쪽 답이 더 많은 불균형 데이터(원본 120행 기준 진행 84, 취소 36).

이번 차시 핵심 수치(실제 실행 결과, max_depth=4, random_state=42)

강의·노트북에서는 반도체 변수와 섞이지 않도록 쉬운 예제 변수 앞에 easy_를 붙인다(반도체 문제는 easy_를 뗀 이름).

  • easy_feature_cols = ["최고기온_C", "습도_pct", "풍속_m_s", "강수량_mm"], easy_y = easy_df["진행여부"].
  • train_test_split(easy_X, easy_y, test_size=0.2, random_state=42, stratify=easy_y) → 92행 / 24행(모의고사 실제 진행 17, 취소 7).
  • 모델 정확도 91.7%(24건 중 22건). "무조건 진행" 기준선 (easy_y_test == 1).mean() = 70.8%(17건). 모델이 기준선보다 5건 더 맞힌다(반도체 데이터는 2건 차이였다).
  • 혼동행렬 confusion_matrix(easy_y_test, easy_pred, labels=[1, -1]) = [[16, 1], [1, 6]]. 실제 진행 17일 중 16일 맞힘, 1일은 취소로 잘못 예측(헛경보: 2024-04-14, 비 12.1mm였지만 진행한 날). 실제 취소 7일 중 6일 잡아냄, 1일 놓침(2024-04-11, 풍속 9.2m/s로 취소한 날). labels를 빼면 [[6, 1], [1, 16]].
  • 특성 중요도: 강수량_mm 69.8%, 최고기온_C 24.8%, 풍속_m_s 5.4%, 습도_pct 0.0%. 중요도는 "모델이 질문에 많이 쓴 열"일 뿐 원인이라는 뜻이 아니다.
  • 트리가 찾은 질문(학습용 92일): "강수량 ≤ 4.75mm?" → 아니면 취소(17일 모두 취소) / "기온 ≤ 31.75℃?" → 아니면 취소(5일) / "풍속 ≤ 9.9m/s?" → 아니면 취소(1일) / "강수량 ≤ 1.0mm?" → 맞으면 진행(61일 중 취소 1일), 아니면(약한 비) 진행으로 예측하지만 8일 중 3일 취소.
  • dropna()를 건너뛰어도 scikit-learn 1.3 이상의 결정트리는 오류 없이 학습한다(결측값을 스스로 처리함). 이때는 120행이 96행 / 24행으로 나뉘고 정확도 83.3%, 기준선 70.8%다. 강의에서는 5차시 복습으로 dropna()를 먼저 한다.

Orange 워밍업 데이터 — week09_orange_wafer_patterns.csv

목적

9차시 PART 1 Orange 워밍업용 데이터다. 웨이퍼 맵의 불량 모양(정상·중심형·가장자리형·스크래치형)을 요약한 숫자 4개로 Tree(결정 트리)가 패턴을 규칙으로 나누는 모습을 Tree Viewer·Test and Score로 보고, 학습한 Tree로 새 웨이퍼 10장(week09_orange_new_wafers.csv)을 Predictions로 예측한다. Orange에서는 orange/week09_orange_wafer_patterns.tab을 연다(불량패턴이 목표 열, 웨이퍼ID는 meta).

가상 상황

공정 지도 위치공정 지도 ⑦ EDS(전기 검사) 웨이퍼 맵의 요약이다. 웨이퍼 240장마다 다이 317개(이 가상 웨이퍼 설정, 지름 300mm — 실제 다이 수는 칩 크기에 따라 다르다) 검사 결과(웨이퍼 다이 합성기)에서 불합격 다이의 개수와 위치 비율을 계산했다.

행 하나의 의미

한 행 = 웨이퍼 1장의 불량 모양 요약(240행).

열 설명

열 이름 쉬운 설명 데이터 형식 단위 예시 결측값 가능 여부

가장자리불량비율_pct불합격 다이 중 가장자리(112mm 바깥)에 있는 비율실수%33.3없음

불량패턴웨이퍼의 불량 모양: 정상 / 중심형 / 가장자리형 / 스크래치형(Orange 목표 열). 정상 = 불량 다이가 몇 개(이 데이터에서 3~8개) 흩어져 있을 뿐 뚜렷한 모양이 없는 웨이퍼(7차시의 "없음")문자열(범주)-정상없음

의도적으로 포함된 패턴(실제 생성 결과)

  • 240행: 정상 120 · 중심형 40 · 가장자리형 40 · 스크래치형 40. 정상 웨이퍼는 불량 다이 3~8개(무작위 위치).
  • 패턴 세기를 웨이퍼마다 다르게 해 일부는 헷갈리게 만들었다(완벽 분류 방지).
  • Orange 실측(Orange 3.40, _1_patterns_done.ows, Tree 깊이 4): 가장자리형 40장은 가장자리불량비율_pct > 35.3 상자 하나(가장자리형 100%, 40/40)에 모두 모인다. 이 질문은 트리의 둘째 줄에서 쓰인다 — 이 가상 웨이퍼는 다이의 37.9%(120/317)가 가장자리 영역이라, 불량이 적게 흩어진 정상 웨이퍼도 가장자리 비율이 평균 약 36%(36.5%)다. 트리의 첫 질문과 정확도(CA)는 실습지 문제 3에서 직접 읽는다.
  • 갈림길 열(불량 개수·위치 비율)은 같은 ⑦ 웨이퍼 맵을 요약한 숫자라, 불량 모양을 나타내는 단서(증상의 묘사)이지 원인도 원인 후보도 아니다. 원인 후보를 찾으려면 ②~⑤ 공정 기록 쪽을 봐야 한다.
