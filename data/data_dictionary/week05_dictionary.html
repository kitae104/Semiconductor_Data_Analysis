5차시 실습 데이터 설명서

대상 파일: week05_dirty_process_data.csv

목적

결측값·중복값·이상값 등 "지저분한 데이터"를 찾아 정리하는 실습을 위해 의도적으로 오염시킨 데이터다.

가상 상황

공장 데이터에 흔히 끼어드는 문제(빈 칸, 같은 기록의 중복 저장, 튀는 값, 잘못된 날짜 형식, 오타 등)를 재현했다. 현실에서는 센서가 잠깐 꺼지거나 통신이 끊겨 빈칸이 생기고, 같은 기록이 두 번 전송돼 중복이 생기며, 센서 고장·단위 실수·입력 실수 또는 실제 설비 문제로 튀는 값이 생긴다. 이 데이터의 오류는 연습을 위해 일부러 넣은 것이라 하나하나의 실제 이유는 없다.

행 하나의 의미

한 행 = 1건의 공정 기록(단, 일부는 중복 저장되었거나 값이 잘못 입력됨).

단위 읽는 법

이번 차시에 새로 나오는 단위들이다. 열 이름의 밑줄 뒤가 단위인 규칙은 1차시와 같다.

표기 읽는 법 뜻
cm (키_cm)센티미터길이. 100cm = 1m
kg (몸무게_kg)킬로그램무게. 1kg = 1000g
sec (처리시간_sec)초 (영어로 second의 줄임)시간. 60초 = 1분

정상 범위 (교육용 예시)

온도 295~305℃, 압력 995~1025 Pa, 가스유량 47~53 slm.

압력_Pa 값의 한계 (교육용 가상 데이터)

압력_Pa는 교육용으로 생성한 가상 값이며 실제 측정값이 아니다. 이번 차시의 실측 범위는 약 996.3~1,033.1 Pa(평균 약 1,013.2 Pa)인데(의도적으로 심은 음수 이상값 2건과 결측값 2건은 제외한 범위다), 이 자릿수는 Pa로 읽은 챔버 압력보다 hPa로 읽었을 때의 자릿수에 가깝다(대기압이 약 1,013 hPa = 101,325 Pa다). 단위 라벨과 값의 자릿수가 서로 맞지 않는다. 이 값이 실제로 어떤 공정 조건을 나타내는지는 단정할 수 없으므로, 실습에서는 압력_Pa의 절대값을 물리적으로 해석하지 않고 수치 열 하나로만 다룬다.

학생이 물어보면"교육용으로 만든 가상 값이라 단위와 자릿수가 실제 공정과 맞지 않습니다. 이번 실습에서는 압력의 절대값을 해석하지 않고 값들 사이의 상대적인 차이만 봅니다"라고 답한다.

데이터를 다시 만들면 1~10차시의 실습 결과 수치와 강의 자료가 모두 함께 바뀌므로, 현재 버전은 값을 그대로 두고 이 한계를 여기에 명시하는 쪽을 택했다.

의도적으로 포함된 이상 현상(실제 생성 결과)

  • 결측값(NaN) 총 10건(온도 3, 압력 2, 가스유량 3, 합격여부 2)
  • 완전 중복 행 3건
  • 날짜 형식이 다른 측정시간 2건
  • 500℃ 이상 극단 고온 2건(약 540.3℃, 557.7℃)
  • 음수 압력 2건(약 -42.9, -27.0 Pa)
  • 비정상 가스유량(음수 또는 200 이상) 2건(-5.0, 250.0 slm)
  • 공정명 오타 3건(중착, 식각 (공백 포함), 포토공정)
  • 합격여부 누락 2건

이번 차시 분석 질문

  • 결측값은 열별로 몇 개씩 있는가?
  • 정제 전후 행 개수와 평균 온도는 어떻게 달라지는가?(실제: 113행 → 102행, 평균 온도 304.9℃ → 300.6℃로 약 4.3℃ 차이, 평균 압력 994.4 → 1013.6. 정제 순서는 합격여부 빈 행 제거 → 측정값 빈칸 중앙값 대체 → 중복 제거 → 이상값 행 제거)
  • 이상값 행을 지우기 전에 다른 열과 함께 보면 무엇이 보이는가?(실제: 이상값 6건 모두 합격(1), 그중 4건이 EQ-03 기록. 오염 위치는 무작위로 정했으므로 이 쏠림은 우연이다. 수업에서는 "확인할 단서"로만 다룬다)
  • (5차시 실습 범위 밖) 공정명 오타 3건과 형식이 다른 측정시간 2건은 "입력 오류"의 예로 데이터에 남아 있다. 5차시에서는 이름만 소개하고 코드로 고치지 않는다.

실제 현업 데이터와 다른 점

완전한 가상 데이터이며, 여기 포함된 오류들은 학습 목적으로 의도적으로 삽입한 것이다. 실제 현업 데이터의 오류 유형은 이보다 다양하고 발견하기 어려울 수 있다.

생활 예제 데이터 — week05_easy_class_records.csv

목적

반도체 데이터(week05_dirty_process_data.csv)를 정리하기 전에, 학급 학생 기록으로 같은 정리 순서 (describe() → 정리 전 값 기억 → isna().sum() → dropna(subset=...) → 중앙값 fillna() → duplicated()·drop_duplicates() → 이상값 찾기·확인·제거 → 정리 전후 비교)를 먼저 연습하는 생활 예제용 가상 데이터다.

가상 상황

담임 선생님이 세 반(1반·2반·3반) 학생 14명의 키·몸무게·수학 점수를 표로 옮겨 적다가 실수를 몇 군데 했다.

행 하나의 의미

한 행 = 학생 1명의 기록(단, 마지막 행은 같은 학생을 한 번 더 적은 중복이다).

열 설명

열 이름 쉬운 설명 데이터 형식 단위 예시 결측값 가능 여부
이름학생 이름문자열-박지호없음
반학생의 반. 빈칸이면 어느 반인지 추측할 수 없어 행을 지운다(반도체 데이터의 합격여부 자리)문자열-1반있음(1칸)
키_cm학생의 키실수cm165.2있음(1칸)

정상 범위 (교육용 예시)

키 140~200cm, 몸무게 35~100kg, 수학 점수 0~100점. 이 범위는 학습용으로 정한 것이다.

의도적으로 포함된 패턴(실제 값)

  • 크기 15행 x 5열.
  • 결측 3칸: 반 1칸(조예준), 키_cm 1칸(최수아), 몸무게_kg 1칸(장서준). 열마다 15행 중 1칸(6.7%).
  • 완전 중복 1행: 마지막 행(행 번호 14)이 박지호(1반, 171.0, 63.5, 78)를 한 번 더 적은 것이다. students.duplicated().sum() = 1.
  • 입력 실수 이상값 1개: 정도윤의 키 1720.0(172.0을 소수점 없이 잘못 적음). students[students["키_cm"] > 250]로 1건 찾는다.
  • 정리 전 describe(): 키 count 14, mean 276.6, 50%(중앙값) 166.75, max 1720.0 / 몸무게 mean 56.4 / 수학 점수 mean 83.1. 평균 키 276.6cm는 이상값 하나 때문에 생긴 값이고, 중앙값 166.75cm는 거의 흔들리지 않는다(빈칸을 평균이 아니라 중앙값으로 채우는 이유).
  • 강의와 같은 순서로 정리한 실제 결과: dropna(subset=["반"]) → 14행 / 중앙값으로 채우기(키 165.2, 몸무게 53.6 — 반 빈칸 행을 지운 뒤 계산) / drop_duplicates() → 13행 / students[students["키_cm"] <= 250] → 12행.
  • 정리 전후 비교: 행 15 → 12, 평균 키 276.6 → 164.8, 평균 몸무게 56.4 → 54.6.
