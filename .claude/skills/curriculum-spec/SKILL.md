# 차시 스펙 설계

## 이 과정이 무엇인지 먼저 안다

- **대상**: 프로그래밍 경험이 **거의 없는 일반인**. 전공자도, 데이터 과학자 지망생도 아니다.
- **목표**: "데이터로 공정 상태를 **설명할 수 있는 사람**"이지, 모델을 튜닝하는 사람이 아니다.
- **데이터**: 전부 교육용으로 생성한 **가상 데이터**. 실제 기업 생산 데이터가 아니다.
- **기준 문서**: `docs/curriculum.md`(v2)가 설계, `docs/restructure-plan.md`가 변경 배경이다.

설계 의도와 실제 파일이 다를 수 있다. **실제 `lectures/weekXX/index.html`과 노트북을 읽어
현재 상태를 확인한 뒤** 스펙을 쓴다. 문서만 읽고 쓴 스펙은 이미 고쳐진 것을 또 고치게 한다.

## 차시 스펙의 필수 항목

한 차시를 정의하려면 아래 8개가 모두 있어야 한다. 하나라도 비면 작성자가 추측하게 되고,
추측한 내용은 앞뒤 차시와 어긋난다.

| 항목 | 설명 | 예 (4차시) |
|---|---|---|
| **선수 지식** | 직전 차시들에서 **실제로 배운** 것 중 이번 차시가 전제하는 것 | 3차시 — 반복문·함수로 한 줄씩 처리하기 |
| **학습 목표** | 학생이 끝나고 **할 수 있게 되는 일**. "이해한다"가 아니라 "~한다" | read_csv로 CSV를 읽고 열 선택·조건 검색·정렬을 한다 |
| **오늘의 질문** | 차시 전체를 꿰는 한 문장 질문. 히어로에 그대로 실린다 | "3차시에 반복문으로 한 줄씩 처리했던 일을, Pandas는 어떻게 한 번에 처리할까?" |
| **다룰 내용** | 개념 목록. 새 함수는 3~5개 이내 | CSV와 DataFrame, 열 선택, 불리언 인덱싱, 정렬, loc/iloc |
| **실습 흐름** | 손을 움직이는 순서. **강의는 수업 흐름 묶음 5~6개, 노트북은 셀 단위 단계**로 적는다(입도가 다른 것이 정상이다). 자세한 규칙은 아래 「강의 단계와 노트북 단계는 입도가 다르다」 | read_csv → 열 선택 → 조건 검색 → 정렬 → loc/iloc → 3차시 결과와 대조 |
| **데이터** | 쓰는 CSV 파일명 | `week04_process_filtering.csv` |
| **핵심 질문 → 데이터 연결** | 이 차시의 분석으로 답하는 구체적 질문 | EQ-02에서 발생한 불합격은 몇 건인가? |
| **다음 차시로 넘기는 것** | 다음 차시가 전제할 결과물 | 조건 검색으로 걸러낸 데이터 — 5차시가 이것을 정제한다 |

## 난이도 계단 규칙

이 과정이 무너지는 방식은 늘 같다 — 한 차시가 혼자 어려워진다.

1. **새 개념 예산 3~5개 — 세는 대상은 "활성 개념"이다.**
   한 차시에 새로 등장하는 파이썬 함수·개념 중 **활성 개념**만 3~5개로 센다(`docs/curriculum.md`).

   | 구분 | 정의 | 예산 |
   |---|---|---|
   | **활성 개념** | 학생이 노트북 TODO를 직접 채우거나, 실습지·`quiz.json`에서 평가받거나, 강의가 정식으로 설명하고 실행시키는 것 | **3~5개** |
   | **노출 전용 개념** | 아래 3조건을 **모두** 만족하는 것. 강사 시연·AI가 생성한 코드·다음 차시 예고 콜아웃에서 **눈으로만** 보는 것 | 예산 밖 |

   노출 전용의 3조건 — **하나라도 어기면 활성으로 센다**:
   1. 자료 본문에 "오늘 배우지 않는다"는 취지의 단서가 **그 자리에** 있다.
   2. 실습지·`quiz.json` 어디에서도 평가하지 않는다.
   3. 학생이 그 코드를 처음부터 작성하지 않는다(완성 코드 실행, 또는 AI가 만들어준 코드).

   **노출 전용 개념은 예산에서 빼는 대신 차시 스펙에 반드시 목록으로 명시한다.** 목록에 없는
   노출 전용 개념은 "빠뜨린 것"과 구분되지 않는다.

   `head()`/`shape`/`columns`처럼 같은 실습 단계에서 한 묶음으로 쓰이는 조회 동작, `input()`/`int()`처럼
   항상 함께 등장하는 짝(`int(input(...))`)은 **1개로 센다**. DataFrame·Series 같은 자료구조 "이름"은
   함수가 아니므로 예산 밖이며 용어 카드로 처리한다.

   활성 개념이 상한을 넘으면 다음 차시로 이월하거나 기존 내용을 덜어낸다. 넘기기로 결정했다면
   **그 사실과 이유를 `docs/curriculum.md`의 해당 차시 「다룰 내용」에 한 줄로 명시한다** —
   조용히 넘기지 않는다. 현재 명시적으로 초과를 허용한 차시는 **4차시(활성 6개)** 하나다.

   > **이 구분이 필요한 이유(2026-09-23 명문화).** 이 과정은 전 차시에 "🤖 AI에게 물어보기" 박스를
   > 두고, 모든 차시 노트북이 "AI로 재미있는 미니 프로그램 만들기"로 끝난다. 이 설계는 *의도적으로*
   > 아직 안 배운 문법을 보여준다. 구분 없이 세면 과정 설계와 규칙이 구조적으로 충돌한다.
   >
   > **판정 근거(실측)** — 1차시는 `notebooks/student/week01_student.ipynb`의 TODO 빈칸이
   > `=`(대입)·f-string·`input()` **셋뿐**이다. 여기에 강의가 정식으로 설명하고 실행시키는
   > `print()`·`type()`(`lectures/week01/index.html:478-480`, 실습 3단계), 그리고 실습지 9번이
   > 평가하는 `int()`(`lectures/week01/worksheet.html:135-146`)를 더해도 — `input()`/`int()`를
   > 위 짝 규칙으로 1개로 세면 — **활성 5개로 상한 내**다.
   > 반면 `if`/`else`·`import`·`random.seed()`·`random.choice()`는 정답용·강사용 노트북의
   > **AI 미니 프로그램 셀에만** 있고(학생용 노트북에는 코드가 없다) 실습지·퀴즈에서 평가하지 않으므로
   > **노출 전용**이다.
2. **이론은 누적, 반복 아님.** 매 차시 개념을 처음부터 다시 설명하지 않고, 이전 차시 위에
   한 단계만 올린다. 대신 **연결 문장은 반드시 넣는다** — "3차시에 `for`+`if`로 했던 걸 한 줄로".
3. **앞에서 안 배운 것을 쓰지 않는다.** 스펙을 쓰기 전에 해당 개념이 실제로 앞 차시에
   나왔는지 `grep`으로 확인한다. 설계 문서에 있다고 실제 자료에 있는 것은 아니다.
4. **Orange3는 예고편이지 선생이 아니다.** 5~10차시에서 Orange3는 항상 **"먼저 Orange3로
   훑어보고 → 이어서 파이썬 코드로 확인"** 순서다. Orange3가 새 개념을 먼저 가르치지 않는다.
5. **"결과 해석 문장 쓰기"는 1~10차시 전부의 고정 활동이다.** 어느 차시에서도 빼지 않는다.
   이 과정의 목표가 "설명할 수 있는 사람"이기 때문이다.
6. **8차시부터 "상관관계 ≠ 원인"을 반복한다.** 이것이 9~10차시의 "예측이 맞았다고 원인을 안다는
   뜻은 아니다"로 이어진다.

## 강의 단계와 노트북 단계는 입도가 다르다

> **2026-09-23 — "노트북 단계와 1:1 대응한다"는 규칙은 폐기됐다.** 아래가 대체 규칙이다.

| | 강의 `index.html` `<div class="step">` | 노트북 `## N단계` |
|---|---|---|
| 단위 | **수업 흐름 묶음** | **셀 단위 작업** |
| 개수 | **5~6개를 넘기지 않는다** | 제한 없음(현재 8~15개) |

1. **강의 실습 단계마다 대응 노트북 단계를 괄호로 병기한다.**
   예: `<b>조건 검색</b> — … 행 개수를 확인한다. (노트북 4~5단계)`
   노트북에 대응이 없는 단계(Orange3 화면, 강의 전용 관찰)는 `(노트북 대응 없음 — …)`이라고 적는다.
2. **순서는 일치해야 한다.** 강의 1단계가 노트북 1~N단계를 묶는 **포함 관계(1:N)는 허용**하고,
   **순서 역전은 금지**한다. 어긋나면 노트북이 아니라 **설계 문서(`docs/curriculum.md` 실습 흐름)를
   기준으로 판정**하고 어긋난 쪽을 고친다.
3. **운영안(`instructor-guide.md`)은 항상 노트북 단계 번호로 지시한다.** 강사는 노트북을 띄워놓고
   진행하기 때문이다. 강의 실습 절을 가리킬 때만 **"강의 실습 N번"** 이라고 접두어를 붙인다.
   접두어 없는 "N단계"는 언제나 노트북을 뜻한다.

> **폐기 근거(실측).** 10차시 전부에서 강의 step과 노트북 `## N단계`를 추출해 대조한 결과,
> 순서 역전은 **4차시 한 곳뿐**이었고(강의 5=loc/iloc↔노트북 11단계, 강의 6=종합↔노트북 7단계)
> 나머지 **9차시는 "순서 일치 + 1:N 포함"** 으로 이미 만들어져 있었다.
> 게다가 10차시 노트북 전부가 동일한 **꼬리 블록**(정리 문장 → AI 질문 → AI 코드 생성 → 연습문제 →
> AI 미니 프로그램)을 갖는다. 1:1로 펼치면 모든 차시의 강의 실습 절이 **11~15단계로 늘어나고
> 그중 5개가 매 차시 똑같아져**, 강의 자료의 "오늘 뭘 하는지" 한눈 보기 기능을 잃는다.
> `docs/curriculum.md`의 각 차시 「실습 흐름」도 이미 5~6개 묶음 단위로 쓰여 있다. 즉 현실이 아니라
> 규칙이 틀렸다.

## 영향 범위를 산출물로 못 박는다

스펙의 변경 항목마다 **어떤 파일이 바뀌는지** 적는다. 이 표를 안 쓰면 반드시 일부가 누락되고,
가장 자주 누락되는 것은 **퀴즈와 데이터사전**이다.

| 변경 성격 | 딸려 오는 산출물 |
|---|---|
| 설명·비유 보강 | 강의 HTML (+ 용어 카드면 실습지) |
| 코드 예제 추가·변경 | 강의 HTML + 노트북 3종 + 운영안 핵심 수치 (+ 실습지) |
| 실습 문제 추가 | 실습지 + 학생용/정답 노트북 + 운영안 (+ 퀴즈) |
| 데이터 열·값 변경 | `generate_weekly_data.py` + 주차 CSV + **데이터사전** + 강의/노트북의 모든 참조 + `validate_datasets.py` |
| 개념 추가 | 위 전부 + `docs/curriculum.md` + **퀴즈** |
| 차시 순서·제목 변경 | 전 차시 `week-nav` + 랜딩 `index.html` + `README.md` + `docs/curriculum.md` |

## 검증 기준을 확인 가능하게 쓴다

스펙의 "검증 기준"은 consistency-qa의 체크리스트가 된다. 확인할 수 없는 문장은 기준이 아니다.

| 나쁜 기준 | 좋은 기준 |
|---|---|
| 설명이 더 쉬워진다 | 새로 등장하는 용어 3개 각각에 한 줄 설명과 비유가 `.term-card`로 있다 |
| 3차시와 연결된다 | 4차시 실습이 3차시와 **같은 CSV·같은 조건**을 쓰고, 결과 건수가 3차시 함수 결과와 일치함을 학생이 직접 확인한다 |
| 퀴즈를 보강한다 | `quiz.json` 문항이 13개 이상이고, 추가 문항 전부가 강의 본문에서 실제로 다룬 내용이다 |
| 노트북이 잘 돌아간다 | `python scripts/validate_notebooks.py`가 week04에서 FAIL 0건 |
| 강의와 노트북이 맞물린다 | 강의 `<div class="step">` 개수와 "노트북"을 포함한 step 개수가 같고, 병기한 노트북 번호의 순서가 단조 증가한다 |

## 범위를 지키는 법

개선 요청은 작업 중에 커진다. 스펙에 **"건드리지 않을 것"** 절을 반드시 넣는다.
명시적으로 범위 밖이라고 적힌 항목은 작업자가 손대지 않는다.

요청이 커리큘럼 원칙과 충돌할 때(예: 비전공자 과정에 고급 Pandas 요구) — 거부하지 않는다.
충돌 사실과 완화안(선택 심화로 분리, 부록으로 이동)을 스펙에 적고 진행한다. 최종 판단은
사용자 몫이다. 다만 **CLAUDE.md의 절대 규칙**(원본 데이터 수정, `fab.csv` 센서 의미 단정,
인과 단정)은 협상 대상이 아니다.
