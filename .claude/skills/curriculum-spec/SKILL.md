# 차시 스펙 설계

## 이 과정이 무엇인지 먼저 안다

- **대상**: 프로그래밍 경험이 **거의 없는 일반인**. 전공자도, 데이터 과학자 지망생도 아니다.
- **목표**: "데이터로 공정 상태를 **설명할 수 있는 사람**"이지, 모델을 튜닝하는 사람이 아니다.
- **데이터**: 전부 교육용으로 생성한 **가상 데이터**. 실제 기업 생산 데이터가 아니다.
- **기준 문서**: `docs/curriculum.md`(v3)가 설계, `docs/restructure-plan.md`가 변경 배경이다.

## v3 수업 구조와 분량 (2026-10-23)

한 차시는 PART 세 개다. **1~8차시**: PART 1 파이썬 → PART 2 Orange3 → PART 3 실습지.
**9·10차시**: PART 1 Orange3 → PART 2 파이썬 최소 + ChatGPT 체험 → PART 3 실습지(모델을 먼저 눈으로 본 뒤 코드로 확인).

**분량 비율(저작용 내부 기준 — 이 스킬에만 둔다)**: 차시당 약 150분 분량을 파이썬 ≈ 80 : Orange ≈ 40 : 실습지 ≈ 30으로
잰다. 9·10차시는 Orange가 파이썬보다 크다(대략 Orange 70 : 파이썬+ChatGPT 50 : 실습지 30). 이 숫자는 콘텐츠가 너무 많거나
적은지 판단할 때만 쓴다. **강의 HTML·실습지·노트북·퀴즈·운영안·랜딩·README에는 분·시간을 절대 쓰지 않는다**(시간 정보 제거
정책, `docs/restructure-plan.md`). 운영안 "수업 흐름"은 순서와 "여기서 쉬기" 표시만 쓴다.

PART 내부 흐름(순서만):
- 파이썬: 오늘의 미션·복습 → 개념과 따라 실행(생활 예제) → [여기서 쉬기] → 반도체 데이터로 확인(열 이름만 바꾸기) → 정리
- Orange3: 위젯 이름표 → 워밍업 데이터(`_1_…_start.ows`) → 반도체 데이터(`_2_…_start.ows`) → 파이썬 결과와 비교 한 문장
- 실습지: 혼자 풀기(노트북 반도체 TODO 3 + Orange 1) → 정답 확인과 해석 문장 발표

과정 전체는 "신입 데이터 담당자의 10일" 이야기로 잇는다. 차시 스펙에 **오늘의 미션** 한 줄을 반드시 쓴다(가상 고지 유지).

설계 의도와 실제 파일이 다를 수 있다. **실제 `lectures/weekXX/index.html`과 노트북을 읽어
현재 상태를 확인한 뒤** 스펙을 쓴다. 문서만 읽고 쓴 스펙은 이미 고쳐진 것을 또 고치게 한다.

## 10차시 구성

| Phase | 차시 | 파이썬(활성 개념) | Orange3 새 위젯 |
|---|---|---|---|
| 1 · 첫걸음 | 1 | `=`, `print`, f-string, `type` | File, Data Table, Distributions |
| | 2 | 리스트·인덱스, `len`/`append`, `max`/`min`/`sum`, 딕셔너리 | Column Statistics |
| | 3 | `if`/`else`, `for` 세기, `def` 하나 | Select Rows |
| 2 · 데이터 다루기 | 4 | `read_csv`, 열 선택, 조건 검색, `sort_values` | Select Columns |
| | 5 | `describe`, `isna().sum()`, `dropna`, `drop_duplicates` | Impute |
| | 6 | 그래프 틀, 막대, 히스토그램, 산점도 | Scatter Plot, Box Plot |
| 3 · 비교와 원인 탐색 | 7 | 비교로 새 열, `groupby().mean()` | Pivot Table |
| | 8 | `corr`, 상관계수 읽기, 범위 밖 조건(`\|`) | Correlations |
| 4 · 예측 | 9 | Feature/Label, `train_test_split`, `fit`, `accuracy_score` (Orange 먼저) | Tree, Tree Viewer, Test and Score, Confusion Matrix |
| | 10 | `predict` (Orange 먼저) | kNN, Logistic Regression, Predictions |

차시별 워밍업 데이터와 위젯 체인은 `docs/curriculum.md`(v3)와 작업 스펙을 본다.

## 차시 스펙의 필수 항목

한 차시를 정의하려면 아래 8개가 모두 있어야 한다. 하나라도 비면 작성자가 추측하게 되고,
추측한 내용은 앞뒤 차시와 어긋난다.

**v3에서 더하는 항목(2026-10-23)**: 오늘의 미션 한 줄 · 노출 전용 목록과 "현재 대비 빼는 것" · Orange PART(워밍업 데이터 —
새 `weekXX_orange_<주제>.csv`의 행 수·열(단위 접미사)·역할·심을 패턴과 목표 수치, 반도체 `.tab`, `_start`/`_done` 위젯 체인, 학생이 볼 설정·화면, 파이썬 결과와 비교 한 문장) ·
실습지 5문제 제목 · 찾아보기 목록(위치·검색어·ChatGPT 질문) · 퀴즈 구성 · 그날 실제로 나는 오류 3개 후보.
학습 목표는 4개 이하.

| 항목 | 설명 | 예 (4차시) |
|---|---|---|
| **선수 지식** | 직전 차시들에서 **실제로 배운** 것 중 이번 차시가 전제하는 것 | 3차시 — 반복문·함수로 한 줄씩 처리하기 |
| **학습 목표** | 학생이 끝나고 **할 수 있게 되는 일**. "이해한다"가 아니라 "~한다" | read_csv로 CSV를 읽고 열 선택·조건 검색·정렬을 한다 |
| **오늘의 질문** | 차시 전체를 꿰는 한 문장 질문. 히어로에 그대로 실린다 | "3차시에 반복문으로 한 줄씩 처리했던 일을, Pandas는 어떻게 한 번에 처리할까?" |
| **다룰 내용** | 개념 목록. 새 함수는 3~5개 이내 | CSV와 DataFrame, 열 선택, 불리언 인덱싱, 정렬, loc/iloc |
| **실습 흐름** | 손을 움직이는 순서. **강의는 수업 흐름 묶음 5~6개, 노트북은 셀 단위 단계**로 적는다(입도가 다른 것이 정상이다). 자세한 규칙은 아래 「강의 단계와 노트북 단계는 입도가 다르다」 | read_csv → 열 선택 → 조건 검색 → 정렬 → loc/iloc → 3차시 결과와 대조 |
| **데이터** | 쓰는 CSV 파일명 | `week04_process_filtering.csv` |
| **핵심 질문 → 데이터 연결** | 이 차시의 분석으로 답하는 구체적 질문 | EQ-02에서 발생한 불합격은 몇 건인가? |
| **다음 차시로 넘기는 것** | 다음 차시가 전제할 결과물 | 조건 검색으로 걸러낸 데이터 — 5차시가 이것을 정제한다 |

## 난이도 계단 규칙

이 과정이 무너지는 방식은 늘 같다 — 한 차시가 혼자 어려워진다.

1. **새 개념 예산 — 파이썬 활성 개념 4개 이하(v3), Orange 새 위젯 2~3개.**
   한 차시에 새로 등장하는 파이썬 함수·개념 중 **활성 개념**만 센다(`docs/curriculum.md`). v2의 3~5개에서 v3(2026-10-23)에
   **상한 4개**로 줄였다. 하한은 없다 — 7차시(2개)·10차시(1개)처럼 앞 차시 재사용이 많은 차시는 적어도 된다.
   Orange는 그 차시에 **처음 쓰는 위젯**을 2~3개로 센다(File은 1차시에서만). 9차시(Tree·Tree Viewer·Test and Score·Confusion
   Matrix 4개)는 Orange 중심 차시라 허용한 예외다. 한 워크플로의 탐색 위젯은 File 제외 2~4개.

   | 구분 | 정의 | 예산 |
   |---|---|---|
   | **활성 개념** | 학생이 노트북 TODO를 직접 채우거나, 실습지·`quiz.json`에서 평가받거나, 강의가 정식으로 설명하고 실행시키는 것 | **4개 이하** |
   | **노출 전용 개념** | 아래 3조건을 **모두** 만족하는 것. 강사 시연·AI가 생성한 코드·다음 차시 예고 콜아웃에서 **눈으로만** 보는 것 | 예산 밖 |

   노출 전용의 3조건 — **하나라도 어기면 활성으로 센다**:
   1. 자료 본문에 "오늘 배우지 않는다"는 취지의 단서가 **그 자리에** 있다.
   2. 실습지·`quiz.json` 어디에서도 평가하지 않는다.
   3. 학생이 그 코드를 처음부터 작성하지 않는다(완성 코드 실행, 또는 AI가 만들어준 코드).

   **노출 전용 개념은 예산에서 빼는 대신 차시 스펙에 반드시 목록으로 명시한다.** 목록에 없는
   노출 전용 개념은 "빠뜨린 것"과 구분되지 않는다.

   `head()`/`shape`/`columns`처럼 같은 실습 단계에서 한 묶음으로 쓰이는 조회 동작, `input()`/`int()`처럼
   항상 함께 등장하는 짝(`int(input(...))`)은 **1개로 센다**. DataFrame·Series 같은 자료구조 "이름"은
   함수가 아니므로 예산 밖이며 용어 카드로 처리한다.

   활성 개념이 상한을 넘으면 다음 차시로 이월하거나, 기존 내용을 덜어내거나, **Orange PART로 넘긴다**(v3 — 예: `fillna` →
   Impute, 박스플롯 → Box Plot, 혼동행렬 → Confusion Matrix, `predict_proba` → Predictions 확률 열). 넘기기로 결정했다면
   **그 사실과 이유를 `docs/curriculum.md`의 해당 차시 「새 개념 예산」에 한 줄로 명시한다** — 조용히 넘기지 않는다.
   v3 현재 의도적 초과를 선언한 차시는 **없다**(v2의 4차시·6차시 초과는 해소).

   > **이 구분이 필요한 이유(2026-09-23 명문화).** 이 과정은 전 차시에 "AI에게 물어보기" 박스를
   > 두고, 모든 차시 노트북이 "AI로 재미있는 미니 프로그램 만들기"로 끝난다. 이 설계는 *의도적으로*
   > 아직 안 배운 문법을 보여준다. 구분 없이 세면 과정 설계와 규칙이 구조적으로 충돌한다.
   >
   > **판정 근거(실측)** — 1차시는 `notebooks/student/week01_student.ipynb`의 TODO 빈칸이
   > `=`(대입)·f-string·`input()` **셋뿐**이다. 여기에 강의가 정식으로 설명하고 실행시키는
   > `print()`·`type()`(`lectures/week01/index.html:478-480`, 실습 3단계), 그리고 실습지 9번이
   > 평가하는 `int()`(`lectures/week01/worksheet.html:135-146`)를 더해도 — `input()`/`int()`를
   > 위 짝 규칙으로 1개로 세면 — **활성 5개로 상한 내**다.
   > 반면 `if`/`else`·`import`·`random.seed()`·`random.choice()`는 정답 노트북의
   > **AI 미니 프로그램 셀에만** 있고(학생용 노트북에는 코드가 없다) 실습지·퀴즈에서 평가하지 않으므로
   > **노출 전용**이다.
   >
   > **2026-10-08 갱신**: AI 미니 프로그램·도전 실습·연습문제는 전 차시에서 제거됐다. 노출 전용 개념은 이제
   > "AI로 한 걸음 더"의 AI 예시 코드와 강사 시연에서만 생긴다. 위 근거는 당시 기록으로 남긴다.
2. **이론은 누적, 반복 아님.** 매 차시 개념을 처음부터 다시 설명하지 않고, 이전 차시 위에
   한 단계만 올린다. 대신 **연결 문장은 반드시 넣는다** — "3차시에 `for`+`if`로 했던 걸 한 줄로".
3. **앞에서 안 배운 것을 쓰지 않는다.** 스펙을 쓰기 전에 해당 개념이 실제로 앞 차시에
   나왔는지 `grep`으로 확인한다. 설계 문서에 있다고 실제 자료에 있는 것은 아니다.
4. **Orange3는 파이썬에서 배운 것을 넓혀 보는 본 활동이다(v3, 2026-10-23).** v2의 "Orange3는 예고편이지 선생이
   아니다 / 5~10차시 Orange 먼저" 규칙은 폐기됐다. 이제 1~10차시 모두 Orange PART가 있고:
   - 1~8차시는 **파이썬 다음에** Orange, 9·10차시만 **Orange 먼저**(모델을 눈으로 본 뒤 코드로 확인).
   - **워밍업 데이터**로 위젯을 익힌 뒤 **반도체 데이터**에 같은 위젯을 다시 쓰고, 그날 파이썬 결과와 **한 문장으로 비교**한다.
   - **워밍업 데이터 규칙(2026-10-23 사용자 결정)**: Orange 내장 데이터(zoo·iris·titanic·heart_disease·housing)는 **쓰지 않는다**
     (일반 데이터로는 반도체 이해가 쌓이지 않는다). 모두 `generate_weekly_data.py`에서 시드를 고정해 만든
     `weekXX_orange_<주제>.csv`다. **1~3차시**는 생활 공공데이터처럼 생긴 데이터(동네 인구·지하철 승하차·대기환경)로 그날
     파이썬 개념에 맞는 위젯을 익힌다. **4~10차시**는 반도체·공정 이해를 쌓는 데이터(8대 공정 흐름표·클린룸 환경·웨이퍼 맵·
     챔버 센서·웨이퍼 패턴)다. 워밍업마다 Orange에서 **분명한 "아하" 하나**를 설계하고, 스펙에 그 목표 수치를 적는다.
   - 신규 데이터 열 이름은 **한국어 이름 + 영문/SI 단위**(`기온_C`, `PM10_ug_m3`, `승차인원_count`, `가격_KRW`)다. 기존 CSV의
     한국어 단위 열(`온도_섭씨`, `판매량_개`, `풀이시간_초` …)은 **그 차시를 재작성할 때만** 이름을 바꾸고 값은 그대로 둔다.
     스펙에 차시별 이름 변경 표를 쓴다(여러 차시가 함께 쓰는 파일은 같은 롤아웃 묶음에서 바꾼다 — 예: 9·10차시의 week09 파일).
   - 이해용 그림(공정 흐름도·웨이퍼 맵 등)은 `scripts/generate_figures.py`가 데이터에서 그린다(`assets/images/generated/`).
     스펙에 차시별 그림 목록과 원천 데이터를 적는다. Orange 화면 캡처는 `data-shot` 빈자리로 둔다.
   - 그날 파이썬 개념을 다른 데이터·넓은 화면으로 확장하는 것이 원칙이다. 파이썬 예산 밖으로 뺀 기능을 Orange가 맡을 수 있다.
     파이썬보다 앞선 *문법*을 Orange가 요구하지는 않는다(Orange에는 문법이 없다).
   - Orange는 항상 `data/weekly/weekXX/orange/*.tab`을 연다(내장 데이터·`sample-datasets` 경로 금지). utf-8-sig CSV를 직접 열면 첫 열 이름에 BOM이
     붙고 `합격여부`(1/-1)가 연속형으로 잡힌다.
5. **"결과 해석 문장 쓰기"는 1~10차시 전부의 고정 활동이다.** 어느 차시에서도 빼지 않는다.
   이 과정의 목표가 "설명할 수 있는 사람"이기 때문이다.
6. **8차시부터 "상관관계 ≠ 원인"을 반복한다.** 이것이 9~10차시의 "예측이 맞았다고 원인을 안다는
   뜻은 아니다"로 이어진다.
7. **실습지는 기본 5문제, 퀴즈는 8~10문항(v3).** 실습지 = 파이썬 3(노트북 반도체 TODO 문제 1~3과 1:1) + Orange 1 + 해석 문장 1.
   **9·10차시는 파이썬 2(노트북 문제 1~2) + Orange 2(문제 3 워밍업, 문제 4 반도체) + 해석 1**(Orange 중심 차시, 2026-10-23 사용자 결정).
   퀴즈 중 Orange 문항 1~2개. 빨리 끝낸 학생용 과제는 운영안에만 둔다.
8. **찾아보기 질문은 평가하지 않는다(v3).** 차시당 3~6개, 개념 설명 옆. 수업 진행에 꼭 필요한 내용은 본문이 직접 설명한다.
   스펙에는 위치·검색어·ChatGPT 질문을 표로 적는다. 8~10차시 질문은 "원인 후보" 관점, fab.csv 센서 질문 금지.
9. **9·10차시 ChatGPT 체험에는 대체 경로가 반드시 있다.** 계정·연령·학교망 때문에 못 쓰는 학생을 위해 강의에 프롬프트와
   "응답 예시"(실제 응답 아님 표기)를 싣고, 노트북에 응답 예시를 완성 셀로 둔다. "AI가 준 숫자는 직접 실행해 확인" 규칙과
   가상 데이터 고지를 함께 둔다.
10. **차시마다 "오늘의 반도체 이해 포인트" 1~2개와 공정 지도 위치를 스펙에 쓴다(2026-10-23).** 이해 포인트는 강의 결과 정리 +
   퀴즈 1문항 + 운영안 마무리 질문으로 확인한다. 4~10차시는 그날 데이터(워밍업·반도체)마다 공정 지도(① 웨이퍼 제조 ② 산화 ③ 포토
   ④ 식각 ⑤ 증착/이온주입 ⑥ 금속 배선 ⑦ EDS ⑧ 패키징, 세정은 단계 사이, 클린룸은 ②~⑥이 이루어지는 FAB의 공간)의 어디에서 나온 데이터인지 한 줄로 적는다.
   1~3차시 생활 데이터 워밍업에는 공장 비유 한 줄을 붙인다.

## 강의 단계와 노트북 단계는 입도가 다르다

> **2026-09-23 — "노트북 단계와 1:1 대응한다"는 규칙은 폐기됐다.** 아래가 대체 규칙이다.

| | 강의 `index.html` `<div class="step">` | 노트북 `## N단계` |
|---|---|---|
| 단위 | **수업 흐름 묶음** | **셀 단위 작업** |
| 개수 | **5~6개를 넘기지 않는다** | 제한 없음(현재 8~15개) |

1. **강의 실습 단계마다 대응 노트북 단계를 괄호로 병기한다.**
   예: `<b>조건 검색</b> — … 행 개수를 확인한다. (노트북 4~5단계)`
   노트북에 대응이 없는 단계(Orange3 화면, 강의 전용 관찰)는 `(노트북 대응 없음 — …)`이라고 적는다.
2. **순서는 일치해야 한다.** 강의 1단계가 노트북 1~N단계를 묶는 **포함 관계(1:N)는 허용**하고,
   **순서 역전은 금지**한다. 어긋나면 노트북이 아니라 **설계 문서(`docs/curriculum.md` 실습 흐름)를
   기준으로 판정**하고 어긋난 쪽을 고친다.
3. **운영안(`instructor-guide.md`)은 항상 노트북 단계 번호로 지시한다.** 강사는 노트북을 띄워놓고
   진행하기 때문이다. 강의 실습 절을 가리킬 때만 **"강의 실습 N번"** 이라고 접두어를 붙인다.
   접두어 없는 "N단계"는 언제나 노트북을 뜻한다.

> **폐기 근거(실측).** 10차시 전부에서 강의 step과 노트북 `## N단계`를 추출해 대조한 결과,
> 순서 역전은 **4차시 한 곳뿐**이었고(강의 5=loc/iloc↔노트북 11단계, 강의 6=종합↔노트북 7단계)
> 나머지 **9차시는 "순서 일치 + 1:N 포함"** 으로 이미 만들어져 있었다.
> 게다가 10차시 노트북 전부가 동일한 **꼬리 블록**(정리 문장 → AI 질문 → AI 코드 생성 → 연습문제 →
> AI 미니 프로그램)을 갖는다. 1:1로 펼치면 모든 차시의 강의 실습 절이 **11~15단계로 늘어나고
> 그중 5개가 매 차시 똑같아져**, 강의 자료의 "오늘 뭘 하는지" 한눈 보기 기능을 잃는다.
> `docs/curriculum.md`의 각 차시 「실습 흐름」도 이미 5~6개 묶음 단위로 쓰여 있다. 즉 현실이 아니라
> 규칙이 틀렸다.

## 검증 기준을 확인 가능하게 쓴다

스펙의 "검증 기준"은 consistency-qa의 체크리스트가 된다. 확인할 수 없는 문장은 기준이 아니다.

| 나쁜 기준 | 좋은 기준 |
|---|---|
| 설명이 더 쉬워진다 | 새로 등장하는 용어 3개 각각에 한 줄 설명과 비유가 `.term-card`로 있다 |
| 3차시와 연결된다 | 4차시 실습이 3차시와 **같은 CSV·같은 조건**을 쓰고, 결과 건수가 3차시 함수 결과와 일치함을 학생이 직접 확인한다 |
| 퀴즈를 보강한다 | `quiz.json` 문항이 13개 이상이고, 추가 문항 전부가 강의 본문에서 실제로 다룬 내용이다 |
| 노트북이 잘 돌아간다 | `python scripts/validate_notebooks.py`가 week04에서 FAIL 0건 |
| 강의와 노트북이 맞물린다 | 강의 `<div class="step">` 개수와 "노트북"을 포함한 step 개수가 같고, 병기한 노트북 번호의 순서가 단조 증가한다 |

## 범위를 지키는 법

개선 요청은 작업 중에 커진다. 스펙에 **"건드리지 않을 것"** 절을 반드시 넣는다.
명시적으로 범위 밖이라고 적힌 항목은 작업자가 손대지 않는다.

요청이 커리큘럼 원칙과 충돌할 때(예: 비전공자 과정에 고급 Pandas 요구) — 거부하지 않는다.
충돌 사실과 완화안(선택 심화로 분리, 부록으로 이동)을 스펙에 적고 진행한다. 최종 판단은
사용자 몫이다. 다만 **CLAUDE.md의 절대 규칙**(원본 데이터 수정, `fab.csv` 센서 의미 단정,
인과 단정)은 협상 대상이 아니다.
