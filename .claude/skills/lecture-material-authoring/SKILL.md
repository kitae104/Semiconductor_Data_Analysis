# 강의 자료 4종 작성

`lectures/weekXX/`의 네 파일을 만든다. 마크업 세부 규격은 필요할 때 아래를 읽는다.

- **`references/html-components.md`** — 페이지 골격, 컴포넌트별 마크업 전문, 클래스 목록
- **`references/quiz-schema.md`** — 퀴즈 7개 타입의 스키마와 작성 기준

## 독자를 잊지 않는다

프로그래밍 경험이 **거의 없는 일반인**이다. 이 한 가지가 모든 문장 선택을 결정한다.

1. **처음 쓰는 용어에는 한 줄 설명과 비유를 붙인다.** "DataFrame"을 설명 없이 쓰지 않는다.
   용어 카드(`.term-card`)는 한 줄 설명 / 쉬운 비유 / 데이터에서의 예 / 자주 하는 오해 네 칸이다.
2. **"간단히", "당연히", "그냥", "쉽게"를 쓰지 않는다.** 모르는 사람에게는 이 말들이
   "이걸 모르는 건 이상한 일"이라는 신호가 된다.
3. **코드보다 이유를 먼저 쓴다.** 각 차시는 "🤔 왜 이걸 배워야 할까?" 섹션으로 시작한다.
4. **앞 차시와 연결한다.** "3차시에 `for`+`if`로 했던 걸 한 줄로" 같은 문장이 차시를 과정으로
   만든다. 연결 없는 차시는 낱개 튜토리얼이다.
5. **결과 해석 문장 쓰기를 뺀 차시는 없다.** 이 과정의 목표는 "설명할 수 있는 사람"이다.

## 절대 규칙

- **`assets/css/common.css`의 기존 클래스만 쓴다**(CLAUDE.md). 새 CSS 프레임워크를 들이지 않는다.
  그 페이지에만 필요한 스타일은 문서의 `<style>` 블록에 한정한다. 전역 CSS가 필요하면 직접
  고치지 말고 design-steward에게 넘긴다.
- **8·9·10차시는 "원인"이 아니라 "원인 후보"로 쓴다.** "원인이다"는 그것이 틀렸음을 가르칠 때,
  반드시 부정 문맥과 함께만 쓴다.
- **`fab.csv`의 `Sensor0~Sensor589`의 물리적 의미를 단정하지 않는다.**
- **실습 데이터는 가상 데이터임이 드러나야 한다.** 실제 생산 데이터처럼 읽히게 쓰지 않는다.
- **없는 기능처럼 보이게 하지 않는다.** `LIVE`, `실시간`, `Online` 같은 표현이나 가짜 대시보드
  수치를 넣지 않는다. 예시 일러스트는 "예시" 라벨 + `.illustration-note`를 단다.

## 코드와 숫자는 지어내지 않는다

이 규칙 하나가 수업 중 사고의 대부분을 막는다.

1. **강의 자료의 코드 블록은 노트북의 해당 셀과 글자 단위로 같아야 한다.** 학생은 강의 화면을
   보며 노트북을 친다. 먼저 notebook-engineer가 코드를 확정하고, 그것을 그대로 싣는다.
2. **출력 예시는 실제 실행 결과만 쓴다.** 모르면 직접 돌려서 얻는다.
   ```bash
   python -c "import pandas as pd; df=pd.read_csv('data/weekly/week04/week04_process_filtering.csv', encoding='utf-8-sig'); print(df.shape); print(df['설비번호'].value_counts())"
   ```
3. **운영안의 "오늘 데이터 핵심 수치"는 특히 실제 값이어야 한다.** 강사가 수업 중에 그대로
   읽는 숫자다. 틀리면 교실에서 바로 드러난다.
4. **숫자를 고치면 네 곳을 함께 고친다** — 강의 HTML, 실습지, 운영안 핵심 수치, 퀴즈 정답.

## 파일별 구조

### 1. 강의 자료 `index.html`

`<main class="page">` 안에 `<section class="block">`을 쌓는다. 순서가 곧 수업 흐름이다.

```
히어로(.hero) — 배지 + 제목 + 오늘의 질문
🎯 학습 목표
🤔 왜 이걸 배워야 할까?
⏮️ 지난 시간 복습
📚 개념 설명 (여러 섹션, 각 h2에 📚)
🟣 실습
🗂️ 핵심 용어 카드
📁 데이터
⚠️ 주의할 점 & 자주 발생하는 오류
🚀 도전 실습
✅ 결과 정리 & 퀴즈
🤖 AI로 한 걸음 더
🟣 연습문제
🎉 AI로 재미있는 미니 프로그램 만들기
📝 과제(다음 차시까지)
❓ 핵심 질문 → 데이터 연결
🔜 다음 차시 예고
```

모든 섹션이 필수는 아니지만 **순서는 바꾸지 않는다** — 10개 차시가 같은 리듬이라 학생이
어디를 보면 되는지 안다. `common.js`가 `main.page > section.block > h2`를 모아 목차를
자동 생성하므로, 이 구조를 벗어나면 목차에서 빠진다.

### 2. 실습지 `worksheet.html`

인쇄해 쓰는 자료다. 번호가 붙은 문제 섹션(`<h2>1. 용어 연결 문제</h2>`)으로 구성한다.
전형적 구성: 용어 연결 → 코드 빈칸 → 조회/선택 → 결과 해석 → 분석 문장 작성 → 도전 →
차시 고유 연습 → 심화 → AI 미니 프로젝트.

**학생용 노트북의 TODO와 같은 것을 요구해야 한다.** 실습지는 "무엇을 해야 하는지",
노트북은 "어디에 쓰는지"다. 둘이 어긋나면 학생이 둘 다 못 푼다.

### 3. 퀴즈 `quiz.json`

`references/quiz-schema.md`를 읽는다. 핵심만:

- 최상위: `week`(숫자, 폴더와 일치), `title`, `questions`(8개 이상)
- 문항 타입 7종: `multiple_choice`, `true_false`, `fill_blank`, `result_prediction`,
  `term_matching`, `chart_choice`, `short_answer`
- `answer`가 인덱스인 타입은 **0부터** 센다. 보기 개수를 넘으면 검사에서 FAIL이다.
- **강의에서 실제로 가르친 것만 묻는다.** 안 가르친 것을 묻는 문항이 가장 흔한 QA 지적이다.

### 4. 강사 운영안 `instructor-guide.md`

강사가 수업 직전에 읽는 문서다. 고정 섹션:

```markdown
# {N}차시 강의 운영안 — {제목}
## 🤔 왜 이걸 배워야 할까? (학생에게 전달할 메시지)
## 수업 흐름
## 준비물
## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
## 강사 설명 포인트
## 질문 예시
## 예상 오개념
## 실습 중 오류 대응
## 빠른 학습자용 추가 과제
## 느린 학습자용 최소 과제
## 수업 마무리 질문
```

**시간 배분(분 단위)은 넣지 않는다** — 이 과정은 시간 정보를 빼는 정책이다
(`docs/restructure-plan.md`). "예상 오개념"과 "실습 중 오류 대응"은 실제로 학생이 겪을 것을
쓴다. 노트북을 돌려보다 만난 오류가 가장 좋은 재료다.

## 문체를 맞춘다

고치기 전에 **같은 차시의 기존 문장을 먼저 읽는다.** 이모지 사용, 섹션 제목 형식, 문장 종결
방식이 달라지면 한 과정으로 읽히지 않는다. 한 차시만 문체가 튀면 그 차시가 잘못 보인다.

## 끝내기 전에

```bash
python .claude/skills/course-consistency-audit/scripts/check_course_consistency.py --week {N} --quiet
```

이 검사는 미정의 class, 깨진 상대경로, 퀴즈 스키마 오류, 표현 규칙 위반을 잡는다. FAIL이
남은 채로 완료라고 보고하지 않는다. 4종 중 일부만 고쳤으면 **무엇이 남았는지 명시한다** —
강의 자료만 고치고 퀴즈를 두면 정답이 틀어진 채 배포된다.
