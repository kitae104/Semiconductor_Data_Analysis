# 반도체 콘텐츠 검수

두 가지를 본다 — **사실이 맞는가**(도메인 정확성), **안전하게 말했는가**(표현 안전성).

검수자는 **파일을 고치지 않는다.** 지적·근거·권장 수정안을 내고 담당자가 고친다.
검수자가 직접 고치면 그 수정은 아무도 다시 검수하지 않는다.

## CLAUDE.md의 절대 금지선

협상 대상이 아니다. 위반은 **차단(blocking)** 등급이다.

### 1. `fab.csv` 센서의 물리적 의미를 단정하지 않는다

`fab.csv`의 `Sensor0~Sensor589`는 SECOM 유형 고차원 센서 데이터이고, **각 센서가 무엇을
측정하는지 확인된 바 없다.** 선택 심화 부록에서 다루더라도 마찬가지다.

| 위반 | 대안 |
|---|---|
| "Sensor59는 챔버 온도를 나타낸다" | "Sensor59는 이름만으로는 무엇을 측정하는지 알 수 없다" |
| "Sensor103의 값이 높으면 압력이 높다는 뜻" | "Sensor103의 값이 높을 때 불량이 많았다 — 다만 이 센서가 무엇인지는 알 수 없다" |

`fab.csv`는 v2 핵심 10차시 경로에서 제외됐다(`docs/restructure-plan.md`). 핵심 차시에서
언급된다면 그것부터 지적한다.

### 2. 8·9·10차시에서 "원인"이 아니라 "원인 후보"로 쓴다

상관관계와 모델 예측은 인과를 증명하지 않는다.

| 위반 | 대안 |
|---|---|
| "온도가 불량의 원인이다" | "온도가 불량의 **원인 후보**로 떠오른다" |
| "진동이 높아서 불합격이 발생했다" | "진동이 높은 구간에 불합격이 몰려 있다" |
| "중요도가 가장 높으므로 이것이 원인이다" | "모델이 이 변수를 가장 많이 참고했다 — 원인이라는 뜻은 아니다" |
| "2위 원인 후보: 습도-불합격 (r=−0.13)" — 관계 없음으로 판정한 변수에까지 후보 라벨 | "습도-불합격 \|r\|=0.13 — 관계 약함, **원인 후보 아님**" |

**"원인 후보"는 만능 안전장치가 아니다.** 그 표현만 붙이면 통과라고 읽으면, 대조군으로 설계한
변수나 결과변수가 다른 쌍에까지 라벨이 붙어 같은 자료의 앞선 서술과 정면충돌한다. 두 가지를
반드시 함께 확인한다.

1. **근거 수치가 함께 있는가** — 상관계수나 비율 없이 "원인 후보"만 있는 서술은 지적한다.
2. **무엇의 후보인지(결과변수)가 명시됐는가** — 한 결과변수에서 후보였다고 다른 결과변수에서도
   후보인 것은 아니다. "온도-두께가 강한 상관"은 온도가 **두께**의 원인 후보라는 뜻이지
   **불합격**의 원인 후보라는 뜻이 아니다.

### 3. 부정 문맥을 위반으로 착각하지 않는다

**"원인이다"가 나온다고 전부 위반이 아니다.** 이 과정은 "그렇게 말하면 안 된다"를 가르친다.

```
정상:  상관관계가 있다고 곧바로 "온도가 원인이다"라고 단정할 수는 없다.
정상:  "상관계수가 높다 = 원인이다"라고 성급하게 결론 내리지 않는다.
정상:  이것이 '온도가 불량의 원인이다'라는 뜻일까요?   ← 발문
위반:  온도가 높은 설비에서 불량이 많았다. 온도가 원인이다.
```

판정 방법: 해당 문장 **앞뒤 80자**를 읽는다. `단정`, `아니`, `없다`, `말고`, `뜻은`,
`≠`, `원인 후보`, `성급`, `결론 내리지` 같은 반증 표현이 함께 있으면 정상이다.
자동 검사 스크립트도 같은 규칙을 쓰지만, 경계가 모호하면 사람이 문맥을 읽고 판정한다.

### 4. `data/raw/`는 읽기 전용

원본 CSV를 수정하는 코드·지시가 콘텐츠에 있으면 차단 지적이다.

## 부호 규약 혼동

**서로 반대다.** 섞어 설명하면 학생이 반드시 틀린다.

| 데이터 | 규약 |
|---|---|
| `반도체_공정_샘플.csv` 계열 (핵심 10차시 데이터) | **1 = 합격, -1 = 불합격** |
| `fab.csv` | **-1 = 정상, 1 = 이상** |

이 차이는 1차시와 `docs/glossary.md`에서 설명된다.

**적용 단위**: 코드에서 `== 1` / `== -1`을 **처음 쓰는 차시마다** 그 자리에 규약 한 줄을 다시
적어야 한다. 1차시에 설명이 있다고 면제되지 않는다 — 8차시 학생은 1차시를 몇 주 전에 들었다.
누락은 **수정 권장**, 두 규약을 **섞은** 경우만 **차단**이다.

## 단위·물리량 정합성

데이터에 실재하는 값이라도 서로 모순될 수 있다. "근거 없는 수치"(데이터에 없는 숫자)와는
다른 결함이고, 용어 정의만 봐서는 잡히지 않는다.

1. **같은 물리량을 다른 단위로 담은 열이 있으면 환산해 대조한다.**
   Pa ↔ Torr ↔ mTorr(1 mTorr = 0.133 Pa), ℃ ↔ K, nm ↔ Å.
   예: 같은 행에 `압력_Pa = 1012`와 `진공도_mTorr = 5`(= 0.67 Pa)가 있으면, 같은 챔버가
   동시에 1012 Pa이면서 0.67 Pa일 수 없다 — 1,500배 모순이다.
2. **값의 자릿수가 그 물리량의 현실적 범위에 있는지 본다.**
   챔버 진공 공정 1~100 mTorr / 대기압 약 101,325 Pa = 1,013 hPa.
   988~1036이라는 범위는 Pa가 아니라 **hPa(대기압)** 패턴이므로 단위 라벨 혼동을 의심한다.
3. **물리적으로 종속이어야 할 두 열의 상관계수가 0에 가까우면** 생성 로직을 의심한다.

확인은 직접 계산한다. 눈으로는 자릿수 모순이 잘 안 보인다.

```bash
python -c "import pandas as pd; df=pd.read_csv('data/weekly/week08/week08_anomaly_root_cause.csv', encoding='utf-8-sig'); print(df.describe().T[['min','max','mean']]); print(df.corr(numeric_only=True).round(2))"
```

이 유형은 보통 **`scripts/generate_weekly_data.py`가 유입 지점**이고 강의 자료는 표시만 한다.
아래 "심각도"의 유입 지점 규정을 따른다.

## 가상 데이터 고지

모든 실습 데이터는 **교육용으로 생성한 가상 데이터**다(README 10장). `반도체_공정_샘플.csv`의
열 구조·값 범위를 참고했을 뿐 실제 생산 데이터가 아니다.

지적 대상:
- 실제 기업 데이터인 것처럼 읽히는 서술
- 현업 의사결정에 쓸 수 있다는 암시
- "이 설비는 실제로 문제가 있다" 같은 실재 단정
- 데이터사전의 "실제 현업 데이터와 다른 점" 절 누락

## 도메인 용어

`docs/glossary.md`가 단일 기준이다. 본문과 다르면 용어집을 기준으로 삼되, 용어집 쪽이
낡았을 가능성도 있으니 curriculum-architect에게 판정을 넘긴다.

핵심 용어와 흔한 오류:

| 용어 | 정확한 설명 | 흔한 오류 |
|---|---|---|
| 웨이퍼 | 칩을 만드는 둥근 원판(기판) | "반도체 공장", "칩 그 자체" |
| 다이 | 웨이퍼를 잘라 만든 칩 하나 | 웨이퍼와 혼용 |
| FAB | 반도체를 생산하는 공장 | 설비 한 대를 가리키는 것으로 오용 |
| 로트(LOT) | 함께 관리·이동되는 웨이퍼 묶음 | 한 장의 웨이퍼로 오해 |
| 설비 | 공정을 수행하는 기계 | 공정과 혼용 |
| 공정 | 증착·식각·포토·세정·산화 등 처리 단계 | 설비와 혼용 |
| 수율 | 투입 대비 양품 비율 | **무엇 대비 무엇인지 빠뜨리면 안 된다.** "불량률의 반대"는 거친 설명 |
| 불량률 | 검사 대비 불량 비율 | 수율과 합이 반드시 100%라고 단정 |
| 파티클 | 공정 중 유입된 미세 이물 | "먼지"로만 뭉뚱그리기 |
| 규격 한계 (Spec, USL/LSL) | 설계·고객이 **미리 정해둔** 허용 범위. 데이터와 무관하다 | 관리 한계와 혼용 |
| 관리 한계 (UCL/LCL) | **데이터에서 계산한** 범위(보통 평균±2σ 또는 3σ). 공정이 평소대로 돌고 있는지를 본다 | 규격 한계와 혼용. 평균±2σ를 "규격"이라 부르기 |

`docs/glossary.md`의 "관리 한계" 정의는 현재 규격과 관리를 구분하지 않는다. **단일 기준인
용어집 자체가 두 개념을 뭉개고 있을 때는** 위 표를 근거로 지적하되, 용어집 보강 필요를
curriculum-architect에게 함께 넘긴다.

용어를 **처음 쓰는 자리**에 한 줄 설명이 있는지도 본다. 비전공자 과정에서 설명 없이 등장하는
전문 용어는 그 자리에서 학습이 끊긴다.

## 비전공자 기준으로 읽기

기술적으로 맞아도 오개념을 만드는 설명은 지적 대상이다.

| 유형 | 예 |
|---|---|
| 비유가 오개념을 심음 | "수율은 시험 점수 같은 것" → 무엇 대비 무엇인지가 사라진다 |
| 설명 없는 전문 용어 | "챔버 압력이 mTorr 단위로" — mTorr가 무엇인지 없이 등장 |
| 장벽이 되는 표현 | "간단히", "당연히", "그냥", "쉽게" |
| 근거 없는 수치 | 데이터에서 확인되지 않는 숫자 |
| 지나친 단순화 | "식각은 깎는 것, 증착은 쌓는 것"까지는 좋으나 그것이 전부인 것처럼 서술 |

## 심각도

| 등급 | 기준 | 처리 |
|---|---|---|
| **차단** | 사실 오류 또는 CLAUDE.md 위반 | 반드시 고친다 |
| **수정 권장** | 오개념을 만들 수 있음 | 고치는 것이 맞다 |
| **제안** | 더 나아질 수 있음 | 선택 |

**근거를 못 대는 지적은 "제안"으로 내린다.** "어색하다"가 아니라 어느 문서의 어느 대목에
어긋나는지 적는다. 확신할 수 없으면 "확인 필요"로 표시하고 무엇을 확인하면 판정되는지 쓴다 —
검수자의 추측이 교재에 실리면 안 된다.

**유입 지점이 검수 범위 밖일 때**: 결함의 뿌리가 `scripts/generate_weekly_data.py`나 데이터사전에
있고 검수 대상 파일은 그것을 표시만 하는 경우가 있다. 이때 **심각도는 낮추지 않는다**(학생이
보는 것은 표시된 결과다). 대신 `담당` 열에 **유입 지점 파일과 소관 에이전트를 함께** 적고,
범위 내 파일에서 할 수 있는 임시 조치(표시 제거·문구 완화)를 별도로 제시한다. 유입 지점을
고치지 않으면 해소되지 않는 지적이므로, 재호출 때 "미해소"로 계속 들고 간다.

## 검수 절차

**중괄호 확장(`week0{8,9}`)을 쓰지 않는다.** 이 저장소는 Windows/PowerShell 우선 환경이라
(CLAUDE.md) 중괄호가 확장되지 않고 파일명으로 해석돼 **조용히 0건을 반환한다.** 경로를 모두
펼쳐 쓰고, `.html`만 훑지 말고 `.md`·`.json`·노트북까지 포함한다 — 운영안과 퀴즈에도 같은
표현이 들어간다. Claude Code에서는 `grep` 대신 **Grep 도구**를 쓰면 이 문제가 없다.

```bash
# 1. 자동으로 잡히는 표현 위반부터 확인 (오탐 걸러진 결과)
python .claude/skills/course-consistency-audit/scripts/check_course_consistency.py --week {N} --quiet

# 2. 인과 표현 전수 확인 (8~10차시) — 문맥은 사람이 읽는다
grep -rn "원인" lectures/week08 lectures/week09 lectures/week10 \
  notebooks/student/week08_student.ipynb notebooks/solutions/week08_solution.ipynb \
  notebooks/instructor/week08_instructor.ipynb data/data_dictionary/week08_dictionary.md

# 3. 센서 의미 단정 확인 (전 범위)
grep -rn "Sensor[0-9]" lectures notebooks data/data_dictionary docs

# 4. 부호 규약 확인 — 코드에서 ==1 / ==-1 을 쓰는 모든 곳
grep -rn "합격여부\|Pass_Fail" lectures notebooks | grep -n "== *-\?1"
```

1단계 결과는 **보고서 서두에 실행 사실과 PASS/WARN/FAIL 집계만 한 줄로** 남기고, 개별 항목은
그것이 **동시에 도메인·표현 위반일 때만** 지적 표에 올린다. 구조 결함(파일 누락, 스키마 오류,
단계 제목 불일치)은 consistency-qa 소관이므로 올리지 않는다.

자동 검사가 **못 잡는 것**에 시간을 쓴다 — 용어의 정확성, 비유의 적절성, 설명 없는 용어,
부호 혼동, 단위·물리량 모순, 근거 없는 수치, "원인 후보" 과다 적용.

## 오탐을 줄인다

검수 보고서에 **"확인했으나 문제없는 항목"** 절을 반드시 넣는다. 의심했다가 문맥상 정상으로
판정한 것을 적는다. 이것이 없으면 다음 검수자가 같은 것을 또 의심하고, 결국 정상인 문장이
"안전하게" 고쳐지다 교육적 의도가 사라진다.
