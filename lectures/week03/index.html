비교 연산자와 if — 질문하고 갈림길 만들기

비교 연산자는 두 값을 비교해 True(참) 또는 False(거짓)를 돌려준다.

기호뜻예
> / <크다 / 작다score > 80
>= / <=크거나 같다(이상) / 작거나 같다(이하)score <= 80
==같은가?subject == "수학"
!=다른가?subject != "수학"
= 와 == 는 다르다 =는 1차시에 배운 "저장하라", ==는 "같은가?"라는 질문이다.

if는 조건이 True일 때만 그 아래 들여 쓴 줄을 실행한다. 들여 쓰지 않은 줄은 조건과 상관없이 실행된다.

Python — 쉬운 예제: 비교와 if (노트북 1단계)
score = 85
subject = "수학"

print(score > 80)
print(score <= 80)
print(subject == "수학")
print(subject != "수학")

if score > 80:
    print("80점을 넘었습니다!")
print("채점 끝")
실행 결과 
True
False
True
False
80점을 넘었습니다!
채점 끝
  • if 줄 끝에는 콜론 :을 붙인다.
  • 그 아래 줄은 스페이스 4칸 들여 쓴다. 들여 쓴 줄까지가 "조건이 참일 때 할 일"이다.

if/else — 둘 중 하나 고르기

조건이 참이면 if 아래를, 거짓이면 else 아래를 실행한다. 36.0 <= body_temp <= 37.5는 "36.0 이상이고 37.5 이하인가?"를 한 번에 묻는다. 범위 안인지 묻는 모양이다.

Python — 쉬운 예제: 체온 판정 (노트북 2단계)
body_temp = 36.5

if 36.0 <= body_temp <= 37.5:
    print("정상 체온입니다.")
else:
    print("다시 재 보세요.")
실행 결과 
정상 체온입니다.

else 줄에도 콜론을 붙이고, else는 if와 같은 위치에서 시작한다.

for — 하나씩 꺼내 개수 세기

for score in scores:는 "리스트 scores에서 값을 하나씩 꺼내 score라는 이름으로 부르며, 아래 줄을 되풀이하라"는 뜻이다.

개수를 세려면 for 바깥에서 세는 변수를 0으로 시작하고, 조건에 맞을 때마다 1씩 늘린다.

Python — 쉬운 예제: 하나씩 꺼내고 세기 (노트북 3단계)
scores = [72, 85, 90, 64, 88]

for score in scores:
    print(score)

pass_count = 0

for score in scores:
    if score >= 80:
        pass_count = pass_count + 1

print(f"80점 이상인 학생은 {pass_count}명입니다.")
실행 결과 
72
85
90
64
88
80점 이상인 학생은 3명입니다.

pass_count = pass_count + 1은 "지금 값에 1을 더해 다시 저장하라"는 뜻이다. 같은 코드의 for 안에 print 한 줄을 넣으면, 한 바퀴 돌 때마다 pass_count가 어떻게 바뀌는지 보인다.

Python — 쉬운 예제: 한 바퀴씩 따라가 보기 (노트북 3단계)
pass_count = 0

for score in scores:
    if score >= 80:
        pass_count = pass_count + 1
    print(f"{score}점 | 80점 이상? {score >= 80} | pass_count = {pass_count}")
실행 결과 
72점 | 80점 이상? False | pass_count = 0
85점 | 80점 이상? True | pass_count = 1
90점 | 80점 이상? True | pass_count = 2
64점 | 80점 이상? False | pass_count = 2
88점 | 80점 이상? True | pass_count = 3
  • 0에서 시작해야 "아직 하나도 안 셌다"에서 출발한다. 0을 for 안에 두면 바퀴마다 0으로 돌아간다.
  • 마지막 print는 들여 쓰지 않았다. 그래서 다 센 뒤 한 번만 출력된다.

함수 — 판정 규칙에 이름 붙이기

def로 규칙에 이름을 붙이고, return으로 결과를 돌려준다. 정의만 하면 아무것도 실행되지 않는다. 이름을 불러야 실행된다.

Python — 쉬운 예제: 합격 판정 함수 (노트북 4단계)
def judge_score(point):
    if point >= 80:
        return "합격"
    else:
        return "불합격"

print(judge_score(85))
print(judge_score(64))
실행 결과 
합격
불합격
  • 괄호 안의 이름(point)은 함수에 넣어 주는 값을 받는 자리다. judge_score(85)라고 부르면 85가 point에 들어가 함수 안에서 쓰이고, judge_score(64)라고 부르면 이번에는 64가 들어간다.
  • 피자 가게의 "잘 구워졌나?" 판정을 직원마다 다르게 하지 않도록 규칙 카드 한 장으로 적어 두는 것과 같다. 한 번 만든 함수는 몇 번이고 다시 부른다.

함수와 for 함께 쓰기

리스트에서 하나씩 꺼내(for) 함수로 판정하고, 그 결과로 개수를 센다. 함수의 결과를 "불합격"과 비교할 때는 ==를 쓴다.

Python — 쉬운 예제: 모두 판정하고 불합격 세기 (노트북 5단계)
for score in scores:
    result = judge_score(score)
    print(f"{score}점 → {result}")

fail_count = 0

for score in scores:
    if judge_score(score) == "불합격":
        fail_count = fail_count + 1

print(f"불합격 판정을 받은 학생: {fail_count}명")
실행 결과 
72점 → 불합격
85점 → 합격
90점 → 합격
64점 → 불합격
88점 → 합격
불합격 판정을 받은 학생: 2명
  • 여기서는 for가 꺼낸 score를 함수에 넣는다. 함수 안에서는 그 값이 point라는 이름으로 쓰인다.
  • if 안에 if를 한 번 더 쓰면(한 단계 더 들여 쓰기) 바깥 조건과 안쪽 조건을 둘 다 만족할 때만 실행된다. 실습지 문제 3-3에서 이 모양을 쓴다.

반도체 데이터로 확인하기

오늘 반도체 데이터는 설비 기록표 week03_python_basics_2.csv(30행)다. 공정 지도 ②~⑤와 세정에서 남긴 기록이다. 오늘 파이썬은 표 파일을 직접 읽지 않는다(4차시에 배운다). 그래서 노트북에는 표에서 옮겨 적은 값이 딕셔너리의 리스트로 들어 있다. (노트북 6단계)

  • 열: 로트번호, 공정명, 설비번호, 온도_C, 합격여부. _C = 섭씨 도. 노트북 딕셔너리에는 오늘 쓰는 네 열(공정명 제외)만 옮겼다.
  • 합격여부는 그 공정을 마친 뒤 검사에서 나온 실제 결과로, 기록(행)마다 따로 매긴 값이다. 1 = 합격, -1 = 불합격.
  • 한 로트는 여러 공정을 차례로 거친다. 그래서 같은 로트번호(예: LOT-0186)가 공정마다 다른 행에 다시 나올 수 있다.
  • 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다. 실제 공장에서는 설비마다 맡는 공정이 정해져 있다.
  • 온도는 교육용 값이라 실제 공정 조건과 다르다. 값의 크기는 해석하지 않고 정해 둔 범위와 비교만 한다.
규격과 연습용 기준 공정 조건에는 사람이 미리 정해 둔 허용 범위가 있다. 이것을 규격(스펙)이라고 한다. 피자 가게 레시피에 "오븐 온도는 몇 도에서 몇 도 사이"라고 적어 둔 것과 같다. 실제 공장에서는 공정·제품마다 규격이 따로 있다. 이 과정에서는 모든 기록에 온도 295~305도 하나를 연습용 기준으로 쓴다(실제 공정의 기준값이 아니다). 기준을 벗어난 기록은 확인 대상이 된다.
두 가지 판정을 나눠 보기
  • 연습용 기준으로 본 판정 — 우리가 코드로 내리는 판정. 온도가 295~305도 안이면 "범위 안", 밖이면 "범위 밖".
  • 합격여부 — 공장 검사에서 나온 실제 결과(1 / -1). 온도만으로 정해진 값이 아니다.
오늘은 두 판정이 얼마나 겹치는지 확인한다.

PART 2 Orange3 — 조건으로 행 고르기

파이썬에서는 for와 if로 한 건씩 판정했다. Orange의 Select Rows는 조건을 창에 적으면 맞는 행만 골라 준다.

위젯 이름표

위젯(화면 이름)어느 묶음에 있나한국어 뜻오늘 하는 일
Select RowsTransform행 고르기오늘 새 위젯. 조건에 맞는 행만 골라 다음 위젯으로 보낸다
Select Rows 조건 만드는 법
  • Select Rows를 File에 이으면 창 위쪽 Conditions 칸에 조건 한 줄이 이미 있다. 첫 조건은 이 줄을 고쳐서 만든다. 왼쪽부터 열 이름 → 비교 방법 → 값 순서로 고른다.
  • 두 번째 조건부터 Add Condition을 누른다. 줄이 여러 개면 모두 만족하는 행만 남는다. 필요 없는 줄은 줄 오른쪽 끝 ×로 지운다.
  • 숫자 열의 비교 방법: is greater than = 보다 크다(초과, 80 자체는 빠진다) · is at least = 이상 · is below = 보다 작다 · is between = 두 값 사이 · is outside = 두 값 바깥. 값 칸이 둘이면 왼쪽에 작은 값, 오른쪽에 큰 값을 넣는다.
  • 글자 열(설비번호 등)은 is를 고르고 목록에서 값을 고른다.

워밍업 — 우리 동네 대기환경

주의할 점 & 자주 발생하는 오류

오류 1 — 콜론을 빼먹었을 때 if score > 80처럼 줄 끝 :이 없으면 SyntaxError: expected ':'가 난다. if·else·for·def 줄 끝에는 콜론을 붙인다.
오류 2 — 들여쓰기를 빼먹었을 때 if 아래 줄을 들여 쓰지 않으면 IndentationError: expected an indented block after 'if' statement on line 2처럼 나온다(줄 번호는 코드마다 다르다). 들여쓰기가 들쭉날쭉하면 IndentationError: unexpected indent가 난다. 스페이스 4칸으로 맞춘다.
오류 3 — 비교에 = 하나를 썼을 때 if score = 80:이라고 쓰면 SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?가 난다. "같은가?"는 ==다.
주의 — 함수에 무엇을 넣었나 check_range(record)처럼 딕셔너리를 통째로 넣으면 TypeError: '<=' not supported between instances of 'int' and 'dict'가 난다. 숫자(295)와 딕셔너리는 크기를 비교할 수 없다는 뜻이다. 온도만 꺼내 check_range(record["온도_C"])로 넣는다. "범위 밖"의 따옴표를 빼먹으면 SyntaxError가 난다(따옴표가 없으면 글자 사이 빈칸을 코드로 읽는다).

결과 정리 & 퀴즈

오늘의 반도체 이해 포인트
  • 공정 조건에는 사람이 미리 정해 둔 허용 범위(규격)가 있고, 실제로는 공정마다 따로 있다. 이 과정은 연습용 기준 295~305도를 쓰고, 벗어난 기록은 확인 대상이 된다.
  • 연습용 기준 밖이라고 모두 불합격은 아니다. EQ-04의 기준 밖 기록 4건 중 실제 불합격은 1건뿐이었다. 기준으로 본 판정과 실제 검사 결과(합격여부)는 다르다 — 기준 밖은 '살펴볼 후보'다. 그래서 온도 하나로 합격·불합격을 정하지 않는다.
  • 파이썬: 비교 연산자와 if/else로 판정하고, for로 개수를 세고, 판정 규칙을 함수 check_range로 만들었다.
  • Orange: Select Rows에 같은 조건을 적어 행을 골랐다. 대기환경에서 PM10이 80보다 큰 날, EQ-04의 연습용 기준 밖 기록.
기록 30건 중 연습용 기준 밖 기록은 12건이고, 그중 실제 검사에서도 불합격(-1)인 기록은 3건이다. 나머지 9건은 기준 밖인데도 합격이었다. 실습지 문제 3·4를 푼 뒤 열어 본다.

나머지 문항은 실습지와 수업 뒤 퀴즈로 복습한다.

Q1. (객관식) body_temp = 36.5일 때 아래 코드의 출력은? if 36.0 <= body_temp <= 37.5: → print("정상 체온입니다."), else: → print("다시 재 보세요.")
  • A. 정상 체온입니다.
  • B. 다시 재 보세요.
  • C. 두 문장 모두 출력된다
  • D. SyntaxError
정답: A. 36.5는 36.0 이상이고 37.5 이하라서 조건이 참이다. if와 else 중 한쪽만 실행된다.
Q2. (참/거짓) check_range가 "범위 밖"이라고 판정한 기록은 실제 검사(합격여부)에서도 모두 불합격이다.
정답: 거짓. EQ-04의 기준 밖 기록 4건 중 실제 불합격은 1건뿐이었다. 연습용 기준으로 본 판정과 실제 검사 결과는 다르다. 기준 밖 기록은 확인 대상(살펴볼 후보)이다.

핵심 질문 → 데이터 연결

  • 질문: 리스트에 담긴 여러 설비 정보를 하나씩 살펴보며, 조건에 맞는 것만 컴퓨터가 골라내게 할 수 있을까?
  • 방법: 기록을 딕셔너리의 리스트로 담고, for로 하나씩 꺼내 check_range로 판정해 센다. Orange에서는 Select Rows에 같은 조건을 적는다.
할 수 있다. 기록 30건 중 연습용 기준 밖 12건을 컴퓨터가 골라냈다. 다만 그중 실제 불합격은 3건이라, 기준은 "살펴볼 후보"를 골라 주는 거름망이다. 실제 결과를 이해하려면 온도 말고 다른 정보도 함께 살펴봐야 한다.
