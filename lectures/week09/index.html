왜 이걸 배워야 할까?

  • 지금까지는 끝난 기록으로 "어디서 불합격이 많았나"를 설명했다.
  • 검사 전에 "이 로트는 불합격일 것 같다"를 알면 다음 공정으로 보내기 전에 막을 수 있다.
  • 일기예보가 잘 맞아도 비가 오는 이유를 다 아는 것은 아니듯, 맞히는 것과 원인을 아는 것은 다르다.

지난 시간 복습

  • 3차시: 사람이 규칙을 썼다 — if 295 <= temp <= 305:이면 합격.
  • 8차시: 진공도가 범위를 벗어난 기록에 불합격이 많았지만 "원인"이 아니라 "원인 후보"라고 불렀다.
  • 오늘: 규칙을 컴퓨터가 지난 기록에서 스스로 찾게 한다.

머신러닝 개념 이해하기

  • 머신러닝: 지난 기록(문제+정답)을 주면 컴퓨터가 규칙을 찾고, 그 규칙으로 새 문제의 답을 예측한다.
  • 생활 예: 지난 날씨와 "야외 체육 수업을 했나"의 기록으로 "내일 수업을 할 수 있을까"를 맞힌다. 오늘은 이 쉬운 예제로 먼저 따라 하고 반도체 데이터에 적용한다.

오늘은 앞의 두 칸과 "규칙이 얼마나 맞나 채점하기"까지 한다. 새 로트 예측은 10차시에 한다.

Feature(문제)와 Label(정답)

  • Feature = 문제지(예측할 때 보는 단서), Label = 답안지(맞히고 싶은 값).
  • 지난 기록에는 둘 다 있고, 새 로트에는 문제지만 있다.

왜 여러 Feature를 함께 넣을까

쉬운 예제 — 비만 보면 놓치는 날 116일 중 비 5mm 이상은 22일 중 21일 취소했다. 비가 5mm 미만이어도 바람 9m/s 이상이거나 32℃ 이상인 9일은 모두 취소했다.

병원에서 체온만 보지 않듯, 모델에도 Feature를 여러 개 넣는다. 반도체 데이터에서도 그런지는 아래 "반도체 데이터로 확인하기"에서 본다.

결정트리 — 스무고개로 규칙 찾기

  • 결정트리는 "○○가 기준값 이하인가?"를 이어 물어 기록을 갈래로 나누고, 마지막 갈래에 많은 쪽으로 답한다.
  • 어떤 열로, 어떤 기준값으로 물을지는 모델이 기록을 보고 고른다. 이것이 "학습"이다.

쉬운 예제 — 야외 수업 모델이 찾은 질문

질문(학습용 92일)예아니오
1. 강수량이 4.75mm 이하인가?질문 2로취소(17일 모두 취소)
2. 최고기온이 31.75℃ 이하인가?질문 3으로취소(5일 모두 취소)
3. 풍속이 9.9m/s 이하인가?질문 4로취소(1일)
4. 강수량이 1.0mm 이하인가?진행(61일 중 취소 1일)진행(약한 비, 8일 중 3일 취소)

"비·더위·바람이면 취소"를 모델이 스스로 찾았다. 습도_pct(관계없게 만든 비교용 열)는 질문에 쓰이지 않았다. 4번 질문은 두 갈래 모두 진행이 많아 답은 같지만, 약한 비 갈래는 8일 중 3일이 취소라 덜 확실하다(10차시 "확률"에서 다시 본다).

max_depth max_depth=4는 "질문은 최대 4번"이라는 뜻이다. 너무 많이 허락하면 기록을 외워 버릴 수 있다.

연습문제와 모의고사 — train/test 나누기

  • train = 연습문제(80%): 모델이 보고 규칙을 찾는 기록. test = 모의고사(20%): 한 번도 보지 않은 기록으로 채점한다.
  • 기출문제 답만 외운 학생은 같은 문제집에서 100점이지만 처음 보는 모의고사에서는 떨어진다. 실력은 모의고사로 잰다.
옵션뜻
test_size=0.220%를 모의고사로 떼어 둔다
random_state=42섞는 방식을 고정해 강의와 같은 숫자가 나온다
stratify=y양쪽의 정답 비율(진행:취소, 합격:불합격)을 거의 같게 맞춘다

정확도와 혼동행렬 — 채점표 천천히 읽기

  • 정확도 = 맞힌 개수 ÷ 전체 개수. 쉬운 예제 모의고사 24일 중 22일 → 91.7%.
  • "무조건 한쪽" 찍기: 24일 중 진행이 17일이라 모두 "진행"으로 찍어도 70.8%다. 정확도는 항상 이 찍기 점수와 나란히 본다.

혼동행렬은 실제 정답과 예측을 짝지어 네 칸으로 센 표다(쉬운 예제 모델).

예측: 진행(1)예측: 취소(-1)
실제: 진행(1)16일 — 맞힘1일 — 헛경보(수업 한 번을 괜히 놓침, 4월 14일)
실제: 취소(-1)1일 — 놓침(강풍 9.2m/s인데 진행 예측, 4월 11일). 가장 곤란한 칸6일 — 잡아냄
화재경보기 비유 헛경보는 귀찮을 뿐이지만, 불이 났는데 안 울리는 경보기는 위험하다. 반도체에서는 "불량 로트를 합격으로 놓친 칸"이다(아래 "반도체 데이터로 확인하기").

"무조건 한쪽" 찍기와 비교하기

Python — 쉬운 예제: 찍기 정확도
easy_baseline = (easy_y_test == 1).mean()

labels=[1, -1]을 빼면 표가 뒤집힌다 숫자가 작은 -1이 첫 줄로 와서 [[6 1] [1 16]]이 된다. 항상 labels=[1, -1]을 붙인다.
STEP 04

④ 예측이 잘 맞아도 원인을 아는 것은 아니다 — 중요도

feature_importances_(중요도)는 각 열이 질문으로 쓰여 기록을 얼마나 잘 갈라 주었는지 나눠 가진 몫이다(합계 100%). 질문에 한 번도 안 쓰인 열은 0%다.

Python — 쉬운 예제: 모델이 많이 참고한 열
for name, importance in zip(easy_feature_cols, easy_model.feature_importances_):
    print(f"{name}: {importance:.1%}")
실행 결과 
최고기온_섭씨: 24.8%
습도_pct: 0.0%
풍속_m_s: 5.4%
강수량_mm: 69.8%

zip(A, B)는 두 목록에서 같은 자리의 값을 한 쌍씩 꺼낸다(첫 쌍은 "최고기온_섭씨"와 약 0.248). for 뒤에 이름을 두 개 쓰면 한 쌍이 name과 importance에 하나씩 나뉘어 담긴다. 결과: 강수량이 기록을 가장 잘 갈랐고, 습도는 쓰이지 않았다.

용의자와 범인 중요도는 "모델이 많이 참고했다"까지다. 중요도가 높고 범위 비교에서도 차이가 확인된 열이 원인 후보(용의자)이고, 범인인지는 추가 실험으로 확인한다.

질문해보기 — 하나 이상 골라서 (노트북 13단계)
  • "머신러닝과 사람이 직접 만든 if 규칙의 차이를 요리 레시피에 비유해서 설명해줘."
  • "혼동행렬의 네 칸을 화재경보기에 비유해서 설명해줘. 어느 칸이 가장 위험한지도 알려줘."
  • "연습문제로 채점하면 왜 실력이 부풀려 보이는지 시험공부에 비유해서 설명해줘."
코드 받아보기 (노트북 14단계) "2×2 혼동행렬 cm이 있어. 윗줄은 실제 합격, 아랫줄은 실제 불합격, 왼쪽은 합격 예측, 오른쪽은 불합격 예측이야. 네 칸을 꺼내서 '실제 합격 몇 건 중 몇 건을 맞혔고, 몇 건을 잘못 의심했는지', '실제 불합격 몇 건 중 몇 건을 잡았고 몇 건을 놓쳤는지'를 f-string 두 줄로 출력하는 파이썬 코드를 만들어줘."
Python — AI가 만들어줄 수 있는 코드 예시
ok_pass = cm[0][0]       # 합격을 합격으로 맞힘
false_alarm = cm[0][1]   # 합격인데 불합격으로 의심
missed = cm[1][0]        # 불합격인데 합격으로 놓침
caught = cm[1][1]        # 불합격을 불합격으로 잡아냄

print(f"실제 합격 {ok_pass + false_alarm}건 중 {ok_pass}건은 맞혔고, {false_alarm}건은 불합격으로 잘못 의심했습니다.")
print(f"실제 불합격 {missed + caught}건 중 {caught}건은 잡아냈고, {missed}건은 합격으로 놓쳤습니다.")
실행 결과 
실제 합격 116건 중 109건은 맞혔고, 7건은 불합격으로 잘못 의심했습니다.
실제 불합격 31건 중 9건은 잡아냈고, 22건은 합격으로 놓쳤습니다.
AI 코드를 다룰 때 꼭 지킬 점
  • 직접 실행해 혼동행렬 숫자(109·7·22·9)와 맞는지 확인한다. cm[1][0]은 "1번 줄의 0번 칸"이다(2차시 인덱스).
  • AI에게도 "1 = 합격, -1 = 불합격, labels=[1, -1] 순서"를 알려 준다.

과제 3 — Orange3와 비교하기 Orange3의 CA와 파이썬 정확도(80.3%)를 나란히 적고, 숫자가 다른 이유를 한 가지 이상 쓴다.

  • 답: 어느 정도는. 정확도 80.3%지만 찍기(78.9%)와 2건 차이이고 불합격 31건 중 22건을 놓쳤다(쉬운 예제는 찍기보다 5일 더 맞힘).
