머신러닝 예측 모델 만들기 — 실습지

문제 1·2·4·5는 공정 기록 week09_pass_fail_train.csv(750행 9열, 교육용 가상 데이터)로, 문제 3은 웨이퍼 맵 요약 week09_orange_wafer_patterns.csv(240행, 교육용 가상 데이터)로 푼다. 공정 지도 위치: 공정 기록 = ②~⑤ + 세정의 공정 조건과 검사 결과(공정 중간 검사 + ⑦ EDS 결과를 모은 교육용 설정) / 웨이퍼 맵 요약 = ⑦ EDS 웨이퍼 맵. 합격여부는 1 = 합격, -1 = 불합격이다. 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록).

문제 1·2는 학생용 노트북 4단계와 같다 — 노트북 1·2단계 셀을 먼저 실행해 df, y와 6개 열 모델의 정확도를 만들어 둔다(3단계 ChatGPT 체험은 PART 2에서 한 것이다). 4단계 숫자가 실습지와 다르면 Kernel → Restart Kernel and Run All Cells… 로 처음부터 다시 실행합니다(3단계에 붙여 넣은 코드가 df·y를 바꿨을 수 있다).

오늘의 미션 — 검사 전에 합격/불합격을 미리 맞히는 모델을 만들자. 그런데 '무조건 합격'이라고 찍는 것보다 나을까?

문제 1 — 온도_C 한 열로 Feature 만들고 나누기 (노트북 4단계 문제 1)

문제 3 — Orange: 웨이퍼 패턴 트리의 첫 질문과 정확도 읽기

PART 1에서 만든 week09_1_patterns 캔버스를 그대로 쓴다. 닫았다면 week09_1_patterns_start.ows를 열어 캔버스 메모 ②·③대로 다시 잇는다(막히면 week09_1_patterns_done.ows).

  1. Tree Viewer를 열어 맨 위 상자(뿌리)의 첫 질문을 읽는다 — 상자 맨 아래 열 이름과, 아래로 뻗은 선 옆의 조건. 상자 안 숫자까지 보려면 왼쪽 Show details in non-leaves에 체크한다.
  2. Test and Score를 열어 Number of folds가 10인지 확인하고, Tree 줄의 CA를 읽는다. 표에는 AUC·CA·F1·Prec·Recall·MCC가 나오는데, CA 한 칸만 읽는다 — 첫 숫자 칸 AUC는 정확도가 아니다.

판단해 보자: 강의 그림에서 사람 눈에 가장 먼저 띄는 단서는 불량 다이가 어디에 모였는지(모양)였다. 그런데 트리는 왜 이 열을 첫 질문으로 골랐을까? 한 줄로 적는다.

첫 질문 불량다이수_count ≤ 11(≤ 11 갈래 145장 / > 11 갈래 95장). CA 0.942(94.2%). "정상"만 찍으면 120 ÷ 240 × 100 = 50% — 트리가 기준선보다 훨씬 잘 맞힌다. 이유(예): "정상 웨이퍼는 불량 다이가 적어서(이 데이터에서 3~8개), 개수만 물어도 정상을 먼저 크게 떼어 낼 수 있다. 모양(가장자리·직선 비율)은 그다음 질문에서 나눈다."
체크포인트 CA가 0.938이면 Number of folds가 5(처음 값)로 남아 있거나, Tree의 깊이 칸(Limit the maximal tree depth to)이 100 그대로다 — 둘 다 확인한다(이 데이터는 깊이 100이어도 트리가 조금만 커져서 그림으로는 알아채기 어렵다). 0.96쯤을 적었다면 CA가 아니라 AUC 칸을 읽은 것이다.

문제 4 — Orange: 공정 기록 트리 채점하고 놓친 불합격 세기

PART 1에서 만든 week09_2_passfail 캔버스(Distributions·Tree·Tree Viewer가 이어진 상태)에 이어 붙인다. 닫았다면 week09_2_passfail_start.ows를 열어 캔버스 메모 ②·③부터 다시 잇는다.

  1. 왼쪽 Evaluate 묶음의 Test and Score를 File과 잇고, Tree도 Test and Score에 잇는다. Number of folds를 10으로 고른다(캔버스 메모 ④).
  2. Evaluate 묶음의 Confusion Matrix를 Test and Score에 잇고 더블클릭한다. Show가 Number of instances인지 본다.
  3. Test and Score의 Tree 줄 CA(첫 숫자 칸 AUC가 아니다)와, Confusion Matrix에서 실제(Actual) -1 줄 · 예측(Predicted) 1 칸의 숫자를 읽는다.

CA를 기준선과 비교해 한 줄로 적는다. 그리고 "무조건 합격"은 실제 불합격을 몇 건 잡는지 생각해 트리와 비교한다. 웨이퍼 패턴(문제 3)과 무엇이 다른가?

CA 0.783(78.3%), 기준선 595 ÷ 750 ≈ 79.3%. 실제 -1 줄은 114 · 41 — 실제 불합격 155건 중 114건을 합격으로 놓치고 41건만 잡았다. "공정 기록 트리의 정확도는 기준선보다 조금 낮다. 웨이퍼 패턴은 기준선(50%)보다 훨씬 높았는데, 오늘 공정 기록으로는 정확도가 '무조건 합격'과 비슷하다." 다만 "무조건 합격"은 불합격 155건을 모두 놓친다. 트리는 41건을 잡았다 — 정확도가 비슷해도 하는 일은 다르다. 그래서 헷갈림 표를 함께 본다. 파이썬 6개 열 모델(80.3% vs 78.9%)과 숫자는 다르지만(Orange는 750행 10겹 평균, 파이썬은 시험용 147개 한 번) 결론은 같다.
체크포인트 Confusion Matrix 표가 비어 있으면 Tree에서 Test and Score로 가는 선이 빠졌다. CA가 0.783과 조금 다르면 Number of folds를 10으로 바꿨는지 본다. CA가 0.739쯤이면 Tree 깊이가 100으로 남아 있다(Tree Viewer 정보 줄이 171 nodes쯤으로 크다) — 깊이를 4로 바꾼다. 0.68쯤을 적었다면 AUC 칸을 읽은 것이다. Orange는 빈칸 행을 지우지 않고 750행을 모두 쓴다 — 표의 합계(∑)가 750이면 맞다. 막히면 week09_2_passfail_done.ows를 연다.

문제 5 — 해석 문장 쓰기

오늘의 질문 "지난 기록만 보고, 아직 검사하지 않은 로트의 합격/불합격을 미리 맞힐 수 있을까?"에 문제 2~4의 숫자로 답하자.

문장 틀 "웨이퍼 패턴은 ______%로 잘 맞히지만, 공정 기록 모델은 기준선 ______%와 비슷한 ______%다. 맞혔다고 원인을 아는 것은 아니다 — 첫 질문 ________은 불합격의 원인 후보일 뿐이다."

이어서 판단해 보자: 이 숫자만으로 "이 모델로 검사를 줄여도 된다"고 보고해도 될까? 문제 4의 놓친 불합격 수를 근거로 한 줄 적는다.

"웨이퍼 패턴은 94.2%로 잘 맞히지만, 공정 기록 모델은 기준선 79.3%와 비슷한 78.3%다. 맞혔다고 원인을 아는 것은 아니다 — 첫 질문 온도_C는 불합격의 원인 후보일 뿐이다."
판단(예): "안 된다. 실제 불합격 155건 중 114건을 합격으로 놓쳤다. 지금 모델은 먼저 살펴볼 로트를 고르는 참고까지만 쓸 수 있고, ⑦ 검사를 대신할 수 없다."
