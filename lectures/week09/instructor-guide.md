## 강사 설명 포인트
- **가장 먼저** "이 데이터는 실제 fab.csv에서 나온 진짜 측정값이지만, 센서 이름과 별칭은
  이번 과정에서 교육용으로 붙인 것"이라는 이중적인 성격을 분명히 한다. 학생들이 "센서59가
  진짜로 챔버 온도를 측정한다"고 오해하지 않도록 반드시 짚고 넘어간다.
- `주요센서_A`, `주요센서_B`를 보여줄 때 "왜 이름을 못 붙였을까?"를 질문으로 던져서 학생 스스로
  "이름을 안다고 의미를 아는 것은 아니다"라는 결론에 도달하게 유도한다.
- 부호 반전(`합격여부` 1=합격 vs `Pass_Fail` -1=정상)은 칠판에 두 표기를 나란히 적어 시각적으로
  비교해준다. `검사결과`(0=정상, 1=이상)로 통일했다는 것을 강조.
- "정확도의 함정"은 반드시 **실제 계산값**으로 보여준다: 전체 데이터 기준 무조건 정상 예측
  정확도 약 93.42%, test 데이터 기준 약 93.37%. 그리고 실제 모델의 test 정확도는 약 92.86%로
  숫자상으로는 더 낮지만, 혼동행렬을 보면 이상 26건 중 2건을 찾아냈다는 점이 "무조건 정상"보다
  실질적으로 낫다는 것을 강조한다. 이 역설적인 결과가 오늘 수업의 핵심 메시지다.
- "예측이 잘 된다"와 "원인을 증명한다"는 다른 말임을 마지막에 다시 한번 문장으로 정리해준다.
  `feature_importances_` 결과를 보여줄 때 반드시 이 경고를 함께 말한다.

  어떻게 표현하시겠어요?"

## 예상 오개념
- "정확도가 높으니 좋은 모델"이라는 단순화 → 혼동행렬을 반드시 함께 보도록 강조.
- "별칭이 있으니 실제 의미를 안다"는 오해 → 데이터 설명서의 경고 문구를 함께 읽어준다.
- "중요도가 높은 센서 = 불량의 원인"이라는 인과관계 오해 → 8주차의 "상관관계 ≠ 원인"
  원칙을 다시 소환해서 연결한다.
- `train_test_split`에서 `stratify`를 빼도 결과가 크게 다르지 않을 것이라는 오해 →
  실제로 이상 사례가 적을 때는 우연히 test에 이상 사례가 거의 없게 나뉠 수 있음을 설명.

## 실습 중 오류 대응
- `ValueError: Input contains NaN`: 결측치 처리(`fillna`/`dropna`) 셀을 건너뛰었는지 확인.
- `KeyError`: 열 이름(특히 `검사결과`, `주요센서_A`, `주요센서_B`)의 오타나 인코딩 문제 확인.
  파일을 `utf-8-sig`로 저장했으므로 `pd.read_csv()`로 기본 설정 그대로 읽으면 문제없다.
- 결과 숫자가 강의안과 다르다고 하는 학생: `random_state=42`가 코드에 정확히 들어갔는지,
  `train_test_split`의 `test_size`, `stratify` 인자가 강의안과 동일한지 확인.

## 빠른 학습자용 추가 과제
- `max_depth`를 2, 4, 8, `None`으로 각각 바꿔가며 train 정확도와 test 정확도를 표로
  정리하고, 어느 지점부터 과적합이 시작되는지 토론해본다.
- `week09_fab_selected_sensors.csv`(원본 부호, 15개 센서)를 열어 `Pass_Fail` 값을 직접
  `검사결과` 방식으로 변환하는 코드(`(df['Pass_Fail'] == 1).astype(int)`)를 작성해보게 한다.

## 느린 학습자용 최소 과제
- 강사가 미리 실행해 둔 코드 결과를 함께 읽으며 "정상 몇 건, 이상 몇 건"과 "혼동행렬에서
  이상을 몇 건 맞혔는가"만 말로 설명할 수 있으면 충분하다.
- `train_test_split`과 `DecisionTreeClassifier` 줄은 강사가 완성된 코드를 제공하고,
  학생은 `accuracy_score`와 `confusion_matrix` 출력 결과를 해석하는 데 집중하게 한다.
