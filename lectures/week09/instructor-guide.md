# 9차시 강의 운영안 — 머신러닝 예측 모델 만들기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

웨이퍼는 ②~⑥ 공정을 여러 번 거친 뒤에야 ⑦ 전기 검사(EDS)를 받는다. 검사 전에 "이 로트는 불합격이 나올 것 같다"를 미리 알 수 있다면 먼저 살펴볼 로트를 고를 수 있다.
3차시에는 사람이 `if`로 규칙을 썼고, 오늘은 컴퓨터가 지난 기록에서 규칙을 찾는다(머신러닝).
오늘의 핵심 교훈은 두 가지다. ① 정확도 하나로는 모른다 — "무조건 합격" 기준선과 나란히 놓는다(피자 가게: 95판이 안 타면 늘 "안 탄다"만 말해도 95%). ② 잘 맞힌다고 원인을 아는 것은 아니다 — 트리의 첫 질문 열도 "원인 후보"까지다.
오늘 데이터에서 그 차이가 숫자로 드러난다. 웨이퍼 맵 요약은 뚜렷한 단서가 있어 94.2%(기준선 50%)를 맞히지만, 오늘 공정 기록은 정확도가 기준선과 거의 같다. 그렇다고 "무조건 합격"이 더 나은 것은 아니다 — "무조건 합격"은 불합격 155건을 모두 놓치고, 트리는 41건을 잡는다. 정확도와 헷갈림 표를 함께 본다.

## 수업 흐름

9·10차시는 **PART 1 Orange3 → PART 2 파이썬 + ChatGPT → PART 3 실습지** 순서다. 노트북은 단계 번호, Orange는 캔버스 메모 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 아홉째 날) → 지난 시간 복습 2문항(진공도 = 원인 후보, Correlations에 합격여부가 없는 이유 → 오늘은 그 열이 맞힐 목표)
2. PART 1 시작: Orange 말 사전, 위젯 이름표(새 위젯 4개: Tree = Model, Tree Viewer = Visualize, Test and Score·Confusion Matrix = Evaluate), 공정 지도 위치 두 줄
3. 개념 네 절: 머신러닝(Feature/Label, 피자 가게 표) → 결정 트리(스무고개) → 학습용·시험용(연습문제·모의고사, 10겹 교차검증) → 정확도와 기준선(헷갈림 표 읽는 법)
4. 워밍업 `week09_1_patterns_start.ows`(학생이 직접): 메모 ② Tree(깊이 4) → Tree Viewer, "가장자리형 100%" 상자 예상하고 찾기 → 메모 ③ Test and Score(10겹) → 메모 ④ Confusion Matrix, "정상으로 헷갈린 패턴" 예상하고 확인. 메모 ⑤ Distributions는 더 해 보기
5. **여기서 쉬기**
6. 반도체 `week09_2_passfail_start.ows`(학생이 직접): 메모 ① 750행 → 메모 ② Distributions(합격여부, Split by None) 기준선 어림 → 확인(595/750 ≈ 79.3%) → 메모 ③ Tree → Tree Viewer(Show details in non-leaves 체크), 뿌리 595/750 = 기준선 연결 → 첫 질문 `온도_C`, 한 줄 더 내려가 양쪽 끝(≤ 293.8 56.0%, > 306.0 46.2%) → "원인 후보" 문장. 메모 ④는 실습지 문제 4로 미룬다
7. PART 2 시작: Orange ↔ 파이썬 짝 표
8. 노트북 1단계: 읽기 `(750, 9)` → 빈칸 수 → 학생 빈칸 `dropna` → `(735, 9)`
9. 노트북 2단계: 학생 빈칸 `"합격여부"` → `(735, 6) (735,)` → `588 147` → 학생 빈칸 `fit`·`y_test` → 예상 후 결과 열기 `정확도: 80.3%`(기준선 78.9%, 147개 중 2개 차이. 그래도 불합격 31개 중 9개를 잡는다 — 기준선은 0개)
10. 노트북 3단계 ChatGPT 체험: 프롬프트 복사 → 빈 셀에 붙여 실행(못 쓰면 응답 예시 셀) → 2단계 숫자와 맞춰 보기(`0.8027…` × 100 = 80.3%) → 직접 바꿔 보기(`stratify=y` 지우기 → `0.7755…`) → 조건이 빠지면 달라지는 숫자 표
11. **여기서 쉬기**(필요하면)
12. PART 3 실습지: 시작할 때 "4단계 숫자가 실습지와 다르면 Kernel → Restart Kernel and Run All Cells… 로 처음부터 다시 실행합니다(3단계에 붙여 넣은 코드가 df·y를 바꿨을 수 있다)."를 한 번 말해 준다. 문제 1·2(노트북 4단계, 온도_C 한 열 모델 — 문제 2는 빈칸 없이 직접 쓰기) → 문제 3(웨이퍼 패턴 첫 질문·CA) → 문제 4(공정 기록 메모 ④: Test and Score + Confusion Matrix) → 문제 5(해석 문장 + 판단) → 정답 확인과 문장 발표
13. 결과 정리·반도체 이해 포인트 → AI로 한 걸음 더(깊이별 정확도) → 과제·10차시 예고

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)

### 웨이퍼 맵 요약(Orange 워밍업) — `week09_orange_wafer_patterns.csv`(교육용 가상 데이터, 240행 6열)
- 공정 지도 위치: ⑦ EDS 웨이퍼 맵의 요약. 정상 120 · 중심형 40 · 가장자리형 40 · 스크래치형 40장. **"정상"은 불량 0개가 아니다** — 불량 다이 3~8개가 흩어져 뚜렷한 모양이 없는 웨이퍼(7차시의 "없음")라고 한 줄 말해 준다. 이 가상 웨이퍼 한 장 = 다이 317개(실제 다이 수는 칩 크기에 따라 다르다).
- `week09_1_patterns_done.ows`(Tree 깊이 4, Test and Score **10겹**, 격리 설정 헤드리스 실측):
  - Tree Viewer 뿌리: `정상 · 50.0%, 120/240`, 첫 질문 **`불량다이수_count` ≤ 11**(145장, `정상 · 82.8%, 120/145`) / > 11(95장). 정보 줄 `17 nodes, 9 leaves`(nodes = 상자 전체, leaves = 끝 상자).
  - 둘째 줄: > 11 갈래 → `가장자리불량비율_pct > 35.3` 상자 **`가장자리형 · 100%, 40/40`** / ≤ 35.3은 55장(중심형 30 · 스크래치형 25 → 다음 질문 `직선불량비율_pct`). ≤ 11 갈래 → `불량다이수_count ≤ 8`(128장, 정상 120) / 8~11(17장 → 다음 질문 `직선불량비율_pct`).
  - 깊이를 안 바꿔도(100) 이 데이터는 트리가 조금만 커진다(19 nodes, 리허설 실측). 5겹이거나 깊이 100이면 CA 0.938.
  - Test and Score(Tree): **CA 0.942** · AUC 0.961 · F1 0.940 · Prec 0.941 · Recall 0.942. "정상"만 찍는 기준선 120 ÷ 240 = 50%.
  - Confusion Matrix(Actual 줄 → Predicted 정상·중심형·가장자리형·스크래치형): 정상 119·1·0·0 / 중심형 **4**·33·0·3 / 가장자리형 0·0·40·0 / 스크래치형 **4**·1·1·34.

### 공정 기록(Orange) — `week09_2_passfail_done.ows`(750행, 빈칸 행을 지우지 않음)
- 공정 지도 위치: ②~⑤ + 세정의 공정 조건과 검사 결과(`합격여부` = 공정 중간 검사 + ⑦ EDS 결과를 한 열에 모은 교육용 설정, 행마다. 같은 로트가 여러 행에 나올 수 있다). 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록). `공정명`·`설비번호`는 meta라 Feature가 아니다(파이썬과 같은 6개 열).
- Distributions(합격여부, Split by None): 1 = **595**, -1 = **155** → 기준선 595 ÷ 750 ≈ **79.3%**.
- Tree Viewer: 뿌리 `1 · 79.3%, 595/750`, 첫 질문 **`온도_C` ≤ 293.8**(`-1 · 56.0%, 42/75`) / > 293.8(`1 · 83.2%, 561/674`). 두 갈래 합 749(온도 빈칸 1건은 Orange가 따로 처리). 정보 줄 `29 nodes, 15 leaves`. 뿌리의 595/750 = 79.3%는 Distributions 기준선과 같다.
  - 한 줄 더 내려가면 > 293.8 갈래가 다시 `온도_C`로 나뉜다: 293.8~306.0 `1 · 87.2%, 518/594`(불합격 76건, 12.8%) / > 306.0 `1 · 53.8%, 43/80`(불합격 37건, 46.2%). 온도 **양쪽 끝**(56.0%, 46.2%)에 불합격이 많고 가운데(12.8%)는 적다 — 8차시 진공도 같은 모양(교육용 가상 관계).
  - 깊이 100 그대로 두면 CA **0.739**, `171 nodes`(리허설 실측). 5겹·깊이 4면 0.781.
- Test and Score(Tree, 10겹): **CA 0.783** · AUC 0.681 · F1 0.759 → 기준선(0.793)보다 조금 낮다. 학생이 첫 숫자 칸 AUC(0.681)를 정확도로 적지 않게 한다 — **CA 한 칸만 읽는다**.
- Confusion Matrix(Tree): Actual 1 → Predicted 1 **546** · -1 49 / Actual -1 → Predicted 1 **114**(놓친 불합격) · -1 **41**. 합 750.

### 공정 기록(파이썬) — `week09_pass_fail_train.csv`(교육용 가상 데이터, 750행 9열)
- 1단계: `(750, 9)` → 빈칸 온도_C 1 · 압력_Pa 3 · 가스유량_slm 3 · 습도_pct 8(합 15) → `dropna()` → `(735, 9)`.
- 2단계: `(735, 6) (735,)` → `588 147` → `fit` 셀 출력 `DecisionTreeClassifier(max_depth=4, random_state=42)` → **`정확도: 80.3%`**(147개 중 118개). 시험용 불합격 31개 중 9개를 잡고 22개를 놓쳤다(실제 -1 → 예측 -1 9 · 1 22, 실제 1 → -1 7 · 1 109).
- 기준선(값으로만, 코드 없음): 시험용 147개 중 합격 116개 → 116 ÷ 147 ≈ **78.9%**. 모델과 2개 차이.
- 4단계(실습지 문제 1·2): `temp_features = ["온도_C"]` → `(735, 1)` → `588 147` → **`온도_C 한 열 정확도: 78.2%`**(기준선보다 낮다). 학습용으로 잘못 채점하면 82.7%(조용한 오답).
- 3단계 응답 예시: `정확도: 0.8027210884353742`(× 100 = 80.3%). 직접 바꿔 보기(`stratify=y` 삭제): `정확도: 0.7755102040816326`.
- 조건이 빠지면(같은 데이터로 실행): `stratify=y` 없음 77.6%(`0.7755102040816326`) / `max_depth=4` 없음 74.8% / `dropna()` 없음 79.3%(시험용 150개 중 119개 — Orange 기준선 79.3%와 숫자만 우연히 같다) / Feature에 `합격여부` 포함 100.0%.
- AI로 한 걸음 더(학습용 / 시험용 정확도): 깊이 2 80.4% / 74.1%, 깊이 4 84.7% / 80.3%, 제한 없음 100.0% / 74.8%.
- 참고(데이터 설명서): 원본 750행 합격 595 · 불합격 155, `dropna()` 뒤 735행 합격 582 · 불합격 153. 압력_Pa 절대값은 해석하지 않는다(교육용 가상 값).

## 강사 설명 포인트

- 오늘은 Orange가 먼저다. 개념(Feature/Label, 스무고개, 연습문제·모의고사, 기준선)을 말로 잡은 뒤 위젯으로 바로 확인한다. 파이썬은 "Orange에서 한 일을 몇 줄로"만 보여 준다(짝 표).
- **정확도는 기준선과 함께, 그리고 헷갈림 표와 함께 읽는다.** 웨이퍼 패턴 94.2% vs 50%, 공정 기록 78.3% vs 79.3%(Orange) / 80.3% vs 78.9%(파이썬). 같은 "80% 안팎"이라도 기준선에 따라 뜻이 다르다.
  정확도가 기준선보다 조금 낮아도 "무조건 합격이 낫다"는 뜻은 아니다 — "무조건 합격"은 불합격 155건(파이썬 시험용 31개)을 모두 놓치고, 트리는 41건(9개)을 잡는다. 하는 일이 다르다.
- Orange와 파이썬 숫자가 다른 것은 정상이다. Orange는 750행으로 10겹 교차검증 평균, 파이썬은 빈칸 15행을 지운 735행에서 시험용 147개로 한 번 채점했다. 결론(정확도는 기준선과 비슷하고, 불합격은 일부만 잡는다)이 같은지를 본다.
- **트리의 첫 질문 열 = 원인 후보.** 트리는 기록을 잘 나누는 열을 고를 뿐이다. 실습지 문제 2의 온도 한 열 모델 78.2%는 "첫 질문 열이라도 혼자서는 충분하지 않다"는 근거다. 원인인지 아닌지와는 별개다 — 정확도가 높았어도 원인 후보까지다(정확도를 인과의 근거로도, 반증으로도 쓰지 않는다). 온도를 원인으로 단정하는 학생에게는 "무엇을 더 확인하면 원인이라 할 수 있을까?"(실험·설비 점검)로 되묻는다.
- 워밍업 첫 질문은 사람이 예상하는 "가장자리 모양"이 아니라 **불량 다이 개수**다. "먼저 개수로 정상을 크게 떼어 내고, 다음 질문에서 모양(비율)으로 나눈다"로 설명한다. 6·7차시의 가장자리 고리는 둘째 줄, **불량 다이 11개 초과 웨이퍼 중에서** `가장자리불량비율_pct > 35.3`(가장자리형 100%)으로 나온다. 이 조건을 빼고 "가장자리 비율 35.3% 초과 = 가장자리형"으로 말하지 않는다 — 이 가상 웨이퍼는 다이 317개 중 120개(약 38%)가 가장자리 영역이라, 불량이 흩어져 있기만 해도 가장자리 비율이 40% 가까이 나온다(정상 웨이퍼 평균 36.5%).
  보충: 불량이 적으면 비율 열이 우연히 크게 나온다(불량 다이가 두세 개뿐이면 거의 늘 한 직선 위에 있다). 그래서 개수부터 묻는 것이 자연스럽다.
- 이 가상 웨이퍼 한 장의 다이 317개는 교육용 격자다(실제 다이 수는 칩 크기에 따라 다르다). 불량패턴 라벨은 ⑦ EDS 웨이퍼 맵을 보고 붙인 교육용 설정이다.
- 공정 기록의 `설비번호`에는 여러 공정 기록이 섞여 있다(교육용 가상 기록). 설비별 차이 이야기는 오늘 하지 않는다. 압력_Pa 절대값도 해석하지 않는다. 온도·두께·진공도도 다섯 공정이 모두 비슷한 크기로 만든 교육용 값이다(실제는 공정마다 크게 다르다).
- 오늘 공정 기록이 기준선과 비슷하게 나오는 것은 교육용으로 단서를 약하게 만든 설계 결과다. "공정 조건으로는 합격/불합격을 예측할 수 없다"는 반도체 일반 사실로 말하지 않는다.
- 예측 모델은 ⑦ 검사를 대신하지 않는다. 오늘 공정 기록 모델은 실제 불합격 155건 중 114건을 놓쳤다 — "먼저 살펴볼 로트를 고르는 참고"까지다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **결정 트리 스무고개**: 대체로 잘 답한다. AI가 지니 불순도·엔트로피 같은 계산을 길게 늘어놓으면 "가장 잘 나누는 질문을 먼저 고른다"까지만 받아들이게 한다.
- **과적합 뜻**: AI가 "트리 깊이가 깊을수록 무조건 나쁘다"처럼 단정할 수 있다. 너무 얕아도 못 맞힌다(깊이 2: 시험용 74.1%)고 보충한다. 오늘 숫자로는 깊이 제한 없음이 학습용 100% / 시험용 74.8%.
- **정확도의 함정 불균형 데이터**: 재현율·정밀도·F1을 길게 소개할 수 있다. 오늘은 기준선 비교와 헷갈림 표의 "놓친 불합격" 칸만 쓴다고 정리한다(Orange 표의 F1·Prec·Recall은 설명하지 않는다).
- **예측과 인과 차이**: AI가 "그 값이 원인이므로 바꾸면 불합격이 줄어든다"처럼 조치로 건너뛸 수 있다. 데이터 밖 근거(그 값만 바꿔 보는 실험, 설비 점검·정비 기록, 현장 엔지니어 확인)가 필요하다는 부분만 받아들이게 한다.

## 예상 오개념

- 정확도가 80%면 좋은 모델이다 → 기준선(무조건 합격)이 79%대라면 정확도로는 차이가 거의 없다.
- 정확도가 기준선보다 낮으면 "무조건 합격"이 더 낫다 → 기준선은 불합격을 하나도 못 잡는다. 트리는 155건 중 41건을 잡았다. 정확도와 놓친 불합격 수를 함께 본다.
- "정상" 웨이퍼는 불량 다이가 0개다 → 이 데이터의 정상은 불량 다이 3~8개가 흩어져 뚜렷한 모양이 없는 웨이퍼다.
- 가장자리 비율이 35.3%를 넘으면 가장자리형이다 → 불량 다이 11개 초과 웨이퍼 중에서만 통하는 규칙이다. 흩어진 불량도 가장자리 비율이 40% 가까이 나온다.
- 정답 열을 Feature에 넣으면 더 잘 맞힌다 → 정답 누설. 오류 없이 100%가 나와도 의미가 없다.
- 학습한 기록으로 채점해도 된다 → 이미 본 문제라 부풀려진다(깊이 제한 없음 학습용 100% vs 시험용 74.8%).
- 트리의 첫 질문 열이 원인이다 → 기록을 잘 나누는 열일 뿐, 원인 후보다. 한 열 모델 정확도가 높든 낮든 원인 여부의 근거가 되지 않는다.
- 온도가 낮을수록 불합격이 많다 → 한 줄 더 보면 온도가 높은 쪽(> 306.0)도 46.2%다. 양쪽 끝이 나쁜 모양이다.
- Orange와 파이썬 숫자가 다르니 하나가 틀렸다 → 행 수(750 vs 735)와 채점 방법(10겹 평균 vs 시험용 147개 한 번)이 다르다.
- 예측 모델이 있으면 검사를 줄여도 된다 → 실제 불합격 155건 중 114건을 놓쳤다. 참고 도구다.
- `fit` 셀의 `DecisionTreeClassifier(max_depth=4, random_state=42)` 출력이 오류다 → 학습을 마친 모델을 보여 주는 표시다.

## 막히는 지점 TOP3와 대처

1. **Test and Score를 10겹으로 안 바꿈 / 선 하나 빠짐** — 새 위젯은 5겹이라 CA가 실습지 정답과 조금 다르다. Tree → Test and Score 선을 빠뜨리면 표가 빈다. 화면에서 "선 두 개(File, Tree)"와 Number of folds 칸을 손으로 짚게 한다. 그래도 안 맞으면 `_done.ows`를 열어 비교한다.
2. **Tree Viewer가 너무 커서 읽지 못함 / 숫자가 안 보임** — 공정 기록은 깊이를 4로 안 바꾸면 그림이 훨씬 커진다(`171 nodes`, CA 0.739). 웨이퍼 패턴은 깊이 100이어도 조금만 커져서 그림으로는 알아채기 어렵다 — Tree 창의 Limit the maximal tree depth to 칸을 직접 확인한다. 중간 상자에 숫자가 없으면 Show details in non-leaves를 켠다. 깊이부터 확인하고, 왼쪽 Zoom 막대로 줄인다. 상자 읽는 법(굵은 글자 / % / n/N / 맨 아래 열 이름)을 칠판에 적어 둔다.
3. **실습지 문제 2(빈칸 없는 셀)에서 멈춤** — 노트북 2단계 학습·정확도 두 셀을 복사해 이름만 바꾸게 한다: `model` → `model1`, `acc` → `acc1`, `X_train`/`y_train`/`X_test`/`y_test` → `X1_train`/`y1_train`/`X1_test`/`y1_test`, 출력 문장. `X_test`를 그대로 두면 `ValueError: The feature names should match those that were passed during fit.`가 난다. 오류 없는 오답 두 가지: 82.7% → 학습용(`X1_train`, `y1_train`)으로 채점했다. 80.3% → `X1`에 6개 열이 들어갔거나 정확도 줄에 `model`·`X_test`가 남았다.

## 실습 중 오류 대응

- `AttributeError: 'DataFrame' object has no attribute '____'` / `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'` / `NameError: name '____' is not defined`: 빈칸을 아직 안 채웠다.
- `NameError: name '합격여부' is not defined`: 열 이름을 따옴표 없이 썼다. `df["합격여부"]`.
- `NameError: name '온도_C' is not defined`: 문제 1 리스트에 열 이름을 따옴표 없이 썼다. `["온도_C"]`.
- `KeyError: 'temp_features'`: 변수 이름을 따옴표로 감쌌다. `df[temp_features]`.
- 오류 없이 4단계 숫자가 다름(`(735, 1)`·`588 147`·78.2%가 아님): 3단계에 붙여 넣은 ChatGPT 코드가 `df`나 `y`를 다른 값으로 덮어썼을 수 있다(예: `dropna` 없이 `df`를 다시 읽음). Kernel → Restart Kernel and Run All Cells…로 위에서부터 다시 실행한다.
- `NameError: name 'train_test_split' is not defined`: 노트북 2단계를 건너뛰고 4단계를 실행했다. 2단계부터 차례로.
- 연쇄 `NameError`(`name 'y'`, `name 'y_test'`, `name 'X1'`): 그 이름을 만드는 앞 셀이 실패했다. 앞 셀부터 고친다.
- `ValueError: Expected a 2-dimensional container but got <class 'pandas.Series'> instead.`로 시작하는 오류: 문제 1에서 대괄호 없이 `temp_features = "온도_C"`로 썼다(`X1.shape`가 `(735,)`).
- `NotFittedError: This DecisionTreeClassifier instance is not fitted yet. Call 'fit' with appropriate arguments before using this estimator.`: `fit` 전에 정확도 셀을 실행했다.
- `ValueError: The feature names should match those that were passed during fit.`: 학습과 채점에 다른 열의 X를 썼다(`X_test`와 `X1_test` 혼동).
- `ValueError: could not convert string to float: 'EQ-02'`: Feature에 글자 열(`설비번호`)을 넣었다.
- 오류 없이 이상한 숫자: 정확도 100% → Feature에 `합격여부`가 들어갔다. 79.3% → `dropna()`를 건너뛰었다(`print(df.shape)`가 `(735, 9)`인지 확인). 문제 2가 80.3% → `X1`에 6개 열이 들어갔거나 `model`·`X_test`가 남았다. 문제 2가 82.7% → 학습용으로 채점했다.
- ChatGPT 코드 숫자가 다름: `stratify=y` 빠짐 77.6%, `max_depth=4` 빠짐 74.8%, `dropna()` 빠짐 79.3%. 조건을 하나씩 비교한다.
- Orange File에 파일 이름이 빨갛게 보임: 키트 폴더 구조가 바뀌었거나 `.ows`를 다른 곳으로 옮겼다. 키트를 다시 풀고 그 안에서 연다.
- Orange CA가 강의와 조금 다름: Number of folds가 5, 또는 Tree 깊이가 4가 아니다(웨이퍼 0.938, 공정 기록 깊이 100이면 0.739). 0.96·0.68쯤이면 AUC 칸을 읽었다.

## 빨리 끝낸 학생용 과제

- 노트북 맨 아래에 셀을 하나 만들어, 문제 2와 같은 모양으로 `진공도_mTorr` 한 열 모델(`X2`, `model2`)의 정확도를 구하고 6개 열 80.3%·기준선 78.9%·온도 한 열 78.2%와 한 줄로 비교한다(강의 과제 1과 같다).
