# 9차시 강의 운영안 — 머신러닝 예측 모델 만들기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

검사 전에 "이 로트는 불합격일 것 같다"를 알면 다음 공정으로 보내기 전에 막을 수 있다. 오늘은 지난 기록 735건으로
그 예측이 얼마나 믿을 만한지 숫자로 따진다. 일기예보처럼, 맞히는 것과 원인을 아는 것은 다르다.

## 수업 흐름

1. 복습: 3차시(사람이 쓴 `if` 규칙 295~305℃), 8차시("원인 후보").
2. 개념은 **쉬운 예제(야외 체육 수업)만으로**: 머신러닝·Feature/Label → 두 데이터의 열과 **부호(`합격여부` 1 = 합격, -1 = 불합격 / `진행여부` 1 = 진행, -1 = 취소)** → 여러 Feature(비만 보면 놓치는 9일) → 결정트리 질문 표 → train/test(기출문제만 외운 학생) → 정확도 91.7% vs 찍기 70.8%, 혼동행렬 `[[16 1] [1 6]]`
3. Orange3 시연(STEP 01): 합격여부 = 범주형·목표(target) → 트리 → 학습·평가, CA를 칠판에 적는다
4. 휴식
5. 쉬운 예제 코드 시연(STEP 02~04, 노트북 1~8단계): 읽기·dropna → X/y → split → fit → 정확도·찍기 → 혼동행렬 → 중요도
6. **반도체 데이터로 확인하기**(강의 절, 정답 노트북으로 시연): 트리 그림과 3차시 비교 → 확인 1 80.3% vs 78.9%(2건 차이) → 확인 2 `[[109 7] [22 9]]`(놓친 불량 22) → 확인 3 중요도 + 범위 밖/안 표 → 원인 후보
7. 학생 실습: 실습지 문제 1~8 = 노트북 9~12단계(반도체), 결과 문장
8. AI로 한 걸음 더(노트북 13·14단계) → 퀴즈·과제·10차시 예고

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
**쉬운 예제**(가상 데이터, `max_depth=4`, `random_state=42`, `test_size=0.2`, `stratify`)
- 120행 → `dropna()` 116행(결측 기온 1·습도 2·풍속 1). 진행 82, 취소 34. 분할 92 / 24(모의고사 진행 17·취소 7).
- 정확도 **91.7%**(22/24), 찍기 **70.8%**(17/24). 혼동행렬 `[[16 1] [1 6]]`(놓침 4월 11일 풍속 9.2m/s, 헛경보 4월 14일 비 12.1mm). `labels`를 빼면 `[[6 1] [1 16]]`.
- 트리: 강수량 ≤ 4.75 → 기온 ≤ 31.75 → 풍속 ≤ 9.9 → 강수량 ≤ 1.0. 중요도: 강수량 69.8%, 기온 24.8%, 풍속 5.4%, 습도 0.0%.

**반도체**(가상 데이터, `압력_Pa`는 크기를 해석하지 않는다)
- 750행 9열 → `dropna()` 735행(결측 온도 1·압력 3·가스유량 3·습도 8). 합격 **582**, 불합격 **153**. 분할 **588 / 147**(모의고사 합격 116·불합격 31).
- 온도×진공도: 둘 다 안 401건 8.0%, 온도만 밖 193건 33.2%, 진공도만 밖 95건 32.6%, 둘 다 밖 46건 56.5%.
  열 하나씩 밖/안: 온도 239건 37.7% / 496건 12.7%, 진공도 141건 40.4% / 594건 16.2%, 가스유량 241건 20.3% / 494건 21.1%.
- 트리(588건): 온도 ≤ 293.95℃? → 온도 ≤ 306.05℃? → 진공도 ≤ 5.49 mTorr?(예 406건 9.4% / 아니오 53건 34.0%).
- 정확도 **80.3%**(118/147), 찍기 **78.9%**(116/147). 혼동행렬 `[[109 7] [22 9]]`, `labels`를 빼면 `[[9 22] [7 109]]`.
- 중요도: 온도 48.8%, 진공도 21.1%, 압력 16.7%, 가스유량 9.2%, 두께 4.2%, 습도 0.0%. 온도-두께 r = 0.81.

## 강사 설명 포인트
- 개념 설명 중에는 반도체 코드를 꺼내지 않는다. 반도체는 "반도체 데이터로 확인하기" 세 가지(찍기 비교·놓친 불량·원인 후보)에 집중하고, 나머지는 실습지에서 학생이 `easy_`를 떼고 풀게 한다.
- 쉬운 예제와 나란히 비교: 찍기보다 5일 vs 2건. 정확도 하나로는 판단할 수 없다.
- 혼동행렬은 공장 말로 한 칸씩("멀쩡한데 의심 7", "불량인데 통과 22"). `labels=[1, -1]`을 일부러 빼서 뒤집히는 것을 보여준다. TP/FN 같은 약어는 쓰지 않는다.
- 원인 후보는 **결과변수(불합격)와 근거 수치 두 가지**(중요도 + 열 하나씩 밖/안 비율)를 함께 말한다. 33.2%·32.6%는 "온도만/진공도만 벗어난" 부분집합 값이라 이 문장에 쓰지 않는다. 압력은 범위 비교를 안 했으니 보류.
- **강사만 알 것**: 가스유량·습도는 합격여부와 관계없게 만든 비교용 열이다. 가스유량 중요도 9.2%는 우연한 패턴의 예다. 두께는 생성 로직에 있지만 온도와 함께 움직여 중요도가 4.2%로 낮다.
- Orange3 CA가 달라도 정상이다(공정명·설비번호 포함, 결측 유지, 기본 깊이 다름, 여러 번 나눠 평균). 그림 9-3 캡처는 CA 0.747(Random sampling 20회·66%·Stratified)이고, 학생 화면 값은 설정에 따라 다를 수 있다.
- 그림 9-1 캡처에는 파일 → 트리 연결선이 없다(학습·평가에는 없어도 된다). 10차시 예측(Predictions)에는 파일 → 트리 연결이 필요하므로 오늘 캔버스에서 이어 두게 한다.

## 예상 오개념
- "정확도가 높으면 좋은 모델" → 찍기도 78.9%다. 혼동행렬을 함께 본다.
- "학습에 쓴 데이터로 채점해도 된다" → 기출문제만 외운 학생 비유. 실력은 모의고사로 잰다.
- "강수량 중요도가 가장 높으니 비가 취소의 원인이다" → 중요도만으로 원인이라고 단정하지 않는다. 비가 원인이라고 말할 수 있는 것은 학교의 "비 오면 취소" 규칙을 따로 알기 때문이다. 반도체에서는 그 확인이 현장 실험이다.
- "혼동행렬 윗줄은 언제나 합격" → `labels=[1, -1]`을 붙였을 때만.
- "중요도가 높은 열 = 불량의 원인" → 범위 비교 수치까지 갖춰도 원인 후보일 뿐이다.

## 실습 중 오류 대응
학생용 노트북을 실제로 실행해 확인한 오류다.
- 빈칸 미기입: `pd.____(...)` → `AttributeError: module 'pandas' has no attribute '____'`(이후 반도체 셀은 `NameError: name 'df' is not defined`),
  `df.____()` → `AttributeError: 'DataFrame' object has no attribute '____'`, `model.____(...)` → `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'`,
  나머지 → `NameError: name '____' is not defined`.
- 변수 섞음(`model.fit(easy_X_train, y_train)`): `ValueError: Number of labels=588 does not match number of samples=92`. 반도체 셀에 `easy_`가 남았는지 확인.
- 파일 이름 오타: `FileNotFoundError: [Errno 2] No such file or directory`.
- 셀 건너뜀: `NameError: name 'X_train' is not defined`, `NameError: name 'y_test' is not defined` → 맨 위부터 다시 실행.
- `fit` 없이 예측: `NotFittedError: This DecisionTreeClassifier instance is not fitted yet.`
- 글자 열 포함(`feature_cols`에 `공정명`을 넣은 경우): `ValueError: could not convert string to float: '식각'`.
- 오류 없이 숫자만 다름: `dropna()` 생략 → 79.3%(735행 확인), 정답 열을 Feature에 넣음 → 100.0%.
