# 9차시 강의 운영안 — 머신러닝 예측 모델 만들고 새 로트 예측하기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

웨이퍼는 ②~⑥ 공정을 여러 번 거친 뒤에야 ⑦ 전기 검사(EDS)를 받는다. 검사 전에 "이 로트는 불합격이 나올 것 같다"를 미리 알 수 있다면 먼저 살펴볼 로트를 고를 수 있다.
3차시에는 사람이 `if`로 규칙을 썼고, 오늘은 컴퓨터가 지난 기록에서 규칙을 찾는다(머신러닝). 그 모델로 아직 검사하지 않은 새 로트까지 예측한다.
오늘의 핵심 교훈은 세 가지다. ① 정확도는 "무조건 합격" 기준선과 나란히 놓고, 헷갈림 표의 놓친 불합격과 함께 읽는다. ② 확률이 애매한 예측은 사람이 다시 본다 — 예측은 판정이 아니라 "어느 것부터 볼지" 정하는 참고다. ③ AI가 쓴 보고 문장의 숫자와 원인 표현은 직접 확인한다 — 트리의 갈림길 열도 "원인 후보"까지다.

## 수업 흐름

9차시는 **PART 1 Orange3 → PART 2 파이썬 + ChatGPT → PART 3 실습지** 순서다. 노트북은 단계 번호, Orange는 캔버스 메모 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 아홉째 날, 새 로트 9개 중 먼저 살펴볼 로트 고르기)
2. PART 1 시작: Orange 말 사전(Show probabilities for 포함), 위젯 이름표(새 위젯 5개: Tree = Model, Tree Viewer = Visualize, Test and Score·Confusion Matrix·Predictions = Evaluate), 공정 지도 위치 네 줄
3. 개념 다섯 절: 머신러닝(Feature/Label, 피자 가게 표) → 결정 트리(스무고개) → 학습용·시험용(10겹 교차검증) → 정확도와 기준선 → 헷갈림 표 읽는 법(모션 그림 장면 순서대로: 빈 틀의 세로 = 실제·가로 = 예측 → 맞힌 합격 → 잡은 불합격 → 괜한 의심 → 놓친 불합격 → 칸마다 센 숫자 → 대각선 = 정확도 → "실제 불합격" 줄에서 놓친 수 읽기. Orange 화면 말 Actual·Predicted·∑만 따로 짚는다) → 새 데이터 예측과 확률(애매하면 사람이 다시 본다)
4. 워밍업 `week09_1_patterns_start.ows`(학생이 직접): 메모 ① File 두 개 확인 → 메모 ② Tree(깊이 4) → Tree Viewer, "가장자리형 100%" 상자 예상하고 찾기 → 메모 ③ Test and Score(10겹) → 메모 ④ Predictions(아래 File + Tree, Show probabilities for 바꾸기), 가장 애매한 새 웨이퍼 메모
5. **여기서 쉬기**
6. 반도체 `week09_2_passfail_start.ows`(학생이 직접): 메모 ① 750행 / 9개 → 메모 ② Distributions 기준선(595/750 ≈ 79.3%) → 메모 ③ Tree → Tree Viewer, 첫 질문 `온도_C` → "원인 후보" 문장(강의에는 첫 갈림길 두 상자만 있다. "양쪽 끝"은 시연 때 말로 보여 준다 — 아래 핵심 수치) → 메모 ④ Predictions, 불합격 확률이 가장 높은 로트 메모. 메모 ⑤는 실습지 문제 4로 미룬다
7. PART 2 시작: Orange ↔ 파이썬 짝 표(Predictions ↔ `predict` 포함)
8. 노트북 1단계: 학생 빈칸 `dropna` → `(735, 9)`
9. 노트북 2단계(빈칸 없음): `(735, 6) (735,)` → `588 147`
10. 노트북 3단계: 학생 빈칸 `fit` → 예상 후 결과 열기 `정확도: 80.3%`(기준선 78.9%)
11. 노트북 4단계: 학생 빈칸 `predict` → `(9, 8)` → 3번째 로트만 -1 → `새 로트 9개 중 불합격 예측 1개`. "파이썬과 Orange는 왜 숫자가 다를까" 콜아웃(두 문장) — 자세한 차이는 아래 「강사 설명 포인트」 표로 말로 보충
12. 노트북 5단계 ChatGPT 체험: 프롬프트 복사 → 응답 예시(또는 받은 답)에서 숫자에 동그라미 → 숫자 대조 셀 실행 → 틀린 곳 두 개 찾기 → "틀린 곳 정답 보기"
13. **여기서 쉬기**(필요하면)
14. PART 3 실습지: 문제 1·2(노트북 6단계, 문제 2는 빈칸 없이 직접 쓰기) → 문제 3(웨이퍼 첫 질문·CA·가장 애매한 새 웨이퍼) → 문제 4(메모 ⑤ Test and Score + Confusion Matrix, Predictions를 파이썬과 비교) → 문제 5(보고 문장 세 개 + 판단) → 정답 확인과 문장 발표
15. 결과 정리(오늘의 질문과 접힌 실습지 결과를 한 절로 합쳤다)·반도체 이해 포인트 → 10차시 예고(실습지 없이 "새 로트 중 어느 것부터 점검할까?"를 AI와 Orange3로 풀어 가는 시연형 종합 수업)

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)

Orange 수치는 **Orange 3.40.0** 실측이다(`_done.ows`를 화면 없이 실행하고 Orange 3.40 라이브러리로 다시 계산해 같은 값을 확인). 수업 PC의 Orange 버전이 다르면 CA·첫 질문 경계값이 조금 다를 수 있으니 수업 전에 `_done.ows`를 한 번 열어 본다.

### 웨이퍼 맵 요약(Orange 워밍업) — `week09_orange_wafer_patterns.csv` 240행 + `week09_orange_new_wafers.csv` 10행(교육용 가상 데이터)
- 공정 지도 위치: ⑦ EDS 웨이퍼 맵의 요약. 정상 120 · 중심형 40 · 가장자리형 40 · 스크래치형 40장. **"정상"은 불량 0개가 아니다** — 불량 다이 3~8개가 흩어져 뚜렷한 모양이 없는 웨이퍼다. 이 가상 웨이퍼 한 장 = 다이 317개.
- Tree Viewer(깊이 4): 뿌리 `정상 · 50.0%, 120/240`, 첫 질문 **`불량다이수_count` ≤ 8**(128장, `정상 · 93.8%, 120/128`) / > 8(112장, `가장자리형 · 35.7%, 40/112`). 정보 줄 `15 nodes, 8 leaves`.
  - > 8 갈래 → `가장자리불량비율_pct > 35.3` 상자 **`가장자리형 · 100%, 40/40`** / ≤ 35.3(72장, 중심형 36) → 다음 질문 `직선불량비율_pct`: ≤ 53.8 `중심형 · 100%, 34/34` / > 53.8 `스크래치형 · 94.7%, 36/38`.
- Test and Score(10겹): **CA 0.946** · AUC 0.964. 5겹이면 CA 0.942. 깊이 100이어도 CA 0.946(`19 nodes, 10 leaves`) — 깊이 실수는 정보 줄로만 알아챈다. 기준선 120 ÷ 240 = 50%.
- Confusion Matrix(Actual 줄 → Predicted 정상·중심형·가장자리형·스크래치형, 교수 참조): 정상 119·1·0·0 / 중심형 3·34·0·3 / 가장자리형 0·0·40·0 / 스크래치형 4·1·1·34.
- Predictions(Show probabilities for = Classes known to the model): N-01·N-06 정상 0.965 / N-02·N-04·N-08 가장자리형 1.000 / N-03·N-07·N-09 중심형 1.000 / N-05 스크래치형 1.000 / **N-10 정상 0.600 · 중심형 0.400(가장 애매)**.
- **운영안 전용 — 새 웨이퍼 의도 패턴(생성기 주석, 학생에게 정답으로 말하지 않는다)**: N-04·N-07·N-10이 "애매(중심 + 가장자리)"로 만든 웨이퍼다. 3.40 Tree는 N-10만 애매하게 답하고 N-04·N-07은 확률 1.000으로 답한다. "확률이 1.0이어도 정답이라는 뜻은 아니다"를 보여 줄 소재로 쓴다(N-04: 불량 다이 9개, 가운데 44.4 · 가장자리 55.6).

### 공정 기록(Orange) — `week09_2_passfail_done.ows`(학습 750행, 빈칸 행을 지우지 않음 / 새 로트 9개)
- 공정 지도 위치: ②~⑤ + 세정의 공정 조건과 검사 결과(`합격여부` = 공정 중간 검사 + ⑦ EDS 결과를 한 열에 모은 교육용 설정). 새 로트 = ⑦ 검사 전. 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록). `공정명`·`설비번호`는 meta라 Feature가 아니다.
- Distributions(합격여부, Split by None): 1 = **595**, -1 = **155** → 기준선 595 ÷ 750 ≈ **79.3%**.
- Tree Viewer: 뿌리 `1 · 79.3%, 595/750`, 첫 질문 **`온도_C` ≤ 293.9**(`-1 · 55.0%, 44/80`) / > 293.9(`1 · 83.4%, 558/669`). 두 갈래 합 749 — 온도 칸이 빈 1건은 Orange가 따로 처리한다(강의에서 뺀 메모, 학생이 물으면 이렇게 답한다). 정보 줄 `29 nodes, 15 leaves`.
  - > 293.9 갈래가 다시 `온도_C`로 나뉜다: 293.9~306.0 `1 · 87.4%, 515/589`(불합격 74건, 12.6%) / > 306.0 `1 · 53.8%, 43/80`(불합격 37건, 46.2%). 온도 **양쪽 끝**(55.0%, 46.2%)에 불합격이 많고 가운데(12.6%)는 적다 — 8차시 진공도처럼 "양쪽 끝이 나쁜" 모양(교육용 가상 관계). 강의 본문에서 뺀 "한 줄 더 내려가 보자" 내용이라, 시연 때 Tree Viewer에서 > 306.0 상자를 손으로 짚어 보여 준다.
  - 깊이 100이면 CA 0.740, `169 nodes`. 5겹·깊이 4는 10겹과 같은 0.777이다.
- Test and Score(Tree, 10겹): **CA 0.777** · AUC 0.685 → 기준선(0.793)보다 조금 낮다. 첫 숫자 칸 AUC를 정확도로 적지 않게 한다.
- Confusion Matrix: Actual 1 → Predicted 1 **547** · -1 48 / Actual -1 → Predicted 1 **119**(놓친 불합격) · -1 **36**. 합 750.
- Predictions(Tree, `합격 : 불합격 → 예측`): 1번째 0.644 : **0.356** · 2번째 0.923 : 0.077 · 3번째 0.741 : 0.259 · 4~6번째 0.923 : 0.077 · 7번째 0.644 : **0.356** · 8~9번째 0.923 : 0.077 → **9개 모두 1(합격)**. 불합격 확률이 가장 높은 로트는 **1번째·7번째**다.

### 공정 기록(파이썬) — 노트북 출력(교육용 가상 데이터)
- 1단계: `(750, 9)` → 빈칸 온도_C 1 · 압력_Pa 3 · 가스유량_slm 3 · 습도_pct 8(합 15) → `dropna()` → `(735, 9)`.
- 2단계: `(735, 6) (735,)` → `588 147`.
- 3단계: `fit` 셀 출력 `DecisionTreeClassifier(max_depth=4, random_state=42)` → **`정확도: 80.3%`**(147개 중 118개). 시험용 불합격 31개 중 9개를 잡고 22개를 놓쳤다. 기준선 116 ÷ 147 ≈ **78.9%**.
- 4단계: `(9, 8)` → 예측 `[1 1 -1 1 1 1 1 1 1]` — **3번째 로트(행 번호 2, 식각 · EQ-04 · 289.8)만 -1** → `새 로트 9개 중 불합격 예측 1개`.
- 5단계 숫자 대조 셀: `정확도: 80.3%` / `기준선(모두 합격): 78.9%` / `불합격 예측: 1개` / `2  식각  EQ-04  289.8`.
- 6단계(실습지 문제 1·2): `temp_features = ["온도_C"]` → `(735, 1)` → `588 147` → **`온도_C 한 열 정확도: 78.2%`**. 학습용으로 잘못 채점하면 82.7%(조용한 오답).
- 새 로트 온도: 294.5, 301.5, **289.8**, 295.6, 299.1, 302.0, 305.2, 299.1, 300.6 — 3번째 로트가 가장 낮다.
- 교수 참고(데이터 설명서의 v2 기록에서 옮김, 수업 코드에는 없다): `dropna()`를 건너뛰면 750행이 150개 시험용으로 나뉘어 정확도 79.3%(150개 중 119개 — Orange 기준선 79.3%와 숫자만 우연히 같다, 조용한 오답). 연습용 기준(실제 공정 규격 아님) 밖/안 불합격 비율(735행): 온도 295~305 밖 239건 중 90건 37.7% / 안 496건 12.7%, 진공도 4.5~5.5 밖 141건 중 57건 40.4% / 안 594건 16.2% — "원인 후보" 문장의 근거 수치로 말할 때 쓴다.

### 파이썬과 Orange의 새 로트 예측이 다르다(3.40 기준)
- 파이썬은 **3번째 로트만 -1**, Orange Tree는 **9개 모두 1**이고 불합격 확률은 **1번째·7번째(0.356)**가 가장 높다(3번째는 0.259). "두 도구가 같은 로트를 가장 의심했다"고 말하지 않는다.
- 차이의 이유: 학습 데이터(파이썬 588행 / Orange 750행)와 트리 기본 설정(Orange Tree의 잎·분할 최소 개수 등)이 다르다. 채점 방법은 새 로트 예측에 영향을 주지 않는다.
- 결론으로 말할 문장: "도구마다 의심한 로트가 다르니 1·3·7번째 로트를 먼저 살펴볼 후보로 두고, ⑦ 검사는 9개 모두 그대로 한다."
- 교수만: 1번째·7번째 로트는 진공도가 4.02·4.35로 연습용 기준(4.5~5.5) 밖이다. 생성 규칙상으로도 불합격 위험이 크게 만들어진 로트다. 생성 규칙을 학생에게 "정답"으로 공개하지 않는다 — 실제 공장에서 원인은 현장 확인으로 정한다는 점이 결론이다.

### ChatGPT 응답 예시 — 일부러 심은 오류 2개(강의 "틀린 곳 정답 보기"와 같은 내용)
- 응답 예시 원문(정확히 3문장): "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 2개이며, 3번째 로트(식각·EQ-04, 온도 289.8도)가 그중 하나입니다. 모델 정확도는 80.3%로 모두 합격이라고 찍는 기준선 78.9%와 큰 차이가 없고, Orange 교차검증에서는 실제 불합격 155건 중 119건을 합격으로 놓쳤습니다. 3번째 로트는 온도가 낮아서 불합격이 생깁니다(이 결과는 교육용 가상 데이터로 만든 것입니다)."
- 숫자별 대조 출처: 80.3%·78.9%·불합격 예측 개수·3번째 로트 정보 → 노트북 5단계 숫자 대조 셀 / "155건 중 119건" → 실습지 문제 4 Confusion Matrix(Orange 3.40 값). 학생이 80.3%를 Orange 0.777과, 78.9%를 Orange 79.3%와 비교해 "틀렸다"고 하면 강의 "파이썬과 Orange는 왜 숫자가 다를까" 콜아웃과 아래 「강사 설명 포인트」의 비교 표로 출처 차이를 짚는다(심은 오류가 아니다).
- **이 두 곳은 연습을 위해 일부러 심은 오류다.** 나머지 숫자(80.3%, 78.9%, 155건 중 119건, 289.8도, 식각·EQ-04)는 모두 맞다.
  1. 틀린 숫자: "불합격으로 예측한 로트는 **2개**" → 실제 **1개**(3번째 로트만).
  2. 원인 단정: "3번째 로트는 온도가 낮아서 불합격이 생깁니다" → 아직 검사 전 로트의 예측이고 함께 나타난 값일 뿐이다. 고친 문장: "3번째 로트는 온도가 9개 중 가장 낮아(289.8도) 먼저 살펴볼 로트이며, 온도는 불합격의 원인 후보로 확인해 볼 값입니다."
- 심은 문장을 "온도가 **높아서**"로 바꾸지 않는다. 데이터 방향과도 어긋나 틀린 곳이 3개가 된다.
- 수업 PC의 Orange가 3.40이 아니면 Confusion Matrix의 놓친 불합격 수가 119와 다를 수 있다. 그러면 학생이 "155건 중 119건"을 세 번째 오류로 지적할 수 있으니, 수업 전에 실습지 문제 4 정답과 화면이 같은지 확인한다.
- 실습지 문제 5 예시 답안: "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 1개(3번째 로트, 식각·EQ-04)입니다. 모델 정확도는 80.3%로 모두 합격이라고 찍는 기준선 78.9%와 큰 차이가 없어, 이 예측은 어느 로트부터 먼저 살펴볼지 정하는 참고로만 쓰고 온도 같은 공정 조건은 불합격의 원인 후보로만 봅니다. 이 결과는 교육용 가상 데이터로 만든 것입니다."

## 강사 설명 포인트

- 오늘은 Orange가 먼저다. 개념(Feature/Label, 스무고개, 연습문제·모의고사, 기준선, 확률)을 말로 잡은 뒤 위젯으로 바로 확인한다. 파이썬은 "Orange에서 한 일을 몇 줄로"만 보여 준다(짝 표).
- **정확도는 기준선과 함께, 헷갈림 표와 함께 읽는다.** 웨이퍼 패턴 0.946 vs 50%, 공정 기록 0.777 vs 79.3%(Orange) / 80.3% vs 78.9%(파이썬). 정확도가 기준선보다 조금 낮아도 "무조건 합격이 낫다"는 뜻은 아니다 — "무조건 합격"은 불합격 155건을 모두 놓치고, 트리는 36건을 잡는다.
- **확률이 애매하면 사람이 다시 본다.** 확률은 모델의 확신이지 맞을 확률의 보장이 아니다. 확률 1.000인 새 웨이퍼(N-04 등)도 그림으로 보면 애매하다 — 확신과 정답은 다르다.
- Orange와 파이썬 숫자가 다른 것은 정상이다. 새 로트 예측까지 다르다는 점이 오늘의 소재다. 강의에는 두 문장 콜아웃만 있으니, 학생이 물으면 아래 표로 보충한다(강의에서 옮긴 표).

  | | 파이썬(PART 2) | Orange(PART 1) |
  |---|---|---|
  | 학습한 데이터 | 빈칸 행을 지운 735행 중 학습용 588행 | 750행 전체(빈칸 포함) |
  | 트리 기본 설정 | scikit-learn 결정 트리(깊이 4) | Orange Tree(깊이 4, 잎·분할 최소 개수 같은 다른 기본값은 조금 다름) |
  | 채점 방법 | 떼어 둔 시험용 147개 | 10겹 교차검증(750행을 10묶음으로 나눠 돌아가며 채점) |
  | 기준선(모두 합격) | 78.9%(시험용 147개 기준) | 79.3%(750행 기준) |
  | 정확도 · 새 로트 예측 | 80.3% · 불합격 예측 1개(3번째 로트) | 0.777 · 불합격 예측 0개(실습지 문제 4 답) |
- **트리의 첫 질문 열 = 원인 후보.** 실습지 문제 2의 온도 한 열 모델 78.2%는 "첫 질문 열이라도 혼자서는 충분하지 않다"는 근거다. 원인 여부와는 별개다. 온도를 원인으로 단정하는 학생에게는 "무엇을 더 확인하면 원인이라 할 수 있을까?"(실험·설비 점검)로 되묻는다.
- 워밍업 첫 질문은 사람이 예상하는 "가장자리 모양"이 아니라 **불량 다이 개수**다. 정상 웨이퍼는 불량 다이가 3~8개라 "8개 이하"로 정상을 먼저 크게 떼어 낸다. 가장자리 고리는 둘째 줄, 불량 다이 8개 초과 웨이퍼 중에서 `가장자리불량비율_pct > 35.3`으로 나온다. 이 조건을 빼고 "가장자리 비율 35.3% 초과 = 가장자리형"으로 말하지 않는다 — 불량이 흩어져 있기만 해도 가장자리 비율이 약 36%(정상 웨이퍼 평균 36.5%) 나온다.
- 공정 기록의 `설비번호`에는 여러 공정 기록이 섞여 있다(교육용 가상 기록). 설비별 차이 이야기는 오늘 하지 않는다. 압력_Pa 절대값도 해석하지 않는다.
- `가스유량_slm`·`습도_pct`는 합격여부와 관계없게 만든 비교용 열이다(생성 규칙, 데이터 설명서에서 옮김). 학생에게 미리 말하지 않는다 — 원인 후보를 고르는 판단을 대신해 주게 된다. 학생이 이 두 열을 원인 후보로 꼽으면 근거 수치(밖/안 합격률 등)가 있는지 되묻는다.
- 오늘 공정 기록이 기준선과 비슷하게 나오는 것은 교육용으로 단서를 약하게 만든 설계 결과다. "공정 조건으로는 합격/불합격을 예측할 수 없다"는 반도체 일반 사실로 말하지 않는다.
- ChatGPT 체험의 요점: 프롬프트에 "원인 후보"라고 쓰라고 해도 단정 문장이 섞일 수 있다. 숫자는 노트북 5단계 셀과 Orange 화면으로 하나씩 대조한다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **결정 트리 스무고개**: 대체로 잘 답한다. AI가 지니 불순도·엔트로피 계산을 길게 늘어놓으면 "가장 잘 나누는 질문을 먼저 고른다"까지만 받아들이게 한다.
- **과적합**(강의 찾아보기에서 뺐다. 학생이 깊이를 왜 4로 하는지 물으면): "깊을수록 무조건 나쁘다"가 아니라 너무 얕아도 못 맞힌다. 오늘 Orange 숫자로는 깊이 100이면 CA 0.740으로 깊이 4(0.777)보다 낮다.
- **정확도의 함정 불균형 데이터**: 오늘은 모션 그래픽 두 개(10문제 시험, 헷갈림 표)로 정확도·불합격 재현율(실제 불합격 중 찾아낸 비율)·불합격 정밀도(불합격이라 한 것 중 진짜 비율)까지만 소개한다. 그림 속 숫자는 예시이고, F1·AUC·MCC는 말 사전의 뜻풀이로만 두고 계산은 하지 않는다.
- **예측 확률의 뜻**: AI가 확률을 "맞을 확률"처럼 설명하거나 보정(calibration) 이야기로 길어질 수 있다. "모델이 얼마나 확신하는지일 뿐, 맞을 확률을 보장하지 않는다"까지만 받아들이게 한다.

## 예상 오개념

- 정확도가 80%면 좋은 모델이다 → 기준선(무조건 합격)이 79%대라면 정확도로는 차이가 거의 없다.
- 정확도가 기준선보다 낮으면 "무조건 합격"이 더 낫다 → 기준선은 불합격을 하나도 못 잡는다. 트리는 155건 중 36건을 잡았다.
- "정상" 웨이퍼는 불량 다이가 0개다 → 이 데이터의 정상은 불량 다이 3~8개가 흩어져 뚜렷한 모양이 없는 웨이퍼다.
- 확률 1.000이면 정답이다 → 모델이 확신했다는 뜻일 뿐이다. N-04는 확률 1.000이지만 그림으로 보면 애매하다.
- 합격(1)으로 예측된 로트는 검사하지 않아도 된다 → 예측은 판정이 아니다. ⑦ 검사는 그대로 한다.
- 새 표를 통째로 `predict`에 넣어도 된다 → 학습 때와 같은 열(`features`)만 넣는다.
- 트리의 첫 질문 열이 원인이다 → 기록을 잘 나누는 열일 뿐, 원인 후보다.
- Orange와 파이썬 숫자가 다르니 하나가 틀렸다 → 학습 데이터·설정·채점 방법이 다르다.
- AI에게 "원인 후보라고 써라"라고 했으니 보고서를 그대로 써도 된다 → 숫자와 단정 문장을 직접 확인한다.

## 막히는 지점 TOP3와 대처

1. **Predictions에 확률이 안 보이거나 Tree 열이 없음** — Show probabilities for가 (None)이거나, Tree → Predictions 선이 빠졌다. 새 데이터 File을 Test and Score에 이은 경우도 있다. 화면에서 "아래 File → Predictions, Tree → Predictions" 선 두 개를 손으로 짚게 한다.
2. **Test and Score를 10겹으로 안 바꿈 / Tree Viewer가 커서 읽지 못함** — 웨이퍼는 5겹이면 CA 0.942다. 공정 기록은 깊이를 4로 안 바꾸면 `169 nodes`, CA 0.740이다. 중간 상자에 숫자가 없으면 Show details in non-leaves를 켠다.
3. **실습지 문제 2(빈칸 없는 셀)에서 멈춤** — 노트북 3단계 학습·정확도 두 셀을 복사해 이름만 바꾸게 한다: `model` → `model1`, `acc` → `acc1`, `X_train`/`y_train`/`X_test`/`y_test` → `X1_train`/`y1_train`/`X1_test`/`y1_test`, 출력 문장. 오류 없는 오답 두 가지: 82.7% → 학습용으로 채점했다. 80.3% → `X1`에 6개 열이 들어갔거나 `model`·`X_test`가 남았다.

## 실습 중 오류 대응

- `AttributeError: 'DataFrame' object has no attribute '____'` / `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'`: 빈칸(`dropna`, `fit`, `predict`)을 아직 안 채웠다.
- `NotFittedError`: `fit` 전에 정확도 셀을 실행했다. 위에서부터 차례로.
- `KeyError: '합격여부'`: 새 로트 표에서 정답 열을 찾았다. 새 로트에는 정답 열이 없다 — 그래서 예측한다(강의 「주의할 점」에서 뺀 오류라 여기서 대응한다).
- `ValueError: The feature names should match those that were passed during fit.`: `model.predict(new_lots)`처럼 표를 통째로 넣었거나, 문제 2에서 `X_test`와 `X1_test`를 섞었다.
- `ValueError: Expected a 2-dimensional container`로 시작하는 오류: 문제 1에서 대괄호 없이 `temp_features = "온도_C"`로 썼다(`X1.shape`가 `(735,)`). 뒷부분 문장은 scikit-learn 버전에 따라 다르게 찍힌다.
- `NameError: name '온도_C' is not defined`: 문제 1 리스트에 열 이름을 따옴표 없이 썼다. `KeyError: 'temp_features'`: 변수 이름을 따옴표로 감쌌다.
- `NameError: name 'train_test_split' is not defined`: 노트북 2단계를 건너뛰었다. 연쇄 `NameError`(`name 'X1'` 등): 그 이름을 만드는 앞 셀부터 고친다.
- 오류 없이 이상한 숫자: 문제 2가 80.3% → `X1`에 6개 열이 들어갔거나 `model`·`X_test`가 남았다. 82.7% → 학습용으로 채점했다.
- Orange File에 파일 이름이 빨갛게 보임: `.ows`를 원래 폴더 밖으로 옮겼다. 원래 폴더의 `_start.ows`를 다시 연다.
- Orange CA가 강의와 조금 다름: 웨이퍼 0.942 → 5겹. 공정 기록 0.740 → 깊이 100. 0.96·0.68쯤 → AUC 칸을 읽었다.

## 빨리 끝낸 학생용 과제

- 노트북 맨 아래에 셀을 하나 만들어, 문제 2와 같은 모양으로 `진공도_mTorr` 한 열 모델(`X2`, `model2`)의 정확도를 구하고 6개 열 80.3%·기준선 78.9%·온도 한 열 78.2%와 한 줄로 비교한다.
