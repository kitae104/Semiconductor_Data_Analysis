# 9차시 강의 운영안 — 머신러닝 예측 모델 만들기

## 🤔 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

지금까지는 이미 일어난 불량을 데이터로 "설명"했지만, 현장에서는 문제가 생기기 전에 "이 로트가
불합격할 것 같다"를 미리 알 수 있으면 훨씬 유용하다. 머신러닝은 과거 데이터의 패턴(온도·압력 등과
합격/불합격의 관계)을 학습해, 아직 결과를 모르는 새 데이터의 합격 여부를 예측하는 방법이다.

**쉬운 예시**: 과거 1,000개 로트의 온도·압력과 합격/불합격 결과를 모델에 학습시키면, 아직 검사하지
않은 새 로트의 온도·압력 값만 보고도 "합격할 가능성이 높다/낮다"를 미리 계산해볼 수 있다 — 지난
시험 성적의 패턴으로 다음 시험 결과를 짐작하는 것과 비슷한 원리다.

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- 원본: **750행 9열**(공정명, 설비번호, 온도_섭씨, 압력_Pa, 가스유량_slm, 두께_nm, 진공도_mTorr,
  습도_pct, 검사결과), 결측치 제거 후 **735행**
- 검사결과 분포: 합격(0) **582건**, 불합격(1) **153건** — 불균형 데이터
- train/test 분리(80/20, stratify): train 588행, test 147행
- `DecisionTreeClassifier(max_depth=4)` 결과: **정확도 78.2%**
- 기준선("무조건 합격" 예측) 정확도: **78.9%** — 모델이 기준선보다 <b>낮다</b>(정확도의 함정!)
- 혼동행렬: `[[109, 7], [25, 6]]` — 실제 불합격 31건 중 6건만 적중(약 19%)
- 특징 중요도: 온도_섭씨 51.7% > 진공도_mTorr 20.8% > 가스유량_slm 10.7% > 두께_nm 9.8% >
  습도_pct 4.4% > 압력_Pa 2.6%

## 강사 설명 포인트
- Orange3 Test and Score에서 나온 정확도를 학생들이 먼저 보고, "생각보다 낮다/높다"는 반응을
  이끌어낸 뒤 코드로 넘어간다.
- "정확도의 함정"은 **반드시 위 실제 계산값**으로 보여준다: 모델 정확도(78.2%)가 기준선
  (78.9%)보다 오히려 낮다는 역설적인 결과가 오늘 수업의 핵심 메시지다. "정확도만 보면 모델이
  일을 안 하는 것과 비슷해 보이지만, 혼동행렬을 보면 그래도 불합격 6건을 찾아냈다"는 균형 잡힌
  해석을 함께 제시한다.
- Feature에 정답 열(`검사결과`)을 실수로 포함시키면 정확도가 비정상적으로 높아진다는 것을
  직접 시연해서 보여주면(예: 100%에 가까운 정확도) "왜 이게 반칙인지" 체감시킬 수 있다.
- `feature_importances_` 결과를 보여줄 때, 8차시에서 상관관계로 찾은 원인 후보(온도, 진공도,
  두께)와 순서가 대체로 일치한다는 것을 강조하되, "예측이 잘 된다"와 "원인을 증명한다"는
  다른 말임을 반드시 함께 짚는다.

## 질문 예시
- "Orange3에서 본 정확도와 오늘 코드로 계산한 정확도(78.2%)가 비슷한가요?"
- "모델 정확도가 기준선보다 낮은데도, 이 모델이 '전혀 쓸모없다'고 말할 수 있을까요? (혼동행렬의
  TP=6을 근거로 토론)"
- "온도_섭씨의 중요도가 가장 높게 나왔는데, 이것이 '온도가 불량의 원인이다'라는 뜻일까요?
  (8차시 복습)"

## 예상 오개념
- "정확도가 높으니 좋은 모델"이라는 단순화 → 혼동행렬을 반드시 함께 보도록 강조.
- Feature에 정답 열을 포함시키는 실수 → 비정상적으로 높은 정확도가 나오면 이 실수를 의심하게 한다.
- "중요도가 높은 특징 = 불량의 원인"이라는 인과관계 오해 → 8차시의 "상관관계 ≠ 원인" 원칙을
  다시 소환해서 연결한다.
- `train_test_split`에서 `stratify`를 빼도 결과가 크게 다르지 않을 것이라는 오해 → 불합격
  사례가 적을 때는 우연히 test에 불합격 사례가 거의 없게 나뉠 수 있음을 설명.

## 실습 중 오류 대응
- `ValueError: Input contains NaN`: 결측치 처리(`dropna`) 셀을 건너뛰었는지 확인.
- `KeyError`: 열 이름 오타나 인코딩 문제 확인. 파일은 `utf-8-sig`로 저장되어 있으므로
  `pd.read_csv()` 기본 설정 그대로 읽으면 문제없다.
- 결과 숫자가 강의안과 다르다고 하는 학생: `random_state=42`가 코드에 정확히 들어갔는지,
  `train_test_split`의 `test_size`, `stratify` 인자가 강의안과 동일한지 확인.

## 빠른 학습자용 추가 과제
- 강의 자료의 "도전 실습"(max_depth를 2, 4, 8로 바꿔보기)을 먼저 시도해보게 한다.
- Feature 목록에서 중요도가 낮았던 `습도_pct`, `압력_Pa`를 빼고 다시 학습시켜 정확도 변화를
  비교해보게 한다.
- 노트북 10단계 "연습문제 — 나무 깊이(max_depth) 바꿔보기"에서 max_depth=2/8 정확도를 비교해
  과소적합·과대적합 트레이드오프를 직접 확인해보게 한다.
- 노트북 11단계 "AI로 재미있는 미니 프로그램 만들기"(합격 예측 미니 데모)에서 `sample` 값을
  여러 번 바꿔보거나, `predict_proba()`로 확률까지 보여주는 코드로 확장해달라고 AI에게
  재요청하며 실습을 더 발전시켜보게 한다.

## 느린 학습자용 최소 과제
- 강사가 미리 실행해 둔 코드 결과를 함께 읽으며 "합격 몇 건, 불합격 몇 건"과 "혼동행렬에서
  불합격을 몇 건 맞혔는가"만 말로 설명할 수 있으면 충분하다.
- `train_test_split`과 `DecisionTreeClassifier` 줄은 강사가 완성된 코드를 제공하고, 학생은
  `accuracy_score`와 `confusion_matrix` 출력 결과를 해석하는 데 집중하게 한다.
