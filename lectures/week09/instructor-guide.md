# 9차시 강의 운영안 — 머신러닝 예측 모델 만들기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

지금까지는 이미 끝난 기록을 보고 "어디서 불합격이 많았나"를 설명했다. 공장에서는 한 걸음 더 나아가,
검사 결과가 나오기 전에 "이 로트는 불합격일 것 같다"를 미리 알고 싶다. 오늘은 지난 기록 735건으로
"공정 조건을 보면 합격/불합격을 맞힐 수 있는가"를 직접 실험하고, 그 결과를 얼마나 믿어도 되는지 숫자로 따진다.

**예를 들면 — 일기예보**: 기상청은 지난 기록(기온, 습도, 구름, 그날 비가 왔는가)을 보고 내일 비를 예측한다.
예보가 잘 맞는다고 "왜 비가 오는지"를 다 안다는 뜻은 아니다. 맞히는 것과 원인을 아는 것은 다르다.

## 수업 흐름

1. 복습: 3차시(사람이 쓴 `if` 규칙 295~305℃)와 8차시("원인"이 아니라 "원인 후보")를 짧게 되짚는다.
2. 머신러닝 개념: 규칙을 사람이 쓰느냐 컴퓨터가 찾느냐 → Feature(문제)/Label(정답) → 열이 공장에서 뜻하는 것 → **부호 확인(1 = 합격, -1 = 불합격, 1~8차시와 같은 표기)**
3. 왜 여러 Feature를 함께 넣는가: 온도×진공도 표(8.0% / 33.2% / 32.6% / 56.5%), 병원 비유
4. 결정트리 = 스무고개: 오늘 모델이 실제로 찾은 질문 3개 그림 → 3차시 규칙과 비교 → `max_depth`는 한 줄만
5. train/test = 연습문제/모의고사, 옵션 세 개(`test_size`, `random_state`, `stratify`) 한 줄씩
6. 정확도와 혼동행렬을 천천히: 118/147 = 80.3%, 찍기 116/147 = 78.9% → 네 칸을 공장 말로(`labels=[1, -1]`) → 놓친 불량(22건)이 가장 위험한 이유
7. 휴식
8. Orange3 시연(강의 STEP 01): 파일(File, 합격여부 = 목표(target), 범주형(categorical), 적용(Apply)) → 트리(Tree) → 학습·평가(Test and Score), CA를 칠판에 적어 둔다
9. 정답 노트북으로 코드 시연(강의 STEP 02~04): 데이터 준비 → 나누기·학습 → 채점(정확도·찍기·혼동행렬) → 중요도와 원인 후보
10. 학생 실습: 학생용 노트북 1~8단계. 먼저 끝난 학생은 7단계 끝 "도전 문제"(강의 STEP 05)
11. AI 활용(노트북 9·10단계) → 연습문제(11단계, 진공도 하나만) → 미니 데모(12단계)
12. 정리 퀴즈 + 과제 안내 + 10차시 예고

## 강사 설명 포인트
- **부호는 1~8차시와 같다**(`합격여부` 1 = 합격, -1 = 불합격). 새로 조심할 곳은 혼동행렬 하나다. `labels=[1, -1]`을 빼면 -1(불합격)이
  첫 줄로 와서 `[[9 22] [7 109]]`가 나온다. 일부러 한 번 빼고 실행해 "숫자는 같고 자리만 바뀐다"를 보여주면 `labels`의 필요가 바로 전달된다.
  "찍기" 코드를 `== -1`로 바꾸면 21.1%(불합격 비율)가 나온다.
- **3차시 규칙과의 비교가 오늘의 핵심 장면이다.** 트리 그림을 띄우고 "아무도 295~305를 알려주지 않았는데 모델이 293.95~306.05를 찾았다"고
  말한다. 그다음 "그럼 이 규칙이 원인을 알려 주나요?"라고 되물어 8차시의 원인 후보로 넘어간다.
- **혼동행렬은 네 칸을 한 칸씩, 공장 말로 읽는다.** 숫자보다 "멀쩡한데 의심(7)", "불량인데 통과(22)"라는 말을 먼저 들려준다.
  화재경보기 비유(헛경보는 귀찮고, 불이 났는데 안 울리면 위험)를 쓴다. TP/FN 같은 영어 약어는 쓰지 않는다.
- 정확도 80.3% vs 찍기 78.9%는 "맞힌 개수 118건 vs 116건, 딱 2건 차이"로 바꿔 말하면 덜 어렵다. 모델은 불량 9건을 잡는 대신
  헛경보 7건을 냈기 때문에 총합이 2건 많을 뿐이다. "모델이 훌륭하다"도 "쓸모없다"도 아니라 "정확도 하나로는 판단할 수 없다"로 정리한다.
- `max_depth`는 "질문 최대 4번" 한 줄로 끝낸다. 깊이 실험은 빠른 학습자용 도전 문제로만 둔다.
- 중요도를 보여줄 때 반드시 **무엇의 원인 후보인지(불합격)와 근거 수치**를 함께 말한다. "온도와 진공도가 불합격의 원인 후보로
  떠오른다(중요도 48.8%·21.1%, 범위 밖 불합격 비율 33.2%·32.6%)." 원인으로 확정하려면 조건을 바꿔 보는 실험이 필요하다고 덧붙인다.
  압력(16.7%)은 강의에서 범위별로 따로 확인하지 않았으므로 "다음에 확인해 볼 열"로만 말한다.
- **강사만 알고 있을 것(데이터 생성 로직)**: 이 데이터는 온도(|온도−300| > 6), 압력(|압력−1012| > 18), 진공도(4.5~5.5 밖),
  두께(|두께−100| > 5)가 범위를 벗어날수록 불합격 확률이 오르도록 만들었고, **가스유량·습도는 합격여부와 관계없게 만든 비교용 열**이다(대조군).
  실제로 가스유량을 범위(47~53 slm)로 나눠도 불합격 비율은 밖 20.3%, 안 21.1%로 차이가 없다. 그런데도 가스유량 중요도가 9.2%로 나온다(습도는 0.0%).
  평균 비교(합격·불합격 평균)로 "관계없음"을 말하지 않는다 — 진공도처럼 범위를 벗어나야 문제가 되는 열은 평균이 거의 같아도 관계가 있을 수 있다(8차시). 모델이 깊은 질문에서 우연한 패턴을 배운 예다. "중요도 = 원인"이 아니라는 근거로 쓸 수 있다.
  두께도 생성 로직에 들어 있지만 중요도가 4.2%로 낮게 나왔다(온도와 r = 0.81로 함께 움직인다). 중요도가 낮다고 관계가 없다는 뜻도 아니다.
- **8차시와 데이터가 다르다.** 8차시 데이터에서는 온도가 두께의 원인 후보였을 뿐 불합격의 후보는 아니었다. 9차시는 별도로 만든 데이터라
  온도 이탈도 불합격과 관련 있게 만들어졌다. 학생이 "8차시엔 온도가 불합격과 관계없다고 했잖아요?"라고 물으면
  "데이터가 다르면 결론도 다시 확인해야 한다. 그래서 '원인'이 아니라 '원인 후보'라고 말한다"고 답한다.
- Orange3 CA는 파이썬 결과와 다를 수 있다(공정명·설비번호 포함, 결측 행 유지, 트리 기본 깊이 다름, 여러 번 나눠 채점한 평균 — 교차 검증 또는 Random sampling. 그림 9-3 화면은 Random sampling 20회·66% 설정). 학생이 적은 CA를 칠판에
  모아 두고, 수업 끝 "핵심 질문"에서 파이썬 결과와 나란히 비교한다.

## 예상 오개념
- "머신러닝은 컴퓨터가 이해하고 판단하는 것" → 기록 속 패턴을 찾을 뿐이고, 우연한 패턴(가스유량 9.2%)도 배운다.
- "정확도가 높으면 좋은 모델" → 찍기도 78.9%다. 모델(80.3%)과 2건 차이다. 불량을 몇 건 잡고 몇 건 놓쳤는지 혼동행렬을 함께 본다.
- "학습에 쓴 데이터로 채점해도 된다" → max_depth=8은 연습문제 94.2%, 모의고사 78.9%. 외운 점수다.
- "Feature를 많이 넣을수록 무조건 좋다" → 여러 열을 함께 보면 놓치는 것이 줄지만, 관계없는 열은 우연한 패턴을 배우게 할 수 있다.
- "혼동행렬 윗줄은 언제나 합격" → `labels=[1, -1]`을 붙였을 때만 그렇다. 빼면 -1(불합격)이 윗줄이다.
- "중요도가 높은 열 = 불량의 원인" → 원인 후보일 뿐이다.

## 실습 중 오류 대응
아래는 학생용 노트북을 실제로 실행해 확인한 오류다.
- 빈칸을 채우지 않고 실행: `df.____()` → `AttributeError: 'DataFrame' object has no attribute '____'`,
  `model.____(...)` → `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'`,
  나머지 빈칸 → `NameError: name '____' is not defined`. 빈칸을 채우게 한다.
- 위 셀을 건너뜀: `NameError: name 'X_train' is not defined`(3단계 미실행), `NameError: name 'y_test' is not defined` 등.
  맨 위부터 다시 실행하게 한다.
- `fit`을 빼고 예측: `NotFittedError: This DecisionTreeClassifier instance is not fitted yet.` 4단계 학습 셀을 먼저 실행하게 한다.
- 글자 열을 Feature에 넣음(과제 2에서 `공정명`을 넣는 경우 등): `ValueError: could not convert string to float: '세정'`. 숫자 열만 넣게 한다.
- 연습문제에서 대괄호를 한 겹만 씀(`X_train["진공도_mTorr"]`): `ValueError: Expected a 2-dimensional container but got <class 'pandas.Series'> instead.`
  `X_train[["진공도_mTorr"]]`처럼 두 겹으로 감싸게 한다.
- **오류 없이 숫자만 다른 경우**: `dropna()`를 건너뛰면 scikit-learn이 결측값을 그대로 학습해 오류 없이 정확도 79.3%가 나온다.
  `print(df.shape)`가 735인지 확인시킨다. `random_state=42`·`test_size=0.2`·`stratify=y`가 빠져도 숫자가 달라진다.
- 정답 열(`합격여부`)을 Feature에 넣으면 오류 없이 정확도 100.0%가 나온다. "답안지를 보고 푼 것"이라고 설명한다.

## 빠른 학습자용 추가 과제
- 노트북 7단계 끝 "도전 문제"(강의 STEP 05): max_depth=8 모델의 연습문제/모의고사 정확도를 4와 비교. 결과는 84.7%/80.3% → 94.2%/78.9%.
- 과제 2(온도·진공도 두 열만)를 수업 중에 먼저 해 보게 한다. 실제 결과는 정확도 80.3%, 혼동행렬 `[[110 6] [23 8]]`로,
  정확도는 6개 열 모델과 같지만 잡은 불량(8건 vs 9건)과 헛경보(6건 vs 7건)가 조금씩 다르다. "같은 정확도, 다른 혼동행렬"을 스스로 발견하게 한다.
- 학생이 "온도 하나만 넣으면 어때요?"를 시도하면 정확도 78.2%, 혼동행렬 `[[103 13] [19 12]]`로 불량은 12건을 잡아
  6개 열 모델(9건)보다 많이 잡지만 헛경보도 13건으로 늘어난다. 무엇을 더 중요하게 보느냐에 따라 평가가 달라지고, 모의고사가 147건뿐이라 몇 건 차이는 나누는 방식에 따라 바뀔 수 있다고 답한다. 열 조합 재실험은 10차시 마지막 활동과 이어진다.
- 미니 데모에서 값을 바꿔 가며 "온도만 바꾸면 그대로, 진공도와 두께를 함께 바꾸면 불합격 위험"을 직접 확인하게 한다.

## 느린 학습자용 최소 과제
- 코드는 노트북 1~6단계의 빈칸만 채워 정확도(80.3%)와 혼동행렬(`[[109 7] [22 9]]`)이 출력되면 충분하다.
- 혼동행렬 네 칸을 공장 말로 읽을 수 있으면 오늘 목표의 핵심을 이룬 것이다(실습지 7번).
- 결과 문장(노트북 8단계)은 실습지 9번의 빈칸 문장을 그대로 채워도 된다.
