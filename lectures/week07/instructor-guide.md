# 7차시 강의 운영안 — 설비·공정 비교와 수율·불량 분석

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

전체 합격률 하나만 보면 "어디서" 불량이 많이 나는지 숨는다. 쪽지시험 기록도 전체 정답률은 75.0%지만 반별로 나누면 87.5%와 62.5%가 있다.
묶어서 비교하면 먼저 살펴볼 곳이 보인다. 다만 비교로 찾은 곳은 이유로 확정된 것이 아니라 **원인 후보**다(피자 가게: 탄 판이 몰린 오븐을 먼저 점검하지만, 도우가 이유일 수도 있다).

## 수업 흐름

PART 1 파이썬 → PART 2 Orange3 → PART 3 실습지 순서다. 노트북은 단계 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 일곱째 날, "합격률이 가장 낮은 설비" — 이 기록에서 합격률을 수율 대신 쓴다) → 지난 시간 복습 2문항(웨이퍼 맵, Box Plot 상자 길이)
2. PART 1 시작: 학생용 노트북 "막혔을 때" 셀 읽기
3. 노트북 1단계: 쪽지시험 기록 읽기(24, 6) → `quiz["정답"] = quiz["정답여부"] == 1` → 18, 75.0
4. 노트북 2단계: `groupby("반")["정답"].mean() * 100` → A반 87.5 · B반 62.5 · C반 75.0, `sort_values()`
5. 노트북 3단계: 오답 유형 `value_counts()`(계산 실수 3 · 문제 잘못 읽음 2 · 개념 부족 1) → 막대
6. **여기서 쉬기**
7. 노트북 4단계 "반도체 데이터로 확인하기": 학생이 `groupby(____)` 빈칸 하나(`"작업조"`)를 채운다(PART 1 유일한 손 연습 — 2단계 "반" 자리를 바꾸는 전이 연습). 이어서 정답 노트북으로 확인 — (300, 11), 작업조별 불합격률 A조 9.8 · B조 15.5 · C조 9.7, 불합격 비율 20% 초과 로트 21개. "B조 때문"이 아니라 "원인 후보"로 읽는 장면을 말로 짚는다.
8. PART 2 Orange: 위젯 이름표(묶음 열 포함) → Pivot Table 창 읽는 법 → 공정 지도 위치 두 줄 → 워밍업 `week07_1_waferlots_start.ows`(학생이 직접: Pivot Table → Select Rows → Scatter Plot) → 반도체 `week07_2_yield_start.ows`는 **강사 시연**(Box Plot만, EQ-02 상자가 가장 김) → 파이썬 결과와 비교 한 문장
9. **여기서 쉬기**(필요하면)
10. PART 3 실습지: 문제 1~3(노트북 5단계) → 문제 4(Orange Pivot Table) → 문제 5(해석 문장 + 판단) → 정답 확인과 문장 발표
11. 결과 정리·반도체 이해 포인트 → AI로 한 걸음 더(노트북 6단계) → 과제·8차시 예고

## 강사 설명 포인트

- 개념은 쪽지시험 기록으로만 설명하고, 공장 기록은 4단계에서 "표 이름과 열 이름만 바뀐다"를 보여 준다. 실습지 힌트가 강의의 어느 예제와 같은 모양인지 짚어 준다.
- 비율은 늘 "무엇 중에"(분모)부터 말한다. 워밍업 Pivot Table은 **다이**를, 공장 기록은 **웨이퍼**를 센다. 이름도 나눈다: 다이를 센 비율 = **수율**(워밍업), 웨이퍼를 센 비율(설비별·로트별) = **합격률**(공장 기록, 수율 대신 쓰는 값).
- 공장 기록은 로트마다 설비 하나·공정 하나만 적어 둔 교육용 단순화다(실제 웨이퍼는 여러 공정을 모두 거친다). 그래서 설비 차이와 공정·로트 차이를 숫자로 떼어 볼 수 없다. B조 15.5%도 B조가 EQ-04 기록 36장을 맡은 영향이 섞여 있다.
- 작은 묶음 주의: EQ-02 52장·EQ-03 56장은 EQ-01 104장의 절반쯤이다. AI 예시에서 EQ-02도 "원인 후보"로 찍히지만 몇 장에 따라 흔들리기 쉽다.
- True/False 열의 평균 = 비율. 1/-1 열을 그대로 평균 내면 안 되는 이유(0.5, 0.76)를 한 번 보여 준다.
- `groupby` 출력의 맨 위(묶은 열 이름)와 맨 아래(`Name: 정답, dtype: float64`)를 짚고, `dtype`은 넘어가도 된다고 말한다.
- 반이 두 명뿐이라 반 정답률이 크게 흔들린다 → "건수가 적은 묶음의 비율은 조심해서 읽는다."
- 오늘부터 "원인 후보" 표현을 쓴다. 작업조 B조(15.5%), 식각-3(83.1%), EQ-04(75.0%) 모두 "먼저 살펴볼 곳"이지 이유로 확정된 것이 아니다.
- `불량유형`은 공정 중간의 두께 측정·표면 검사와 마지막 전기 검사(⑦ EDS)에서 찾은 것을 한 열에 모아 둔 교육용 설정이다(전기 검사가 파티클·두께를 찾는 것이 아니다). 같은 행의 `공정명` 작업에서 생겼다는 뜻이 아니다. 설비 4대가 여러 공정 기록을 함께 남긴 교육용 가상 기록이다.
- 설비 이름: 워밍업은 식각-1·식각-2·식각-3, 공장 기록은 EQ-01~EQ-04다. 서로 다른 설비라고 분명히 말한다.
- 압력 절대값은 해석하지 않는다(데이터 설명서 "압력_Pa 값의 한계"). 오늘은 압력을 쓰지 않는다.

## Orange 시연 체크리스트

- [ ] `week07_1_waferlots_start.ows`를 연다. File을 더블클릭해 3,804행이 들어왔는지 확인한다. 빨간 파일 이름이 보이면 데이터 파일을 찾지 못한 것이다 — `.ows`를 원래 폴더에서 다시 연다.
- [ ] File → Pivot Table(Transform 묶음): 처음에는 Rows `합격여부`, Columns `None`(대각선 표)이 뜬다 — Rows `설비번호`, Columns `합격여부`로 바꾼다. Aggregations Count(기본 체크). 식각-3 -1 칸 214.0. "다이를 센다"를 말로 짚는다. 강의의 "세어 본 결과 보기"는 학생이 계산한 뒤 연다.
- [ ] File → Select Rows(Transform): 첫 줄에 `합격여부 is 1`이 이미 들어 있다. **줄을 추가하지 말고** 첫 줄을 `설비번호` is `식각-3`으로 바꾼다 → 1,268행. 1,054행이면 첫 줄이 남아 합격 다이만 골라진 것(빨간 점 0개).
- [ ] Select Rows → Scatter Plot(Visualize): 처음에는 x `웨이퍼ID`, y `설비번호`(세로줄 점) — Axis x `다이_X`, Axis y `다이_Y`로 바꾸고 Color `합격여부` 확인. 창을 정사각형에 가깝게 키운다. 가장자리 고리를 학생이 말로 먼저 설명하게 한 뒤 "보이는 것 확인 보기"를 연다.
- [ ] 그 뒤에 생성 그림(웨이퍼 12장 맵)을 보여 주고 "식각-3 네 장이 모두 같은 모양"을 확인한다. 결론 문장: "식각-3의 가장자리 처리 조건이 원인 후보다."
- [ ] `week07_2_yield_start.ows`(300행) → 캔버스 메모 ③(강사 시연) Box Plot: 처음에는 Variable `웨이퍼번호`, Subgroups `합격여부` — Variable `온도_C`, Subgroups `설비번호`로 바꾼다 → EQ-02 상자가 가장 김(8.85). 메모 ② Pivot Table은 시연하지 않는다(실습지 문제 4).
- [ ] Data Table 뒤에 위젯을 잇지 않는다(출력은 선택 행뿐). 보기 위젯은 File·Select Rows에서 잇는다.
- [ ] 늦은 학생은 `_done.ows`를 열어 따라잡게 한다.
- [ ] Pivot Table 숫자에 `.0`이 붙어 보여도 개수다. Values 칸은 Count만 쓸 때 상관없다.
- [ ] `불량유형`은 `.tab`에서 meta(참고용 열)지만 Pivot Table Rows 목록에는 나온다. 실습지 문제 4 ③에서 Rows를 불량유형으로 바꿔 두께 불량 11(Total 36)을 문제 3과 맞춰 본다. 막대는 파이썬으로 그린다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **반도체 수율 뜻**: AI가 "업계 평균 수율은 몇 %"처럼 숫자를 단정하는 경우가 있다. 수율 수준은 제품·공정·시기마다 크게 다르고 오늘 숫자는 교육용 가상 값이라고 짚는다. 다이 단위·웨이퍼 단위 등 분모가 다를 수 있다는 점을 보충한다.
- **파레토 차트**: AI가 "80/20 법칙"을 정확한 규칙처럼 설명하기도 한다. 경험적 표현일 뿐이고, 오늘은 누적 선 없이 막대만 그린다고 말한다.
- **비교만으로 원인을 단정할 수 없는 이유**: AI 답이 어려운 통계 용어(교란 변수 등)로 흐르면 "다른 조건이 함께 달랐을 수 있다"는 한 문장으로 정리해 준다. 오늘 예: EQ-02는 온도 상자가 가장 길지만 합격률이 가장 낮은 설비는 EQ-04다.
- **웨이퍼 불량 패턴 종류**: AI가 "가장자리형 = 반드시 특정 장비 고장"처럼 이유를 하나로 단정할 수 있다. 패턴은 어디를 먼저 볼지 정하는 단서일 뿐이라고 바로잡는다. 오늘 데이터의 패턴은 교육용으로 심은 것이다.

## 예상 오개념

- 문제 1에서 4단계를 따라 `== -1`을 쓴다 → 오류 없이 12.0(불합격률). 문제 2에서 `["합격여부"]`를 평균 낸다 → 오류 없이 96.2 · 73.1 · 82.1 · 50.0(순위는 같아 더 위험). 문제 3에서 `== 1` → 빈 `Series([])`, 빈 그래프.
- 1/-1 열을 평균 내면 합격률이다 → 0.76(공장)·0.5(쪽지시험)는 비율이 아니다. True/False 열을 먼저 만든다.
- `==`와 `=`는 비슷하다 → `=`는 값을 넣는다. `df["합격"] = df["합격여부"] = 1`은 오류 없이 `합격여부` 열을 덮어쓴다.
- Pivot Table은 웨이퍼를 센다 → 표의 한 행을 센다. 워밍업은 다이, 공장 기록은 웨이퍼.
- 합격률이 가장 낮은 설비 = 원인 → 원인 후보다. 그 설비에 어려운 공정이나 문제 로트가 몰렸을 수 있다.
- 온도가 가장 들쭉날쭉한 설비가 합격률도 가장 낮을 것이다 → EQ-02(온도 상자 8.85)와 EQ-04(합격률 75.0%)는 다르다.
- 불량유형 "식각 부족"은 그 행의 공정명이 식각이라서 생겼다 → 불량 유형과 그 행의 공정명은 따로 기록된 것이다.
- 식각-3과 EQ-03은 같은 설비다 → 워밍업 설비(식각-1~3)와 공장 기록 설비(EQ-01~04)는 다른 데이터의 다른 설비다.

## 막히는 지점 TOP3와 대처

1. **문제 2에서 `groupby(____)[____]` 빈칸에 따옴표를 빠뜨림** — `groupby(설비번호)` → `NameError: name '설비번호' is not defined`. "열 이름은 늘 따옴표"를 칠판에 적어 둔다. 대괄호 열 선택을 지우면 `TypeError: dtype 'str' does not support operation 'mean'`.
2. **문제 1을 건너뛰고 문제 2 실행** — `KeyError: 'Column not found: 합격'`. 문제 1 셀(합격 열 만들기)부터 실행하게 한다. `==`를 `=`로 써서 결과가 100.0이 나왔다면 4단계(`read_csv`)부터 다시 실행해야 한다.
3. **Orange에서 Pivot Table을 못 찾거나 Select Rows를 Pivot Table 뒤에 이음** — Pivot Table과 Select Rows는 둘 다 **Transform** 묶음이다. Select Rows는 File에서 따로 잇는다(Pivot Table 뒤가 아님). Scatter Plot은 Select Rows 뒤에 잇는다.

## 실습 중 오류 대응

- `TypeError: dtype 'str' does not support operation 'mean'`: `df.groupby("설비번호").mean()`처럼 열을 고르지 않았다. `["합격"]`을 넣는다.
- `NameError: name '설비번호' is not defined`: 열 이름에 따옴표가 없다.
- `KeyError: 'Column not found: 합격'`: 문제 1 셀을 실행하지 않았다.
- 오류 없이 합격률 100.0: `==`를 `=`로 썼다. 고친 뒤 4단계부터 다시 실행한다.
- 오류 없이 0.76: `합격여부`(1/-1)를 그대로 평균 냈다. `합격` 열의 평균을 낸다.
- `____`를 채우지 않고 실행(실제 메시지): 숫자·열 이름 자리 `NameError: name '____' is not defined` / 함수 이름 자리 `AttributeError: 'Series' object has no attribute '____'`. 빈칸을 채운다.
- 연쇄 오류: 앞 셀이 실패하면 `NameError: name 'eq_rate' is not defined`(문제 2 둘째 셀·6단계 AI 셀), `NameError: name 'defect_counts' is not defined`(문제 3 막대 셀). 앞 셀부터 고친다.
- `KeyError: '불량 유형'`(띄어쓰기)·`KeyError: '오답유형'`(3단계 열 이름을 그대로 베낌): 열 이름은 `불량유형`이다.
- 문제 3 막대에서 한글이 네모로 깨짐: 3단계 첫 그래프 셀(`plt.rcParams[…]` 두 줄)을 실행하지 않았다. 불량 유형 이름이 겹치면 `plt.xticks(rotation=45)`를 넣는다.
- Orange File에 파일 이름이 빨갛게 보임: `.ows`를 원래 폴더 밖으로 옮겼거나 폴더 구조가 바뀌었다. 원래 폴더의 `_start.ows`를 다시 연다.

## 빨리 끝낸 학생용 과제

- 워밍업 Pivot Table에서 Rows를 `웨이퍼ID`로 바꿔 웨이퍼 12장의 불합격 다이 수를 읽고, 식각-3 네 장(W-09~W-12)이 모두 비슷한지 확인한다(웨이퍼별 수율 83.9 · 83.3 · 82.6 · 82.6%).
- Select Rows 조건을 `설비번호 is 식각-2`로 바꿔 웨이퍼 맵을 그리고, 한 줄로 이어진 불량(W-06)이 보이는지 찾는다. 식각-3과 모양이 어떻게 다른지 한 문장으로 적는다.
- 공장 기록 Orange에서 Distributions(Visualize)를 File에 잇고 Variable `합격여부`, Split by `설비번호`로 골라, -1 쪽 막대에서 가장 높은 설비가 문제 4와 같은지 확인한다(캔버스 메모에는 없는 추가 과제).
