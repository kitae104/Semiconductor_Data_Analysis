# 7차시 강의 운영안 — 설비·공정 비교와 수율·불량 분석

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

공장에서 가장 자주 나오는 질문은 "어느 설비를 먼저 점검해야 하지?"다. 이 질문에 답하려면 기록을 설비별로
**묶어서** 비교해야 한다. 전체를 한꺼번에 보면 괜찮아 보여도, 나눠 보면 한 곳만 유독 나쁜 경우가 많다.

**예를 들면**: 오늘 데이터는 웨이퍼 300장 중 264장이 합격해 전체 합격률 88.0%다. 설비 4대로 나눠 보면
EQ-01 98.1%, EQ-03 91.1%, EQ-02 86.5%, **EQ-04 75.0%**다. 전체 숫자 88.0% 안에 이 차이가 숨어 있었다.
이 숫자는 오늘 데이터의 실제 실행 결과라 수업에서 그대로 확인된다.

## 수업 흐름

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- 교육용 가상 데이터. **300행(로트 75개 × 웨이퍼 4장) 11열**. `합격여부` 1 = 합격, -1 = 불합격.
  온도·압력·진공도는 단위와 자릿수가 실제 공정과 맞지 않는 가상 값이다(데이터 설명서 "압력_Pa 값의 한계").
  학생이 물으면 "교육용으로 만든 값이라 크기를 해석하지 않고 기록끼리 비교만 합니다"라고 답한다.
- 전체: 264장 합격 → `88.0`(%). 불합격 36장(12.0%).
- 설비별 처리 장수(`count`): EQ-01 104 / EQ-02 52 / EQ-03 56 / EQ-04 88
- 설비별 합격 장수(`sum`): EQ-01 102 / EQ-02 45 / EQ-03 51 / EQ-04 66
- 설비별 합격률(`pass_rate.round(1)`): EQ-01 98.1 / EQ-02 86.5 / EQ-03 91.1 / **EQ-04 75.0**
- 설비별 불합격 장수와 불량률: EQ-01 2장(1.9%) / EQ-02 7장(13.5%) / EQ-03 5장(8.9%) / EQ-04 22장(25.0%)
- "1장 더 불합격하면": EQ-02 45/52=86.5% → 44/52=84.6%(약 1.9%p↓), EQ-01 102/104=98.1% → 101/104=97.1%(약 1.0%p↓)
- 설비별 평균 온도(`.round(1)`): EQ-01 300.2 / EQ-02 300.1 / EQ-03 299.3 / EQ-04 301.7
- 로트 수율: 로트당 4장이라 0·25·50·75·100% 다섯 값뿐. 80% 미만 로트 **21개**(전체 75개 중)
- EQ-04 로트 22개: 수율 100% 11개 / 75% 4개 / 50% 4개 / 25% 2개 / 0% 1개 → 80% 미만 **11개**
  (참고: 80% 미만 21개의 설비 구성은 EQ-04 11 · EQ-03 5 · EQ-02 4 · EQ-01 1이다. 강의 코드는 EQ-04만 직접 계산한다.)
- 최저 수율 로트: `LOT-0008` 0.0% — 4장 모두 EQ-04 · 증착 · B조, 불량유형은 정렬 불량·두께 불량·패턴 불량·파티클 각 1장
- 불량 유형(36건): 두께 불량 11 / 패턴 불량 6 / 파티클 5 / 오염 5 / 정렬 불량 4 / 식각 부족 4 / 전기적 특성 불량 1.
  비율: 30.6 / 16.7 / 13.9 / 13.9 / 11.1 / 11.1 / 2.8. 상위 3가지 22건 = 약 61.1%
- 도전(설비×작업조) 합격률: EQ-01 A 100.0 · B 95.0 · C 100.0 / EQ-02 A 79.2 · B 100.0 · C 90.0 /
  EQ-03 A 100.0 · B 84.4 / EQ-04 A 81.2 · B 69.4 · C 75.0. 장수: EQ-02 B조 8장(가장 적음), EQ-04 B조 36장.
  EQ-03은 C조 기록이 없어 결과가 11줄이다.
- 과제 참고: 공정별 합격률 산화 86.2 / 세정 95.0 / 식각 92.3 / **증착 76.9** / 포토 86.1(장수 80·80·52·52·36),
  작업조별 A조 90.2 / B조 84.5 / C조 90.3
- AI 예시 코드: EQ-02·EQ-04에 `점검 필요`. 랭킹: 1위 EQ-01, 2위 EQ-03, 3위 EQ-02, 4위 EQ-04

## 강사 설명 포인트
- **이 차시가 "어렵다"는 구간의 시작이다. 코드보다 그림과 숫자 대비를 먼저.** "왜 묶나 → 왜 여러 열을 보나 →
  조심할 점"을 개념 절에서 충분히 말한 뒤 코드로 넘어간다. 개념 절의 표 숫자는 모두 뒤 코드에서 다시 나온다고 미리 말해 준다.
- **수율은 "무엇 중에 무엇"을 함께 말한다.** "수율 92"가 아니라 "사과 100개 중 상품 92개 → 92%". 이 과정은
  웨이퍼 1장 = 검사 1건으로 단순화했고, 실제 공장은 칩(다이) 단위로 세는 경우가 많다는 점을 한 번 짚는다.
- **`합격여부`는 1/-1이다.** 칠판에 "1 = 합격, -1 = 불합격"을 크게 적는다. `df["합격여부"].mean()`을 바로 하면
  EQ-04가 0.5로 나와 합격률(75.0%)처럼 읽히지 않는다는 점을 보여 주고, 그래서 `합격` 열(True/False)을 만든다고 설명한다.
- **groupby는 그림(SVG)으로 먼저.** "이름표끼리 모아서 → 바구니마다 계산". `groupby`만 실행하면
  `<pandas.api.typing.SeriesGroupBy object at 0x...>`만 나온다는 것을 직접 보여 주면 "계산을 붙여야 한다"가 기억에 남는다.
- `count` → `sum` → `mean` 순서로 보여 주고, `66 ÷ 88 = 0.75`를 칠판에서 같이 계산해 `mean()`이 "합격 장수 ÷ 처리 장수"를
  대신 해 줬다는 것을 확인시킨다.
- **"건수가 적은 쪽의 비율은 흔들린다"**는 리뷰 별점 비유(리뷰 2개 5.0 vs 500개 4.7)로 먼저 감을 잡게 하고,
  EQ-02 52장 vs EQ-01 104장 숫자로 확인한다. 도전 문제의 EQ-02 B조(8장, 100%)가 좋은 예다.
- **"EQ-04가 원인일까요?"를 반드시 묻는다.** 학생이 "네"라고 하면 EQ-04 로트 22개 중 11개가 100%라는 결과와
  LOT-0008에 증착·B조가 함께 있었다는 결과를 보여 주며 1차시 "용의자 ≠ 범인"으로 연결한다. 결론은 "원인 후보".
- **강사만 알고 있을 것**: 이 데이터는 생성기가 설비마다 불합격 확률을 다르게 줘서(EQ-04가 가장 높음) 만든 것이다.
  수업에서는 "EQ-04가 실제로 문제 설비다"라고 말하지 않는다. 가상 데이터이고, 오늘 분석으로 말할 수 있는 것은 "원인 후보"까지다.
- 파레토는 "많은 것부터 줄 세우면 앞 몇 개가 큰 몫"이라는 감각만 잡는다. 이 데이터는 7가지 중 상위 3가지가 약 61.1%로,
  흔히 말하는 80/20만큼 쏠리지는 않는다. 숫자를 80/20에 억지로 맞추지 않는다.

## 예상 오개념
- "전체 합격률이 88.0%면 모든 설비가 88% 근처다" → 설비별로 나누면 75.0~98.1%로 벌어진다.
- "합격 장수가 많은 설비가 좋은 설비다" → 처리 장수가 다르므로 비율로 비교한다.
- "합격률 100%면 완벽하다" → 몇 장 중의 100%인지 본다(EQ-02 B조는 8장).
- "평균 온도가 비슷하면 설비 사이에 차이가 없다" → 합격률은 크게 달랐다. 열 하나만 보면 놓친다.
- "EQ-04 합격률이 낮다 = EQ-04 로트는 다 나쁘다" → 22개 중 11개는 수율 100%.
- "가장 많이 나온 불량 유형(두께 불량) = 원인" → 파레토는 우선순위만 알려 준다.
- "수율 + 불량률은 언제나 100%" → 오늘처럼 판정이 합격/불합격 두 가지뿐일 때만 그렇다.

## 실습 중 오류 대응
아래는 이 차시 코드로 직접 실행해 확인한 오류다(pandas 3.0.2).
- `ValueError: level name 온도_섭씨 is not the name of the index`: `df.groupby("설비번호", "온도_섭씨")`처럼 열 이름을 콤마로
  나열한 경우. `df.groupby("설비번호")["온도_섭씨"].mean()`으로 고치게 한다. 도전 문제에서 `groupby("설비번호", "작업조")`로
  쓰면 `ValueError: level name 작업조 is not the name of the index`가 난다 — 두 열은 `["설비번호", "작업조"]`처럼 대괄호로 감싼다.
- `KeyError: 'Column not found: 온도'`: 열 이름 오타. `print(df.columns)`로 정확한 이름(`온도_섭씨`)을 확인한다.
- `TypeError: dtype 'str' does not support operation 'mean'`: `df.groupby("설비번호").mean()`처럼 계산할 열을 고르지 않아
  글자 열까지 평균을 내려 한 경우. `["온도_섭씨"]`처럼 열을 고르게 한다.
- `SyntaxError: leading zeros in decimal integer literals are not permitted`: `df[df["설비번호"] == EQ-04]`처럼 따옴표를 빠뜨린 경우.
  노트북 4단계의 `"EQ-04"`, `"LOT-0008"` 빈칸에서 자주 나온다.
- `FileNotFoundError`: 경로의 `../../`를 빠뜨렸거나 노트북을 `notebooks/student/`가 아닌 곳에서 연 경우.
- 오류 없이 숫자가 이상함: `<pandas.api.typing.SeriesGroupBy object at 0x...>`가 나오면 계산(`.mean()` 등)을 안 붙인 것이다.
  `df.groupby("설비번호")["합격여부"].mean()`으로 EQ-04가 0.5처럼 나오면 1/-1을 바로 평균 낸 것이다 — 1단계의 `합격` 열을 쓰게 한다.
- `NameError: name 'pass_rate' is not defined`(8·10단계): 3단계 셀을 실행하지 않고 넘어온 경우. 위에서부터 다시 실행하게 한다.
- 빈칸 `____`을 채우지 않고 실행한 경우: 자리에 따라 `AttributeError: module 'pandas' has no attribute '____'`(1단계 첫 셀),
  `AttributeError: 'DataFrame' object has no attribute '____'`(2단계), `NameError: name '____' is not defined`(값 자리),
  `SyntaxError: invalid syntax`(4단계 비교 기호 자리)가 난다. 1단계 첫 셀이 실패하면 그 아래 셀은 모두
  `NameError: name 'df' is not defined`가 나므로, 맨 위 빈칸부터 채우고 차례로 다시 실행하게 한다.
- 막대그래프 한글이 네모로 깨짐: 5단계 셀의 `plt.rcParams["font.family"] = "Malgun Gothic"` 줄을 지웠거나 Mac인 경우(Mac은 `"AppleGothic"`).
