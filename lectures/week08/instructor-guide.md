# 8차시 강의 운영안 — 공정 이상과 원인 후보 찾기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

공정 값 7개는 짝지으면 21쌍이다. 상관관계는 "어느 짝부터 볼지" 정해 주는 도구이고, 데이터가 주는 것은 용의자 명단
(원인 후보)까지다. 예: 진공도가 범위를 벗어난 기록에 불합격이 많았다 → "진공도는 원인 후보"라고 말한다.

## 수업 흐름

1. 복습(1·5·6·7차시) → 오늘의 데이터 두 가지(가게 30일·반도체 450건, 둘 다 가상) → 정상 범위(규격)
2. 상관관계 직관: 예시 산점도 세 장 → 상관계수(-1~1, 부호=방향, 크기=세기) → 학습용 기준 표(0.7/0.3)
3. 상관관계 ≠ 인과관계: 아이스크림·물놀이 사고(더운 날씨) → 가게의 아이스크림-핫초코 -0.85 → 용의자와 범인
4. 휴식 → Orange3 시연: 파일(File) → 상관관계(Correlations), 순위표에서 읽을 세 가지
5. 파이썬 개념은 쉬운 예제로만 시연(노트북 1~6단계): 기준선 26.7% → 상관계수 0.97·-0.89·-0.85 → 비교용 습도 0.02 →
   `|`·`&` 도입, 냉동고(-0.06인데 75.0% vs 9.1%) → 습도 범위(30.0% vs 25.0%) → 원인 후보 예시 문장
6. "반도체 데이터로 확인하기" 시연(확인 1~4): 기준선 11.1% → 온도-두께 0.71 vs 습도-두께 -0.01 → 진공도(-0.02인데 25.6% vs 8.1%) →
   온도(9.8% vs 11.5%) → 오늘의 결론
7. 학생 실습: 실습지 문제 1~6 = 노트북 7~9단계(반도체 데이터) → AI 활용(10·11단계) → 퀴즈, 과제, 예고

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- 두 데이터 모두 가상 데이터. `압력_Pa`는 단위와 자릿수가 실제와 맞지 않는 가상 값이다(크기를 해석하지 않는다).
- **가게(30행 7열, `손님평가` 1 = 좋음/-1 = 불만)**: 불만 8일, 26.7%. 기온-아이스크림 0.97, 기온-핫초코 -0.89,
  아이스크림-핫초코 -0.85, 습도-아이스크림 0.02. 냉동고(-20~-16℃): 상관계수 -0.06, 범위 밖 8일 중 6일 75.0% / 안 22일 중 2일 9.1%
  (너무 차가움 4일 중 3일, 너무 따뜻함 4일 중 3일). 습도(50~70%): 밖 10일 30.0% / 안 20일 25.0%.
- **반도체(450행 12열, `합격여부` 1 = 합격/-1 = 불합격)**: 불합격 50건, 11.1%. 온도-두께 0.71, 습도-두께 -0.01, 진공도-합격여부 -0.02.
  AI 코드(11단계) 두께 상관계수: 온도 0.71, 압력 0.09, 진공도 0.01, 진동 0.07, 냉각수온도 0.01, 습도 -0.01.
- Orange3 상위: 두께-온도 +0.710, 측정시간-합격여부 +0.158, 습도-합격여부 +0.126. 진공도-합격여부 약 -0.02.
- 진공도(4.5~5.5 mTorr): 밖 78건(불합격 20건) 25.6% / 안 372건(30건) 8.1%. 4.5 미만 39건 중 9건 23.1%, 5.5 초과 39건 중 11건 28.2%.
- 온도(295~305℃): 밖 92건(9건) 9.8% / 안 358건(41건) 11.5%.

## 강사 설명 포인트
- **쉬운 예제로 개념, 반도체로 핵심 확인.** 확인 시연 때 "가게 코드에서 무엇만 바꿨나요?"를 묻는다(`shop` → `df`, 열 이름, 범위 숫자).
  실습지 문제마다 힌트에 "같은 모양의 쉬운 예제"를 적어 두었다.
- **그림 먼저, 점수는 나중.** 산점도 세 장으로 방향을 먼저 묻는다. 경계 0.3/0.7은 학습용 기준이라고 말한다.
- **-0.85.** "핫초코가 덜 팔려서 아이스크림이 팔렸나요?" → 둘 다 기온을 따라 움직였다(생성 시 두 판매량 사이 직접 연결 없음).
- **무엇과 비교했나.** 0.97 옆에 0.02, 0.71 옆에 -0.01을 놓는다. 건강검진 참고치 비유.
- **`|`·`&`는 오늘 처음.** "너무 낮다 또는 너무 높다"를 말로 정리한 뒤 기호를 보인다. 괄호와 `|` 입력법(Shift + `\`, 한글 키보드 `₩`)을 화면에서 강조.
- **무엇의 후보인지.** 온도는 두께의 원인 후보이지 불합격의 후보가 아니다(9.8% vs 11.5%).
- **상관계수가 놓치는 모양.** 냉동고로 감을 잡고 진공도 구간 셋 표(23.1/8.1/28.2%)로 U자를 보인다.
- **강사만 알고 있을 것 — 약한 점수는 우연으로도 나온다.** 합격 여부는 생성 단계에서 진공도 이탈로만 정했다
  (`scripts/generate_weekly_data.py`의 week08). 그런데도 습도-합격여부 0.126, 측정시간-합격여부 0.158이 나오고, 습도를 45%로 나누면
  15.5% vs 7.0%, 측정시간 앞 절반 225건의 불합격 34건 / 뒤 절반 16건이다. 모두 우연이다. 먼저 꺼내지는 않는다.
- **"습도도 차이가 나는데 왜 진공도만 후보냐"고 물으면**: ① 진공도는 데이터를 보기 전에 정한 규격 범위로 나눴고, 습도 45%는
  데이터를 본 뒤 고른 기준이다(가게 습도 50~70%는 강의에서 미리 정한 학습용 범위로 쓴다). ② 진공도는 양쪽 끝(23.1%, 28.2%)이
  각각 따로 높다. 그래도 우연 가능성을 0으로 만들 수 없어 "원인 후보"라고 부른다. 습도가 우연이라고 단정할 수 있는 것은 가상 데이터라서다.
- 부호 규약을 칠판에 적는다: `손님평가` 1 = 좋음/-1 = 불만, `합격여부` 1 = 합격/-1 = 불합격. Orange3 순위표의 "+"는 "값이 클수록
  합격(1)이 조금 많다"는 뜻이다.

## 예상 오개념
- 상관계수가 높으면 원인 → 제3의 요인(기온), 우연, 데이터는 "왜"를 적지 않는다.
- 부호가 크기 → 부호는 방향, 크기는 세기.
- 0에 가까우면 관계없음 → 냉동고 75.0% vs 9.1%, 진공도 U자.
- 온도-두께 0.71이니 "불량 원인 후보" → 무엇의 후보인지 적게 한다.
- 약한 점수(0.13)에도 후보 이름 → "약함"은 후보로 올리지 않는다.
- 범위를 벗어나면 반드시 불합격 → 진공도 범위 밖 78건 중 불합격 20건.
- 가게 코드를 옮기며 `shop`을 그대로 둠 → `shop["온도_섭씨"]`는 `KeyError`. 반도체는 `df`다.

## 실습 중 오류 대응
노트북 코드로 실제 실행해 확인한 오류다(pandas 3.0.2).
- `ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().`: `or`/`and`를 썼다 → `|`/`&`.
- `TypeError: Cannot perform 'ror_' with a dtyped [float64] array and scalar of type [bool]`: 조건 괄호 누락 → 조건마다 괄호.
- `ValueError: could not convert string to float: 'EQ-02'`: 글자 열에 `corr()` → 숫자 열끼리만.
- `KeyError: '진공도'`: 열 이름은 `진공도_mTorr`. `print(df.columns)`로 확인. `shop`에 반도체 열 이름을 써도 `KeyError`.
- `NameError: name 'vac_out' is not defined`: 범위 나누기 셀을 건너뜀 → 위에서부터 다시 실행.
- 빈칸 미입력: 값 자리 `NameError: name '____' is not defined`, 기호 자리 `SyntaxError: invalid syntax. Perhaps you forgot a comma?`,
  메서드 자리 `AttributeError`, 열 이름 자리 `KeyError: '____'`.
- 한글이 네모(□), `UserWarning: Glyph ... missing from font(s) DejaVu Sans.`: 2단계 첫 셀의 `plt.rcParams` 두 줄 실행 확인(Mac `"AppleGothic"`).
