# 8차시 강의 운영안 — 공정 이상과 원인 후보 찾기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

불합격이 나오면 "그때 무엇이 달랐나"를 찾아야 한다. 오늘은 두 도구를 쓴다. 함께 움직이는 정도를 재는 상관계수, 그리고 범위 밖일 때만 문제가 되는 값을 찾는 범위 비교다.
그리고 찾은 값은 "원인"이 아니라 **"원인 후보"**로 말한다. 함께 움직인다는 것만으로는 원인을 확정할 수 없다(아이스크림·물놀이 사고, 피자 가게의 탄 피자 비유).
오늘 데이터에서 그 차이가 숫자로 드러난다. 온도는 두께와 0.71로 강하게 함께 움직이지만 불합격과는 아니고, 진공도는 상관계수로는 안 보이지만 범위 밖일 때 불합격률이 기준선의 약 2.3배다.

## 수업 흐름

PART 1 파이썬 → PART 2 Orange3 → PART 3 실습지 순서다. 노트북은 단계 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 여덟째 날) → 지난 시간 복습 2문항(Pivot Table EQ-04 75.0%, 식각-3 가장자리 = 단서)
2. PART 1 시작: 학생용 노트북 "막혔을 때" 셀 읽기, 가게 기록 열 표
3. 노트북 1단계: 가게 기록 읽기 `(30, 7)` → 기준선 26.7
4. 노트북 2단계: 기온–아이스크림 산점도 → `corr()` 0.97, 기온–핫초코 -0.89(부호 = 방향, 크기 = 세기)
5. 노트북 3단계: 습도–아이스크림 0.02(비교용 열과 나란히)
6. 노트북 4단계: 첫 셀은 학생이 직접 쓰는 냉동고 산점도(2단계 산점도 4줄과 같은 모양, x `냉동고온도_C`, y `손님평가`) — 아래 줄(-1) 점 8개 중 6개가 양쪽 끝에 몰린 것을 확인 → 냉동고–손님평가 -0.06 → 범위 밖 `8 6` → 75.0(`|`와 괄호, `|`는 엔터 위 `₩` 키 + Shift)
7. 노트북 5단계: 원인 후보 문장("불만의 원인 후보다" — 이 문장은 숫자를 보고 사람이 정한 결론을 코드에 적은 것) → 상관관계 ≠ 인과관계(아이스크림·물놀이 개념도)
8. **여기서 쉬기**
9. 노트북 6단계 "반도체 데이터로 확인하기": 정답 노트북으로 시연 — `(450, 12)`, 압력–두께 0.09, 온도 범위 밖 `92 9.8`, 범위 안 `358 11.5`("범위 밖이라고 다 원인 후보는 아니다"). 비교 기준은 **기준선 하나**라고 말한다(범위 안 비율은 참고). 공정 기록 기준선 11.1%는 실습지 문제 1의 답이라 여기서 말하지 않는다
10. PART 2 Orange: Orange 말 사전 → 위젯 이름표(Correlations = Unsupervised 묶음) → 공정 지도 위치 두 줄 → 워밍업 `week08_1_chamber_start.ows`(학생이 직접: Correlations 1~3위 읽기, Scatter Plot RF파워–식각률) → 반도체 `week08_2_anomaly_start.ows`는 **강사 시연**(캔버스 메모 ③ Scatter Plot 온도–두께 + 색 합격여부, ④ Find Informative Projections) → 파이썬 결과와 비교 표. PART 3 전에는 "진공도"라는 답을 말하지 않는다 — 학생에게는 "위쪽 짝에 자주 나오는 열을 메모해 두라"고만 한다
11. **여기서 쉬기**(필요하면)
12. PART 3 실습지: 문제 1~3(노트북 7단계, 문제 2 두 번째 셀은 빈칸 없이 직접 쓰기, 문제 3 둘째 셀은 숫자 두 개만 출력 — 높은지 낮은지는 학생이 판단) → 문제 4(Orange Correlations, 메모 ②) → 문제 5(해석 문장 + 판단) → 정답 확인과 문장 발표
13. 결과 정리·반도체 이해 포인트 → AI로 한 걸음 더(노트북 8단계) → 과제·9차시 예고

- 4단계: 냉동고–손님평가 `-0.06`, 범위(-20~-16℃) 밖 `8 6`(8일 중 6일 불만), 범위 밖 불만률 `75.0`.

## 강사 설명 포인트

- 개념은 가게 기록으로만 설명하고, 공정 기록은 6단계에서 "표 이름과 열 이름만 바뀐다"를 보여 준다. 실습지 힌트가 강의의 어느 예제와 같은 모양인지 짚어 준다.
- 상관계수는 **부호 = 방향, 크기 = 세기**. -0.89는 "나쁜 관계"가 아니다. 강함·중간·약함 경계(0.3, 0.7)는 이 과정의 연습용 기준이다.
- 숫자 하나는 크다 작다 감이 안 온다 → 비교용 열(습도)과 나란히 놓는다(0.97 vs 0.02, 0.71 vs -0.01).
- 상관계수는 곧은 띠 한 방향만 잰다. 냉동고·진공도처럼 양쪽 끝이 다 나쁜 값은 0에 가깝게 나오므로 범위 밖 기록의 비율을 기준선과 비교한다.
- **"원인 후보"는 근거 숫자와 "무엇의 후보인지"를 함께 말한다.** 온도는 두께의 원인 후보(0.71)지만 불합격의 원인 후보는 아니다(9.8% vs 11.5%). "원인 후보"를 아무 값에나 붙이지 않는다 — 습도는 원인 후보가 아니다.
- 워밍업 챔버 데이터의 관계(RF파워·가스유량과 함께 오르고 누적사용시간과 반대)는 교육용 가상 관계라고 반드시 말한다. 실제 장비의 법칙으로 가르치지 않는다.
- 연습용 기준(온도 295~305℃, 진공도 4.5~5.5 mTorr)은 실제 공정 기준이 아니다. 실제로는 공정·제품마다 기준이 따로 있다. 범위 밖 = 불합격이 아니다(진공도 범위 밖 78건 중 58건은 합격).
- 압력 열이 셋이다: 공정 기록 `압력_Pa`(약 1017)와 `진공도_mTorr`(약 5), 워밍업 `챔버압력_mTorr`. 교육용 데이터에서 서로 다른 측정 설정으로 만든 값이라 크기가 맞지 않는다(5 mTorr는 1 Pa도 안 된다). 압력 절대값은 해석하지 않는다(데이터 설명서 "압력_Pa 값의 한계"). 오늘은 수치 열 하나로만 쓴다.
- 비교 기준은 **기준선(전체 불합격률) 하나**로 통일한다. 6단계의 범위 안 비율(11.5%)은 참고다. 온도: 9.8% < 기준선 11.1%(문제 1 이후에 말한다), 진공도: 25.6% vs 기준선 11.1%.
- PART 3 전에는 미션의 답(진공도)을 말하지 않는다. 강의도 진공도 연습용 기준·진공 찾아보기를 PART 3에 두었다.
- 이 기록의 `설비번호`에는 여러 공정 기록이 섞여 있다(교육용 가상 기록). 설비별 차이 이야기는 오늘 하지 않는다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **상관계수 읽는 법**: AI가 0.3·0.7 같은 경계를 "정해진 기준"처럼 말할 수 있다. 분야마다 다르고 이 과정의 경계는 연습용이라고 보충한다. "-0.9 = 나쁜 관계"로 답하면 바로잡는다.
- **상관관계 인과관계 차이**: 대체로 잘 답한다. 다만 "인과를 확인하려면 상관계수가 0.9 이상이어야 한다"처럼 숫자로 인과를 판정하는 답은 틀렸다 — 상관계수가 아무리 커도 그것만으로는 인과를 확정하지 못한다.
- **반도체 공정 진공 이유**: AI가 특정 공정의 진공도 숫자(몇 mTorr가 정상)를 단정할 수 있다. 공정·설비마다 다르고 오늘 4.5~5.5는 연습용 기준이라고 짚는다. "숫자가 작을수록 진공에 가깝다"를 반대로 말하는 답이 있으면 바로잡는다.
- **원인 후보 확인하는 방법**: AI가 "진공도가 원인이므로 진공 펌프를 교체하라"처럼 결론으로 건너뛸 수 있다. 데이터 밖 근거(그 값만 바꿔 보는 실험, 점검·정비 기록, 현장 엔지니어 확인)가 필요하다는 부분만 받아들이게 한다.

## 예상 오개념

- 부호 -는 나쁜 관계다 → 방향일 뿐이다(한쪽이 오를 때 다른 쪽은 내려감).
- 상관계수가 0에 가까우면 관계가 전혀 없다 → 곧은 띠 관계가 없다는 뜻이다. 양쪽 끝이 다 나쁜 값(냉동고 -0.06, 진공도)은 범위로 나눠 봐야 보인다.
- 상관계수가 크면 원인이다 → 원인 후보까지다. 제3의 요인(더운 날씨)이 둘 다 움직였을 수 있다.
- 한 결과의 원인 후보는 다른 결과의 원인 후보다 → 온도는 두께의 후보지만 불합격의 후보는 아니다.
- 연습용 기준 밖 = 불합격 → 온도 범위 밖 92건의 불합격률 9.8%, 진공도 범위 밖도 78건 중 58건은 합격이다.
- 진공도 숫자가 클수록 진공이 강하다 → 숫자가 작을수록 남은 기체가 적다(진공에 가깝다).
- Orange Correlations에 합격여부가 없으니 데이터가 잘못됐다 → 합격여부는 결과(범주) 열이라 숫자 열끼리 계산하는 Correlations에 나오지 않는다.
- 챔버 워밍업의 관계(RF파워 ↑ → 식각률 ↑)는 실제 장비의 법칙이다 → 교육용 가상 관계다.

## 막히는 지점 TOP3와 대처

1. **`|` 조건의 괄호와 키 위치** — `|`는 한국어 키보드에서 엔터 위 `₩` 키를 Shift와 함께 누른다(`l`(소문자 L)이나 `/`를 치는 학생이 있다). 괄호를 빠뜨리면 `TypeError: Cannot perform 'ror_' with a dtyped [float64] array and scalar of type [bool]`, `|` 대신 `or`를 쓰면 `ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().`가 난다. 4단계 `freezer_out` 줄을 화면에 띄우고 "조건 하나 = 괄호 하나"를 손으로 짚게 한다.
2. **같은 이름의 변수(`base_rate`, `r_humid`)** — 1단계에도 `base_rate`(가게, 26.7)가 있다. 실습지 문제 1을 건너뛰고 문제 3을 실행하면 오류 없이 "기준선 26.7%"가 찍힌다. 문제 1에서 나누는 표를 `shop`으로 쓰면 100%가 넘는 숫자가 나온다. "공장 = `df`, 가게 = `shop`"을 칠판에 적어 둔다.
3. **문제 2 두 번째 셀(빈칸 없는 셀)에서 멈춤** — 바로 위 셀을 복사해 열 이름 두 곳(`온도_C` → `습도_pct`, 변수 `r_temp` → `r_humid`)만 바꾸면 된다고 안내한다. 열 이름을 줄여 `"습도"`로 쓰면 `KeyError: '습도'`가 난다.

## 실습 중 오류 대응

- `TypeError: Cannot perform 'ror_' …`: `|` 양쪽 조건 중 괄호가 빠졌다.
- `ValueError: The truth value of a Series is ambiguous.`로 시작하는 오류: `|` 대신 `or`를 썼다.
- `ValueError: could not convert string to float: 'EQ-02'`: 글자 열(`설비번호`)로 `corr()`를 했다. 숫자 열끼리만 계산한다.
- `KeyError: '습도'`: 열 이름을 줄여 썼다. `습도_pct`로 쓴다(`print(df.columns)`로 확인).
- `NameError: name '습도_pct' is not defined`: 열 이름을 따옴표 없이 썼다. `df["습도_pct"]`처럼 따옴표 안에 쓴다.
- `____`를 채우지 않고 실행(실제 메시지): 문제 1 `NameError: name '____' is not defined` / 문제 2 `AttributeError: 'Series' object has no attribute '____'` / 문제 3 기호 빈칸 `SyntaxError: invalid syntax. Perhaps you forgot a comma?`. 빈칸을 채운다.
- `NameError: name 'vac_out_fail' is not defined`: 문제 3 첫 셀이 실패한 채 둘째 셀을 실행했다. 첫 셀부터 고친다.
- `0 0` 다음 `ZeroDivisionError: division by zero`: 문제 3에서 `|` 대신 `&`를 썼다(4.5보다 작으면서 5.5보다 큰 값은 없다).
- 오류 없이 이상한 숫자: 문제 3 둘째 셀 기준선이 `26.7` → 문제 1 셀을 실행하지 않았다. 문제 1 기준선이 100%를 넘음 → 나누는 표를 `shop`으로 썼다. 문제 1 `88.9` → 합격(1)을 셌다. 문제 2 습도–두께 `0.29` → `shop["습도_pct"]`로 썼다(두 열 모두 `df`에서). 문제 3 `78 58` → 합격(1)을 셌다. 문제 3 불합격률 `4.4` → `df`로 나눴다(`vac_out`으로 나눈다).
- Orange File에 파일 이름이 빨갛게 보임: 키트 폴더 구조가 바뀌었거나 `.ows`를 다른 곳으로 옮겼다. 키트를 다시 풀고 그 안에서 연다.
- Orange Correlations 값이 강의와 다름: 맨 위 칸이 Spearman correlation으로 바뀌었다. Pearson correlation으로 되돌린다.

## 빨리 끝낸 학생용 과제

- 진공도 범위 밖을 "너무 낮음"(`df["진공도_mTorr"] < 4.5`)과 "너무 높음"(`> 5.5`)으로 나눠 각각 불합격률을 구한다(조건 하나씩이라 `|`가 필요 없다). 결과: 4.5 미만 39개 기록 중 9개 불합격(23.1%), 5.5 초과 39개 중 11개 불합격(28.2%) — 양쪽 다 기준선 11.1%보다 높다는 것을 한 문장으로 적고, 실습지 문제 3 정답의 막대 그림과 맞춰 본다.
- 6·7차시에 쓴 `value_counts()`로 "같은 때 다른 조건도 달랐나"를 확인한다: 진공도 범위 밖 78건을 `vac_out["설비번호"].value_counts()`로 세면 EQ-01 25 · EQ-02 15 · EQ-03 18 · EQ-04 20, 공정명은 산화 19 · 증착 16 · 포토 16 · 세정 14 · 식각 13으로 고르게 퍼져 있다. "범위 밖 기록이 한 설비·한 공정에 몰려 있지는 않다"까지 말할 수 있고, 그래도 원인 확정은 아니다(데이터에 없는 다른 조건이 있을 수 있다).
- Orange `week08_2_anomaly_start.ows`의 Scatter Plot에서 Find Informative Projections 1위 짝(습도_pct·진공도_mTorr)을 골라 보고, 진공도 축의 양쪽 끝에서 빨간 점의 비율이 가운데보다 높아 보이는지 한 줄로 적는다(참고: 범위 밖 23.1%·28.2% vs 범위 안 8.1%. 점으로는 약하게 보인다). 습도에는 우연히 생긴 약한 차이(데이터 설명서 "우연히 생긴 약한 관계")가 있지만 설계상 관계없는 비교용 열이라 원인 후보로 올리지 않는다는 점도 덧붙인다.
