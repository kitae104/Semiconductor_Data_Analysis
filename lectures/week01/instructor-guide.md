## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

10차시 동안 공장 숫자를 다룬다. 숫자가 어디서 왜 생겼는지 알아야 표가 보인다.
오늘은 칩이 만들어지는 흐름(공정 지도)을 피자 가게 비유로 한 번 보고, 공장 기록표의 합격·불합격을 파이썬 변수에 담아 문장으로 보고한 뒤,
Orange 막대로 직접 세어 확인한다. 오늘의 미션: "입사 첫날, 공장 기록표 40건을 받았다 — 합격·불합격이 몇 건인지 직접 세어 보고, 한 문장으로 보고하자."
미션의 답(합격 32 · 불합격 8)은 처음부터 말하지 않고, PART 2에서 Orange 막대로 학생이 직접 읽게 한다.

## 강사 설명 포인트

- 반도체 용어는 **피자 가게 비유 하나로** 통일한다. 웨이퍼 = 피자 도우, 칩(다이) = 피자 조각, 공정 = 레시피 단계, 로트 = 같은 오븐에 함께 들어간 판들, 설비 = 오븐, 센서 기록 = 요리 중 온도계 메모, EDS = 자르기 전 조각(칩)마다 전기로 검사, 패키징 = 조각을 하나씩 포장 상자에 담기. 산화는 "철이 녹슬듯 표면에 얇은 막 키우기"로 말한다(밖에서 덧입히는 증착과 구분하기 위해). 공정 지도 그림의 비유 문구와 강의 표가 같다.
- 공정 이름은 외우게 하지 않는다. "8대 공정" = 칩을 만드는 큰 단계 여덟 개. 이온주입은 "정해진 자리에 아주 작은 알갱이(이온)를 넣어 전기가 통하는 성질을 바꾸는 일" 한 줄로 충분하다.
- ②~⑥이 층마다 되풀이된다는 점(금속 배선도 여러 층), 세정은 번호 없이 단계 사이마다 한다는 점을 그림의 화살표로 짚는다. 4차시부터 데이터마다 "공정 지도 위치"를 이 번호로 말한다.
- EDS를 전공정·후공정 중 어디에 넣는지는 자료마다 다르다. 이 과정은 후공정에 둔다. 자르기 전 웨이퍼 상태에서 한다는 점이 ⑦ → ⑧ 순서의 이유다.
- 표 한 행 = "어느 로트의 몇 번 웨이퍼가 어느 설비에서 어떤 공정을 거친 기록 한 번". 합격여부는 웨이퍼 단위 결과다. 강의 표 둘째 행을 소리 내어 읽어 준다.
- `합격여부` 부호(1 = 합격, -1 = 불합격)를 칠판에 적어 둔다.
- 합격 비율 80.0%(불합격률 20.0%의 나머지)는 "기록 40건 중 합격 기록"의 비율이다. 계산 모양은 수율과 같지만 수율(생산한 것 중 정상 제품 비율) 그 자체는 아니다.
- 개념 설명은 카페 예제로만 한다. 반도체는 "반도체 데이터로 확인하기"에서 질문을 먼저 던지고 [코드와 결과 보기]를 연다. 6단계(강의 확인 1·2)의 32·8은 "표에서 센 값이 미리 적혀 있다, 맞는지는 PART 2에서 직접 센다"로 넘긴다.
- `input()`은 노출 전용이다. 강사 화면에서 한 줄만 보여 주고 실습·과제에는 쓰지 않는다.
- `f`를 빼먹으면 오류 없이 중괄호가 그대로 나오는 모습을 직접 실행해 보여 준다.
- PART 2의 Split by 공정명 장면에서 "세정이 원인일까요?"라고 되물어 "원인 후보"(더 확인할 대상)를 소개한다. 실습지 문제 5에서 EQ-03으로 같은 판단을 학생이 직접 쓴다.
- **강사만 알 것**: 합격여부는 공정·설비와 무관하게 무작위로 만든 가상 값이다. "세정 10 중 불합격 5", "EQ-03 12 중 불합격 3"은 우연이므로 "기록이 적어 우연일 수 있다"를 꼭 함께 말한다.

## Orange 시연 체크리스트

1. 키트 압축을 푼 `semiconductor_kit` 폴더에서 Orange 메뉴 File > Open → `week01_1_town_start.ows`.
2. File 위젯 더블클릭 → 파일 이름 `week01_orange_town_population.tab`과 열 목록이 보이는지 확인. 빨간 글씨면 폴더 구조가 바뀐 것이다(키트를 다시 풀게 한다).
3. File 오른쪽 반원을 끌어 빈 곳에 놓기 → 목록에서 Data Table. Info 칸의 `30 instances`, `1 meta attribute`(동)를 읽어 준다.
4. File에서 한 갈래 더 → Distributions. Variable 목록에서 `주요연령대`를 직접 클릭한다(Orange가 전에 고른 열을 기억해 다른 열이 먼저 보일 수 있다). 40~50대 막대에 마우스를 올리고 잠시 기다려 툴팁 12를 읽는다.
5. Columns 칸 Split by → 구. 툴팁이 표 모양(맨 윗줄 = 막대 전체, 아래 줄 = 색별 개수)으로 바뀌는 것을 보여 준다. 실습지 문제 4에서 같은 동작을 하므로 건너뛰지 않는다. None으로 되돌리는 것도 보여 준다.
6. `week01_2_process_start.ows`를 열고 같은 순서로 Data Table → Info `40 instances`, `Target with 2 values`, `3 meta attributes`, "4 + 1 + 3 = 8열".
7. Distributions → Variable `합격여부`. 이 표는 Split by가 처음부터 `합격여부`로 잡혀 있으므로 None으로 바꾼다. -1 막대 툴팁 `-1: 8 (20.00 %)`를 읽고 "미션의 답"으로 정리한다.
8. Split by → 공정명. 불합격 막대 툴팁에서 세정 5(가장 많음)를 읽고 "원인 후보"로 연결한다. Split by 설비번호는 실습지 문제 4이므로 시연하지 않는다.
9. 파이썬 결과와 비교 한 문장: "파이썬 변수에 담은 합격 32 · 불합격 8이 막대 높이와 같다."
10. 따라오지 못한 학생은 `week01_1_town_done.ows`, `week01_2_process_done.ows`로 따라잡게 한다.
- Data Table 뒤에 다른 위젯을 잇지 않는다(Data Table의 출력은 고른 행뿐이라 비어 있다). 모든 위젯은 File에서 갈래로 잇는다.
- CSV를 File에서 직접 열면 `합격여부`가 숫자로 읽혀 Distributions가 히스토그램이 된다. 반드시 `orange/` 폴더의 `.tab` 또는 `_start.ows`로 연다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **웨이퍼 왜 둥근가**: AI가 "회전시키며 코팅하기 좋아서"만 말하는 경우가 있다. 핵심은 실리콘 덩어리(잉곳)를 원기둥으로 키워 얇게 썰기 때문이라는 점이다. 회전 이점은 덧붙는 이야기로 둔다.
- **반도체 8대 공정**: AI·검색 결과마다 단계 수와 이름이 조금씩 다르다(이온주입을 따로 세거나, EDS를 "테스트"라고 부르거나, EDS를 전공정에 넣는 등). 하는 일이 공정 지도와 같으면 맞는 답이라고 말해 준다. AI가 "되풀이는 산화~증착뿐"이라고 하면 금속 배선도 여러 층으로 깐다고 보충한다.
- **공장이 기록을 남기는 이유**: AI가 특정 회사의 실제 시스템이나 수치를 단정해 말할 수 있다. 확인할 수 없는 회사 이야기는 넘기고, "추적"과 "감시" 두 가지만 확인한다.
- **파이썬 변수 뜻**: AI가 "메모리 주소", "참조" 같은 깊은 이야기로 넘어갈 수 있다. 오늘은 "이름표가 붙은 상자"까지만 이해하면 충분하다고 말해 준다.

## 예상 오개념

- 웨이퍼 한 장 = 칩 한 개 → 한 장 위에 칩 여러 개를 함께 만든다(그림의 다이 317개, 실제 개수는 칩 크기에 따라 다르다).
- 공정을 한 바퀴 돌면 칩 완성 → ②~⑥을 층마다 되풀이한다.
- 표 한 행 = 로트 하나 → 한 행은 웨이퍼 한 장의 공정 기록 한 번이다.
- `=`를 "같다"로 읽음 → "오른쪽 값을 왼쪽 이름에 저장하라". 비교는 3차시에 배운다.
- 25.0이나 20.0이 나오면 틀렸다고 생각함 → 나누기 결과는 늘 float라서 소수점이 붙는다.
- 막대가 가장 높은 공정·설비 = 원인 → 눈에 띄는 것은 원인 후보일 뿐이다.

## 막히는 지점 TOP3와 대처

1. **노트북 7단계 문제 3의 조용한 오답** — 나누는 수에 `total_count`(40)나 카페의 `total`(10)을 넣으면 오류 없이 7.5나 30.0이 나온다. "무엇 중에서의 비율인가 → EQ-03 12건 중"을 짚고 `eq03_count`를 쓰게 한다. `NameError`가 나면 위 셀을 건너뛴 것이다(Kernel → Restart Kernel and Run All Cells…, 첫 빈칸에서 멈추는 것은 정상).
2. **Orange에서 위젯 잇기** — 반원을 끄는 동작이 낯설다. 왼쪽 목록에서 위젯을 끌어 온 뒤 File의 오른쪽 반원에서 새 위젯 왼쪽 반원까지 선을 긋는 방법을 한 번 더 보여 준다. 안 되면 `_done.ows`를 연다.
3. **Distributions의 Split by** — 공장 기록표에서는 Split by가 처음부터 합격여부로 잡혀 툴팁이 표 모양으로 나온다. Columns 칸의 위치를 화면에서 짚어 주고, None ↔ 공정명 ↔ 설비번호로 바꿔 보게 한다.

## 실습 중 오류 대응

- `NameError: name '____' is not defined`: 빈칸을 안 채우고 실행했다. `____`는 빈칸 표시일 뿐이고 밑줄 개수와 상관없이 필요한 만큼 쓴다.
- 문제 2에서 `SyntaxError`(invalid syntax): 따옴표 바로 앞 빈칸(`f`)을 안 채웠다. `f "…"`처럼 f 뒤에 띄어쓰기를 넣어도 같은 오류가 난다.
- `NameError: name 'Cups' is not defined`처럼 이름 앞에 대문자가 섞임: 대소문자·철자를 위 셀과 똑같이 맞춘다.
- `NameError: name '아메리카노' is not defined`: 글자에 따옴표를 빼먹었다.
- 결과에 `{pass_count}`가 그대로 나옴: f-string의 `f`를 빼먹었다(오류는 나지 않는다).
- Orange File 위젯에 빨간 글씨: 키트 폴더 구조가 바뀌었거나 `.ows`를 키트 밖으로 옮겼다. 키트를 다시 풀고 `_start.ows`를 다시 연다.
- 커널 끊김: 커널 재시작 후 맨 위부터 다시 실행.

## 빨리 끝낸 학생용 과제

- 노트북 7단계 아래에 셀을 하나 만들어, 불합격 8건 중 EQ-03의 3건이 차지하는 비율을 계산하고 f-string 문장으로 출력해 본다(3 ÷ 8 × 100 = 37.5). Orange 툴팁 표의 "in group" 칸과 비교한다.
- Orange 워밍업에서 Variable을 `구`로 바꿔 구마다 동이 몇 개인지 막대로 읽어 본다(모두 6개).
- Orange 반도체 데이터에서 Variable을 `설비번호`, Split by를 None으로 두고 기록이 가장 많은 설비를 찾는다(EQ-01, 13).
