# 1차시 강의 운영안 — 반도체 공정과 데이터 처음 만나기 + 변수·출력

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

앞으로 10차시 동안 반도체 공장에서 나온 숫자를 다룬다. 그 숫자가 어디서, 왜 생겼는지 모르면 표는
의미 없는 숫자 나열로만 보인다. 그래서 오늘은 공장 이야기부터 시작하고, 이어서 숫자를 코드 안에
기억해두는 가장 작은 단위인 변수와 출력을 배운다.

**예를 들면**: 매일 아침 "어제 만든 웨이퍼 중 합격이 몇 건, 불합격이 몇 건인지" 보고하는 담당자가
"합격 32, 불합격 8"을 `pass_count`, `fail_count`라는 이름으로 저장해두면 매번 다시 세지 않고
`print()`로 꺼내 볼 수 있다.

## 수업 흐름

1. 오리엔테이션: 10차시 전체 흐름 소개. "전공·코딩 경험이 없어도 된다"를 먼저 말해 긴장을 푼다.
2. 반도체 개념: 일상 속 반도체 → 도체/부도체/반도체와 스위치 비유 → 웨이퍼·다이·칩(쿠키 비유)
3. 만드는 과정: 큰 그림 4단계(준비 → 회로 새기기 → 검사 → 자르고 포장) → 대표 작업 6가지 표 → FAB·클린룸 → 로트·설비·센서
4. 휴식
5. 데이터 개념: 공장이 기록을 남기는 이유(블랙박스 비유) → 행과 열 → 합격(1)/불합격(-1) → 데이터 표 한 행을 문장으로 읽기
6. "여러 열 함께 보기" 맛보기: 공정명별 불합격 표, 온도 범위 관찰 → "원인"이 아니라 "원인 후보"
7. 파이썬과 Jupyter Notebook 사용법(셀, Shift+Enter, 실행 순서, 주석) → 변수·자료형·print·f-string·input() 강의와 시연
8. 학생 실습: 학생용 노트북 1~4단계. 먼저 끝난 학생은 4단계 끝 "도전 문제"(강의 STEP 03)
9. AI 활용(노트북 5·6단계) → 연습문제(7단계) → 공정 운세 미니 프로그램(8단계)
10. 정리 퀴즈 + 과제 안내 + 다음 차시 예고

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- 교육용 가상 데이터이며 실제 생산 기록이 아니다. 온도는 공정 구분 없이 약 300℃ 근처로, 압력은 약 1,000 근처로
  만들어져 실제 공정 조건과 다르다. 학생이 물으면 "교육용으로 만든 값이라 실제 공정의 온도·압력과 다릅니다.
  이번 과정에서는 값의 크기를 해석하지 않고 기록끼리 비교만 합니다"라고 답한다(데이터 설명서에도 같은 내용).
- `week01_semiconductor_process_overview.csv`: 40행 8열. `합격여부` 1(합격) 32건, -1(불합격) 8건.
- 공정명별 기록/불합격: 세정 10건/5건, 포토 9건/2건, 산화 6건/1건, 증착 8건/0건, 식각 7건/0건.
- 학습용 정상 온도 범위(295~305℃) 밖 기록은 2건(305.5℃ 불합격, 293.6℃ 합격). 불합격 8건 중 7건은 범위 안.
- 코드 실행 결과: 불합격률 `20.0%`, 도전 문제 `합격률은 80.0%입니다.`, AI 예시 코드 `합격률 80.0% → 점검 필요`,
  연습문제 `두 설비의 평균 온도는 23.8도입니다.`
- 공정 운세는 `random.seed(42)`로 고정해 항상
  `지민님의 오늘의 반도체 공정 운세: 오늘은 식각 공정에서 대박이 납니다!`가 나온다.

## 강사 설명 포인트
- **반도체 파트는 이름보다 "무엇을 하는지"를 먼저.** 공정 이름 6개를 외우게 하지 않는다. 표의
  "생활 속 비유" 열을 읽어주고, 학생이 비유로 다시 설명할 수 있으면 충분하다.
- 반도체를 "제품 이름"으로 아는 오해를 초반에 바로잡는다. 반도체는 물질의 성질이고, 그 성질로 스위치를 만든다.
- 웨이퍼-다이-칩은 반드시 그림(쿠키 반죽판 비유)과 함께 설명한다.
- 공정 흐름도는 "한 층을 만드는 순서의 한 예"라고 분명히 말한다. 6단계를 한 바퀴 돌면 칩이 완성된다는
  오해가 가장 흔하다. "아파트를 한 층씩 올리듯 수백 번 반복"을 강조한다.
- `합격여부` 부호(1=합격, -1=불합격)를 칠판에 크게 적어두고 수업 내내 언급한다.
- **"여러 열 함께 보기"는 계산 없이 표만 보여준다.** 공정명별 표는 강사가 미리 세어 둔 결과라고 말한다.
  학생에게 "불합격이 어디에 몰려 있나요?"라고 묻고, 세정이라는 답이 나오면 "그럼 세정이 원인일까요?"라고
  되묻는다. 의사 비유(체온만 보고 진단하지 않는다)와 "용의자 ≠ 범인" 비유로 "원인 후보"라는 말을 소개한다.
  이 차시에서는 개념 소개만 하고, 7~8차시에서 직접 계산한다고 예고한다.
- **강사만 알고 있을 것**: 이 데이터의 합격여부는 공정과 관계없이 무작위로 만들어졌다. 즉 "세정 10건 중 5건 불합격"은
  순수한 우연이다. 수업에서 세정을 실제 단서처럼 강조하지 말고 "우연일 수도 있다"는 문장을 꼭 함께 말한다.
  7~8차시 복습 때 "우연도 이렇게 그럴듯해 보일 수 있다"는 예로 공개해도 좋다.
- 파이썬 코드를 처음 보여주기 전에 Jupyter Notebook의 셀·Shift+Enter·실행 순서 번호를 화면에서 직접 보여준다.
- 변수는 "이름표가 붙은 상자", `=`는 "저장하라"는 뜻임을 반드시 강조한다.
- f-string은 "편지 양식 빈칸 채우기"로 소개하고, `f`를 빼먹었을 때 중괄호가 그대로 출력되는 모습을 직접 실행해 보여준다.
- `input()`은 항상 문자열을 돌려준다는 점을 `print(type(age_text))` 출력(`<class 'str'>`)으로 눈으로 확인시킨다.

## 예상 오개념
- FAB을 특정 회사 이름으로 오해 → "공장"이라는 일반 용어임을 강조.
- 산화→포토→식각→이온 주입→증착→세정 6단계를 한 번 거치면 칩이 완성된다고 생각 → 층마다 반복, 수백 단계, 몇 주~몇 달.
- 데이터에서 눈에 띄는 것 = 원인이라고 생각 → "단서(원인 후보)와 원인은 다르다", 확인 과정이 필요하다.
- "데이터 분석 = 어려운 수학"이라는 선입견 → 오늘 한 일(32건/8건을 세고 비율을 구한 것)도 데이터 분석의 시작이다.
- `=`를 수학의 "같다"로 착각 → 비교에는 `==`를 쓴다는 것을 3차시 예고로 짧게 언급.
- `input()`의 결과가 자동으로 숫자가 될 거라고 오해 → 항상 문자열이며 `int()` 변환이 필요하다.

## 실습 중 오류 대응
- `NameError: name 'pass_count' is not defined`: 1단계 셀을 실행하지 않고 아래 셀부터 실행한 경우다.
  맨 위 셀부터 차례대로 실행하게 한다.
- `SyntaxError: leading zeros in decimal integer literals are not permitted`: 문자열에 따옴표를 빼먹은 경우다
  (`equipment = EQ-03`). 따옴표로 감싸게 한다.
- `TypeError: can only concatenate str (not "int") to str`: `input()` 결과를 바꾸지 않고 숫자와 더한 경우다.
  `int()`로 바꾸게 한다.
- 셀이 끝나지 않고 `[*]`로 멈춰 있음: `input()` 입력칸에 값을 넣고 Enter를 누르지 않은 경우다.
- 빈칸 `____`을 채우지 않고 실행해 `NameError: name '____' is not defined`가 나는 경우: 빈칸을 채우게 한다.
- Jupyter 커널 연결 끊김: 커널을 다시 시작한 뒤 맨 위 셀부터 순서대로 재실행.

## 빠른 학습자용 추가 과제
- 노트북 4단계 끝의 "도전 문제 — 합격률 문장 만들기"(강의 STEP 03).
- f-string의 `:.2f`, `:.0f`로 바꿔 보며 결과 차이를 관찰하게 한다.
- 노트북 8단계 공정 운세에서 운세 문장을 공정별로 나눠달라고 AI에게 다시 요청해보게 한다.
  `random.seed(42)` 줄을 지우고 여러 번 실행해 결과가 바뀌는 것도 확인하게 한다.

## 느린 학습자용 최소 과제
- 강의 데이터 표의 한 행을 문장으로 읽을 수 있으면 충분하다(실습지 3번).
- 코드는 노트북 1단계(`pass_count = 32`, `print(pass_count)`)와 2단계 f-string 기본까지만 성공해도 충분하다.
  `input()`은 짝 활동으로 강사·동료가 함께 도와준다.
