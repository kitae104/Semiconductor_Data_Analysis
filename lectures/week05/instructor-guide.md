# 5차시 강의 운영안 — 데이터 훑어보기와 정리(EDA)

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

공장 기록에는 빈칸·중복·튀는 값이 끼어들고, 정리하지 않으면 코드는 돌아가도 숫자가 틀린다.
반 학생 기록에서 키 1720cm 하나 때문에 평균 키가 276.6cm로 나오고, 공장 기록에서는 평균 온도가 304.9도로 나온다(정리 후 300.6도).
그리고 빈칸을 "채우는" 방법도 튀는 값을 먼저 확인하지 않으면 채운 값까지 엉터리가 된다(클린룸 2543.66 장면).

## 강사 설명 포인트

- 개념은 반 기록으로만 설명하고, 공장 기록은 6단계에서 "표 이름만 바뀐다"를 보여 준다. 실습지 힌트가 강의의 어느 예제와 같은 모양인지 짚어 준다.
- `dropna()`·`drop_duplicates()`는 원래 표를 바꾸지 않는다 — 앞에 `students =` / `clean =`를 붙인다. 다음 셀의 `shape`로 확인하게 한다.
- 튀는 값은 지우기 전에 다른 열과 함께 본다(키 1720cm·몸무게 66kg → 입력 실수 의심). 튀는 값 = 불량이라고 단정하지 않는다.
- 오늘 연습용 기준·제외 기준(온도 400, 압력 0, 가스유량 0~200, 파티클 10,000)은 모두 교육용이다. 압력 절대값은 해석하지 않는다(데이터 설명서 "압력_Pa 값의 한계").
- PART 2의 핵심 장면은 "채운 값 2543.66"이다. 학생이 직접 Data Table(채운 뒤)에서 그 칸을 찾게 하고, "평균 안에 무엇이 들어 있었나?"를 묻는다. 결론: **채우기 전에 튀는 값부터 확인한다.**
- Orange Impute(3.35)에는 중앙값 채우기가 없다. Average/Most frequent만 안내한다.
- 파이썬 vs Orange는 "같은 결과"가 아니라 "다른 정리 방법이라 다른 결과"로 설명한다. 강의 비교 표의 파이썬 칸은 실습지에서 학생이 채우게 비워 두었다.
- 클린룸 등급·파티클 기준은 실제 규격을 단정하지 않는다("교육용 예시 기준").

## Orange 시연 체크리스트

- [ ] 키트를 압축 푼 폴더 그대로에서 `orange3/week05/week05_1_cleanroom_start.ows`를 연다. File 위젯을 더블클릭해 72행이 들어왔는지 확인한다. 빨간 파일 이름이 보이면 키트 폴더 구조가 바뀐 것이다 — 키트를 다시 풀게 한다.
- [ ] File → Feature Statistics: 파티클 Missing 4, Max 99999 / 습도 Missing 3 / 차압 Missing 2, Min -5.0.
- [ ] File → Impute(Transform 묶음): Default Method를 **Average/Most frequent**로 바꾼다(기본값은 Don't impute). Impute → Data Table: `파티클_count_per_m3` 열 머리글을 눌러 큰 값부터 정렬하면 99999 아래에 2543.66 4칸이 모인다. 강의의 "채운 값 확인 보기"는 학생이 찾은 뒤 연다.
- [ ] Impute → Select Rows(`파티클_count_per_m3` is below 10000, `차압_Pa` is at least 0) → Feature Statistics: 70행, 파티클 Max 2543.66.
- [ ] `week05_2_dirty_process_start.ows`(113행) → Feature Statistics: 온도 Missing 3, Max 557.73.
- [ ] File → Impute: 위쪽 Default Method = Average/Most frequent. 아래쪽 Individual Attribute Settings의 **왼쪽 열 목록**에서 `합격여부`를 누르고 **오른쪽 버튼**에서 Remove instances with unknown values. 위쪽 Default Method 칸의 같은 이름 버튼은 누르지 않는다고 말로 경고한다.
- [ ] Impute → Select Rows 네 줄(`온도_C` is at most 400, `압력_Pa` is at least 0, `가스유량_slm` is at least 0, `가스유량_slm` is below 200) → Data Table(105행) + Feature Statistics(온도 Mean 300.75).
- [ ] Data Table 뒤에 위젯을 잇지 않는다(출력은 선택 행뿐). 보기 위젯은 File·Impute·Select Rows에서 갈래로 잇는다.
- [ ] 늦은 학생은 `_done.ows`를 열어 따라잡게 한다.
- [ ] **알려진 차이(학생에게 묻지 않는다)**: Orange는 글자 앞뒤 공백을 지우고 읽어 `"식각 "`(뒤 공백 오타)를 `"식각"`과 합친다. 그래서 `공정명` 종류 수가 pandas 8종, Orange 7종으로 다르다. 학생이 발견하면 "Orange가 읽을 때 공백을 지우기 때문"이라고만 답하고 넘어간다. 공정명 종류 수는 오늘 다루지 않는다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **평균과 중앙값 차이**: AI가 "중앙값으로 채우는 게 항상 낫다"처럼 단정하는 경우가 있다. 오늘 포인트는 "평균은 튀는 값에 끌려간다"까지다. Orange Impute에는 중앙값이 없다는 점도 보충한다.
- **NaN 뜻**: AI가 `NaN`을 "0" 또는 "오류"로 설명하기도 한다. "값이 없음(빈칸)"이고 0과 다르다는 점, pandas 평균은 NaN을 빼고 계산한다는 점을 보충한다.
- **센서 값이 튀는 이유**: AI 답이 "튀는 값 = 불량"으로 흐르면 바로잡는다. 기록 오류(센서 고장·통신·입력 실수)와 실제 상태 변화 둘 다 가능하고, 다른 열과 함께 확인한다.
- **클린룸이 왜 필요한가**: AI가 클린룸 등급 숫자(ISO 등급 등)를 길게 늘어놓을 수 있다. 등급 기준은 규격마다 다르고, 오늘 데이터의 10,000 선은 교육용 예시라고 짚는다.

## 예상 오개념

- 빈칸 = 0 → 키를 안 잰 학생은 0cm가 아니다.
- `dropna()`만 실행하면 표가 바뀐다 → `students = students.dropna()`처럼 다시 저장해야 한다.
- 튀는 값도 `isna()`로 잡힌다 → 값이 있으므로 범위 조건으로 찾는다.
- 중복 3건을 지우면 6행이 사라진다 → 복사본 3행만 지워진다(104 → 101).
- 빈칸을 평균으로 채우면 늘 안전하다 → 튀는 값이 남아 있으면 채운 값도 튄다(2543.66).
- 99,999는 먼지가 아주 많았다는 뜻이다 → 센서가 측정 실패를 알린 오류 코드다.
- 파이썬과 Orange 결과가 다르면 한쪽이 틀렸다 → 지우기 vs 채우기, 중복 처리가 달라 결과가 다르다.
- 튀는 값 2건이 모두 EQ-03이니 EQ-03이 문제다 → 튀는 값 위치는 무작위로 정했다. "확인해 볼 단서"까지만 말한다.

## 막히는 지점 TOP3와 대처

1. **노트북 7단계 문제 2·3에서 `clean`과 `df`를 헷갈림** — 문제 3 마지막 셀의 빈칸을 `df`로 채우면 정리 전후가 304.9로 같다. "정리 전 = `df`, 정리 후 = `clean`"을 칠판에 적어 둔다.
2. **Orange Impute에서 합격여부 설정을 못 찾음** — 위쪽 Default Method를 고른 뒤, 아래쪽 Individual Attribute Settings의 **왼쪽 열 목록**에서 `합격여부`를 눌러야 오른쪽 버튼으로 그 열만의 방법을 고를 수 있다. 개별 설정을 빠뜨리면 113 → **107행**, 온도 Mean 300.63 — 합격여부 빈칸 2개가 "합격(1)"으로 지어내 채워진다. 위쪽 칸에도 같은 이름의 Remove instances with unknown values가 있어 그쪽을 누르면 104 → **98행**(300.60), Average를 고르지 않으면(Don't impute) **99행**(300.51)이 나온다(모두 orange-infra 실측). 위쪽은 Average/Most frequent 그대로 둔다. "검사 결과는 지어내 채우지 않는다"는 이유를 말로 짚고 설정 화면을 함께 확인한다.
3. **Select Rows 조건의 연산자 이름** — "이하 = is at most", "이상 = is at least", "미만 = is below"를 화면에 띄워 둔다. 가스유량은 같은 열에 조건 두 줄을 넣어야 한다.

## 실습 중 오류 대응

- 오류 없이 `shape`가 그대로: 앞의 `students =`(`clean =`)를 빠뜨렸다.
- `AttributeError: 'function' object has no attribute 'sum'`: `isna.sum()`처럼 괄호를 빠뜨렸다. `isna().sum()`으로 고친다.
- 문제 3에서 `(2, 9)`가 나옴: 부등호를 거꾸로 썼다(`>= 400`). 튀는 값 2행만 남은 것이다.
- `KeyError: '온도'`: 열 이름을 줄여 썼다. 오늘 열 이름은 `온도_C`다(`print(df.columns)`로 확인).
- `NameError: name 'df' is not defined`: 6단계 셀을 실행하지 않고 7단계로 왔다. "막혔을 때" 셀대로 위에서부터 다시 실행한다.
- `____`를 채우지 않고 실행(실제 메시지): 문제 1 `AttributeError: 'Series' object has no attribute '____'` / 문제 2 `AttributeError: 'DataFrame' object has no attribute '____'` /
  문제 3 비교 기호 `SyntaxError: invalid syntax. Perhaps you forgot a comma?`, 표 이름 `NameError: name '____' is not defined`. 빈칸을 채운다.
