# 5차시 강의 운영안 — 데이터 훑어보기와 정리(EDA)

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

공장 데이터는 사람이 아니라 센서·설비·네트워크가 자동으로 쌓는다. 그 과정에서 빈칸, 같은 기록의 중복,
말이 안 되게 튀는 값이 끼어든다. 정리하지 않고 계산하면 코드는 오류 없이 돌아가는데 숫자가 틀린다.

**숫자로 보여주기**: 오늘 데이터의 정리 전 평균 압력은 994.4로, 학습용 정상 범위(995~1025)보다 낮다.
이 숫자만 보면 "압력이 정상보다 낮은 공장"이라는 결론이 나온다. 그런데 113건 중 음수 기록 2건을 정리하면
1013.6으로 범위 한가운데다. 평균 온도도 304.9에서 300.6으로 내려간다. 몇 건의 튀는 값이 결론을 뒤집는다.

**비유**: 같은 영수증을 두 번 적거나 0을 하나 더 붙인 가계부로는 이번 달 지출을 믿을 수 없다.

3. 개념: 오늘 데이터의 열 다시 보기 → 공장 데이터가 지저분해지는 네 가지 이유(표) → 빈칸은 0이 아니다 → 오늘의 순서 5단계

## 강사 설명 포인트
- **"왜"를 숫자로 먼저.** 정리 전후 표를 수업 초반에 보여주고, 실습 마지막 6단계에서 학생이 직접 같은 숫자를 얻게 한다.
  "처음에 본 그 숫자를 여러분이 직접 만들었다"로 수업을 닫는다.
- 네 가지 문제는 이름보다 "공장에서 왜 생기나"로 설명한다. 표의 이유는 실제 현장에서 흔한 예이고,
  오늘 데이터의 오류는 연습용으로 일부러 넣은 것이라 각각의 실제 이유는 알 수 없다고 분명히 말한다.
- 칠판에 나란히 적는다: "결측값 = 칸이 비어 있음 → `isna()`", "이상값 = 값은 있는데 말이 안 됨 → 조건 검색".
- **지울까 채울까는 한 줄 기준만**: "결과는 지우고, 측정값은 채운다." 채울 값은 중앙값(용돈 비유: 1·1·2·2·100만 원 → 평균 21.2, 중앙값 2).
- `dropna()`/`fillna()`/`drop_duplicates()`는 원래 `df`를 바꾸지 않는다. 앞에 `df =`를 붙이는 이유를 실습 전에 짚는다.
- **이상값은 "지울 대상"이 아니라 "확인할 대상".** 건강검진 혈압 300 비유를 쓴 뒤 고온 2건을 다른 열과 함께 출력한다.
  "둘 다 합격이네요?", "둘 다 EQ-03이네요?"를 학생이 먼저 말하게 유도한다. 1차시 "여러 열 함께 보기"와 연결한다.
- **강사만 알고 있을 것**: 생성 스크립트에서 이상값 위치는 무작위로 골랐다. "6건 중 4건이 EQ-03"은 우연이다.
  수업에서 EQ-03을 실제 문제 설비처럼 말하지 말고 "현장이라면 이런 질문이 생긴다", "6건뿐이라 우연일 수 있다"를 꼭 함께 말한다.
- "정상 범위 밖"과 "있을 수 없는 값"을 구분한다. 정리 후에도 310.9도가 남는데, 이 값은 지우지 않는다.
  범위를 조금 벗어났다고 지우면 진짜 신호까지 지운다.
- 오늘의 이상값 기준(온도 400 초과, 압력 0 미만, 가스유량 0 미만 또는 200 이상)은 교육용으로 정한 기준이라고 말한다.
- `loc`로 값만 고치는 방법은 표에서 구경만 한다(코드 실습 없음).

## 예상 오개념
- 결측값을 0으로 착각 → 시험을 안 본 학생과 0점 받은 학생은 다르다.
- `dropna()`를 실행하면 `df`가 바로 바뀐다고 오해 → `df = df.dropna(...)`처럼 다시 저장해야 한다. 바로 다음 셀의 `shape`로 확인시킨다.
- 이상값도 `isna()`로 잡힌다고 오해 → 값이 "있으므로" 조건 검색으로 찾는다.
- 이상값은 무조건 지우는 것이라고 오해 → 지우기 전에 들여다본다. 진짜 설비 문제의 신호일 수 있다.
- 정상 범위(295~305) 밖이면 모두 이상값이라고 오해 → 오늘 지우는 것은 "있을 수 없는 값"뿐이다.
- 중복 3건을 지우면 6행이 사라진다고 오해 → 원본은 남고 복사본 3행만 지워진다(111 → 108).
- 이상값이 한 설비에 몰려 있으니 그 설비가 원인이라고 단정 → "확인할 단서"까지만. 설비 비교는 7~8차시.

## 실습 중 오류 대응
- `KeyError: '온도'`: 열 이름을 `온도_섭씨`가 아니라 줄여 썼다. `print(df.columns)`로 확인하게 한다.
- `AttributeError: 'function' object has no attribute 'sum'`: `df.duplicated.sum()`처럼 괄호를 빼먹었다. `df.duplicated().sum()`.
- `TypeError: Invalid comparison between dtype=float64 and str`: `df["온도_섭씨"] > "400"`처럼 숫자를 따옴표로 감쌌다.
- `AttributeError: 'DataFrame' object has no attribute '____'`: 빈칸 `____`을 채우지 않고 실행했다(예: `df.____()`).
- `SyntaxError: invalid syntax. Perhaps you forgot a comma?`: 비교 기호 빈칸(`df["온도_섭씨"] ____ 400`)을 채우지 않고 실행했다.
- `NameError: name '____' is not defined`: 숫자 빈칸(`df["압력_Pa"] >= ____`)을 채우지 않고 실행했다.
- 오류는 없는데 `shape`가 줄지 않음: `dropna`·`drop_duplicates` 앞의 `df =`를 빠뜨렸다.
- 6단계에서 정리 전후가 똑같이 나옴(`102 → 102`, `300.6 → 300.6`): 1단계 "정리 전 값 기억해 두기" 셀을 정리가 끝난 뒤 다시 실행했다.
  "커널 → 다시 시작 후 모두 실행"으로 처음부터 실행하게 한다.
- Orange3 Column Statistics의 입력 숫자가 113이 아님: Data Table에서 행을 클릭해 선택했다. Data Table의 Clear Selection을 누르게 한다.
- Orange3에서 Feature Statistics 위젯을 못 찾음: 버전에 따라 이름이 Column Statistics다(같은 위젯).
- 도전 문제 2 ②에서 `str[5]`로 쓴 경우: 정리 후 102행 중 101행이 나온다. 파이썬은 위치를 0부터 세므로 5번째 글자는 `str[4]`다.
