# 5차시 강의 운영안 — 데이터 훑어보기와 정리(EDA)

## 🤔 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

실제 현장 데이터는 센서 오류나 기록 누락으로 빈 값·터무니없는 값이 섞여 있기 마련이다. 이런 "더러운
데이터"를 그대로 분석하면 평균·그래프·모델 결과가 모두 왜곡되므로, 분석을 시작하기 전 반드시 데이터를
훑어보고 정리하는 단계가 필요하다.

**쉬운 예시**: 온도 센서가 잠깐 오작동해서 "-999도"라는 값이 하나 섞여 들어갔다고 하자. 이 값 하나
때문에 전체 평균 온도가 실제(약 300도)와 완전히 다르게 계산될 수 있다. 이런 이상값·빈 값을 먼저 찾아
정리해야 이후의 계산과 그래프를 믿을 수 있다.

  최종 **102행, 결측 0건**
- 정제 전 평균 온도(113행): **약 304.9℃** / 정제 후 평균 온도(102행): **약 300.6℃** / 차이: **약 4.3℃**

## 강사 설명 포인트
- Orange3 Data Table을 먼저 보여줄 때, 결측 셀이 빈칸으로 표시되는 것과 Feature Statistics의
  Max 열에서 500이 넘는 값이 눈에 띄는 것을 학생들이 스스로 발견하게 유도한다.
- "결측값 = 칸이 비어 있음", "이상값 = 칸에 값은 있지만 말이 안 됨"이라는 구분을 칠판에 나란히
  적어 강조한다.
- `isna()`는 결측값만 잡아낸다는 점, 이상값(500℃, 음수 압력)은 `isna()`로 잡히지 않고 조건
  검색으로 따로 찾아야 한다는 점을 반드시 짚는다.
- 평균 대 중앙값 차이는 "반 학생 용돈" 비유로 설명하면 이해가 빠르다.
- `dropna()`/`fillna()`가 원본을 바꾸지 않는다는 점(반환값을 다시 저장해야 함)을 실습 전에 미리 경고한다.
- `describe()`를 가장 먼저 보여주며 "결측을 하나씩 세기 전에 숫자 요약부터 훑어보는 것이
  실무 습관"이라는 점을 짚는다. `count`가 전체 행 수보다 적은 열, `mean`이 `50%`(중앙값)보다
  훨씬 큰 열을 학생들이 스스로 짚어내도록 유도한다.
- 이상값 처리에서 "행 삭제"만 배우고 끝내지 말고, 4차시에서 배운 `loc`로 값만 정정하는
  `df.loc[조건, "열"] = 값` 예시를 함께 보여주며 "삭제 vs 정정" 판단 기준을 짚는다.

## 예상 오개념
- 결측값을 0으로 착각 → `0`은 "측정된 값이 0"이고 `NaN`은 "측정 자체가 안 됨"이라는 차이를 명확히 한다.
- `dropna()`를 실행하면 원본이 자동으로 바뀐다고 오해 → `df = df.dropna()`처럼 재할당이 필요함을 강조.
- 이상값도 `isna()`로 잡힌다고 오해 → 이상값은 "값이 존재"하므로 조건 검색(`df["온도_섭씨"] > 400`)으로 찾아야 함을 실습으로 직접 보여준다.
- 중복 3건을 제거하면 행이 3장씩(총 6행) 사라진다고 오해 → 중복 쌍마다 "여분 1개"만 제거되어 행 개수가 정확히 3만큼만 줄어듦을 코드로 확인시킨다.

## 실습 중 오류 대응
- `KeyError`: `df.columns`로 정확한 열 이름을 다시 확인하게 한다(특히 `가스유량_slm`, `처리시간_sec` 철자).
- `fillna()`에 중앙값을 잘못 넣어 다른 열 전체가 바뀌는 경우: 반드시 `df["열이름"] = df["열이름"].fillna(값)` 형태로 열을 지정했는지 확인.
- 조건 검색 결과가 빈 표로 나오는 경우: 비교 연산자(`<`, `>`)와 열 이름 철자를 다시 확인하게 한다.

## 빠른 학습자용 추가 과제
- 공정명 오타(`중착`, `포토공정`, 공백이 붙은 `식각 `)를 `str.strip()`과 `replace()`로 통일한 뒤, 정제 전/후 `value_counts()` 결과 변화를 비교해보게 한다.
- 날짜 형식이 다른 `측정시간` 2건을 두 단계로 찾아보게 한다. ① `df[df["측정시간"].str.len() != 16]`
  → **1건만 나온다**(`2024/03/05`, 10자). ② 나머지 1건 `03-05-2024 10:00`은 정상값과 **똑같이 16자**라
  길이로는 안 잡힌다 → `df[df["측정시간"].str[4] != "-"]`로 **2건 모두** 잡힌다.
  **강사가 먼저 알고 있을 것**: ①에서 1건만 나오는 것은 학생의 코드 실수가 아니라 데이터가 그렇게
  생긴 것이다. "1건밖에 안 나오는데요?"라는 질문이 나오면 정정하지 말고 "왜 그럴까?"로 되물어
  "글자 수가 같아도 형식은 다를 수 있다"는 감각으로 이어간다(6차시 시계열 그래프 예고).
- 노트북 10단계 "연습문제 — 나만의 정제 리포트 만들기"에서 1~3단계의 `isna()`·`duplicated()`를
  재사용해 원본 파일을 직접 다시 읽어보게 한다.
- 노트북 11단계 "AI로 재미있는 미니 프로그램 만들기"(이상값 탐정 게임)에서는, 예시 값에서 왜
  용의자가 하나도 안 잡히는지(극단값이 표준편차 자체를 부풀리는 효과) AI에게 되물어보며
  기준(2배→3배)이나 방법(IQR)을 바꿔 다시 시도해보게 한다.

## 느린 학습자용 최소 과제
- `df.isna().sum()`으로 결측값 개수만 확인하고, "어떤 열에 결측이 가장 많은지" 말로 설명할 수 있으면 충분하다.
- `dropna()`와 `fillna()` 중 하나만 골라 실행해보고, 실행 전후 `df.shape`가 어떻게 달라지는지 확인한다.
