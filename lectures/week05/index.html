데이터 훑어보기와 정리(EDA)

오늘의 질문: "공장 기록에 섞인 빈칸·중복·튀는 값을 정리하면, 평균은 얼마나 달라질까?"

오늘의 미션 — 입사 다섯째 날, 센서 기록에 빈칸·중복·튀는 값이 섞여 있다. 정리해서 믿을 수 있는 평균 온도를 보고하자. (신입 데이터 담당자의 10일 이야기와 공장·데이터는 모두 교육용 가상이다.)

학습 목표

  • 빈칸·중복·튀는 값이 왜 생기고, 평균을 어떻게 틀어지게 하는지 설명할 수 있다.
  • describe()와 isna().sum()으로 문제가 있는 열을 찾을 수 있다.
  • dropna()·drop_duplicates()·범위 조건으로 표를 정리하고, 정리 전후의 행 수와 평균을 비교할 수 있다.
  • Orange3 Impute로 빈칸을 채워 보고, 튀는 값이 남은 채로 평균을 채우면 생기는 문제를 말할 수 있다.

선수 지식: 4차시 — read_csv, 조건 검색 / 3차시 — Orange Select Rows / 2차시 — Orange Feature Statistics

왜 이걸 배워야 할까?

공장 기록에는 빈칸·중복·튀는 값이 끼어든다. 정리하지 않으면 코드는 돌아가도 숫자가 틀린다.

오늘 쓰는 반 학생 기록에서도, 키를 잘못 적은 값(1720cm) 하나 때문에 평균 키가 276.6cm로 나온다. 정리하면 163.8cm다.

비유 — 가계부 같은 영수증을 두 번 적은 가계부로는 지출을 믿을 수 없다. 분석 전에 데이터를 훑어보고 정리하는 일을 EDA(탐색적 데이터 분석)라고 한다.

PART 1 파이썬 — 빈칸·중복·튀는 값 정리하기

개념은 반 학생 기록(week05_easy_class_records.csv, 15행 5열, 생활 예제용 가상 데이터)으로 익힌다.

열뜻
이름, 반학생 이름과 반
키_cm, 몸무게_kg키(센티미터), 몸무게(킬로그램). 밑줄 뒤가 단위다
수학점수_pt수학 점수. _pt는 점수(points)라는 뜻

이 표에는 빈칸 3칸, 두 번 적은 학생 1명, 잘못 적은 키 1개가 일부러 섞여 있다. 하나씩 찾아서 정리한다.

숫자 요약 보기 — describe()

describe()는 숫자 열마다 개수·평균·최솟값·최댓값을 한 번에 보여 준다. 2차시 Orange Feature Statistics의 코드판이다.

Python — 읽고 요약하고, 정리 전 값 기억하기 (노트북 1단계)
import pandas as pd

students = pd.read_csv("week05_easy_class_records.csv", encoding="utf-8-sig")
print(students.shape)

print(students.describe())

before_count = len(students)
before_height = round(students["키_cm"].mean(), 1)
print(before_count, before_height)

빈칸 세고 지우기 — isna(), dropna()

빈칸은 pandas에서 NaN(값 없음)으로 읽힌다. 키를 안 잰 학생은 0cm가 아니다 — 0과 빈칸은 다르다.

  • isna().sum() — 칸마다 "비었나?"를 확인하고, 열마다 빈칸 개수를 센다.
  • dropna() — 빈칸이 하나라도 있는 행을 지운다. 결과를 students =로 다시 저장해야 남는다.
Python — 빈칸 세고 지우기 (노트북 2단계)
print(students.isna().sum())

students = students.dropna()
print(students.shape)

중복 행 찾고 지우기 — duplicated(), drop_duplicates()

duplicated()는 앞의 행과 모든 칸이 같은 행을 찾고, .sum()이 그 개수를 센다. drop_duplicates()는 그 복사본만 지운다.

Python — 중복 행 세고 지우기 (노트북 3단계)

students = students.drop_duplicates()
print(students.shape)

튀는 값 찾고 빼기 — 범위 조건

튀는 값(이상값)은 값이 있어서 isna()로는 안 잡힌다. 4차시에 배운 조건 검색으로 찾는다. 사람 키가 250cm를 넘는 일은 거의 없으니, 오늘은 250cm를 넘으면 잘못 적은 값으로 본다.

Python — 튀는 값 찾기 (노트북 4단계)

PART 2 Orange3 — 빈칸 채우기와 튀는 값

PART 1에서는 빈칸 행을 지웠다. Orange에서는 빈칸을 채우는 방법을 본다. 채울 때 무엇을 조심해야 하는지가 오늘의 핵심이다.

워크플로 열기

  1. 실습 환경의 폴더 구조를 그대로 둔다(데이터 경로가 폴더 구조에 맞춰져 있다).
  2. Orange3에서 File → Open을 누르고 week05_1_cleanroom_start.ows를 연다.
  3. 캔버스에 File 위젯 하나와 ①~④ 안내 메모가 보이면 준비가 끝난 것이다. 막히면 같은 폴더의 _done.ows(완성본)를 연다.

위젯 이름표

채운 값을 보자 빈칸 4칸이 모두 2543.66으로 채워졌다. 평소 값(1,000 안팎, 오류 코드를 뺀 평균 1,089.1)의 2배가 넘는다. Impute는 그 열의 평균으로 채우는데, 평균 안에 99,999가 들어가 평균이 끌려 올라갔기 때문이다. 튀는 값이 남은 채로 평균을 내 빈칸을 채우면, 채운 값도 엉터리가 된다 — 그래서 채우기 전에 튀는 값부터 확인한다.
3
튀는 값 거르기 — Transform 묶음의 Select Rows를 Impute에 잇는다. 창에서 Add Condition을 누르고 열 → 연산자 → 숫자 순서로 고르는 일을 조건마다 되풀이해 두 줄을 넣는다: 파티클_count_per_m3 is below 10000, 차압_Pa is at least 0. Select Rows에 Feature Statistics를 하나 더 잇는다.

읽을 것 — 72행 중 오류 코드 행과 음수 차압 행이 빠져 70행이 남는다. 그런데 정리 후 파티클 Max가 2543.66, 바로 아까 채운 값이다. 99,999는 지웠지만, 그 값으로 계산해 채운 숫자는 표에 그대로 남았다. 튀는 값을 먼저 확인하고 채웠다면 채운 값이 이렇게 끌려 올라가지 않았다.

차압 -5.0은 바깥 공기가 밀려 들어올 수 있는 방향이라, 센서 오류인지 실제 상황인지 따로 확인할 값이다. 오늘은 평균 계산에서만 뺀다.

Q1. (객관식) describe() 결과에서 키_cm의 count가 14였다(전체 15명). 이것이 뜻하는 것은?
  • A. 키가 14cm인 학생이 있다
  • B. 키 칸 하나가 비어 있다
  • C. 같은 학생이 14번 적혔다
