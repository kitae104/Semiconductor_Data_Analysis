데이터 훑어보기와 정리(EDA) — 실습지

왜 이걸 배워야 할까?

  • 공장 데이터는 센서·설비·네트워크가 자동으로 쌓기 때문에 빈칸, 같은 기록의 중복, 말이 안 되게 튀는 값이 끼어든다.
  • 정리하지 않고 계산하면 오류 없이 틀린 숫자가 나온다. 오늘 데이터는 정리 전 평균 압력이 994.4(학습용 정상 범위 995~1025 밖)였지만, 음수 기록 2건을 정리하니 1013.6이 됐다.

2. 공장에서 생긴 일 연결 문제

공장에서 생긴 일이 데이터에 어떤 문제로 남을지 골라보자(결측값 / 중복값 / 이상값 / 입력 오류).

공장에서 생긴 일데이터에 남는 문제
① 통신이 잠깐 끊겨 온도 값이 서버에 들어오지 않았다.( )
② 통신이 불안정해 같은 기록을 서버에 두 번 보냈다.( )
③ 온도 센서가 고장 나 540도가 찍혔다.( )
④ 작업자가 "증착"을 "중착"으로 잘못 입력했다.( )
① 결측값 ② 중복값 ③ 이상값 ④ 입력 오류. 이상값은 센서 고장일 수도 있지만 진짜 설비 문제일 수도 있어서, 지우기 전에 확인한다.

4. 지울까, 채울까

오늘 기준은 "결과는 지우고, 측정값은 채운다"였다. 각 상황에 dropna(지우기)와 fillna(채우기) 중 무엇이 알맞은지 골라보자.

상황dropna / fillna
① 합격여부(검사 결과)가 비어 있다.( )
② 온도_섭씨 한 칸만 비어 있고, 같은 행의 압력·가스유량·합격여부는 멀쩡하다.( )
③ ②번 빈칸을 채울 값으로 평균과 중앙값 중 무엇이 더 안전한가? (온도에 557도 같은 값이 섞여 있다)( )
① dropna — 검사 결과를 짐작해 채우면 없던 결과를 지어내는 셈이다. ② fillna — 행을 지우면 멀쩡한 다른 값까지 버린다. ③ 중앙값 — 평균은 557도 같은 튀는 값에 끌려가지만 중앙값은 거의 흔들리지 않는다.

5. describe() 읽기 문제

df.describe()에서 온도_섭씨 열만 옮겨 적었다(소수 둘째 자리까지).

count   110.00
mean    304.94
50%     300.45
min     291.30
max     557.73
  1. 전체 113행 중 count가 110이다. 빈칸은 몇 개인가?
  2. 평균(304.94)이 중앙값(300.45)보다 크다. 무엇이 섞여 있다는 신호일까?
1) 113 - 110 = 3개. 2) 다른 값보다 훨씬 큰 값(이상값)이 평균을 끌어올리고 있다는 신호다. 실제로 max가 557.73이다.

6. 이상값 들여다보기

고온 이상값 2건을 다른 열과 함께 출력했다(교육용 가상 데이터).

     설비번호 공정명       온도_섭씨  합격여부
17  EQ-03  식각  540.315405   1.0
67  EQ-03  증착  557.727366   1.0
  1. 두 기록의 검사 결과는 무엇인가? 이 사실에서 무엇을 의심해볼 수 있을까?
  2. 두 기록의 공통점은 무엇인가?
  3. 동료가 "그럼 EQ-03이 불량의 원인이네"라고 말했다. 어떻게 답하면 좋을까?
1) 둘 다 합격(1)이다. 정상 범위(295~305)보다 200도 넘게 뜨거웠는데 합격했으니, 온도 기록이 잘못됐을 가능성을 먼저 확인해볼 만하다. 2) 둘 다 EQ-03 설비 기록이다(가스유량 이상값 2건도 EQ-03). 3) "EQ-03 센서를 점검해볼 단서는 되지만, 이 기록들은 모두 합격이었고 6건뿐이라 우연일 수도 있어. 원인이라고 단정할 수는 없어."

7. 결과 해석과 문장 쓰기

정리 전후 비교 코드를 실행한 결과다.

행 개수: 113 → 102
평균 온도: 304.9 → 300.6
평균 압력: 994.4 → 1013.6
문장 작성 빈칸을 채워보자. "원본 ____행을 정리해 ____행이 남았고, 평균 온도는 ____ 내려갔다. 평균 온도가 내려간 까닭은 ____________ 때문이다."
"원본 113행을 정리해 102행이 남았고, 평균 온도는 4.3(304.9 - 300.6) 내려갔다. 평균 온도가 내려간 까닭은 540도·557도 같은 고온 이상값 2건이 평균을 끌어올리고 있었기 때문이다."

9. 도전 — 공정명 오타 통일

도전 df["공정명"].value_counts()로 오타(중착, 포토공정, 뒤에 공백이 붙은 식각 )를 확인하고, str.strip()과 replace()로 통일해보자. (노트북 6단계 "도전 문제 1")
체크포인트 공백을 먼저 지워야 식각 과 식각이 하나로 합쳐진다. 두 단계를 마치면 공정명이 5개(포토 24, 세정 22, 산화 21, 증착 19, 식각 16)만 남는다.

10. 도전 — 형식이 다른 측정시간 찾기

도전 정상 측정시간은 2024-03-05 10:00처럼 16글자다. ① str.len()으로 16글자가 아닌 기록을 찾고, ② str[4]로 5번째 글자가 -가 아닌 기록을 찾아 두 결과를 비교해보자. (노트북 6단계 "도전 문제 2")
체크포인트 ①은 1건(2024/03/05), ②는 2건(2024/03/05, 03-05-2024 10:00)이 나온다. 03-05-2024 10:00은 정상값과 똑같이 16글자라 길이로는 걸리지 않는다. 한 가지 방법으로 다 찾았다고 믿지 말자.
