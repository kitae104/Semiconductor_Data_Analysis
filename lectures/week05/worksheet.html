빈칸 행을 지울 때 몇 행, 중복 행을 지울 때 몇 행이 줄었나?

dropna, drop_duplicates → (104, 9), (101, 9). 빈칸이 있는 행 9행(113 → 104), 중복 복사본 3행(104 → 101)이 줄었다. 함수 뒤 괄호 ()를 빠뜨리면 표가 아니라 함수가 저장된다.

문제 4 — Orange로 정리하고 파이썬과 비교하기

Orange3에서 week05_2_dirty_process_start.ows를 연다. 강의 PART 2 "반도체 — 지저분한 공장 기록 정리하기"의 순서를 따른다.

  1. File에 Feature Statistics를 잇고, 온도_C의 Missing과 Max.를 읽는다.
  2. File에 Impute(Transform 묶음)를 잇는다. 위쪽 Default Method = Average/Most frequent. 아래쪽 Individual Attribute Settings의 왼쪽 열 목록에서 합격여부를 누르고 오른쪽 버튼 중 Remove instances with unknown values를 고른다. 위쪽 Default Method 칸의 같은 이름 버튼은 누르지 않는다.
  3. Impute에 Select Rows를 잇고 Add Condition으로 조건 네 줄(가스유량은 같은 열을 두 번): 온도_C is at most 400, 압력_Pa is at least 0, 가스유량_slm is at least 0, 가스유량_slm is below 200.
  4. Select Rows에 Data Table과 Feature Statistics를 잇고, 남은 행 수와 온도_C의 Mean을 읽는다.

문제 3의 파이썬 결과(행 수·평균 온도)와 다른 이유를 한 줄로 적자.

정리 전 Missing 3, Max 557.73 / 정리 후 105행 / 온도 Mean 300.75(화면에 300.7로 보이면 그것도 정답). 다른 이유(예): "파이썬은 빈칸 행과 중복 행을 지워 95행이 남았고, Orange는 빈칸을 평균으로 채우고 중복 행을 남겨 105행이 남았다. 정리 방법이 달라 행 수와 평균이 다르다."
체크포인트 Orange 행 수 흐름: 113 → Impute 뒤 111(합격여부 빈 2행 삭제) → Select Rows 뒤 105. 107행이면 합격여부 개별 설정을 빠뜨린 것(합격여부 빈칸이 "합격"으로 채워짐), 98행이면 위쪽 Default Method에서 Remove instances를 누른 것, 99행이면 Average/Most frequent를 고르지 않은 것이다. 그 밖의 숫자면 Select Rows 조건 네 줄(연산자·숫자)을 다시 확인한다. 막히면 같은 폴더의 week05_2_dirty_process_done.ows를 연다.

문제 5 — 해석 문장 쓰기

오늘의 질문 "공장 기록에 섞인 빈칸·중복·튀는 값을 정리하면, 평균은 얼마나 달라질까?"에 문제 3의 숫자로 답하자.

문장 틀 "정리 전 평균 온도는 ______도, 정리 후 ______도다. 540도·557도 같은 튀는 값 등이 평균을 약 ______도 끌어올리고 있었다."
세 빈칸 모두 문제 3의 출력으로 채운다. 마지막 빈칸은 정리 전 평균에서 정리 후 평균을 뺀 값이다.
"정리 전 평균 온도는 304.9도, 정리 후 300.6도다. 540도·557도 같은 튀는 값 등이 평균을 약 4.3도 끌어올리고 있었다."(304.9 − 300.6 = 4.3. 빈칸·중복 행을 지운 효과도 조금 섞여 있어 "등"이라고 쓴다.) (Orange 결과로 "정리 후 300.75도"라고 써도 되지만, 그때는 "빈칸을 평균으로 채우고 중복을 남긴 결과"라고 함께 밝힌다.)
