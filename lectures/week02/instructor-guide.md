# 2차시 강의 운영안 — 리스트와 딕셔너리

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

실제 공정에는 값이 하나만 있는 게 아니라, 여러 설비·여러 시점의 측정값이 함께 존재한다. 리스트는
이런 "여러 개의 값"을, 딕셔너리는 "이름표가 붙은 값들의 묶음"을 다루는 방법이며, 4차시부터 배우는
표(DataFrame)도 결국 이 둘을 확장한 것이다.

**쉬운 예시**: 한 설비의 온도를 하루에 5번 측정했다면 값 5개를 변수 5개로 따로 만드는 건 번거롭다.
리스트에 `[298, 301, 299, 305, 300]`처럼 담아두면 최고·최저·평균 온도를 한 번에 계산할 수 있고,
딕셔너리로 `{"설비번호": "EQ-03", "온도_섭씨": 301}`처럼 이름표를 붙이면 이 값이 어느 설비의 기록인지도
함께 관리할 수 있다.

## 수업 흐름

1. 지난 시간 복습: 1차시에서 만든 변수(`pass_count = 32`)를 다시 띄우고, "값 하나"의 한계를 체감시키기
2. 오늘의 질문 제시 — "여러 개의 측정값을 한 번에 담고, 각 값에 이름표까지 붙이려면 어떻게 해야 할까?"
3. 리스트 개념 설명(생성, 인덱싱, 슬라이싱, len/append) + 용어 카드 — 과일 리스트(`fruits`) 예제로 먼저 감을 잡는다(노트북 1단계 앞부분 「따라 해보기」 셀)
4. 강사 코드 시연: 리스트 만들기 → 인덱싱/슬라이싱 → max/min/sum/평균
5. 딕셔너리 개념 설명(생성, 키로 값 접근, 값 수정/새 키 추가) — 사람 딕셔너리(`person`)·학생 목록(`students`) 예제로 먼저 감을 잡는다(노트북 6단계·9단계 앞부분 「따라 해보기」 셀)
6. 강사 코드 시연: 딕셔너리 만들기 → 값 접근 → 리스트 안에 딕셔너리 담기
7. 휴식
8. 학생 실습: 리스트 만들기 → 인덱싱/슬라이싱 → 통계 계산 → 딕셔너리 → 딕셔너리의 리스트 → 종합 실습(노트북 1~10단계).
   강의 개념 절의 「직접 해보기」 4개는 노트북 3·5·8·9단계 끝의 「직접 해보기」 셀이다(학생용은 일부 빈칸 + 바로 아래 **참고** 셀).
9. 도전 실습(빠른 학습자): 노트북 11단계 안의 「도전 문제 1」(온도만 모은 리스트 + `max()`), 「도전 문제 2」(딕셔너리에 `"합격여부": 1` 키 추가)
10. 정리 퀴즈 + 과제 안내 + 다음 차시 예고

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- `temperatures = [295.4, 298.1, 312.6, 301.0, 296.8]` → `temperatures[0]` 295.4, `temperatures[1]` 298.1,
  `temperatures[-1]` 296.8, `temperatures[1:3]` → `[298.1, 312.6]`, `temperatures[-2:]` → `[301.0, 296.8]`
- `append(303.2)` 뒤(값 6개): 최댓값 312.6, 최솟값 295.4, 합계 1807.1, 평균 301.2(`round(average, 1)`),
  온도 범위 `max - min` → `17.200000000000045`(부동소수 오차) → `:.1f`로 `17.2`
- `equipment_list` 3대: EQ-01 식각 301.2 / EQ-02 증착 308.7 / EQ-03 포토 297.5 → 최고 온도 308.7(EQ-02)
- 연습문제 압력: 최댓값 1022.9, 최솟값 998.7, 평균 1009.6(저장값 1009.64)
- 럭키 설비(`random.seed(7)`): EQ-03 / 포토 / 297.5도

## 강사 설명 포인트
- 리스트를 소개하기 전에 "변수 하나에는 값을 하나만 담을 수 있다"는 1차시의 한계를 반드시
  먼저 체감시킨다. 리스트가 "왜 필요한지" 동기부여가 없으면 개념이 겉돈다.
- 리스트 인덱스가 0부터 시작한다는 점은 이번 차시에서 가장 많이 틀리는 지점이다. 상자 그림을
  칠판에 그려 "첫 번째 상자의 번호표가 0"이라는 것을 눈으로 반복해서 보여준다.
- 딕셔너리를 소개할 때는 리스트와 곧바로 비교한다 — "리스트는 순서로, 딕셔너리는 이름표로
  값을 구분한다"는 문장을 칠판에 나란히 적어두고 수업 내내 참조한다.
- "리스트 안에 딕셔너리를 담는다"는 개념은 이번 차시의 핵심 도약이다. 3장의 카드가 든 상자
  그림(강의 자료의 SVG 참고)으로 설명하면 4차시 Pandas의 표(행=딕셔너리 하나, 표 전체=리스트)
  개념과 자연스럽게 연결된다.

## 예상 오개념
- 리스트 인덱스가 1부터 시작한다고 착각 → 실제로 `list[1]`을 실행해 "두 번째" 값이 나오는 것을
  직접 보여준다.
- 슬라이싱 `[1:3]`에 인덱스 3의 값까지 포함된다고 착각 → "끝 인덱스는 포함되지 않는다"를
  실제 실행 결과로 반복 확인시킨다.
- 딕셔너리도 리스트처럼 `[0]`으로 접근하려 시도 → `KeyError: 0`이 나는 것을
  직접 보여주고, "딕셔너리는 키로만 접근한다"고 짚어준다.
- 리스트는 `[ ]`, 딕셔너리는 `{ }`를 혼동 → "순서만 있으면 대괄호, 이름표가 있으면 중괄호"로
  암기 문구를 함께 반복한다.
- f-string 안에서 딕셔너리 키에 큰따옴표를 중복 사용해 `SyntaxError` 발생 → f-string 바깥이
  큰따옴표면 안쪽 딕셔너리 키는 작은따옴표를 써야 한다는 규칙을 강조한다.

## 실습 중 오류 대응
- `IndexError: list index out of range`: `len()`으로 리스트 길이를 먼저 확인하게 한다.
- `KeyError`: `print(딕셔너리이름)`으로 전체 키를 먼저 출력해 정확한 키 이름을 확인하게 한다.
- `SyntaxError`(따옴표 중복): f-string 바깥/안쪽 따옴표 종류가 다른지 확인하게 한다.
- 대괄호 `[]`와 중괄호 `{}`를 혼동해 오류가 나는 경우: 리스트인지 딕셔너리인지 다시 묻고
  올바른 기호로 고치게 한다.
- AI가 준 코드가 `equipment_list = [...]`처럼 9단계에서 만든 이름을 그대로 쓰면 설비 목록이 새 목록으로
  덮어써져, 공정명을 꺼내는 뒤 코드에서 `KeyError`가 날 수 있다: 강의 예시처럼 이름을 `sample_list` 등으로
  바꾸게 하거나 9단계 셀을 다시 실행하게 한다.

## 빠른 학습자용 추가 과제
- 강의 자료의 "도전 문제 1"(딕셔너리의 리스트에서 온도만 모은 새 리스트 만들어 `max()` 적용)과
  "도전 문제 2"(딕셔너리에 새 키 추가)를 먼저 시도해보게 한다. 노트북 11단계 안 「도전 문제 1」「도전 문제 2」
  셀에 있으며, 학생용은 인덱스·함수 이름·키 이름이 빈칸이고 빈칸 셀 아래 **참고** 셀이 강의 자료의 어느 절을
  다시 보면 되는지 알려준다. 예상 결과: `[301.2, 308.7, 297.5]` → `308.7`(EQ-02), 도전 문제 2는
  `{'설비번호': 'EQ-06', '공정명': '증착', '온도_섭씨': 303.4, '합격여부': 1}`(8단계 「직접 해보기」에서
  `equipment`를 EQ-06으로 다시 만든 뒤 기준).
- 딕셔너리에 `keys()`, `values()`를 검색해서 스스로 사용해보게 한다(3차시 반복문 예고 겸용).
- 노트북 14단계 연습문제(압력 리스트·새 설비 딕셔너리)로 리스트·딕셔너리를 한 번 더 반복
  연습시킨다.
- 노트북 15단계 "AI로 재미있는 미니 프로그램 만들기"(오늘의 럭키 설비 뽑기)에서 설비를 더
  추가해달라고 AI에게 재요청하며 리스트를 확장해보게 한다. 강의 예시 코드는 `random.seed(7)` 줄로 결과를
  고정해 몇 번을 실행해도 EQ-03(포토, 297.5도)이 뽑힌다. seed 줄을 지우면 실행할 때마다 달라진다는 것을
  함께 보여준다.

## 느린 학습자용 최소 과제
- 리스트 인덱싱(`temperatures[0]`, `temperatures[-1]`)까지만 성공해도 충분하다. 슬라이싱과
  딕셔너리는 강사·동료와 함께 짝 활동으로 진행한다.
- 딕셔너리는 미리 만들어진 `equipment` 예시에서 값을 꺼내보는 것(`equipment["설비번호"]`)만
  성공해도 이번 차시 최소 목표는 달성한 것으로 인정한다.
