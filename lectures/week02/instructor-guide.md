# 2차시 강의 운영안 — 리스트와 딕셔너리

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

설비는 온도를 한 번만 재지 않는다. 같은 설비가 같은 작업을 해도 잴 때마다 값이 조금씩 다르다. 1차시처럼 상자 하나에 값 하나를 담으면 상자가 끝없이 늘어난다.
오늘은 여러 값을 리스트에 담아 최고·최저·평균으로 요약하고, 딕셔너리로 값에 이름표를 붙인다. 이 둘이 4차시 "표"의 재료다.
오늘의 미션: "팀장이 EQ-03 설비 온도 7개를 메모로 줬다 — 최고·최저·평균을 정리해 보고하자."
미션의 답(최고 308.5 · 최저 292.2 · 평균 302.6)은 처음부터 말하지 않는다. 학생이 노트북 7단계에서 직접 구한다.

## 강사 설명 포인트

- 리스트 = 번호 붙은 약통, 딕셔너리 = 이름표 붙은 사물함. 반도체 비유는 1차시 피자 가게 하나로 유지한다: 설비 = 오븐, 설비번호 = 오븐 번호("몇 번 오븐에서 구운 판인지 적는다").
- "함수"는 노출 전용 한 줄 정의다: `print()`, `len()`처럼 이름 뒤에 괄호를 붙여 일을 시키는 것. 노트북 TODO의 "함수 이름을 채우세요" = 괄호 앞 이름을 쓰라는 뜻.
- 인덱스가 0부터라는 점을 강의 그림(월요일 = [0])으로 짚는다. `-1` = 마지막 칸.
- 평균 24.3만 보면 수요일 30.5가 안 보인다 → "그래서 최고·최저를 함께 본다". 이 문장이 PART 2 지하철(Mean 2876.58 vs Max 9872)과 온도(Mean 303.8 vs Max 317.9)까지 이어지는 오늘의 줄기다.
- `round(값, 1)`은 노출 전용이다. "소수 첫째 자리까지 반올림" 한 줄로 넘긴다. f-string 서식(`:.1f`)은 쓰지 않는다.
- 슬라이싱(`week_temps[0:5]`)과 딕셔너리의 리스트(5단계)는 구경만 한다. 실습·과제·퀴즈에 내지 않는다.
- "반도체 데이터로 확인하기"는 EQ-02로 한다. 미션 EQ-03은 실습 문제로 남겨 두어 학생이 직접 구하게 한다. 질문을 먼저 던지고 [코드와 결과 보기]를 연다.
- "같은 설비·같은 작업이라도 측정값은 매번 조금씩 다르다"는 일반 개념으로만 말한다. 오늘 표의 설비별 기록에는 여러 공정이 섞여 있으므로, EQ-02 4건이나 EQ-03 7건의 퍼짐을 "측정 변동"의 증거로 말하지 않는다. "값이 여러 개라 최고·최저·평균으로 요약한다"까지만 말한다.
- Data Table을 설비번호로 정렬할 때(시연 6) 바로 옆 공정명 열을 먼저 짚는다: "한 설비에 여러 공정 기록이 섞여 있다. 설비 4대가 여러 공정 기록을 함께 남긴 교육용 가상 기록이다. 실제 공장은 보통 설비마다 맡는 공정이 정해져 있다." 설비번호는 "어느 기계의 기록인지 구분하는 번호"로만 설명한다.
- 확인 2(`first["온도_C"]`)에서 "표의 열 이름 = 딕셔너리의 키"를 짚는다. 4차시 표로 가는 다리다. `_C` = 섭씨 도(1차시 규칙)를 한 번 상기한다.
- 7단계 문제 3은 빈칸이 없는 전이 문제다. 문제 2와 4단계 딕셔너리를 위에서 찾아 이름만 `eq04`로 바꾸면 된다고 안내하고, 변수 이름에 따옴표를 붙이는 조용한 오답을 미리 경고한다.
- 8단계 AI 코드의 `for`/`if`는 3차시 예고다. 안에 오늘 배운 `append()`·`len()`이 쓰였다는 점만 짚는다. 강의 페이지의 실행 결과는 접혀 있다(EQ-03 최저·최고가 들어 있어서).

## 학생들이 자주 찾아볼 질문과 보충 설명

- **파이썬 리스트 인덱스 0부터**: AI가 "메모리 주소에서 떨어진 거리(오프셋)" 같은 깊은 이야기로 넘어갈 수 있다. 오늘은 "맨 앞에서 몇 칸 떨어졌나 → 첫 칸은 0" 수준이면 충분하다고 말해 준다.
- **파이썬 리스트와 딕셔너리 차이**: AI가 튜플·집합(set)이나 "딕셔너리는 순서가 없다" 같은 이야기를 덧붙일 수 있다. 오늘은 리스트와 딕셔너리 둘만 다룬다. 지금 쓰는 파이썬에서는 딕셔너리도 넣은 순서대로 출력된다는 점만 보충한다.
- **반도체 로트 뜻**: AI가 "한 로트 = 웨이퍼 25장"처럼 숫자를 단정할 수 있다. 많이 쓰이는 묶음 크기이지만 공장·제품마다 다를 수 있다고 보충한다. AI가 고른 피자 비유가 1차시(로트 = 같은 오븐에 함께 들어간 판들)와 달라도 "함께 이동·작업하는 웨이퍼 묶음, 묶음 번호로 추적한다"는 핵심이 같으면 맞다. "한꺼번에 옮기고 같은 순서로 처리하기 편하다"는 답도 맞는 내용이다.
- **지하철 데이터가 실제와 다르다는 질문**: 중앙역·출근의 승차가 매우 많고 하차가 적은 것은 실제 도심역 패턴과 다를 수 있다. 가상 도시의 가상 데이터라 "주거지와 환승 노선이 몰린 역으로 설정했다"고 답한다.

## 예상 오개념

- 첫 칸이 1번 → 0번이다. 칸이 7개면 마지막은 `[6]` 또는 `[-1]`이다.
- `len()`이 마지막 칸 번호를 준다 → 개수(7)를 준다. 마지막 칸 번호는 개수 − 1(6)이다.
- 딕셔너리에서 값을 꺼낼 때도 중괄호를 쓴다 → 만들 때 `{ }`, 꺼낼 때 `[ ]`.
- 변수 이름도 따옴표로 감싼다 → 이름표(키)만 따옴표, 변수 이름은 따옴표 없이.
- 설비번호가 같으면 같은 작업의 기록이다 → 오늘 표는 한 설비 아래 여러 공정 기록이 섞여 있다(교육용 가상 기록). 공정명 열도 함께 본다.
- Feature Statistics의 Mode가 최고·최저 → Mode는 가장 흔한 값이다. 오늘은 Max.·Min. 칸을 읽는다.
- 파이썬 최고(EQ-03 308.5)와 Orange 최고(317.9)가 다르면 어느 한쪽이 틀렸다 → 담은 범위가 다르다(EQ-03 7건 vs 표 전체 20건).
- 불합격 기록이 평균보다 뜨거우니 온도 때문에 불합격이다 → 같은 설비의 더 뜨거운 기록(317.9, 316.6)은 합격이다. 한 건으로 이유를 말할 수 없다.

## 실습 중 오류 대응

- `IndexError: list index out of range`: 없는 칸 번호를 썼다(칸 7개에 `[7]`). 마지막은 `[-1]`.
- `KeyError: '혈액형'`: 없는 키를 썼다. 오타·띄어쓰기를 확인하고 `print(딕셔너리)`로 키를 본다.
- `NameError: name '평균' is not defined`: 키에 따옴표를 빼먹었다(`report[평균]` → `report["평균"]`).
- `NameError: name 'report' is not defined`: 문제 3 첫째 셀이 실패(또는 미실행)한 채 둘째 셀을 실행했다. 첫째 셀부터 고쳐 실행한다.
- `SyntaxError: invalid syntax`: 딕셔너리를 대괄호로 만들었다(`student = ["이름": "지민"]`). 중괄호로 바꾼다.
- `TypeError: 'list' object is not callable`: 인덱스에 소괄호를 썼다(`eq03_temps(0)` → `eq03_temps[0]`).
- `NameError: name '____' is not defined`: 빈칸을 안 채우고 실행했다. `____`는 빈칸 표시일 뿐이고 밑줄 개수와 상관없이 필요한 만큼 쓴다.
- append 결과가 5개: 2단계 append 셀을 두 번 실행했다. 위 셀 `cart = [...]`부터 다시 실행한다.
- Orange File 위젯에 빨간 글씨: 키트 폴더 구조가 바뀌었거나 `.ows`를 키트 밖으로 옮겼다. 키트를 다시 풀고 `_start.ows`를 다시 연다.
