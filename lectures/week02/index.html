오늘의 질문: "여러 개의 측정값을 한 번에 담고, 각 값에 이름표까지 붙이려면 어떻게 해야 할까?"

List of Dict
  • 여러 측정값을 리스트에 담고, 칸 번호(인덱스)로 값을 하나 또는 여러 개 꺼낼 수 있다.
  • max()·min()·sum()·len()으로 최고·최저·평균을 구하고, 평균만 볼 때 놓치는 "튀는 값"을 말할 수 있다.
  • 딕셔너리로 설비 한 대의 기록에 이름표(키)를 붙이고, 키로 값을 꺼내고 바꿀 수 있다.
  • "딕셔너리의 리스트"가 표(행과 열)와 같은 모양이라는 것을 설명하고, 원하는 칸의 값을 꺼낼 수 있다.

왜 이걸 배워야 할까?

  • 공장의 온도 센서는 하루에도 여러 번 온도를 잰다. 값이 하나가 아니라 여러 개다.
  • 1차시에 배운 변수는 상자 하나에 값 하나다. 값이 100개면 변수 100개를 만들어야 할까? 그래서 오늘은 여러 값을 한 줄로 묶어 담는 법(리스트)을 배운다.
  • 그리고 "301.2"라는 숫자만 있으면 어느 설비의 무슨 값인지 알 수 없다. 값마다 이름표를 붙이는 법(딕셔너리)도 배운다.
예를 들면 어떤 설비의 온도를 하루 동안 여섯 번 쟀다. 여섯 값의 평균은 301.2도로 학습용 정상 범위(295~305도) 안이다. "오늘 온도는 정상"이라고 보고하면 될까? 여섯 값을 하나씩 늘어놓고 보면 그중 한 번은 312.6도까지 올라갔다. 여러 값을 한 번에 담아 두어야 평균·최고·최저를 함께 보고, 이런 "튀는 값"을 놓치지 않는다.

지난 시간 복습

1차시 연결
  • 변수 = 이름표가 붙은 상자 하나. pass_count = 32처럼 상자 하나에 값 하나를 넣었다.
  • f-string으로 값을 문장에 넣었다. f"합격은 {pass_count}건", 소수 첫째 자리까지는 {값:.1f}.
  • 공정 데이터는 표다. 한 행 = 작업 1건의 기록, 한 열 = 기록 항목(설비번호, 온도 등). 합격여부는 1 = 합격, -1 = 불합격.
  • 불합격 8건을 공정명과 함께 보니 세정에 몰려 있었다. 숫자 하나보다 여러 값을 함께 볼 때 질문이 생긴다.

STEP 01

리스트 — 번호 붙은 칸에 여러 값 담기

오늘 다룰 값은 공장에서 무엇일까

  • 설비 안에는 온도를 재는 센서(1차시의 "체온계")가 있다. 센서는 하루에도 여러 번 온도를 기록한다.
  • 오늘 처음 다룰 값은 한 설비의 온도 센서가 하루 동안 다섯 번 잰 온도다(교육용 가상 값). 295.4, 298.1, 312.6, 301.0, 296.8
  • 이 과정에서는 295~305도를 학습용 정상 범위로 정해 두고 쓴다. 실제 공정의 기준이 아니다.

리스트란 무엇인가

  • 여러 값을 순서대로 한 줄로 담는 상자 묶음이 리스트(List)다.
  • 만드는 법: 대괄호 [ ] 안에 값을 콤마(,)로 나열한다.
비유 — 번호 붙은 약통 칸마다 번호가 붙은 약통(또는 서랍장)을 떠올리자. 칸 하나에 값 하나가 들어가고, 칸은 순서대로 붙어 있다. "몇 번 칸"이라고 말하면 그 칸의 값을 꺼낼 수 있다. 변수 다섯 개(temp1~temp5)를 따로 만드는 대신, 약통 하나에 다섯 칸을 쓰는 것이다.

먼저 과일 이름 세 개로 모양을 보자.

Python — 가장 단순한 리스트
fruits = ["사과", "바나나", "포도"]
print(fruits)
실행 결과 
['사과', '바나나', '포도']

숫자도 같은 방법으로 담는다. 오늘의 온도 다섯 개를 리스트로 만들자.

Python — 온도 리스트 만들기
temperatures = [295.4, 298.1, 312.6, 301.0, 296.8]
print(temperatures)
실행 결과 
[295.4, 298.1, 312.6, 301.0, 296.8]

칸 아래 숫자가 칸 번호(인덱스)다. 첫 번째 칸의 번호는 1이 아니라 0이다. 보라색 2번 칸(세 번째 값 312.6)이 오늘 계속 등장하는 "튀는 값"이다.

인덱스 — 칸 번호로 값 하나 꺼내기

  • 리스트 이름 뒤에 [번호]를 붙이면 그 칸의 값을 꺼낸다. 이 번호를 인덱스(Index)라고 한다.
  • 번호는 0부터 센다. 번호 = "맨 앞 칸에서 몇 칸 떨어져 있나"라고 생각하면 된다. 첫 칸은 맨 앞에서 0칸 떨어져 있으니 0번, 세 번째 칸은 2칸 떨어져 있으니 2번이다. 자의 눈금이 1이 아니라 0에서 시작하는 것과 같다.
  • -1은 "뒤에서 첫 번째", 즉 마지막 칸이다. 값이 몇 개인지 몰라도 마지막 값을 꺼낼 수 있다.
Python — 인덱스로 꺼내기
print(temperatures[0])    # 첫 번째 값
print(temperatures[2])    # 세 번째 값
print(temperatures[-1])   # 마지막 값
실행 결과 
295.4
312.6
296.8
가장 흔한 실수 — "1번이 첫 번째"라고 생각하기
  • temperatures[1]은 첫 번째가 아니라 두 번째 값(298.1)이다.
  • 칸이 5개면 번호는 0~4번이다. 5번 칸은 없으므로 temperatures[5]는 IndexError가 난다.
Python — 직접 확인하기
print(temperatures[1])    # 두 번째 값(첫 번째가 아니다!)
# print(temperatures[5])  # 칸은 0~4번뿐 → IndexError
실행 결과 
298.1

두 번째 줄 맨 앞의 #을 지우고 실행하면 IndexError: list index out of range("칸 번호가 범위를 벗어났다")가 난다. 확인한 뒤에는 #을 다시 붙여 둔다.

AI에게 물어보기 — 복사해서 AI 챗봇에 붙여넣기
파이썬 리스트 번호가 왜 1이 아니라 0부터 시작하는지, 자의 눈금 같은 일상 비유로 3줄 이내로 설명해줘.

이렇게 확인해보자: AI의 설명대로라면 temperatures[1]이 두 번째 값(298.1)이 되는지 맞춰보자.

슬라이싱 — 여러 칸을 한 번에 꺼내기

  • 리스트[시작:끝]처럼 콜론(:)을 쓰면 여러 칸을 한 번에 잘라낸다. 이것을 슬라이싱(Slicing)이라고 한다.
  • 규칙은 하나다. 시작 번호 칸은 들어가고, 끝 번호 칸은 들어가지 않는다. [1:3]은 "1번 칸부터 3번 칸 앞까지", 즉 1번·2번 칸이다.
  • 꺼내지는 개수는 끝 - 시작이다. [1:3]이면 3 - 1 = 2개.
  • 시작을 비우면 "처음부터", 끝을 비우면 "마지막까지"다.

점선 두 개 사이만 잘려 나온다. 1번 칸 앞에서 자르고, 3번 칸 앞에서 자른다. 그래서 3번 칸(301.0)은 빠진다.

Python — 슬라이싱
print(temperatures[1:3])   # 1번 칸부터 3번 칸 앞까지
print(temperatures[:2])    # 처음부터 2번 칸 앞까지
print(temperatures[2:])    # 2번 칸부터 끝까지
실행 결과 
[298.1, 312.6]
[295.4, 298.1]
[312.6, 301.0, 296.8]
  • 값 하나를 꺼내면([2]) 숫자가 나오지만, 슬라이싱으로 꺼내면 결과도 리스트라서 대괄호로 감싸여 나온다.
직접 해보기 temperatures[-2:]를 실행해 보자. "뒤에서 두 번째 칸부터 끝까지"라는 뜻이다. 결과가 [301.0, 296.8]인지 확인하자. (노트북 3단계 "직접 해보기" 셀)

개수 세기와 값 추가하기 — len(), append()

  • len(리스트) — 칸이 몇 개인지 센다(length, 길이).
  • 리스트.append(값) — 리스트 맨 끝에 칸을 하나 붙이고 값을 넣는다. 오후에 한 번 더 쟀더니 303.2도였다고 하자.
Python — 개수 세기와 추가
print(len(temperatures))

temperatures.append(303.2)
print(temperatures)
print(len(temperatures))
실행 결과 
5
[295.4, 298.1, 312.6, 301.0, 296.8, 303.2]
6
주의 — append 셀은 한 번만 실행
  • 노트북에서 이 셀을 두 번 실행하면 303.2가 두 번 붙는다. 마지막 줄이 7이 나오면 맨 위부터 다시 실행한다.
  • temperatures = temperatures.append(303.2)처럼 다시 저장하지 않는다. append()는 리스트를 그 자리에서 바꿀 뿐 돌려주는 값이 없어서, temperatures가 빈 값(None)이 되어 버린다.

빈 리스트 []에서 시작해 하나씩 채울 수도 있다. 3차시에서 자주 쓰는 모양이다.

Python — 빈 리스트에서 시작하기
new_temps = []
new_temps.append(299.5)
new_temps.append(300.2)
print(new_temps)
실행 결과 
[299.5, 300.2]

최고·최저·평균 구하기 — max(), min(), sum()

  • max() 가장 큰 값, min() 가장 작은 값, sum() 모두 더한 값.
  • 평균 = 합계 ÷ 개수 = sum(리스트) / len(리스트)
  • 지금 temperatures에는 303.2를 추가한 값 6개가 들어 있다.
Python — 최고·최저·평균
print(max(temperatures))
print(min(temperatures))
print(sum(temperatures))

average = sum(temperatures) / len(temperatures)
print(f"평균 온도는 {average:.1f}도입니다.")
실행 결과 
312.6
295.4
1807.1
평균 온도는 301.2도입니다.
직접 해보기 하루 동안 온도가 얼마나 오르내렸는지(온도 범위 = 최고 - 최저) 구해 보자. temp_range = max(temperatures) - min(temperatures)로 계산하고 print(f"온도 범위는 {temp_range:.1f}도입니다.")로 출력한다. 결과는 온도 범위는 17.2도입니다.다. (노트북 5단계 "직접 해보기" 셀)

왜 여러 값을 함께 봐야 할까 — 평균에 숨는 "튀는 값"

방금 구한 값을 학습용 정상 범위(295~305도)와 나란히 놓아 보자.

무엇을 봤나값정상 범위 안?
첫 번째 측정값 하나 ([0])295.4도안
평균301.2도안
최저 (min)295.4도안
최고 (max)312.6도 (2번 칸)밖 — 7.6도 넘음
  • 값 하나만 보거나 평균만 보면 "오늘 온도 정상"이라고 말하게 된다.
  • 최고값을 함께 보면 세 번째 측정(2번 칸)에서 312.6도까지 올라간 순간이 보인다. 평균은 튀는 값 하나를 나머지 정상 값들 사이에 섞어 버려서, 숫자 하나로는 드러나지 않는다.
  • 1차시에는 여러 열(공정명과 합격여부)을 함께 봤다. 오늘은 한 열 안의 여러 값을 함께 본다. 둘 다 "숫자 하나만 보지 않는다"는 같은 생각이다.
비유 — 하루 체온 기록 아침·점심·저녁에 잰 체온의 평균이 36.8도라도, 오후에 한 번 38.5도까지 올랐다면 의사는 그 한 번을 눈여겨본다. 평균, 최고, 최저를 함께 봐야 "언제 무슨 일이 있었나"라는 질문이 생긴다.
튀는 값 = 불량일까? 아직 알 수 없다. 312.6도는 "더 살펴볼 기록"이라는 단서다. 그 시점의 검사 결과(합격여부)나 다른 기록과 함께 봐야 한다. 오늘 종합 실습에서도 정상 범위를 벗어났는데 합격(1)인 기록을 만난다.
STEP 02

딕셔너리 — 이름표로 찾는 사물함

리스트만으로는 불편한 순간

  • 설비 한 대의 기록에는 설비번호, 공정명, 온도처럼 뜻이 서로 다른 값이 들어 있다.
  • 리스트로 ["EQ-01", "식각", 301.2]처럼 담으면 "2번 칸이 온도였지?"를 사람이 외워야 한다. 칸이 10개, 20개로 늘면 헷갈린다.
  • 이럴 때 칸 번호 대신 이름표로 값을 찾는 딕셔너리(Dictionary)를 쓴다.
비유 — 이름표 붙은 사물함, 국어사전
  • 사물함 문마다 "설비번호", "공정명", "온도_섭씨"라는 이름표가 붙어 있다. 몇 번째 칸인지 몰라도 이름표만 보면 연다.
  • 국어사전에서 단어(이름표)를 찾으면 뜻(내용)이 나오는 것과 같다. 그래서 이름도 Dictionary(사전)다.
  • 이름표를 키(key), 그 안의 내용을 값(value)이라고 한다.
리스트딕셔너리
괄호대괄호 [ ]중괄호 { }
값을 찾는 법칸 번호(0, 1, 2 …)이름표(키)
비유번호 붙은 약통이름표 붙은 사물함
어울리는 값같은 종류 여러 개(하루 온도 여러 번)뜻이 다른 값 묶음(설비 한 대의 기록)

딕셔너리 만들기

  • 중괄호 { } 안에 키: 값을 콤마로 나열한다.
  • 글자 값은 따옴표로 감싸고("식각"), 숫자 값은 따옴표 없이 쓴다(301.2). 1차시 자료형 규칙과 같다.

먼저 사람 한 명의 정보로 모양을 보자.

Python — 가장 단순한 딕셔너리
person = {"이름": "지민", "나이": 15}
print(person)
print(person["이름"])
실행 결과 
{'이름': '지민', '나이': 15}
지민

같은 방법으로 설비 한 대의 기록을 담는다. 키 이름은 1차시 표의 열 이름(설비번호, 공정명, 온도_섭씨)을 그대로 썼다. 키-값 쌍을 한 줄에 하나씩 적으면 읽기 쉽다.

Python — 설비 한 대를 딕셔너리로
equipment = {
    "설비번호": "EQ-01",
    "공정명": "식각",
    "온도_섭씨": 301.2,
}
print(equipment)
실행 결과 
{'설비번호': 'EQ-01', '공정명': '식각', '온도_섭씨': 301.2}

왼쪽 보라색 칸이 이름표(키), 오른쪽이 내용(값)이다. 순서를 몰라도 이름표로 바로 찾는다.

키로 값 꺼내기

  • 딕셔너리[키] — 리스트의 칸 번호 자리에 이름표를 넣는다. 키는 글자라서 따옴표까지 쓴다.
Python — 키로 꺼내기
print(equipment["설비번호"])
print(equipment["온도_섭씨"])
# print(equipment["압력_Pa"])   # 없는 이름표 → KeyError
실행 결과 
EQ-01
301.2
없는 이름표를 쓰면 KeyError 마지막 줄의 #을 지우고 실행하면 KeyError: '압력_Pa'가 난다. 이 사물함에 "압력_Pa"라는 이름표가 없기 때문이다. 오타(띄어쓰기, 밑줄 빠뜨림)도 같은 오류가 난다. print(equipment)로 이름표를 먼저 확인하자.

값 바꾸기와 키 추가하기

  • 딕셔너리[키] = 값 — 이미 있는 키면 값이 바뀌고, 없던 키면 이름표가 새로 생긴다.
  • 온도를 다시 재 보니 305.5도였고, 검사 결과(합격)가 나와서 합격여부 이름표를 하나 더 붙인다고 하자. 합격여부는 1차시와 같은 규칙이다: 1 = 합격, -1 = 불합격.
Python — 값 바꾸기, 키 추가하기
equipment["온도_섭씨"] = 305.5   # 있던 키 → 값 바꾸기
equipment["합격여부"] = 1        # 없던 키 → 새로 추가(1 = 합격)
print(equipment)
실행 결과 
{'설비번호': 'EQ-01', '공정명': '식각', '온도_섭씨': 305.5, '합격여부': 1}
직접 해보기 딕셔너리 값을 f-string 문장에 넣어 보자. print(f"{equipment['설비번호']} 설비는 {equipment['공정명']} 공정, 온도는 {equipment['온도_섭씨']}도입니다.") 결과는 EQ-01 설비는 식각 공정, 온도는 305.5도입니다.다. (노트북 7단계 "직접 해보기" 셀)
따옴표 규칙 — 바깥은 큰따옴표, 안쪽 키는 작은따옴표 f-string 바깥을 큰따옴표(")로 감쌌다면 안쪽 키는 작은따옴표('공정명')로 쓴다. 같은 따옴표를 겹치면 파이썬이 문장이 어디서 끝나는지 헷갈려, 파이썬 3.11 이하에서는 SyntaxError: f-string: unmatched '['가 난다.
STEP 03

딕셔너리의 리스트 — 표의 한 행 = 딕셔너리 하나

  • 딕셔너리 하나 = 설비 한 대의 기록이다. 설비가 세 대라면? 딕셔너리 세 개를 리스트 하나에 담는다. 이것을 딕셔너리의 리스트라고 부른다.
  • 1차시에 본 표를 떠올리자. 한 행 = 기록 1건, 한 열 = 기록 항목이었다. 딕셔너리의 리스트는 바로 그 표 모양이다.
  • 아래 설비 3대의 설비번호·공정명·온도는 설명용으로 만든 값이다. 오늘 데이터 파일 속 짝(예: EQ-02 식각)과는 다르다.
리스트 칸 번호설비번호공정명온도_섭씨
[0]EQ-01식각301.2
[1]EQ-02증착308.7
[2]EQ-03포토297.5
표와 코드가 이렇게 짝지어진다
  • 표의 가로 한 줄(행) = 딕셔너리 하나 = 설비 한 대의 기록
  • 표 맨 윗줄의 열 이름 = 딕셔너리의 키(이름표)
  • 표 전체 = 딕셔너리들을 담은 리스트, 리스트의 칸 번호가 곧 행 번호
Python — 설비 3대를 딕셔너리의 리스트로
equipment_list = [
    {"설비번호": "EQ-01", "공정명": "식각", "온도_섭씨": 301.2},
    {"설비번호": "EQ-02", "공정명": "증착", "온도_섭씨": 308.7},
    {"설비번호": "EQ-03", "공정명": "포토", "온도_섭씨": 297.5},
]
print(len(equipment_list))
print(equipment_list[0])
실행 결과 
3
{'설비번호': 'EQ-01', '공정명': '식각', '온도_섭씨': 301.2}
  • len()은 행(설비)이 몇 개인지 센다. [0]으로 꺼내면 행 하나, 즉 딕셔너리 하나가 통째로 나온다.

표의 한 칸 꺼내기 — [행 번호] 다음 [열 이름]

  • 표에서 칸 하나를 찾을 때처럼, 몇 번째 행을 먼저 고르고 무슨 열을 다음에 고른다.
  • equipment_list[1]["온도_섭씨"] = 1번 행(두 번째 설비)으로 가서 → 온도_섭씨 칸 → 308.7
  • 극장 좌석을 "몇 번째 줄, 무슨 자리"로 찾는 것과 같다. 순서를 바꿔 equipment_list["온도_섭씨"][1]로 쓰면 리스트에 이름표를 넣은 셈이라 TypeError가 난다.
Python — 원하는 칸 꺼내기
print(equipment_list[0]["온도_섭씨"])   # 0번 행의 온도_섭씨 칸
print(equipment_list[1]["설비번호"])    # 1번 행의 설비번호 칸
실행 결과 
301.2
EQ-02
직접 해보기 equipment_list[2]["공정명"]을 출력해 세 번째 설비의 공정명을 확인하자. 위 표에서 답(포토)을 먼저 찾고 실행해 비교한다. (노트북 8단계 "직접 해보기" 셀)
4차시 미리보기 4차시에는 Pandas라는 도구로 CSV 파일을 열어 표로 다룬다. 그 표의 한 행도 오늘처럼 "이름표가 붙은 값 묶음"이다. 오늘 손으로 만든 딕셔너리의 리스트가 그 표를 이해하는 기초가 된다.

리스트

List
한 줄 설명

Slicing

가상 값이라는 점 기억하기 온도_섭씨는 공정 종류와 관계없이 약 300도 근처로 만든 교육용 숫자다. 실제 공장에서는 작업마다 온도가 크게 다르다. 이 과정에서는 온도의 크기를 실제 공정 조건으로 해석하지 않고, 기록끼리 비교하는 연습용 숫자로만 쓴다. 맨 위 예제의 하루 온도 다섯 개(295.4 …)와 equipment_list의 설비 3대도 설명을 위해 만든 값이다. 또 이 파일은 설비와 공정이 무작위로 짝지어져 있다(예: EQ-04 한 대가 포토·식각·산화·증착 기록에 모두 나온다). 1차시에 배운 대로 실제 공장에서는 설비마다 맡는 공정이 정해져 있다.

주의할 점 & 자주 발생하는 오류

오류 1 — 없는 칸 번호
  • IndexError: list index out of range
  • 원인: 칸이 5개(0~4번)인 리스트에서 temperatures[5]처럼 없는 번호를 썼다. 번호가 0부터라는 것을 잊은 경우가 많다.
  • 해결: len()으로 칸 수를 확인한다. 마지막 칸 번호는 "칸 수 - 1"이다.
오류 2 — 없는 이름표
  • KeyError: '압력_Pa' 또는 KeyError: 0
  • 원인: 딕셔너리에 없는 키를 썼거나 오타가 있다. 딕셔너리에 리스트처럼 [0]을 쓴 경우도 같다.
  • 해결: print(equipment)로 이름표를 확인하고 글자 그대로 쓴다.
오류 3 — f-string 안에서 따옴표 겹침
  • SyntaxError: f-string: unmatched '['
  • 원인: f"{equipment["공정명"]}"처럼 바깥과 안쪽에 같은 큰따옴표를 썼다.
  • 해결: 안쪽 키는 작은따옴표로 쓴다. f"{equipment['공정명']}"
오류 4 — 꺼내는 순서를 바꿈
  • TypeError: list indices must be integers or slices, not str
  • 원인: equipment_list["온도_섭씨"][1]처럼 리스트에 이름표부터 넣었다. 리스트는 숫자 번호만 받는다.
  • 해결: equipment_list[1]["온도_섭씨"] — 행 번호 먼저, 키 다음.
주의 — 대괄호와 중괄호 만들 때: 리스트는 [ ], 딕셔너리는 { }. 꺼낼 때는 둘 다 대괄호 [ ]를 쓴다 (temperatures[0], equipment["설비번호"]). "만들 때만 괄호 모양이 다르다"로 기억하자.

결과 정리 & 퀴즈

더 많은 문제는 실습지에 있다.

Q1. (객관식) temperatures = [295.4, 298.1, 312.6, 301.0, 296.8]일 때 temperatures[1]의 값은?
  • A. 295.4
  • B. 298.1
  • C. 312.6
  • D. 오류가 난다
정답: B. 번호는 0부터 센다. [0]이 295.4, [1]이 두 번째 값 298.1이다.
Q2. (참/거짓) temperatures[1:3]에는 1번, 2번, 3번 칸의 값이 모두 들어 있다.
정답: 거짓. 끝 번호 칸(3번)은 빠진다. 1번·2번 칸만 들어 있어 [298.1, 312.6]이다.
Q3. (빈칸) equipment = {"설비번호": "EQ-01", "공정명": "식각"}에서 식각을 꺼내려면? print(equipment[______])
정답: "공정명". 딕셔너리는 이름표(키)로 꺼낸다. 키는 글자라 따옴표까지 쓴다.
Q4. (객관식) 리스트와 딕셔너리의 차이로 가장 알맞은 것은?
  • A. 리스트는 칸 번호로, 딕셔너리는 이름표(키)로 값을 찾는다
  • B. 리스트는 숫자만, 딕셔너리는 글자만 담을 수 있다
  • C. 딕셔너리는 값을 하나만 담을 수 있다
  • D. 둘은 완전히 같다
정답: A. 리스트 = 번호 붙은 약통, 딕셔너리 = 이름표 붙은 사물함.
Q5. (결과 예측) 강의의 equipment_list에서 equipment_list[1]["온도_섭씨"]의 값은?
정답: 308.7. 1번 행(두 번째 설비 EQ-02)으로 가서 온도_섭씨 칸을 읽는다.
Q6. (서술) 하루 온도 6건의 평균이 301.2도였다. 이 숫자만 보고 "오늘 온도는 정상"이라고 보고하면 무엇을 놓칠까?
예시 답안: "평균 301.2도는 학습용 정상 범위(295~305도) 안이지만, 최고값을 함께 보면 세 번째 측정(2번 칸)에서 312.6도까지 올라가 범위를 벗어났다. 평균만 보면 이 튀는 값을 놓친다."

AI로 한 걸음 더 — 질문하고 코드 받아보기

1차시에 이어서 모르는 내용은 AI 챗봇에게 물어보자. AI의 답도 틀릴 수 있으니 강의 내용과 비교하고, 코드는 직접 실행해서 확인한다. 회사의 실제 데이터나 개인정보는 붙여넣지 않는다.
질문해보기 — 하나 이상 골라서 (노트북 10단계)
  • "파이썬 리스트와 딕셔너리를 약통과 사물함에 비유해서 차이를 설명해줘."
  • "딕셔너리 여러 개를 리스트에 담은 것이 엑셀 표와 어떻게 닮았는지 예를 들어 설명해줘."
  • "파이썬 리스트 번호가 왜 1이 아니라 0부터 시작하는지, 자의 눈금 같은 일상 비유로 3줄 이내로 설명해줘."
코드 받아보기 (노트북 11단계) "온도 리스트 [295.4, 298.1, 312.6, 301.0, 296.8]의 최고값, 최저값, 평균을 계산해서 하나의 딕셔너리로 정리해 출력하는 파이썬 코드를 만들어줘. 리스트 이름은 temps로 해줘."
Python — AI가 만들어줄 수 있는 코드 예시
temps = [295.4, 298.1, 312.6, 301.0, 296.8]
report = {
    "최고": max(temps),
    "최저": min(temps),
    "평균": round(sum(temps) / len(temps), 1),
}
print(report)
실행 결과 
{'최고': 312.6, '최저': 295.4, '평균': 300.8}
AI 코드를 다룰 때 꼭 지킬 점
  • 딕셔너리의 값 자리에 계산 결과(max(temps))를 바로 넣을 수 있다는 점이 새롭다. 오늘 배운 것들의 조합이다.
  • round(값, 1)은 소수 첫째 자리까지 반올림하는 함수다. 처음 보는 함수가 나오면 "이건 무슨 뜻이야?"라고 AI에게 되물어 보자.
  • AI 코드가 temperatures처럼 앞에서 쓴 이름을 다시 만들면 내 리스트가 바뀐다. 그래서 이름을 temps로 해 달라고 했다.

연습문제 — EQ-02 설비 온도 요약하기

오늘 데이터 파일에서 EQ-02 설비의 기록 4건(가상 데이터)의 온도만 옮겨 왔다.

로트번호공정명온도_섭씨
LOT-0122식각302.5
LOT-0105증착299.8
LOT-0195증착298.8
LOT-0053세정305.6
직접 해보기 (노트북 12단계)
  • 네 온도를 리스트 eq02_temps에 담는다.
  • summary = {"설비번호": "EQ-02"}를 만들고, "최고온도", "최저온도" 키를 추가해 최고·최저값을 넣는다.
  • 평균 온도를 :.1f로 출력한다. 최고 온도가 정상 범위(295~305도) 안인지도 확인한다.
eq02_temps = [302.5, 299.8, 298.8, 305.6]
summary = {"설비번호": "EQ-02"}
summary["최고온도"] = max(eq02_temps)
summary["최저온도"] = min(eq02_temps)
print(summary)

eq02_avg = sum(eq02_temps) / len(eq02_temps)
print(f"EQ-02 평균 온도는 {eq02_avg:.1f}도입니다.")
실행 결과: {'설비번호': 'EQ-02', '최고온도': 305.6, '최저온도': 298.8}
EQ-02 평균 온도는 301.7도입니다.
해석: 평균 301.7도는 정상 범위 안이지만 최고 305.6도(LOT-0053, 세정)는 범위를 0.6도 넘었다.

AI로 재미있는 미니 프로그램 만들기 — 오늘의 럭키 설비 뽑기

오늘의 미니 프로젝트 (노트북 13단계) 오늘 배운 딕셔너리의 리스트로 재미있는 프로그램을 AI에게 만들어 달라고 해 보자. 코드를 다 이해하지 못해도 괜찮다. "AI에게 요청 → 실행 → 결과 확인"의 흐름을 한 번 더 경험하는 것이 목표다.
프롬프트 예시 — 그대로 물어보기 "설비 정보 딕셔너리 4개를 리스트에 담고, random.choice()로 하나를 무작위로 뽑아 '오늘의 럭키 설비'라는 제목과 함께 설비번호·공정명·온도를 출력하는 파이썬 코드를 만들어줘. 리스트 이름은 machines로 해줘."
Python — AI가 만들어줄 수 있는 코드 예시
import random
random.seed(7)  # 실행할 때마다 같은 결과가 나오도록 고정

machines = [
    {"설비번호": "EQ-01", "공정명": "식각", "온도_섭씨": 301.2},
    {"설비번호": "EQ-02", "공정명": "증착", "온도_섭씨": 308.7},
    {"설비번호": "EQ-03", "공정명": "포토", "온도_섭씨": 297.5},
    {"설비번호": "EQ-04", "공정명": "세정", "온도_섭씨": 299.9},
]

lucky = random.choice(machines)
print("*** 오늘의 럭키 설비 ***")
print(f"설비번호: {lucky['설비번호']}")
print(f"공정명: {lucky['공정명']}")
print(f"온도: {lucky['온도_섭씨']}도")
실행 결과(seed 7로 고정) 
*** 오늘의 럭키 설비 ***
설비번호: EQ-03
공정명: 포토
온도: 297.5도
더 놀아보기
  • random.seed(7) 줄을 지우고 여러 번 실행해 보자. 실행할 때마다 다른 설비가 뽑힌다.
  • "설비를 2개 더 추가해줘"라고 다시 요청해 뽑기 대상을 늘려 보자. 리스트에 딕셔너리가 늘어나는 모습을 볼 수 있다.
  • import와 random.choice()는 구경만 하자. "리스트에서 한 칸을 무작위로 골라 준다" 정도면 충분하다.
