# 4차시 강의 운영안 — Pandas 가장 기본적인 부분

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

3차시에는 `for`와 `if` 네 줄로 기록을 하나씩 꺼내 셌고, 1~3차시 Orange에서는 File로 표를 열고 Select Rows로 행을 골랐다.
오늘은 그 일을 Pandas로 한다. CSV 파일을 표로 읽고, 필요한 열만 고르고, 조건에 맞는 행만 한 줄로 남기고, 큰 값부터 줄 세운다.
공장 기록이 금방 수백, 수천 줄이 되는 이유도 오늘 Orange 공정 흐름표에서 확인한다 — ②~⑥ 공정을 층마다 되풀이하는 것도 큰 이유다.
오늘의 미션: "기록 100건짜리 CSV 파일을 받았다 — EQ-02에서 불합격이 몇 건인지 찾아 보고하자."
미션의 답(25건 중 5건, 20.0%)은 처음부터 말하지 않고, 실습지 문제 2(파이썬)와 문제 4(Orange)에서 학생이 직접 얻게 한다. 강의 본문은 같은 모양의 EQ-01(31건 중 2건)로 시연한다.

## 수업 흐름

PART 1 파이썬 → PART 2 Orange3 → PART 3 실습지 순서다. 노트북은 단계 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 넷째 날, 답은 묻기만 한다) → 지난 시간 복습 2문항(`pass_count` 3, Select Rows 조건 두 줄이면 같거나 줄어든다)
2. PART 1 시작: 학생용 노트북 "막혔을 때" 셀 읽기. "Orange에서 하던 일을 코드로" 표를 짚는다.
3. 노트북 1단계: 카페 주문 읽기(`read_csv`, `head()`) — 행 번호는 0부터
4. 노트북 2단계: `shape` (12, 7), `columns`(끝의 `dtype='str'` 설명)
5. 노트북 3단계: 열 하나 / 여러 열(대괄호 두 겹), `loc`은 구경 셀만 실행(4500)
6. 노트북 4~5단계: `cafe["종류"] == "커피"`의 True/False → 커피 (5, 7) → 5000원 초과 5건(학생용은 비교 기호 `>`가 빈칸) → 그중 "별로예요" 3건
7. 노트북 6단계: `sort_values("가격_KRW", ascending=False).head(5)`
8. **여기서 쉬기**
9. 노트북 7단계 "반도체 데이터로 확인하기": 정답 노트북으로 시연(학생용은 `print(df.shape)`의 `shape`가 빈칸) — (100, 8), 열 8개, EQ-01 31건 중 불합격 2건, 전체 불합격률 13.0%. "한 행 = 작업 한 번의 기록"(반도체 이해 포인트 2)을 짚는다. 설비 4대가 여러 공정 기록을 함께 남긴 교육용 가상 기록이라는 점도 말한다.
10. PART 2 Orange: Orange 말 사전 → 위젯 이름표(Select Columns·Select Rows = Transform 묶음) → Select Columns 창 읽는 법 → 공정 지도 그림과 위치 두 줄 → 워밍업 `week04_1_flow_start.ows`(학생이 직접, 8행 → 5행, "남은 단계 확인 보기"는 학생이 센 뒤 연다) → 반도체 `week04_2_filtering_start.ows`(EQ-01 → 31행 → 불합격 2행) → 파이썬 결과와 비교 한 문장
11. **여기서 쉬기**(필요하면)
12. PART 3 실습지: 문제 1~2(노트북 8단계 빈칸) → 문제 3(빈칸 없이 직접 쓰는 전이 문제) → 문제 4(Orange — PART 2 캔버스에서 설비번호 조건 값만 EQ-02로) → 문제 5(해석 + "이 숫자만으로 고장이라 말할 수 있나" 판단) → 정답 확인과 문장 발표
13. 결과 정리·반도체 이해 포인트 → 핵심 질문의 "미션 결과 보기"는 실습지 뒤에 연다 → AI로 한 걸음 더(노트북 9단계) → 과제·5차시 예고

## 강사 설명 포인트

- 개념은 카페 주문으로만 설명하고, 공정 기록은 7단계에서 "파일 이름·표 이름·열 이름만 바뀐다"를 보여 준다. 실습지 힌트가 강의의 어느 예제와 같은 모양인지 짚어 준다.
- 강의 PART 1 첫머리의 "Orange에서 하던 일을 코드로" 표로 시작한다. File = `read_csv`, Data Table = `head()`, Select Rows = 조건 검색, 열 머리글 정렬 = `sort_values`.
- 대괄호 두 겹은 "안쪽은 2차시에 배운 리스트, 바깥은 표에서 꺼내기"로 설명한다.
- 조건 검색은 두 단계로 보여 준다. 먼저 `check = cafe["종류"] == "커피"`의 True/False 목록을 보이고, 그것을 `cafe[ ]`에 넣으면 True인 행만 남는다(체로 거르기). 3차시 `for`+`if` 네 줄과 나란히 놓는다.
- `loc`은 노출 전용이다. 3단계 (구경) 셀만 실행하고 실습·퀴즈·과제에는 쓰지 않는다.
- 불합격률 = 불합격 건수 ÷ **그 설비의** 기록 수 × 100. 건수만으로 비교하면 기록이 많은 설비가 나빠 보일 수 있다(과제 1: EQ-02와 EQ-04는 불합격 5건으로 같지만 분모가 다르다).
- 공정 흐름표 워밍업의 핵심은 "②~⑥이 층마다 되풀이된다 → 같은 공정 기록이 수없이 쌓인다"이다. 오늘 공정 기록의 `공정명`은 흐름표 ②~⑤에 해당하고, 세정은 흐름표에 행이 없는 "단계 사이 씻기"다.
- 4차시는 원인 이야기를 하지 않는다. EQ-02 20.0%는 "더 살펴볼 후보"까지만 말한다(비율 1위는 EQ-04 22건 중 5건 — 과제 1에서 드러난다). 25건 중 5건이라 한 건만 달라도 비율이 4%p씩 바뀐다(문제 5 판단).
- 온도·압력 등은 교육용 값이라 크기를 해석하지 않는다.

## Orange 시연 체크리스트

- [ ] 키트를 압축 푼 폴더 그대로에서 `orange3/week04/week04_1_flow_start.ows`를 연다. File 위젯을 더블클릭해 8행이 들어왔는지 확인한다. 빨간 파일 이름이 보이면 키트 폴더 구조가 바뀐 것이다 — 키트를 다시 풀게 한다.
- [ ] Select Columns는 **Transform** 묶음에 있다. File에 잇고 더블클릭 → 왼쪽 Ignored / 오른쪽 Features·Target·Metas 상자를 보여 준다. 열을 눌러 고르고 가운데 `<` 버튼(또는 끌어다 놓기)으로 Ignored에 보낸다. 되돌리기는 Reset.
- [ ] 워밍업: Features의 구분·측정단위, Metas의 주요설비·대표측정값을 Ignored로 → Select Rows(Select Columns에 잇는다) `반복여부 is 여러 번` → Data Table, `공정순서` 열 머리글 클릭 → 5행.
- [ ] `week04_2_filtering_start.ows`(100행) → Select Columns: Features의 공정명·압력_Pa·가스유량_slm, Metas의 측정시간·로트번호를 Ignored로. **합격여부는 Target에 둔다**고 말로 경고한다.
- [ ] Select Rows `설비번호 is EQ-01` → Data Table Info 31행 → Add Condition `합격여부 is -1` → 2행, `온도_C` 열 머리글로 큰 값부터(303.0 · 301.2). 범주 열 값은 목록에서 고른다(직접 타이핑 아님).
- [ ] Data Table 뒤에 위젯을 잇지 않는다(출력은 선택 행뿐).
- [ ] EQ-02는 시연하지 않는다 — 실습지 문제 4다. 학생은 PART 2 캔버스를 닫지 말고 문제 4에서 설비번호 조건 값만 EQ-02로 바꾼다. `week04_2_filtering_done.ows`는 EQ-02 설정이 저장돼 있어 미션 답이 바로 보이므로 학생에게 안내하지 않는다 — 늦은 학생은 강의 PART 2 반도체 단계 1~4를 다시 따라 하게 한다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **CSV 파일이란**: AI가 "엑셀 파일의 한 종류"라고 설명하기도 한다. CSV는 쉼표로 칸을 나눈 글자 파일이고, 엑셀은 그것을 열 수 있는 프로그램 중 하나라고 보충한다. 엑셀로 열고 저장하면 인코딩이 바뀌어 한글이 깨질 수 있으니 키트 CSV는 엑셀에서 저장하지 않게 한다.
- **pandas 조건 검색**: AI가 `&`, `|`, `query()`, `loc` 같은 다른 방법을 함께 늘어놓을 수 있다. 오늘은 `df[df["열"] == 값]`과 "골라낸 표에서 한 번 더 고르기"만 쓴다고 짚는다.
- **불량률 분모**: AI가 수율·불량률 정의를 공장 실무 용어로 길게 설명할 수 있다. 오늘은 "그 설비의 기록 수로 나눈다"까지만 확인한다.
- **8대 공정 반복 이유**: AI가 되풀이 횟수를 "수십 번", "수백 번"처럼 단정하기도 한다. 칩 종류와 층 수에 따라 다르다고 보충하고, 숫자는 외우지 않게 한다. 이온주입을 증착과 따로 세는 자료도 있다 — 이 과정은 공정 지도 ①~⑧ 번호를 쓴다.

## 예상 오개념

- `shape()`처럼 괄호를 붙인다 → `shape`는 괄호 없이 쓴다(`TypeError: 'tuple' object is not callable`).
- 여러 열을 대괄호 한 겹으로 고른다 → 리스트로 감싼 두 겹이다.
- `df["설비번호"] == "EQ-02"`만으로 행이 골라진다 → True/False 목록일 뿐이다. 바깥 `df[ ]`에 넣어야 한다.
- `=`와 `==`를 헷갈린다 → 조건은 "같은가?"(`==`)다.
- `sort_values`는 기본이 큰 값부터다 → 기본은 작은 값부터, 큰 값부터는 `ascending=False`.
- 불합격 건수가 같으면 불합격률도 같다 → 분모(그 설비의 기록 수)가 다르면 비율이 다르다.
- 온도가 높은 기록은 불합격이다 → 온도 상위 5건 중 불합격은 1건뿐이다.
- 세정도 8대 공정의 한 단계다 → 단계 사이마다 하는 씻기라 흐름표에 행이 없다.

## 막히는 지점 TOP3와 대처

1. **노트북 8단계 문제 2의 조용한 오답** — 두 번째 줄을 `df`에서 고르면 오류 없이 `25 13`(전체 불합격 13건), `-1`에 따옴표를 붙이면(`"-1"`) 오류 없이 `25 0`, 분모를 `df`로 쓰면 오류 없이 5.0%가 나온다. 합격여부는 숫자라 따옴표 없이 쓴다. "첫 줄에서 만든 `eq02`에서 다시 고른다"를 칠판에 적고, 강의 확인 2의 `eq01_fail = eq01[...]` 줄과 나란히 비교하게 한다.
2. **Orange Select Columns에서 열을 옮기는 법** — 상자 이름(Ignored · Features · Target · Metas)과 가운데 화살표 버튼을 화면에서 손으로 짚는다. 합격여부를 Ignored로 보내면 Select Rows에서 합격여부 조건을 만들 수 없다 → Target으로 되돌리거나 Reset 후 다시 한다.
3. **열 이름 오타(`KeyError`)** — `온도_C`의 대문자 C, `가격_KRW`의 대문자 KRW를 소문자로 쓰는 일이 가장 많다. `print(df.columns)` 출력에서 복사해 붙이게 한다.

## 실습 중 오류 대응

- `FileNotFoundError: [Errno 2] No such file or directory: '../../data/weekly/week4/week04_process_filtering.csv'`: 폴더·파일 이름 오타(이 예는 `week04` 폴더를 `week4`로 씀). 메시지 끝의 경로를 강의 코드와 비교하고, 노트북을 키트의 `notebooks/student`에서 열었는지 확인한다.
- `KeyError: '온도_c'`: 열 이름 대소문자. `print(df.columns)`로 확인한다.
- `KeyError: ('설비번호', '온도_C', '합격여부')`: 여러 열을 대괄호 한 겹으로 썼다. 두 겹으로 감싼다.
- `TypeError: 'tuple' object is not callable`: `shape()`처럼 괄호를 붙였다.
- `SyntaxError: leading zeros in decimal integer literals are not permitted`로 시작하는 오류: `== EQ-02`처럼 글자 값에 따옴표를 빠뜨렸다.
- `NameError: name '____' is not defined`: 노트북 빈칸을 아직 채우지 않았다.
- `NameError: name 'small' is not defined` / `NameError: name 'eq02_fail' is not defined`: 문제 1·2의 앞 셀(빈칸 셀)이 실패해서 다음 셀에서 연쇄로 난다. 앞 셀부터 고친다.
- `NameError: name 'df' is not defined`: 7단계 셀을 실행하지 않고 8단계로 왔다. "막혔을 때" 셀대로 위에서부터 다시 실행한다.
- 오류 없이 낮은 온도 5건(맨 위 287.0): 문제 3에서 `ascending=True`로 썼다. 문제 3은 빈칸 없이 직접 쓰는 문제라, 6단계 `cafe.sort_values("가격_KRW", ascending=False).head(5)`를 보고 표 이름·열 이름만 바꾸게 한다.
- Orange File에 파일 이름이 빨갛게 보임: 키트 폴더 구조가 바뀌었거나 `.ows`를 다른 곳으로 옮겼다. 키트를 다시 풀고 그 안에서 연다.
