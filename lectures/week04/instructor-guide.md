# 4차시 강의 운영안 — Pandas 가장 기본적인 부분

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

1차시에는 40줄짜리 표를 강사가 눈으로 세어 "불합격 8건"이라고 알려줬다. 오늘 표는 100줄이고, 실제 공장은
하루에도 수십만 줄이 쌓인다. Pandas는 파이썬 안의 "표 전용 공구"로, 표를 코드로 열고 고르고 줄 세운다.
한 번 쓴 코드는 100줄이든 10만 줄이든 그대로 다시 쓸 수 있다.

**예를 들면**: 100건 전체로 보면 불합격은 13건(13.0%)이라 평범해 보인다. 그런데 설비별로 따로 떼어 보면
EQ-04는 22건 중 5건(22.7%), EQ-02는 25건 중 5건(20.0%), EQ-03은 22건 중 1건(4.5%)이다. 같은 공장 안에서
약 다섯 배 차이가 난다(기록이 적어 우연일 수 있다는 말을 함께 한다). "따로 떼어 보는" 도구가 오늘 배우는 조건 검색이다.

## 수업 흐름

1. 복습: 1차시 표(행·열) → 2차시 "딕셔너리의 리스트" → 3차시 `for`+`if`로 305도 넘는 설비 고르기. "이걸 10만 줄에 하려면?"을 묻는다.
2. 오늘의 질문과 "왜 배우나": 전체 13.0% vs 설비별 불합격률(강의 "왜 이걸 배워야 할까?"의 숫자)
3. CSV와 DataFrame: `read_csv` → `head()` 결과 표 → 열 이름이 공장에서 뜻하는 것 한 줄씩 → DataFrame = 딕셔너리의 리스트 그림 → `shape`·`columns`
4. 열 선택: 열 하나(Series) → 여러 열 `[[ ]]`. 한 겹으로 쓰면 `KeyError`가 나는 것을 직접 실행해 보여준다.
5. 조건 검색: 엑셀 필터 비유 → `check` 결과(True/False)를 먼저 보여주고 → `df[조건]` → 체크 표시 그림 → 3차시 for+if와 한 줄 비교(305도 초과 13건) → 불합격 13건 → 고온 13건 중 불합격 3건
6. 휴식
7. 정렬(온도 상위 5건) → loc 맛보기(`df.loc[0, "온도_섭씨"]`, 조건+열) → iloc은 실행만
8. 종합: EQ-02 불합격 5건·20.0% → 불합격 5건을 공정명·온도와 함께 보기 → 설비별 표 → "원인"이 아니라 "원인 후보"
9. 학생 실습: 학생용 노트북 1~8단계. 먼저 끝난 학생은 8단계 끝 "도전 문제 1~2"
10. AI 활용(노트북 9·10단계) → 연습문제(11단계, 세정 공정) → 설비 검색기(12단계)

## 강사 설명 포인트
- **DataFrame은 "1차시에 눈으로 본 그 표를 파이썬이 읽어 들고 있는 것"이라고 먼저 말한다.** 이어서 행 하나 = 2차시 딕셔너리 하나라는 그림을 보여준다.
- 열 이름 표를 한 줄씩 읽어 준다. 반도체 용어를 다시 외우게 하지 않고 "로트번호 = 택배 상자 번호"처럼 비유만 상기시킨다.
- `head()`에는 괄호가 있고 `shape`·`columns`에는 없다는 점을 "명령 vs 원래 가진 정보"로 짧게 구분한다. 깊이 들어가지 않는다.
- **`[[ ]]`는 반드시 틀린 코드를 먼저 실행해 `KeyError: ('설비번호', '온도_섭씨', '합격여부')`를 보여준 뒤 고친다.**
  "바깥은 꺼내 줘, 안쪽은 열 이름 리스트"라는 한 문장을 칠판에 적는다.
- 조건 검색은 반드시 두 단계로 보여준다. ① `check = df["설비번호"] == "EQ-02"`의 True/False 목록 → ② `df[조건]`.
  엑셀 필터에서 체크박스에 체크하는 화면을 떠올리게 한다. 그림의 행 번호가 0, 2, 3으로 원래 번호를 유지하는 점도 짚는다.
- 3차시 `for`+`if` 코드와 한 줄 코드를 나란히 놓고 "Pandas가 100번의 `if`를 대신 해 준다"고 말한다.
- `== -1`을 쓰는 순간 "이 데이터는 1 = 합격, -1 = 불합격"을 다시 말한다(0이 아니다).
- "고온 13건 = 불합격 13건?" 질문으로 여러 열 함께 보기를 체험시킨다. 같은 숫자라도 같은 기록이 아니다(겹치는 것은 3건).
- **loc은 맛보기만 한다.** `df.loc[행, 열]` 모양(쉼표 앞 행, 뒤 열)과 "값을 고칠 때도 쓸 수 있다(5차시에서 잠깐 다시 본다)"만 전달한다.
  `iloc`은 실행만 하고 넘어간다. 5~10차시 어디에서도 iloc을 쓰지 않으므로 "이런 방법도 있다" 정도로만 소개한다. loc/iloc 슬라이스 끝 포함 여부 비교는 다루지 않는다(아래 "축소한 내용" 참고).
- 종합에서는 "5건"에서 멈추지 않고 그 5건의 공정명·온도를 꺼내 보게 한다. 1차시의 "여러 열 함께 보기"·"원인 후보" 흐름을 이어 간다.
  "EQ-04가 원인이다"가 아니라 "EQ-02·EQ-04를 원인 후보로 더 살펴볼 만하다"까지만 말한다. 비교는 7차시, 원인 후보 좁히기는 8차시라고 예고한다.
- 가상 데이터라 설비와 공정이 무작위로 짝지어져 있다(실제 공장에서는 설비마다 맡는 공정이 정해져 있다). 학생이 "EQ-01이 왜 모든 공정을 하나요?"라고 물으면 이렇게 답한다.
- **강사만 알고 있을 것**: 데이터 생성 시 EQ-02에 불합격이 몰리도록 설계했지만, 실제 생성 결과는 비율로 EQ-04가 더 높게 나왔다
  (데이터 설명서 "의도적으로 포함된 패턴"). 학생이 "EQ-02가 진짜 문제 설비냐"고 물으면 "가상 데이터라 실제 설비 이야기가 아니며,
  기록 수가 적어 우연도 섞여 있을 수 있다"고 답한다.
- 축소한 내용(2026-10-02 개정): loc/iloc 슬라이스 끝 포함·미포함 비교, `iloc[행, 열]`, `df.columns.get_loc()`, `iloc`에 열 이름을 넣었을 때의 오류,
  `&` 두 조건 검색, 작은 연습 표 `pd.DataFrame({...})` 미리 보기는 빠졌다. 질문이 나오면 iloc은 "뒤 차시에서는 쓰지 않으니 이런 방법이 있다는 것만 알아두자", `&`는 "8차시에서 처음 배운다"고 답한다.

## 예상 오개념
- 여러 열을 `df["설비번호", "온도_섭씨"]`처럼 대괄호 한 겹으로 고르려 한다 → 두 겹 `[[ ]]`. 바깥은 꺼내기, 안쪽은 리스트.
- 조건식에 `=` 하나를 쓴다 → 비교는 `==`(3차시 복습).
- 조건 검색이 원본 `df`를 바꾼다고 생각한다 → 결과는 새 표. 변수(`eq02 = ...`)에 저장해야 다시 쓴다.
- `sort_values()`의 기본이 큰 값부터라고 생각한다 → 기본은 오름차순, 큰 값부터는 `ascending=False`.
- 불합격 건수가 같으면 불합격률도 같다고 생각한다 → 전체 기록 수가 다르면 비율이 다르다(EQ-02 20.0% vs EQ-04 22.7%).
- "온도가 높으면 불합격"이라고 짐작한다 → 고온 13건 중 불합격은 3건, 불합격 13건 중 10건은 305도 이하.
- 비율이 높은 설비 = 불량의 원인이라고 결론 낸다 → 원인 후보일 뿐, 기록 수가 적고 다른 요인이 섞여 있을 수 있다.
- `합격여부`의 불합격을 0으로 생각한다 → 이 데이터는 -1이 불합격이다.

## 실습 중 오류 대응
- `AttributeError: module 'pandas' has no attribute '____'`: 1단계 빈칸을 채우지 않고 실행했다. `read_csv`를 채우게 한다.
- `NameError: name 'df' is not defined`: 1단계 셀이 실패했거나 실행하지 않았다. 1단계부터 다시 실행한다.
  1단계가 실패하면 아래 모든 셀이 같은 오류를 내므로, 맨 처음 난 오류부터 본다.
- `SyntaxError: invalid syntax`: 비교 기호나 대괄호 자리의 `____`를 채우지 않고 실행했다.
- `NameError: name '____' is not defined`: 연습문제 11단계의 `cleaning_fail = ____` 빈칸을 채우지 않았다.
- `FileNotFoundError: [Errno 2] No such file or directory: 'week04_process_filtering.csv'`: 경로를 줄여 썼다.
  `"../../data/weekly/week04/week04_process_filtering.csv"`를 그대로 복사하게 한다. 노트북이 `notebooks/student/` 안에 있어야 이 경로가 맞는다.
- `KeyError: '온도'`: 열 이름 오타. `print(df.columns)`에서 정확한 이름(`온도_섭씨`)을 복사하게 한다.
- `KeyError: ('설비번호', '온도_섭씨', '합격여부')`: 여러 열을 대괄호 한 겹으로 골랐다. `[[ ]]`로 고친다.
- `SyntaxError: cannot assign to subscript here. Maybe you meant '==' instead of '='?`: 조건식에 `=` 하나를 썼다.
- `TypeError: 'tuple' object is not callable`: `df.shape()`처럼 괄호를 붙였다.
- `NameError: name 'false' is not defined`: `ascending=false`. `False`는 첫 글자가 대문자다.
- 오류 없이 `(0, 8)`이 나옴: `"eq-02"`처럼 소문자·띄어쓰기가 데이터와 다르다. 철자를 데이터와 똑같이 맞춘다.
- 10단계에서 AI 코드를 실행한 뒤 11단계에서 `KeyError: '공정명'`: AI 코드의 `df = pd.DataFrame(...)` 줄이 100행 데이터를
  예시 데이터로 덮어썼다. 그 줄을 지우고 1단계 셀을 다시 실행해 `df`를 되살린다.
