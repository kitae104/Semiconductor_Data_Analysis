# 10차시 강의 운영안 — 모델 평가와 새 데이터 예측

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

9차시에 만든 모델은 "공부를 마친 학생"이다. 오늘은 그 학생의 모의고사(test) 점수를 제대로 읽고, 정답지가 없는
실제 시험(새 로트 9건)을 보게 한다. 점수를 잘못 읽으면 쓸모없는 모델을 믿게 되고, 예측이 맞아도 원인을 안 것은
아니라는 점까지 짚으면 10차시 과정이 하나의 줄기로 묶인다.

**예를 들면**: "답이 거의 다 ①번인 시험"에서는 전부 ①번으로 찍어도 79점이 나온다. 오늘 test 데이터가 그렇다.
합격이 116건, 불합격이 31건이라 "전부 합격"이라고 찍어도 78.9%를 맞히는데, 모델 정확도는 80.3%로 2건 더 맞힌 정도다.

## 수업 흐름

1. 지난 시간 복습: Feature(단서)·Label(정답), train/test 나누기. 단서 열 6개가 공장에서 뜻하는 것을 한 줄씩 상기
2. **부호** 칠판 판서: `합격여부` 1 = 합격, -1 = 불합격(1~8차시와 같은 표기). 확률 열 순서는 `classes_` `[-1 1]`을 따른다는 것도 함께 적어 둔다
3. STEP 01 9차시 모델 다시 만들기(정답 노트북 1단계 시연) — `(735, 9)`, `588 147` 확인
4. STEP 02 모델 평가: 정확도 → "100개 중 불합격 5개" 쉬운 예와 화재경보기 비유 → 기준선 78.9% → 혼동행렬(노트북 2단계)
5. 휴식
6. STEP 03 새 로트 예측: 모의고사/실제 시험 비유 → 새 로트에 정답 열 `합격여부`가 없음을 눈으로 확인 → 열 구성이 같아야 하는 이유(주의 상자) → `predict()`(노트북 3~4단계)
7. STEP 04 `classes_` 확인 → `predict_proba()` 열 순서 표 → 막대그림 → 2번(불합격 예상)과 0번·6번이 높은 이유("비슷한 과거 로트 묶음" 표) → 원인 후보 표현(노트북 5단계)
8. 학생 실습: 학생용 노트북 1~5단계. 먼저 끝난 학생은 5단계 끝 "도전 문제"
9. STEP 05 Orange3 재확인: 예측(Predictions) 위젯 시연, 두 도구가 다를 수 있는 이유
10. STEP 06 과정 전체 되짚기: 큰 줄기 그림 → 차시별 한 문장 표 → "예측이 맞아도 원인을 안 것은 아니다"(우산 비유). 노트북 6단계 회고 작성
11. AI 활용(노트북 7·8단계) → 연습문제(9단계) → 수료증 미니 프로그램(10단계)
12. 정리 퀴즈 + 과제 안내 + 과정 마무리 인사

- 묶음별 수치: `sklearn.tree.export_text(model, feature_names=feature_cols, show_weights=True)`와 `model.apply(X_train)`으로 확인했다.
  - 2번: "온도 293.95 이하, 압력 1009.0 초과, 가스유량 53.94 이하" 갈래, 연습문제 로트 44건 중 27건 불합격(0.614).
  - 0번·6번: "온도 293.95 초과 306.05 이하, 진공도 4.425 이하" 갈래, 24건 중 9건 불합격(0.375).
  - 1·3·4·5·7·8번: "온도 293.95 초과 306.05 이하, 진공도 4.425 초과 5.495 이하" 갈래, 382건 중 29건 불합격(0.076).

    **정답 없는 새 로트의 확률만으로 후보를 정하면 모델 출력으로 모델을 설명하는 순환 논리가 된다.** 강의 본문도 이 비율을 근거로 쓴다.
  - 강사만 알고 있을 것: 2번의 압력은 1009.2로 갈래 기준 1009.0을 겨우 넘는다. 1009.0 이하였다면 연습문제 로트 10개가 모두 합격인 갈래로 갔다.
    작은 차이로 묶음이 바뀌는 것이 트리 모델의 성질이라는 질문이 나오면 이 예로 답한다.
- 연습문제(노트북 9단계): 불합격 확률 > 0.5인 위험 로트 **1개**(2번, `predict()`의 -1 예측과 같다), 0.3 이상이면 **3개**(0번·2번·6번).
- 도전 문제(`max_depth=8`): 새 로트 예측 `[-1 1 1 1 1 1 1 1 1]` — 0번이 -1, 2번이 1로 깊이 4 모델과 두 로트에서 답이 엇갈린다.
  깊이 4는 연습문제 84.7% / test 80.3%, 깊이 8은 연습문제 94.2% / test 78.9%(기준선과 같음).
- AI 예시 코드(위험도 함수, 기준 0.5/0.3): "높음" 1건(61.4%), "보통" 2건(37.5%), "낮음" 6건(7.6%).

## 강사 설명 포인트
- **부호는 1~8차시와 같다.** `합격여부`와 예측값 모두 1 = 합격, -1 = 불합격이다. 헷갈리는 곳은 **확률 열 순서**다.
  `classes_`가 `[-1 1]`이라 `predict_proba`의 0번 열이 불합격 확률이다. 강의의 열 순서 표를 짚고, `proba[:, 1]`을 쓰면
  오류 없이 합격 확률이 붙는다는 것을 보여준다.
- **평가는 계산보다 질문으로.** "모델 점수를 읽는 세 가지 질문"(찍기보다 나은가 / 불합격을 몇 개 잡았나 / 멀쩡한 걸 몇 개 잡았나)을
  칠판에 적고 오늘 숫자로 하나씩 답하게 한다. 혼동행렬은 "줄은 실제, 칸은 예측"만 기억시킨다.
- 모델이 찍기보다 겨우 2건 더 맞혔고 불합격은 31건 중 9건만 잡았다. "쓸모없다"가 아니라 "80%라는 숫자만으로는 판단할 수 없다"가 메시지다.
- **새 로트는 채점할 수 없다.** 오늘은 "모델이 맞았는지"를 확인하는 시간이 아니다. 실제 시험처럼 결과는 실제 검사 뒤에 안다.
- **열 구성이 같아야 하는 이유**는 정답 노트북 3단계의 주석 처리된 줄(`# model.predict(new_lots)`)의 주석을 풀어 실제 `ValueError`를 보여주면
  가장 잘 전달된다. 시연 후 다시 주석 처리한다.
- 2번·0번·6번 해석에서 "온도가 낮아서, 진공도가 낮아서 불합격된다"는 말이 나오면 바로 "원인 후보"로 고쳐 말한다. 모델은 이유가 아니라
  "그런 묶음에 과거 불합격이 많았다"는 사실만 안다.
- **강사만 알고 있을 것**: 이 가상 데이터는 `scripts/generate_weekly_data.py`에서 온도·압력·진공도·두께가 정해 둔 범위를 벗어나면
  불합격 확률이 올라가도록 만들었고(진공도는 4.5 미만 또는 5.5 초과), 가스유량·습도는 합격여부와 관계없게 만든 대조군 열이다.
  그런데 트리 갈래에는 가스유량 기준(53.94, 47.475)도 등장하고, 2번 로트의 묶음도 가스유량 조건으로 정해졌다(`export_text`로 확인). "모델이 참고한 열 = 원인"이 아니라는 좋은 예이니,
  과정 회고에서 "예측이 맞아도 원인을 안 것은 아니다"를 설명할 때 공개해도 좋다. 학생 앞에서 진공도를 확정된 원인처럼 말하지 않는다.
- Orange3 그림 10-2(`assets/images/orange3/week10_02_predictions.png`)는 아직 캡처 전이라 강의에는 점선 자리 상자가 보인다. 학생 화면에는 9행이 나와야 한다.
- 과정 회고는 큰 줄기 그림 네 칸(살핀다 → 함께 본다 → 관계를 찾는다 → 예측한다)을 먼저 보여주고, 차시별 표는 학생에게
  "이 차시는 네 칸 중 어디?"라고 물으며 읽는다. 마지막은 우산 비유로 "예측 ≠ 원인"을 정리한다.

## 예상 오개념
- "정확도가 높으면 좋은 모델" → 불합격이 드물면 찍기만으로도 정확도가 높다. 기준선과 혼동행렬을 함께 본다.
- "확률 표의 왼쪽 열은 합격 확률" → 열 순서는 `classes_`(`[-1 1]`)를 따르므로 왼쪽(0번) 열이 불합격 확률이다. 불합격 확률이 0.924처럼 나온 학생은 `proba[:, 1]`을 쓴 것이다.
- "새 로트도 정답이 있을 것" → 새 로트에는 `합격여부` 열이 없다. `new_lots["합격여부"]`는 `KeyError`가 난다.
- "열 이름만 맞으면 순서는 상관없다", "열이 더 많아도 알아서 골라 쓴다" → 둘 다 `ValueError`가 난다. `feature_cols`를 그대로 쓴다.
- "예측이 같으면(둘 다 합격) 위험도도 같다" → `predict_proba()`로 0.375와 0.076의 차이를 보여준다.
- "predict()와 확률은 따로 논다" → 0.5 기준 위험 로트(2번)가 `predict()`의 -1 예측과 같다는 것을 연습문제에서 확인시킨다.
- "더 복잡한 모델(깊이 8)이 더 좋다" → 연습문제 점수만 오르고 test 점수는 내려간다(도전 문제).
- "두 도구 결과가 다르면 한쪽이 틀렸다" → 학습한 행, 단서 열, 설정, 빈칸 처리 방식이 다르면 결과가 달라질 수 있다.
- "모델이 많이 참고한 열 = 원인" → 원인 후보일 뿐이다. 예측이 맞아도 원인을 안 것은 아니다.

## 실습 중 오류 대응
- `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'`: 메서드 이름 빈칸(`fit`, `predict`, `predict_proba`)을
  채우지 않고 실행한 경우다.
- `NotFittedError: This DecisionTreeClassifier instance is not fitted yet.`: 1단계 `fit` 빈칸을 비운 채 2단계로 넘어간 경우다.
  1단계 마지막 셀을 채워 다시 실행하게 한다. 도전 문제에서 나면 `model2`를 만드는 첫 셀을 건너뛴 것이다.
- `NameError: name '____' is not defined`: 값·변수 빈칸을 채우지 않은 경우다.
- `NameError: name 'model' is not defined`: 1단계를 건너뛰었거나 커널을 다시 시작한 경우다. 맨 위부터 다시 실행한다.
  도전 문제에서 `NameError: name 'model2' is not defined`가 나면 도전 문제 첫 셀을 건너뛴 것이다.
- `SyntaxError: invalid syntax`: 9단계 비교 기호 빈칸(`>`)을 비워 둔 경우다.
- `ValueError: The feature names should match those that were passed during fit.`: `X_new` 대신 `new_lots`를 넣었거나 열 순서·개수를
  바꾼 경우다. 메시지 아래 줄(`Feature names unseen at fit time` 등)을 읽게 하고 `feature_cols`를 그대로 쓰게 한다.
- `KeyError: '합격여부'`: 새 로트에서 정답 열을 찾은 경우다. 새 로트는 채점할 수 없다고 다시 설명한다.
- `KeyError: '불합격_확률'`: 5단계 두 번째 셀(불합격 확률 열 붙이기)을 실행하지 않고 8·9단계로 간 경우다.

## 빠른 학습자용 추가 과제
- 노트북 5단계 끝 "도전 문제"(강의 「도전 실습」): `max_depth=8` 모델과 비교하고, "연습문제 답을 외운 학생"에 빗대어 한 문장으로 정리하게 한다.
- 연습문제 기준을 0.5 → 0.3으로 바꿔 1개 → 3개가 되는 것을 확인하고, "기준을 낮추면 놓치는 로트는 줄지만 멀쩡한 로트까지 다시 확인하게 된다"를
  한 문장으로 적게 한다.
- 과제 3(선택): `feature_cols`에서 열 하나를 빼고 다시 학습해 test 정확도를 기준선 78.9%와 비교하게 한다. `X_new`도 같은 목록으로 다시 만들어야 한다는 점을 확인시킨다.

## 느린 학습자용 최소 과제
- 노트북 1단계(모델 다시 만들기)와 4단계(`predict()`)까지만 성공해도 충분하다.
- 평가는 계산 없이 실습지 2번 1)(100개 중 불합격 5개 → 전부 합격이면 95%)만 말로 설명할 수 있으면 된다.
- 회고는 큰 줄기 네 칸 중 가장 기억에 남는 칸 하나를 골라 말로 표현하면 된다.
