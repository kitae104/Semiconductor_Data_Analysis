# 10차시 강의 운영안 — 모델 평가와 새 데이터 예측

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

모델을 만드는 이유는 아직 검사하지 않은 새 로트를 미리 보기 위해서다. 그런데 9차시 모델의 정확도 80.3%는 "모두 합격" 78.9%와 큰 차이가 없었다.
그래서 새 데이터에 쓰기 전에 두 가지를 확인한다. 다른 모델도 같은 답을 내는지(모델끼리 답이 갈리면 사람이 다시 본다), 그 숫자를 보고서에 옮길 때 틀리거나 부풀리지 않았는지(AI가 쓴 보고서도 직접 실행해 확인한다).
마지막 차시이므로 10일의 큰 줄기(기록 → 표 → 정리 → 그림 → 비교 → 원인 후보 → 예측)와 공정 지도로 과정을 마무리한다.

## 수업 흐름

9·10차시는 PART 1 Orange3 → PART 2 파이썬 + ChatGPT → PART 3 실습지 순서다. 노트북은 단계 번호로 지시한다.

1. 오늘의 질문·오늘의 미션(입사 열째 날, 마지막 날) → 지난 시간 복습 2문항(80.3% vs 78.9%, Confusion Matrix 114칸)
2. PART 1 시작: 위젯 이름표(새 위젯 kNN·Logistic Regression·Predictions), 공정 지도 위치 네 줄
3. 워밍업 `week10_1_newwafers_start.ows`(학생이 직접): 세 모델 → Test and Score(10겹) CA 읽기 → Predictions에서 답이 갈린 웨이퍼 찾기 → "읽은 숫자 확인 보기"는 학생이 찾은 뒤 연다
4. 반도체 `week10_2_newlots_start.ows`는 **강사 시연** 1~2(Test and Score CA + 기준선 79.3%, Confusion Matrix에서 Logistic Regression 불합격 예측 0) — 3(Predictions)은 실습지 문제 4로 남긴다
5. **여기서 쉬기**
6. PART 2 파이썬: Jupyter 켜기, "막혔을 때" 셀 → 노트북 1단계(모델 다시 만들기, 80.3%) → 노트북 2단계(새 로트 읽기 (9, 8) → `predict` 빈칸 2개 → 불합격 예측 1개)
7. ChatGPT 체험(노트북 4단계): 프롬프트 붙여 넣기(못 쓰면 강의 응답 예시) → 틀린 곳 찾기 → 노트북 4단계 숫자 대조 셀 실행 → "틀린 곳 정답 보기"
8. 파이썬 vs Orange 표 한 문장
9. **여기서 쉬기**(필요하면)
10. PART 3 실습지: 문제 1~2(노트북 3단계) → 문제 3(Orange 워밍업 기록) → 문제 4(Orange Predictions, 파이썬과 비교) → 문제 5(고친 보고 문장) → 정답 확인과 문장 발표
11. 결과 정리·반도체 이해 포인트 → 과정을 마치며(10차시 표, 노트북 5단계 회고) → 과제 안내·마무리 인사

### 워밍업(Orange) — 학습 `week09_orange_wafer_patterns.csv` 240장 / 새 웨이퍼 `week10_orange_new_wafers.csv` 10장
- 공정 지도 위치: 둘 다 ⑦ EDS 웨이퍼 맵 요약(새 웨이퍼 = 방금 ⑦을 마친 웨이퍼).
- Test and Score(10겹): Tree **0.942**(AUC 0.961) · kNN **0.900**(AUC 0.974) · Logistic Regression **0.971**(AUC 0.994). 기준선(모두 "정상"으로 찍기) = 120 ÷ 240 = **50%** — CA를 말할 때 늘 함께 말한다. 새로 놓으면 5겹으로 시작한다 — 10으로 바꾸지 않으면 숫자가 조금 다르다.
- Predictions(답이 갈림): **N-04** Tree 스크래치형(확률 0.67) / kNN 정상 / Logistic Regression 정상(0.54, 중심형 0.46). **N-10** Tree 중심형(0.57) / kNN 정상 / Logistic Regression 정상(0.97).
- N-07은 세 모델 모두 중심형이지만 Tree·Logistic Regression 중심형 확률 0.57(kNN 0.80).
- 나머지: N-01·N-06 정상, N-02·N-08 가장자리형, N-03·N-09 중심형, N-05 스크래치형(세 모델 같음).
- 새 웨이퍼 숫자: N-04 불량 다이 9(중심 44.4 · 가장자리 55.6 · 직선 33.3), N-10 불량 다이 7(42.9 · 57.1 · 57.1).
- **운영안 전용 — 새 웨이퍼 의도 패턴(생성기 주석, 학생에게 정답으로 말하지 않는다)**: N-01 정상 · N-02 가장자리형 · N-03 중심형 · **N-04 애매(중심+가장자리)** · N-05 스크래치형 · N-06 정상 · **N-07 애매(중심+가장자리)** · N-08 가장자리형 · N-09 중심형 · **N-10 애매(중심+가장자리)**.
  애매한 3장 중 2장(N-04, N-10)에서 답이 갈렸고, N-07은 답은 같지만 확률이 낮았다. "정답"이 없는 웨이퍼이므로 "사람이 다시 본다"가 결론이다.

### 반도체(Orange) — 학습 `week09_pass_fail_train.csv` 750행 / 새 로트 `week09_new_lots_to_predict.csv` 9개
- 공정 지도 위치: 학습용 = ②~⑤ + 세정 공정 조건 → ⑦ 결과 / 새 로트 = ②~⑤ + 세정을 마쳤지만 아직 ⑦ 검사 전(학습용 162행과 새 로트 9번째 행이 세정 기록).
- 합격여부: 1 = 595, -1 = 155 → 기준선 595 ÷ 750 = **79.3%**(0.793).
- Test and Score(10겹): Tree **0.783**(AUC 0.681) · kNN **0.769**(AUC 0.603) · Logistic Regression **0.793**(AUC 0.553).
- Confusion Matrix(Number of instances, 행 = 실제, 열 = 예측 1 · -1):
  - Tree: 실제 1 → 546 · 49 / 실제 -1 → **114** · 41 (불합격 예측 90)
  - kNN: 557 · 38 / **135** · 20 (불합격 예측 58)
  - Logistic Regression: 595 · 0 / **155** · 0 (불합격 예측 **0** = 무조건 합격)
- Predictions(Tree, Show probabilities for = Classes known to the model, `합격 : 불합격 → 예측`): 1번 0.85 : 0.15 · 2번 0.94 : 0.06 · **3번 0.74 : 0.26** · 4번 0.85 : 0.15 · 5번 0.94 : 0.06 · 6번 0.94 : 0.06 · 7번 0.80 : 0.20 · 8번 0.85 : 0.15 · 9번 0.94 : 0.06 → **9개 모두 1(합격)**. 3번째 로트의 불합격 확률이 9개 중 가장 높다.

### 파이썬 — 정답 노트북 출력
- 노트북 1단계: 750행 → `dropna()` 735행 → 학습용 588 / 시험용 147(실제 불합격 31). `정확도: 80.3%`.
- 노트북 2단계: `(9, 8)`. 예측 `[1 1 -1 1 1 1 1 1 1]` — 3번째 로트(행 번호 2, 식각 · EQ-04 · 289.8)만 -1. `새 로트 9개 중 불합격 예측 1개`.
- 노트북 3단계(실습지 1·2): 문제 1 `X_test`, `-1` → **16** / 문제 2 `시험용 147개 중 실제 불합격 31개, 불합격 예측 16개`.
  참고(코드로 다루지 않음): 불합격 예측 16개 중 실제 불합격은 9개 — 시험용 실제 불합격 31개 중 22개를 놓쳤다.
- 노트북 4단계 숫자 대조: `정확도: 80.3%` / `기준선(모두 합격): 78.9%` / `불합격 예측: 1개` / 3번째 로트(식각 · EQ-04 · 289.8).
- 새 로트 온도: 294.5, 301.5, **289.8**, 295.6, 299.1, 302.0, 305.2, 299.1, 300.6 — 3번째 로트가 가장 낮다.
- 3번째 로트가 걸린 파이썬 트리 갈래: 온도_C ≤ 293.95 → 압력_Pa > 1009.0 → 가스유량_slm ≤ 53.94 → -1. 9차시 Orange Tree Viewer 첫 갈림길도 온도_C ≤ 293.8(온도가 낮은 쪽)이다.

### ChatGPT 응답 예시 — 일부러 심은 오류 2개(강의 "틀린 곳 정답 보기"와 같은 내용)
- 응답 예시 원문(프롬프트가 요청한 대로 **정확히 3문장**): "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 2개이며, 3번째 로트(식각·EQ-04, 온도 289.8도)가 그중 하나입니다. 모델 정확도는 80.3%로 모두 합격이라고 찍는 기준선 78.9%와 큰 차이가 없고, Orange 교차검증에서는 실제 불합격 155건 중 114건을 합격으로 놓쳤습니다. 3번째 로트는 온도가 낮아서 불합격이 생깁니다(이 결과는 교육용 가상 데이터로 만든 것입니다)."
- 숫자별 대조 출처: 80.3%·78.9%·불합격 예측 개수·3번째 로트 정보 → 노트북 4단계 숫자 대조 셀 / "155건 중 114건" → PART 1 Confusion Matrix 표의 Tree 줄. 학생이 80.3%를 Orange 0.783과, 78.9%를 Orange 79.3%와 비교해 "틀렸다"고 하면 강의 "나란히 보기" 표로 출처 차이를 짚는다(심은 오류가 아니다).
- **이 두 곳은 연습을 위해 일부러 심은 오류다.** 나머지 숫자(80.3%, 78.9%, 155건 중 114건, 289.8도, 식각·EQ-04)는 모두 맞다.
  1. 틀린 숫자: "불합격으로 예측한 로트는 **2개**" → 실제 **1개**(3번째 로트만). 고친 문장: "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 1개(3번째 로트, 식각·EQ-04)입니다."
  2. 원인 단정: "3번째 로트는 온도가 낮아서 불합격이 생깁니다" → 온도가 가장 낮다는 방향은 데이터와 맞지만, 아직 검사 전 로트의 예측이고 함께 나타난 값일 뿐이다.
     고친 문장: "3번째 로트는 온도가 9개 중 가장 낮아(289.8도) 먼저 살펴볼 로트이며, 온도는 불합격의 원인 후보로 확인해 볼 값입니다." (근거로 9차시 Orange 트리의 첫 갈림길 온도_C ≤ 293.8을 말해 줄 수 있다.)
- 심은 문장을 "온도가 **높아서**"로 바꾸지 않는다. 그러면 데이터 방향과도 어긋나 틀린 곳이 3개가 된다.
- 실습지 문제 5 예시 답안(노트북 4단계 정답 셀과 같은 글자): "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 1개(3번째 로트, 식각·EQ-04)입니다. 모델 정확도는 80.3%로 모두 합격이라고 찍는 기준선 78.9%와 큰 차이가 없어, 이 예측은 어느 로트부터 먼저 살펴볼지 정하는 참고로만 쓰고 온도 같은 공정 조건은 불합격의 원인 후보로만 봅니다. 이 결과는 교육용 가상 데이터로 만든 것입니다."

## 강사 설명 포인트

- 오늘의 핵심 문장 두 개: "정확도는 기준선과 함께 읽는다", "모델끼리 답이 갈리면 사람이 다시 본다". Logistic Regression 장면(정확도 1등 = 불합격 0건)이 첫 문장을 가장 잘 보여 준다.
- 기준선이 두 개다. 파이썬 78.9%(시험용 147개)와 Orange 79.3%(750행). 숫자가 다른 이유는 세는 대상이 달라서다. 보고서에는 숫자와 함께 출처를 적게 한다.
- Orange Tree와 파이썬 트리는 학습한 데이터(750행 전체 vs 빈칸을 지운 735행 중 588행)와 모델 기본 설정(Orange Tree의 잎·분할 최소 개수 등)이 달라 새 로트 예측이 다르다. 정확도가 다른 데는 채점 방법(10겹 vs 시험용 147개)도 더해진다. 채점 방법은 새 로트 예측에는 영향을 주지 않는다. "어느 쪽이 틀렸다"가 아니다.
- 새 로트 예측은 모델이 좋든 나쁘든 ⑦ 검사를 대신하지 않는다. 모델은 "어느 로트부터 먼저 살펴볼지" 순서를 정하는 일을 돕는다. 두 도구가 모두 3번째 로트를 가장 의심스럽게 봤다는 점을 짚는다(파이썬 -1, Orange 불합격 확률 0.26으로 최고).
- kNN·Logistic Regression의 원리는 깊이 들어가지 않는다. kNN = 이웃 투표(기본 5개), Logistic Regression = 세 번째 의견. 오늘 목표는 "모델을 여러 개 놓고 비교하는 습관"이다.
- 예측 확률은 "모델이 얼마나 확신하는지"이지 맞을 확률의 보장이 아니다.
- ChatGPT 체험의 요점: 프롬프트에 "원인 후보"라고 쓰라고 해도 단정 문장이 섞일 수 있다. 숫자는 노트북 4단계 셀로, Orange 숫자는 PART 1 화면으로 하나씩 대조한다.
- 강사만: 이 가상 데이터의 생성기는 온도·압력·진공도·두께가 연습용 범위를 벗어나면 불합격 확률이 일정량 올라가게(계단식으로 +0.20/0.15/0.25/0.15) 만들었다(`scripts/generate_weekly_data.py`). 하지만 데이터만 보는 분석가는 이 규칙을 알 수 없다 — 실제 공장에서 "원인"은 현장 확인으로 정한다는 점이 수업의 결론이다. 생성 규칙을 학생에게 "정답"으로 공개하지 않는다.
- 강사만: 생성 규칙으로 보면 1번째·7번째 로트(진공도 4.02·4.35로 연습용 범위 4.5 미만)의 생성 불합격 확률이 0.31로, 3번째 로트(0.26)보다 높다. 모델이 진공도 단서를 잡지 못한 것이다. 그래서 "3번째 로트가 진짜 가장 위험하다"고 말하지 않는다 — "두 도구가 가장 의심한 로트라 먼저 살펴볼 근거가 된다"까지만 말한다.
- 공정 지도: 모든 데이터에 위치 한 줄을 붙였다. 과정을 마치며 표의 "공정 지도에서" 열을 짚으며 10일 동안 ②~⑤ + 세정 설비 기록과 ⑦ 검사 결과를 오갔다는 것을 정리한다.

## Orange 시연 체크리스트

- [ ] 키트를 압축 푼 폴더 그대로에서 `orange3/week10/week10_1_newwafers_start.ows`를 연다. File 두 개(위: 학습 웨이퍼 240장, 아래: 새 웨이퍼 10장)가 데이터를 읽었는지 더블클릭해 행 수를 확인한다. 빨간 파일 이름이 보이면 키트 폴더 구조가 바뀐 것이다 — 키트를 다시 풀게 한다(10차시 키트는 9차시 데이터 폴더도 쓴다).
- [ ] Model 묶음: Tree(**Limit the maximal tree depth to** 4)·kNN·Logistic Regression → 위 File.
- [ ] Evaluate 묶음: Test and Score ← 위 File + 세 모델. **Number of folds 10**으로 바꾼다(기본 5). CA 0.942 · 0.900 · 0.971(기준선 50% — 정상 120/240과 함께 말한다).
- [ ] Predictions ← **아래 File** + 세 모델. Predictions 표 바로 위 줄의 Show probabilities for → **Classes known to the model**(새 데이터에 정답 열이 없어 기본값은 (None)이고 확률이 안 보인다. 다른 두 항목은 회색으로 꺼져 있다. `_start.ows` 메모 ⑤(워밍업)·④(반도체)와 같은 안내). N-04·N-10 줄에서 답이 갈린다.
- [ ] 새 데이터 File을 Test and Score에 잇지 않는다(정답 열이 없어 채점 불가).
- [ ] `week10_2_newlots_start.ows`(위: 750행, 아래: 9개) → 세 모델 → Test and Score(10겹) CA 0.783 · 0.769 · 0.793 → 기준선 595 ÷ 750 = 79.3%를 칠판에 쓴다.
- [ ] 반도체 `_start.ows` 메모 ②(세 모델 + Test and Score + Confusion Matrix)는 강사 시연이다. 학생은 실습지 문제 4에서 Tree와 메모 ③·④(Predictions, 확률 보기)만 한다.
- [ ] Test and Score 표는 CA 한 칸만 읽게 한다(AUC·F1 등 다른 열은 오늘 보지 않는다).
- [ ] Test and Score → Confusion Matrix: 왼쪽 목록에서 Tree(114) → kNN(135) → **Logistic Regression(불합격 예측 열 0)** 순서로 눌러 보여 준다. Logistic Regression 위젯에 학습 관련 경고 표시가 보일 수 있다 — 결과를 읽는 데는 지장이 없다고 말하고 넘어간다.
- [ ] Predictions(아래 File + Tree)는 시연하지 않는다 — 실습지 문제 4에서 학생이 직접 한다. 학생 화면 기대값: 9개 모두 1, 3번째 줄 `0.74 : 0.26 → 1`.
- [ ] 늦은 학생은 `_done.ows`를 열어 따라잡게 한다. `_done.ows`의 위젯 이름에는 한국어 뜻이 괄호로 붙어 있다(예: Tree (결정 트리)).

## 학생들이 자주 찾아볼 질문과 보충 설명

- **kNN 이웃 투표**: AI가 거리 계산식(유클리드 거리 등)을 길게 늘어놓을 수 있다. 오늘은 "숫자가 가장 비슷한 학습 데이터 k개의 다수결"까지면 충분하다. Orange 기본 k = 5. k가 작으면 몇 개에 흔들리고 크면 넓게 본다.
- **예측 확률의 뜻**: AI가 "확률 0.6이면 그만큼 맞는다"처럼 보장하는 말투로 설명하기도 한다. 모델이 얼마나 확신하는지일 뿐이고, 결정 트리의 확률은 그 갈래에 모인 학습 데이터 중 그 답의 비율에 가깝다고 보충한다.
- **혼동행렬 읽기**: AI가 "불합격을 놓치는 쪽이 항상 더 위험하다"고 단정할 수 있다. 공정·비용에 따라 다르다는 점, 그래서 정확도와 함께 놓친 칸을 따로 본다는 점을 짚는다. 정밀도·재현율 같은 용어가 나오면 "오늘은 칸의 숫자만 읽는다"고 정리한다.

- "ChatGPT 보고서의 숫자 중 무엇이 맞고 무엇이 틀렸나요? 어떻게 확인했나요?"

## 예상 오개념

- 정확도가 가장 높은 모델이 가장 좋은 모델이다 → 기준선과 Confusion Matrix를 함께 본다(Logistic Regression 0.793 = 불합격 0건).
- 예측 = 확정 판정 → 검사 전 로트의 참고이고, ⑦ 검사는 그대로 한다.
- 모델이 합격이라고 하면 안전하다 → Orange는 3번째 로트를 합격으로 예측했지만 불합격 확률이 9개 중 가장 높았다.
- 모델끼리 다수결로 정하면 된다 → 답이 갈린 웨이퍼는 사람이 다시 본다.
- 파이썬과 Orange 결과가 다르면 한쪽이 틀렸다 → 학습한 데이터·채점 방법이 다르다.
- 예측이 맞으면 원인을 안 것이다 → 단서는 원인 후보다.
- AI가 쓴 보고서는 숫자가 정확하다 → 직접 실행해 대조한다(응답 예시의 "2개").
- 불합격 확률 0.26은 그 로트가 실제로 불합격할 가능성을 보장한 숫자다 → 모델이 얼마나 확신하는지일 뿐 보장이 아니다.

## 막히는 지점 TOP3와 대처

1. **Predictions에 확률이 안 보이거나 예측 열이 없음** — 새 데이터에 정답 열이 없으면 Show probabilities for의 기본값이 (None)이다. Classes known to the model로 바꾸게 한다. 예측 열 자체가 없으면 모델 → Predictions 선을 잇지 않은 것이다(새 데이터 File만 이었다).
2. **CA·예측이 강의 숫자와 다름(오류 없음)** — Test and Score의 Number of folds가 5(처음 값) 그대로이거나, Tree 깊이를 4로 바꾸지 않았다. Tree 창의 깊이 체크박스는 이미 켜져 있고 값만 100이라 "체크를 켜야 하나?"에서 멈춘다 — 숫자만 4로 바꾸게 한다. 깊이 100이면 워밍업에서 답이 갈린 웨이퍼가 N-04 하나로 줄고, 반도체 Predictions는 1번째·8번째 로트가 -1이 되어 "불합격 2개"(응답 예시에 심은 숫자와 같음)가 나온다. 반도체 Predictions에서 3번째 줄이 `0.74 : 0.26 → 1`이 아니면 Tree를 아래 File(새 로트)에 이은 경우도 있다 — 모델은 위 File(학습용)에 잇는다.
3. **실습지 문제 2(직접 쓰기)에서 오류 없이 틀린 숫자** — 강의 줄을 복사해 `new_lots['예측']`을 그대로 두면 "불합격 예측 1개"가 나온다(새 로트를 센 것). 같은 숫자가 두 번 나오면 실제 불합격과 불합격 예측에 같은 변수를 썼다. 실제 = `y_test`, 예측 = `test_pred`를 칠판에 적어 둔다. f-string 안 따옴표가 바깥과 겹치면 Python 3.11에서 `SyntaxError: f-string: unmatched '['`가 난다(3.12부터는 허용 — PC마다 다를 수 있다).

## 실습 중 오류 대응

- `NameError: name 'model' is not defined`: 노트북 1단계 셀을 실행하지 않았다. "막혔을 때" 셀대로 위에서부터 다시 실행한다.
- `ValueError: The feature names should match those that were passed during fit.`: `model.predict(new_lots)`처럼 표를 통째로 넣었거나 열이 다르다. `new_lots[features]`로 고친다.
- `KeyError: 'features'`: `new_lots["features"]`처럼 변수 이름을 따옴표로 감쌌다.
- `AttributeError: 'DecisionTreeClassifier' object has no attribute '____'`: 노트북 2단계 빈칸을 채우지 않았다.
- `NameError: name '____' is not defined`: 노트북 3단계 문제 1 빈칸을 채우지 않았다.
- `ValueError: Expected a 2-dimensional container but got <class 'pandas.Series'> instead.`로 시작하는 오류: 문제 1에 `X_test` 대신 `y_test`(정답)를 넣었다.
- 오류 없이 불합격 예측이 0개: `== "-1"`처럼 숫자를 따옴표로 감쌌다. `예측` 값은 숫자 -1이다.
- `NameError: name 'test_pred' is not defined`: 문제 1 셀을 실행하지 않고 문제 2를 실행했다.
- `KeyError: '예측'`(2단계 f-string 셀, 4단계 숫자 대조 셀): 2단계 빈칸 셀을 채우지 않아 `예측` 열이 아직 없다. 4단계 셀은 두 줄을 찍고 멈춰 "반쯤 된 것"처럼 보인다. 2단계 빈칸 셀부터 채워 실행한다.
- 문제 1에서 오류 없이 114: `X_test` 대신 `X`(735행 전체)를 넣었다(Confusion Matrix의 114와 우연히 같다). 오류 없이 131: `-1` 대신 `1`을 넣어 합격을 셌다.
- Orange File에 파일 이름이 빨갛게 보임: 키트 폴더 구조가 바뀌었거나 `.ows`를 다른 곳으로 옮겼다. 키트를 다시 풀고 그 안에서 연다.

## 빨리 끝낸 학생용 과제

- 워밍업 Predictions에서 N-07 줄을 보고, 세 모델 답이 같은데도 사람이 다시 볼 만한지 확률을 근거로 한 문장으로 적는다(Tree·Logistic Regression 중심형 0.57, kNN 0.80).
- 반도체 Predictions에 kNN과 Logistic Regression도 이어, 세 모델이 새 로트 9개를 어떻게 예측하는지 비교한다(Logistic Regression은 학습 데이터 750건을 모두 합격으로 예측했던 모델이다 — 새 로트에서도 그런지 확인).
- 과제 2(보고서 한 장)를 수업 중에 완성해 옆 사람과 바꿔 읽고, 숫자마다 출처(파이썬/Orange)가 적혀 있는지 서로 확인한다.

## 느린 학습자용 최소 과제

- 노트북 1·2단계(완성 코드 + 빈칸 2개)를 실행하고 결과를 강의 화면과 비교한다.
- 실습지는 문제 1(빈칸 2개)과 문제 5(문장 틀 채우기)만 해도 충분하다. 막히면 "정답 보기"로 빈칸만 채운다.
- "새 로트 9개 중 1개가 불합격으로 예측됐지만, 모델 정확도가 기준선과 비슷해서 먼저 살펴볼 참고로만 쓴다"를 말로 설명할 수 있으면 된다.
