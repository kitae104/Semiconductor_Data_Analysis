# 10차시 강의 운영안 — 모델 평가와 새 데이터 예측

## 🤔 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

모델을 만들었다고 끝이 아니다. 그 모델이 학습에 쓰지 않은 새로운 데이터에서도 잘 맞아야 실제
현장에서 믿고 쓸 수 있다. 새 로트에 `predict()`를 적용해보고 Orange3와 비교하는 과정은, 모델을 실제
업무에 투입하기 전 마지막 검증 단계에 해당한다.

**쉬운 예시**: 9차시에서 만든 모델에 아직 검사 결과가 나오지 않은 새 로트 10개를 넣어 예측했더니
"8개는 합격 예상, 2개는 불합격 예상"이라는 결과가 나왔다. 이후 실제 검사 결과와 맞춰보면, 이 모델을
앞으로 얼마나 믿고 사용할 수 있는지 판단할 수 있다.

## 이 차시의 성격

10차시는 **10주 과정의 마지막 차시**로, 새 이론(predict/predict_proba)을 짧게 다루고 나머지는
1~9차시를 되짚으며 마무리하는 세션이다. 이전에 있던 "미니 프로젝트"는 별도 차시로 남기지 않고,
머신러닝 예측 실습을 9~10차시 두 차시로 확장하는 것으로 대체했다(배경:
`docs/restructure-plan.md`).

## 수업 흐름

1. 지난 시간 복습: 9차시에서 만든 모델(정확도 78.2%, 온도_섭씨가 가장 중요) 되짚기
2. 강사 코드 시연: 9차시 모델 다시 만들기 → 새 로트 예측(predict) → 확률 확인(predict_proba)
3. Orange3 시연: Predictions 위젯으로 같은 새 로트 재확인, scikit-learn 결과와 비교
4. 학생 실습: 에디터 파일 단계별 따라 하기(TODO 채우기)
5. 휴식
6. 10차시 되짚기 — 1~9차시 핵심 내용을 표로 훑어보며 학생들과 함께 복습
7. 도전 실습: `max_depth`를 바꿔 다시 학습시키고 예측이 달라지는지 비교
8. 과정 회고 작성 — 가장 기억에 남는 내용, 더 공부하고 싶은 주제
9. 정리 퀴즈 + 과정 마무리 인사

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)
- 새 로트 9건 모두 **"합격(0)"으로 예측**됨
- 불합격 확률: 대부분 6.7~15.8%이지만, **0번 로트(EQ-02, 온도 294.5℃)와 6번 로트(EQ-01, 온도
  305.2℃)는 36.4%로 눈에 띄게 높음** — 둘 다 정상범위(295~305℃) 경계에 가까운 온도
- 이 두 로트는 실제로 정답을 알 수 없는 "진짜 새 데이터"이므로, 오늘은 확률로만 위험도를
  가늠할 수 있다는 점을 강조

## 강사 설명 포인트
- 오늘은 "정답을 알려주는 시간"이 아니다 — 새 로트는 정답이 없으므로, "모델이 맞았는지"는
  이 자리에서 확인할 수 없다는 것을 분명히 한다. 이것이 실제 현업 예측의 현실이라는 점을
  강조한다.
- `predict()`만 보면 9건 모두 "합격"으로 똑같아 보이지만, `predict_proba()`를 함께 보면
  0번·6번 로트가 상대적으로 위험하다는 것을 발견하는 과정을 반드시 라이브로 보여준다.
  "예측은 같아도 확신의 정도는 다르다"는 메시지가 오늘의 핵심이다.
- 10차시 되짚기 표를 보여줄 때, 단순히 읽어주지 말고 학생들에게 "이 차시에서 가장 기억나는
  코드 한 줄"을 즉석에서 물어보며 참여를 유도한다.
- 마지막 인사에서는 "10차시 동안 배운 순서(읽기→정제→시각화→비교→원인탐색→예측)는 다른
  데이터를 만나도 그대로 쓸 수 있는 뼈대"라는 메시지로 과정을 마무리한다.

## 질문 예시
- "9개 로트가 모두 '합격'으로 예측됐는데, 이 모델을 100% 믿어도 될까요?"
- "불합격 확률이 36.4%인 로트를, 확률이 6.7%인 로트와 똑같이 취급해도 될까요?"
- "10차시 동안 배운 내용 중, 처음 들었을 때는 이해가 안 됐는데 지금은 이해되는 것이 있나요?"

## 예상 오개념
- "새 로트도 정답이 있을 것"이라는 오해 → 이번 데이터는 의도적으로 정답 라벨이 없는 "진짜 새
  데이터"임을 강조한다.
- "예측이 같으면(둘 다 합격) 위험도도 같다"는 오해 → `predict_proba()` 결과로 직접 반박한다.
- "모델을 더 복잡하게 만들면(max_depth를 늘리면) 항상 더 좋다"는 오해 → 9차시에서 이미 다룬
  "정확도의 함정"과 연결해, 복잡한 모델이 항상 낫지는 않다는 것을 도전 실습으로 확인시킨다.

## 실습 중 오류 대응
- `ValueError: columns are missing`: `feature_cols` 리스트가 9차시와 동일한지, 새 데이터에도
  같은 열이 있는지 확인하게 한다.
- `NameError`: 9차시 모델(`model`, `X_train` 등)을 다시 만드는 1단계를 건너뛰었는지 확인.

## 빠른 학습자용 추가 과제
- 강의 자료의 "도전 실습"(max_depth를 바꿔 다시 예측하기)을 먼저 시도해보게 한다.
- 본인이 직접 값을 정한 가상의 로트를 만들어(2차시 딕셔너리 복습) 예측해보게 한다.
- 노트북 9단계 연습문제(위험 로트 개수 세기)는 4차시 조건 검색을 다시 쓰는 순환 복습이다 —
  빠른 학습자에게는 기준값(0.5)을 0.3으로 바꿔보면 위험 로트 개수가 어떻게 달라지는지도
  확인해보게 한다.
- 노트북 10단계 "AI로 재미있는 미니 프로그램 만들기"(10차시 완주 인증서 만들기)는 10주 전체
  과정을 자축하며 마무리하기 좋은 활동이다 — 가장 기억에 남는 차시 이름을 인증서에 함께
  넣어달라고 AI에게 재요청하며 발표시켜보면 좋은 마무리가 된다.

## 느린 학습자용 최소 과제
- `predict()`까지만 성공해도 충분하다. `predict_proba()`는 강사가 결과를 함께 보여주며
  "확률이 다르다"는 개념만 이해시킨다.
- 10차시 되짚기는 표를 함께 읽으며 "가장 기억에 남는 차시 1개"만 말로 표현해도 충분하다.
