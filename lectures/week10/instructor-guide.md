# 10차시 강의 운영안 — 종합 실습: AI와 Orange3로 공정 데이터 분석하기

## 왜 이걸 배워야 할까? (학생에게 전달할 메시지)

현장 데이터에는 문제지가 붙어 있지 않다. 문제를 정하고, 점검하고, 비교하고, 예측하고, 확인한 숫자로 보고하는 것까지가 분석이다.
오늘은 "새 로트 10개 중 어느 것부터 점검할까?" 한 문제를 AI와 Orange3로 끝까지 풀어 보이며 "데이터 분석이란 이런 것"을 보여 준다. AI는 빠른 조수이고, 숫자는 Orange 화면으로 직접 확인한다.

## 수업 흐름

교수 시연형이다. 실습지·노트북·발표는 없다. 학생은 강의를 보며 따라 본다.

1. 오늘의 질문·미션 → PART 1: 새 로트 10개 표("눈으로는 어느 것이 위험한지 모른다"), 공정 지도 위치, 가상 데이터 고지와 설비↔공정 짝 고지를 소리 내어 읽는다. AI 5단계 그림.
2. PART 2 단계 1: 계획 프롬프트 → 계획 응답 예시 → "어디가 이상한가?" 묻고 고친 점을 연다.
3. 단계 2·3: `week10_1_explore_start.ows`로 점검·정리 → Pivot Table 두 개로 설비·작업조 비교.
4. **여기서 쉬기**
5. 단계 4: `week10_2_predict_start.ows`로 기준선 → Tree → Tree Viewer → Test and Score → Confusion Matrix → Predictions.
6. 단계 5: 해석 프롬프트 → 해석 초안 응답 예시 → 학생에게 틀린 곳 두 개를 찾게 한 뒤 고친 점을 연다.
7. PART 3: 결론 문장 3개를 각자 써 본다(해보기) → 몇 명이 읽어 본다 → 예시를 연다 → "오늘 분석 한눈에 보기" 표 → 과정을 마치며.

## 준비물

- 프로젝터, Orange3, 가능하면 ChatGPT(무료 계정으로 충분). 못 쓰면 강의의 응답 예시 2개("실제 AI 응답 아님")로 진행한다.
- Orange: `week10_1_explore_start.ows`(점검·비교), `week10_2_predict_start.ows`(예측). `_done.ows`는 교수 참조용이며 학생에게 주지 않는다.
- 데이터(교육용 가상): `week10_capstone_lots.csv`(480행 13열), `week10_capstone_new_lots.csv`(10행 11열). ChatGPT에는 CSV를 올리지 않는다.

## 오늘 데이터 핵심 수치(실제 실행 결과, 강의 중 반드시 확인)

Orange 3.40 실측(`_done.ows` 실행). 공정 지도 위치: ②~⑤ + 세정 설비 기록(센서) → ⑦ EDS 결과, 새 로트는 ⑦ 검사 전.

- **단계 2 점검**: 480행. 빈칸 14칸(온도_C 5 · 진공도_mTorr 5 · 습도_pct 4, 14행 모두 합격 행). 온도 Max 3028, Mean 317.27. 입력 실수(소수점 누락) 3행: LOT-0017 3006.0 · LOT-0616 3028.0 · LOT-0534 2980.0.
  Select Rows(`온도_C` is below 1000) → **472행**(입력 실수 3 + 온도 빈칸 5가 함께 빠짐). Impute(Average/Most frequent) → 빈칸 0(진공도 5.0113, 습도 44.9338로 채움). `불량유형` 빈칸 364칸은 합격 행이라 정상.
- **단계 3 비교(Impute 뒤 472행)**: EQ-01 83.6% · EQ-02 78.7% · EQ-03 80.0% · **EQ-04 58.7%**(64/109), 설비 차이 **24.9%p**. A조 78.3% · **B조 73.1%** · C조 75.7%, 작업조 차이 **5.2%p**.
- **단계 4 예측(원본 480행으로 학습)**: 기준선 **75.8%**(364/480). Tree(깊이 4) 첫 질문 `진공도_mTorr ≤ 4.49`(36행 중 35행 -1), 옆 갈래 `> 5.49`(40행, -1 많음), 그 아래 `진동_mm_s ≤ 0.641`. CA **0.902**(10겹). Confusion Matrix 실제 1 → 344 · 20 / 실제 -1 → **27(놓침)** · 89.
  Predictions(`P(1) : P(-1)`): NEW-01·02·04·05 `0.896 : 0.104` · **NEW-03 `0.000 : 1.000 → -1`** · **NEW-06 `0.438 : 0.562 → -1`(애매)** · NEW-07~10 `0.972 : 0.028`. NEW-03 진공도 5.78(기준 밖), NEW-06 EQ-04·진동 0.720, NEW-09 진공도 4.52(기준 경계인데 합격 예측).
- **472행 / 480행**: 단계 3은 정리한 472행, 단계 4는 `predict` 캔버스의 원본 480행이다. 그래서 강의 단계 3에는 전체 합격률을 적지 않았다. 학생이 원본 480행으로 Pivot Table을 만들면 숫자가 조금 다르다(EQ-04 66/112) — 틀린 것이 아니니 몇 행 기준인지 적게 한다.

## 응답 예시에 심은 문제와 고친 문장(교수용)

응답 예시 2개는 모두 "실제 AI 응답 아님"이다. 아래는 **연습을 위해 일부러 심은 것**이며, 강의에도 "고친 점"으로 접어 두었다. 나머지 숫자는 위 핵심 수치와 같다.

- **계획 응답 예시**: 2단계 "빈칸이 없으므로 정리 단계 없이 바로 분석" → 빈칸 14칸, 튀는 값 3건. 점검·정리가 먼저다. 기준선(Distributions)과 Confusion Matrix가 빠진 것도 짚는다.
- **해석 초안 응답 예시** — 함정 2개
  1. "B조는 야간 작업이 많아서 집중력이 떨어져 불합격이 늘어난 것" → 근무 시간대는 데이터에 없는 말(AI가 지어냄)이고 원인 단정이다. 작업조 차이 5.2%p는 설비 차이 24.9%p보다 훨씬 작다.
  2. "결정 트리의 정확도는 90.2%로 높아서 이 모델은 믿을 만하며" → 기준선 75.8%와 놓친 불합격(116건 중 27건)이 빠졌다.
  - 함정 문장을 바꾸지 않는다. "B조"를 다른 조로 바꾸면 숫자까지 틀려 함정이 3개가 된다(가장 낮은 조는 B조).
- **평가 대신 확인**: 학생 결론 문장에 ① 숫자 + 비교 대상 ② 결론과 "원인 후보" ③ 가상 고지가 있는지 손가락으로 세어 피드백한다(점수 없음).

## 교수 설명 포인트

- 핵심 문장 두 개: "숫자는 Orange 화면으로 직접 확인한다", "함께 나타난 것은 원인 후보까지만 말한다".
- "오늘 분석 한눈에 보기" 표로 마무리한다 — 문제 → 점검 → 비교 → 예측 → 확인 → 보고. 각 단계가 몇 차시에서 배운 것인지 짚는다(점검 5, 비교 7, 예측 9).
- 작업조는 대조군이다. "가장 낮은 무리는 늘 있다 — 차이의 크기를 견준다"를 짚는다.
- 트리 갈림길(진공도 4.49 / 5.49, 진동 0.641)이 연습용 기준(4.5~5.5, 0.64)과 거의 같다는 점을 보여 주되, "트리가 썼으니 원인"이 아니라 "원인 후보"라고 말한다.
- **심어 둔 패턴(교수만, 학생에게 정답으로 공개하지 않는다)**: `scripts/generate_weekly_data.py`의 `gen_week10_capstone()`(시드 330).
  불합격 확률 = 0.04 + 0.75·[진공도 4.5~5.5 밖] + 0.60·[진동 0.64 초과] + 0.30·[온도 300±9 밖], 상한 0.9. 두께_nm = 100 + 0.5·(온도 − 300) + 잡음.
  진동은 EQ-04만 크게, 온도는 EQ-02만 넓게 만들었고, 작업조·공정명·가스유량·습도는 불합격과 관계없는 대조군이다. 새 로트의 생성상 불합격 확률은 NEW-03 0.79, NEW-06 0.64, 나머지 0.04.
  "원인은 현장 확인으로 정한다"가 수업의 결론이다.

## Orange 시연 체크리스트

- [ ] `week10_1_explore_start.ows`를 열고 File에 480행이 들어왔는지 본다. 파일 이름이 빨가면 `.ows`를 원래 폴더 밖으로 옮긴 것이다.
- [ ] File → Column Statistics: Missing, 온도_C의 Max·Mean을 짚는다.
- [ ] File → Select Rows(`온도_C` is below 1000) → Impute(Default Method: Average/Most frequent). 472행이 된 것을 보이고 "온도 빈칸 행도 함께 빠진다"를 말한다.
- [ ] Impute → Pivot Table 두 개(Rows 설비번호 / 작업조, Columns 합격여부). 1 칸 ÷ Total 칸을 칠판에 계산한다.
- [ ] `week10_2_predict_start.ows`: Distributions(합격여부) → Tree(깊이 4) → Tree Viewer → Test and Score(Number of folds 10, 새로 놓으면 5) → Confusion Matrix → Predictions(Show probabilities for → Classes known to the model). 새 로트 File은 Predictions에만 잇는다.

## 학생들이 자주 찾아볼 질문과 보충 설명

- **프롬프트 잘 쓰는 법**: AI가 "역할 부여"나 긴 형식을 권할 수 있다. 오늘 필요한 것은 데이터 설명·열 이름·쓸 도구·가상 데이터 네 가지다.
- **AI 환각 숫자 검증**: AI가 "출처를 물어보면 된다"고만 답하기도 한다. 오늘 방법은 숫자마다 Orange 화면에서 같은 숫자를 찾는 것이다.
- **상관관계와 인과관계**: AI가 "무작위 대조 실험"까지 길게 설명할 수 있다. 현장 확인(설비 점검, 조건을 바꿔 본 기록)으로 원인 후보를 좁힌다는 정도면 충분하다.

## 질문 예시

- "튀는 값 3건만 뺐는데 왜 472행이 됐을까요?"
- "정확도 0.902면 좋은 모델인가요? 무엇과 함께 말해야 하나요?"

## 예상 오개념

- AI가 숫자나 데이터 상태를 말하면 계산한 것이다 → 파일을 올리지 않았으므로 내가 준 숫자이거나 지어낸 것이다.
- 가장 낮은 무리(B조)가 원인이다 → 작업조 차이 5.2%p vs 설비 차이 24.9%p로 견주면 원인 후보로 보기에도 근거가 약하다.
- 정확도 90%면 믿을 만하다 → 기준선 75.8%와 놓친 불합격 27건을 함께 본다.
- 예측 -1 = 불합격 확정 → 점검 순서의 참고이고 ⑦ 검사는 그대로 한다.

## 막히는 지점 TOP3와 대처

1. **Select Rows 뒤 472행(오류 없음)** — 숫자 조건이 빈칸 행도 뺀다. 480행 그대로면 조건의 열·숫자를 확인한다.
2. **CA가 강의와 다름** — Number of folds가 5 그대로이거나 Tree 깊이가 4가 아니다.
3. **결론 문장을 못 씀** — 해보기의 ①②③ 칸을 하나씩 채우게 하고, "오늘 분석 한눈에 보기" 표의 숫자를 가져다 쓰게 한다.

## 실습 중 오류 대응

- Predictions에 확률이 없음: Show probabilities for를 Classes known to the model로 바꾼다. 예측 열이 없으면 Tree → Predictions 선이 없다.
- ChatGPT가 "파일을 올려 달라"고 함: 올리지 않고 "열 설명만으로 Orange3 위젯 계획을 세워 줘"라고 다시 요청한다.

## 빨리 끝낸 학생용 과제

- 진공도 기준 밖 합격률 보기: Impute 뒤 Select Rows(`진공도_mTorr` is outside 4.5, 5.5) → 76행 중 합격 9행. 기준 안과 비교해 한 문장으로 쓴다("원인 후보" 사용).
- NEW-09(진공도 4.52, 기준 경계)가 왜 합격 예측인지 Tree Viewer 갈림길(4.49)로 설명한다.

## 느린 학습자용 최소 과제
