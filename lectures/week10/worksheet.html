모델 평가와 새 데이터 예측 — 실습지

문제 1·2·4·5는 공정 기록 week09_pass_fail_train.csv(학습용 750행)와 새 로트 week09_new_lots_to_predict.csv(9개)로, 문제 3은 새 웨이퍼 week10_orange_new_wafers.csv(10장)로 푼다. 모두 교육용 가상 데이터다. 공정 지도 위치: 공정 기록 = ②~⑤ + 세정 공정 조건 → ⑦ 결과, 새 로트 = ②~⑤ + 세정을 마쳤지만 아직 ⑦ 검사 전, 새 웨이퍼 = ⑦ EDS 웨이퍼 맵 요약. 설비 4대(EQ-01~EQ-04)가 여러 공정 기록을 함께 남겼다(교육용 가상 기록). 문제 1~2는 학생용 노트북 3단계와 같다 — 노트북 1·2단계 셀을 먼저 실행해 model과 X_test·y_test를 만들어 둔다. 합격여부·예측은 1 = 합격, -1 = 불합격이다.

문제 1 — 시험용 147개 예측하고 불합격 예측 개수 세기 (노트북 3단계 문제 1)

새 로트는 정답을 아직 모르지만, 9차시에 떼어 둔 시험용 147개는 정답(y_test)을 안다. 모델이 시험용 147개 중 몇 개를 불합격으로 예측하는지 세자. 힌트: 강의 PART 2 "새 로트 예측하기"의 model.predict(new_lots[features]), (new_lots['예측'] == -1).sum()과 같은 모양이다. 시험용 X는 이미 features 열 6개로 되어 있다.

Python — 노트북 3단계 문제 1
# TODO: 시험용 X 이름과, 불합격을 뜻하는 숫자를 채우세요.

모델은 시험용 147개 중 몇 개를 불합격으로 예측했나?

X_test, -1 → 16. 147개 중 16개를 불합격으로 예측했다. y_test(정답)를 넣으면 ValueError: Expected a 2-dimensional container but got <class 'pandas.Series'> instead.로 시작하는 오류가 난다. 모델에는 단서 열(X)을 넣는다.
체크포인트 오류 없이 다른 숫자가 나오는 실수가 있다. 114가 나오면 X_test 대신 X(빈칸 행을 지운 735행 전체)를 넣은 것이다 — Confusion Matrix의 114와 우연히 같은 숫자라 맞는 줄 알기 쉽다. 131이 나오면 -1 대신 1을 넣어 합격 예측을 센 것이다. "-1"처럼 따옴표로 감싸면 0이 나온다.

문제 2 — 실제 불합격 개수와 함께 한 문장으로 보고하기 (노트북 3단계 문제 2, 직접 쓰기)

이번에는 빈칸이 없다. 강의 PART 2의 print(f"새 로트 {len(new_lots)}개 중 불합격 예측 {(new_lots['예측'] == -1).sum()}개")와 같은 모양으로 직접 쓴다. 출력 문장은 시험용 147개 중 실제 불합격 …개, 불합격 예측 …개다. 147은 len(y_test)로, 실제 불합격은 y_test에서, 불합격 예측은 문제 1의 test_pred에서 센다. 숫자를 직접 적지 말고 코드로 센다.

# TODO: 여기에 직접 써 보세요 — print(f"시험용 …개 중 실제 불합격 …개, 불합격 예측 …개")

실제 불합격 수와 불합격 예측 수를 비교하자. 이 숫자만으로 "모델이 불합격을 다 찾아냈다"고 말할 수 있을까?

print(f"시험용 {len(y_test)}개 중 실제 불합격 {(y_test == -1).sum()}개, 불합격 예측 {(test_pred == -1).sum()}개")

말할 수 없다. 실제 불합격은 31개인데 모델은 16개만 불합격이라고 했다. 16개가 모두 맞았더라도 적어도 15개는 합격으로 놓친 것이다. 정확도 80.3%만 보면 이 점이 안 보인다.

NameError: name 'test_pred' is not defined가 나면 문제 1 셀을 먼저 실행한다.

문제 3 — Orange 워밍업: 모델 셋 비교와 답이 갈린 웨이퍼

강의 PART 1 "워밍업 — 새 웨이퍼 10장"에서 연 week10_1_newwafers_start.ows(막히면 _done.ows)로 푼다.

  1. Tree(Limit the maximal tree depth to 4)·kNN·Logistic Regression을 위 File에 잇는다.
  2. Test and Score를 위 File에 잇고 세 모델을 모두 잇는다. Number of folds를 10으로 바꾸고 CA 열을 읽는다.
  3. Predictions를 아래 File에 잇고 세 모델을 모두 잇는다. 줄마다 세 모델의 답을 비교한다.
읽을 것내 답
CA — Tree / kNN / Logistic Regression( ) / ( ) / ( )
세 모델의 답이 갈린 웨이퍼ID( )

새 웨이퍼 10장(빨간 칸 = 불합격 다이, 교육용 가상 데이터).

답이 갈린 웨이퍼를 위 그림에서 찾아, 불합격 다이가 어떻게 놓여 있는지 한 줄로 적자. 왜 모델들이 헷갈렸을까?

CA: Tree 0.942 / kNN 0.900 / Logistic Regression 0.971(화면에 소수 셋째 자리까지 보인다). 학습용 240장 중 정상이 120장이라 기준선은 50%(0.50)다. 세 모델 모두 기준선보다 훨씬 높은 0.90 이상이다.
답이 갈린 웨이퍼: N-04(Tree 스크래치형, kNN·Logistic Regression 정상), N-10(Tree 중심형, kNN·Logistic Regression 정상).
그림에서(예): "N-04(9개)와 N-10(7개)은 불합격 다이가 적고, 가운데와 가장자리에 흩어져 있어 한 모양으로 보기 어렵다. 그래서 모델마다 다른 답을 냈다 — 사람이 웨이퍼 맵을 다시 볼 웨이퍼다."
체크포인트 CA가 조금 다르게 나오면 Number of folds가 5(처음 값) 그대로인지, Tree의 깊이가 4인지 확인한다. 답이 갈린 웨이퍼가 N-04 하나뿐이면 Tree 깊이를 4로 바꾸지 않은 것이다(깊이 100이면 N-10도 세 모델이 같은 답을 낸다). Predictions에 모델 이름 열이 안 생기면 모델에서 Predictions로 선을 잇지 않은 것이다. Test and Score에 아래 File(새 웨이퍼)을 이으면 정답 열이 없어 채점할 수 없다.

문제 4 — Orange 반도체: 새 로트 예측을 파이썬과 비교하기

Orange3에서 키트의 week10_2_newlots_start.ows를 연다. 위 File = 학습용 공정 기록 750행, 아래 File = 새 로트 9개다. 캔버스 메모 중 Tree 하나와 메모 ③·④(Predictions와 확률 보기)만 해도 된다.

  1. Model 묶음의 Tree를 위 File에 잇고, 더블클릭해 Limit the maximal tree depth to를 4로 바꾼다.
  2. Evaluate 묶음의 Predictions를 아래 File에 잇고, Tree도 Predictions에 잇는다.
  3. 새 데이터에는 정답 열이 없어 처음에는 확률이 안 보입니다. Predictions 표 위의 Show probabilities for를 Classes known to the model로 바꾸세요. Tree 열에 0.85 : 0.15 → 1 같은 글자가 보인다. 앞의 두 숫자는 차례로 1(합격)일 확률, -1(불합격)일 확률이고, 화살표 뒤가 예측이다.
읽을 것내 답
Orange Tree가 불합격(-1)으로 예측한 로트 수( )개
파이썬 predict()(강의 PART 2)와 예측이 다른 로트( )번째 로트
그 로트의 Orange 불합격(-1) 확률( )

두 도구의 예측이 다른 이유를 한 줄로 적자.

Orange Tree는 9개 모두 합격(1)으로 예측했다(불합격 예측 0개). 파이썬과 다른 로트는 3번째 로트(식각 · EQ-04)다 — 파이썬은 -1, Orange는 1. 그 로트의 Orange 불합격 확률은 0.26(0.74 : 0.26 → 1)으로, 9개 중 가장 높다.
다른 이유(예): "파이썬은 빈칸 행을 지운 뒤 학습용 588행으로 학습했고, Orange는 750행 전체로 학습했다. 트리의 기본 설정도 조금 다르다. 학습한 데이터와 설정이 달라 같은 결정 트리라도 예측이 달라질 수 있다." 두 도구 모두 3번째 로트를 가장 의심스럽게 봤다는 점은 이 로트부터 먼저 살펴볼 근거가 된다(가장 위험한 로트라는 확인은 아니다).
체크포인트 확률 없이 1만 보이면 Show probabilities for가 (None)인 것이다. 불합격 예측이 2개(1번째·8번째 로트)로 나오거나 3번째 로트 줄이 0.74 : 0.26 → 1이 아니면 Tree 깊이가 4인지, Tree를 위 File(학습용)에 이었는지 확인한다. 막히면 같은 폴더의 week10_2_newlots_done.ows를 연다.

문제 5 — 보고 문장 고쳐 쓰기

강의 PART 2의 "응답 예시(실제 AI 응답 아님 · 틀린 곳이 숨어 있음)"에서 찾은 틀린 숫자와 원인 단정 문장을 고쳐, 팀장에게 보낼 최종 보고 문장 세 개를 쓰자. 노트북 4단계 "고친 보고 문장" 칸에도 같은 문장을 쓴다.

문장 틀 "새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 ____개(____번째 로트, ______)입니다. 모델 정확도는 ____%로 모두 합격이라고 찍는 기준선 ____%와 큰 차이가 없어, 이 예측은 어느 로트부터 먼저 살펴볼지 정하는 참고로만 쓰고 온도 같은 공정 조건은 ________로만 봅니다. 이 결과는 ____________로 만든 것입니다."

하나 더 판단해 보자. 문제 4에서 Orange Tree는 3번째 로트를 합격(1)으로 예측했다. 이것만으로 "3번째 로트는 안전하니 검사를 건너뛰어도 된다"고 말할 수 있을까?

"새 로트 9개 중 결정 트리가 불합격으로 예측한 로트는 1개(3번째 로트, 식각·EQ-04)입니다. 모델 정확도는 80.3%로 모두 합격이라고 찍는 기준선 78.9%와 큰 차이가 없어, 이 예측은 어느 로트부터 먼저 살펴볼지 정하는 참고로만 쓰고 온도 같은 공정 조건은 불합격의 원인 후보로만 봅니다. 이 결과는 교육용 가상 데이터로 만든 것입니다."
고친 곳: 응답 예시의 "2개" → 1개, "온도가 낮아서 불합격이 생깁니다" → 온도는 불합격의 원인 후보로만 본다. 이 두 곳은 연습을 위해 일부러 심은 오류였다.
판단: 말할 수 없다. 예측은 확정 판정이 아니므로 모델이 좋든 나쁘든 ⑦ 검사는 그대로 한다 — 모델은 살펴볼 순서를 정하는 일을 도울 뿐이다. 게다가 이 모델은 정확도가 기준선과 큰 차이가 없고, 같은 로트를 파이썬은 불합격으로 예측했으며 Orange에서도 불합격 확률(0.26)이 9개 중 가장 높았다.
