# 10주 교육과정 설계 (Curriculum) — v2

대상: 프로그래밍 경험이 **전혀 없는** 일반인. 매주 2시간, 총 10주.
목표: 전문 데이터 과학자 양성이 아니라, 반도체 공정 데이터를 스스로 열어보고
"어떤 설비에서 문제가 있었는가"를 데이터로 설명하고, 간단한 합격/불합격 예측 모델까지
직접 만들어 볼 수 있게 하는 것.

공통 색상 의미: 🔵 개념 · 🟢 정상/합격/성공 · 🟠 주의/확인 필요 · 🔴 이상/불량/오류 · 🟣 실습/도전.

> **v2 변경 이유**: v1(최초 설계)은 프로그래밍 완전 초보자에게 파이썬 기초(변수·리스트·딕셔너리·
> 조건문·반복문·함수) 없이 바로 Pandas부터 시작해 진입장벽이 높았다. 또한 9주차 `fab.csv`
> (590개 센서, 고차원 데이터)는 반도체 산업 이해나 파이썬 숙련도와 무관하게 난이도가 급격히
> 높아지는 구간이었다. v2는 ①앞부분에 파이썬 기초 2주를 배치하고, ②코드 작성이 아직 낯선
> 학습자를 위해 중간중간 **Orange3**(마우스 클릭 기반 노코드 데이터 분석 도구)로 같은 데이터를
> 다시 확인해보는 활동을 추가하며, ③마지막 예측 실습은 `fab.csv` 대신 1주차부터 다뤄온
> `반도체_공정_샘플.csv` 계열 데이터로 **합격/불합격 예측 모델을 만들고 새 데이터를 예측**해보는
> 것으로 단순화한다. `fab.csv`는 핵심 커리큘럼에서 제외하고, 희망하는 반에 한해 강사가 선택적으로
> 다루는 심화/부록 자료로만 남긴다.
>
> 이 문서는 **설계(구성) 문서**이며, 각 주차의 실제 HTML/노트북/데이터는 이후 세션에서 주차별로
> 다시 작성한다. v1 대비 무엇이 재사용 가능하고 무엇이 새로 필요한지는
> [`docs/restructure-plan.md`](restructure-plan.md)를 참고한다.

## Week 01. 반도체 공정과 데이터 처음 만나기

- **선수 지식**: 없음(첫 주차)
- **학습 목표**: 반도체/웨이퍼/칩의 차이 이해, 공정 흐름 이해, 데이터가 왜 생기는지 이해,
  Colab 화면에 익숙해지고 이미 만들어진 코드를 실행해 결과를 관찰한다(직접 코드 작성은 최소화).
- **오늘의 질문**: "반도체는 어떻게 만들어지고, 그 과정은 어떤 기록을 남길까?"
- **이론**: 반도체란 무엇인가, 웨이퍼→칩 제작 흐름, FAB의 의미, 공정 설비와 센서, 데이터의 행과 열,
  합격/불합격, "이 과정에서 파이썬을 왜 배우는가"에 대한 동기부여
- **실습**: Colab 열기, 이미 준비된 셀 실행해보기(Shift+Enter), CSV 업로드, `head()`로 표 구경하기,
  `value_counts()`로 합격/불합격 세어보기 — 코드는 강사가 제공, 학습자는 실행과 관찰에 집중
- **데이터**: 1주차 개요용 데이터(기존 `week01_semiconductor_process_overview.csv` 재사용 가능)
- **핵심 질문 → 데이터 연결**: 합격과 불합격은 몇 건인가?

## Week 02. 파이썬 기초 Ⅰ — 변수, 자료형, 리스트, 딕셔너리

- **선수 지식**: 1주차 — Colab 사용법
- **학습 목표**: 변수에 값 저장하기, 숫자/문자열/불리언 구분, 리스트로 여러 값 담기,
  딕셔너리로 이름표 붙여 값 관리하기. 반도체 공정 예시로 자료형 감각 익히기.
- **오늘의 질문**: "측정값 하나하나를 어떻게 이름 붙여 기억하고, 여러 개를 한 번에 담을 수 있을까?"
- **이론**: 변수와 대입, 숫자형/문자열형/불리언, 리스트(순서 있는 여러 값), 인덱싱, 딕셔너리(키-값 쌍),
  리스트 vs 딕셔너리를 언제 쓰는가
- **실습**: 온도 하나를 변수에 저장 → 하루치 온도 여러 개를 리스트에 저장 → 리스트 길이·특정 위치 값
  꺼내기 → 설비 1대의 정보(설비번호·공정명·온도)를 딕셔너리로 표현 → 여러 설비를 딕셔너리의 리스트로
  표현해보기
- **데이터**: 소량의 측정값 예시(기존 `week02_basic_process_values.csv` 일부 재사용 가능, 리스트/딕셔너리
  실습에 맞게 축소된 별도 예시 필요)
- **핵심 질문 → 데이터 연결**: 이 리스트에서 가장 높은 온도와 가장 낮은 온도는 몇 번째 값인가?

## Week 03. 파이썬 기초 Ⅱ — 조건문, 반복문, 함수

- **선수 지식**: 2주차 — 변수·리스트·딕셔너리
- **학습 목표**: `if`로 조건에 따라 다르게 판단하기, `for`로 여러 값을 반복 처리하기, `def`로 반복되는
  계산을 함수로 만들어 재사용하기. "합격/불합격을 코드로 직접 판정"해보는 것이 이번 주 목표.
- **오늘의 질문**: "온도가 정상 범위를 벗어났는지, 사람이 눈으로 보지 않고 컴퓨터가 대신 판단하게
  하려면 어떻게 해야 할까?"
- **이론**: 비교 연산자(`>`, `<`, `==`), `if`/`elif`/`else`, `for`로 리스트 순회하기, 누적 합/개수 세기,
  함수 정의와 호출, 매개변수와 반환값
- **실습**: 온도 하나를 조건문으로 정상/비정상 판정 → `for`로 리스트의 모든 온도를 순회하며 정상 개수
  세기 → 평균 계산을 함수로 만들기 → 합격/불합격 판정을 함수로 만들어 여러 로트에 반복 적용 →
  직접 만든 함수 결과와 4주차부터 배울 Pandas 결과를 비교(예고)
- **데이터**: 2주차와 동일 계열 데이터 재사용(로트 여러 개, 온도/합격여부 포함)
- **핵심 질문 → 데이터 연결**: 내가 만든 판정 함수로 걸러낸 불합격 로트 수는 몇 개인가?

## Week 09. 머신러닝으로 합격/불합격 예측하기 (+ Orange3로 모델 비교)

- **선수 지식**: 1~8주차 전체 — 특히 3주차(조건문으로 직접 판정)와 8주차(상관관계) 위에 "예측"이라는
  새 관점을 얹는다
- **학습 목표**: `반도체_공정_샘플.csv` 계열 데이터로 합격/불합격을 예측하는 간단한 분류 모델을
  scikit-learn으로 만들고, **새 측정값을 넣어 예측**까지 해본다. 같은 모델을 Orange3(Tree, Test and
  Score, Predictions 위젯)로도 만들어보며 두 방식의 결과를 비교한다. (v1의 `fab.csv` 590센서 실습은
  난이도가 높아 핵심 과정에서 제외 — 희망 시 강사가 심화 부록으로 별도 진행)
- **오늘의 질문**: "온도·압력 같은 측정값만 보고, 이 로트가 합격일지 불합격일지 미리 알 수 있을까?"
- **이론**: Feature(특징)와 Label(정답), train/test 분리, 분류(classification), 정확도, 혼동행렬,
  "정상이 대부분인 데이터"에서 정확도만 보면 안 되는 이유, 새 데이터에 대한 예측(`predict()`)
- **실습**: `반도체_공정_샘플.csv` 계열 데이터 불러오기 → 결측치 처리(4~5주차 복습) → Feature/Label
  나누기 → `train_test_split` → `DecisionTreeClassifier` 학습 → 정확도·혼동행렬 확인 → 새로운 측정값
  1건을 직접 입력해 `predict()`로 합격/불합격 예측 → **Orange3 실습**: File → Tree(또는 다른 분류기)
  → Test and Score → Predictions 위젯으로 동일한 데이터에 대해 코드 없이 모델을 만들고 정확도 비교
- **데이터**: `반도체_공정_샘플.csv` 기반으로 학습에 충분한 행 수를 갖춘 신규 파생 데이터 필요
  (원본은 200행·결측 다수라 그대로 쓰기 어려움 — 데이터 설계 개정 시 확정)
- **핵심 질문 → 데이터 연결**: 내가 새로 입력한 측정값에 대해 두 방식(scikit-learn/Orange3)의 예측이
  같은가? 다르다면 왜 다를 수 있는가?

## 주차 간 연결 원칙

- 2~3주차의 파이썬 기초(변수·리스트·딕셔너리·조건문·반복문·함수)는 이후 모든 주차에서 "Pandas가
  대신 해주는 일"로 반복 연결한다(예: 4주차 "3주차에 `for`+`if`로 했던 걸 한 줄로").
- 이론은 매주 새로 반복하지 않고 이전 주차 개념 위에 한 단계씩만 추가한다.
- 코드는 이전 주차에서 배운 함수를 재사용하고, 매주 새 함수는 3~5개 이내로 제한한다.
- Orange3는 5·6·8·9주차에서 "코드로 먼저 해본 것을 코드 없이 재확인"하는 순서로만 사용하고, Orange3
  단독으로 새 개념을 먼저 도입하지 않는다.
- "결과 해석 문장 쓰기"는 1주차부터 10주차까지 매주 포함되는 고정 활동이다.
- 8주차부터는 "상관관계 ≠ 원인"이라는 문구를 반복 강조해 10주차 보고서 작성 습관, 그리고 9주차의
  "예측이 맞았다고 원인을 안다는 뜻은 아니다"라는 메시지로 연결한다.
- `fab.csv`는 핵심 10주 과정에서 제외한다. 다루고 싶은 반은 9주차 이후 선택 부록으로만 진행하고,
  그 경우에도 Sensor0~589의 실제 물리적 의미는 절대 단정하지 않는다(`CLAUDE.md` 규칙 유지).
