# 10차시 교육과정 설계 (Curriculum) — v3

대상: 프로그래밍 경험이 **전혀 없는** 일반인. 총 10차시.
목표: 전문 데이터 과학자 양성이 아니라, 반도체 공정 데이터를 스스로 열어 보고
"어떤 설비에서 문제가 있었는가"를 데이터로 설명하고, 간단한 합격/불합격 예측 모델까지
직접 만들어 볼 수 있게 하는 것. 그 과정이 **재미있어야** 끝까지 따라온다.

공통 색상 의미: 파랑 개념 · 초록 정상/합격/성공 · 주황 주의/확인 필요 · 빨강 이상/불량/오류 · 보라 실습.

> **v3 변경 이유(2026-10-23)**: v2와 그 뒤 두 차례 초보자 눈높이 개정(2026-10-02, 10-08)을 거쳐도 차시 대부분이
> 파이썬 코드였고, Orange3는 5~10차시에 짧은 "예고편"으로만 나왔다. 프로그래밍이 처음인 수강생에게는 여전히
> 무거웠다. v3는 다음을 바꾼다.
> 1. **파이썬은 초보 필수만** — 차시당 새 활성 개념 4개 이하.
> 2. **Orange3가 본 활동** — 1차시부터 매 차시, 쉬운 워밍업 데이터 → 반도체 데이터 순서로 "데이터 분석이 뭔지" 체감한다.
>    Orange는 그날 파이썬에서 배운 것을 넓혀 보는 역할이다(파이썬에서 뺀 박스플롯·빈칸 채우기·혼동행렬 등을 맡는다).
> 3. **수업은 PART 1·2·3** — 1~8차시는 파이썬 → Orange3 → 실습지, 9·10차시는 Orange3 → 파이썬 최소 + ChatGPT 체험 → 실습지.
> 4. **찾아보기 질문** — 배경지식이 필요한 곳에 검색어·ChatGPT 질문·확인 포인트를 붙인다(평가하지 않는다).
> 5. **"신입 데이터 담당자의 10일"** 이야기로 차시를 잇는다(hero의 "오늘의 미션" 한 줄. 이야기·데이터 모두 가상).
> 6. **실습지는 기본 5문제**(파이썬 3 + Orange 1 + 해석 문장 1, 9·10차시는 파이썬 2 + Orange 2 + 해석 1), 퀴즈는 8~10문항으로 수업 후 자율 복습.
> 7. **Orange 워밍업은 직접 만든 가상 데이터만**(1~3차시 생활 공공데이터풍, 4~10차시 반도체·공정 이해용). 열 이름은 한국어 + 영문/SI 단위.
>
> **시간 정보 제거 정책은 그대로다.** 이 문서와 모든 강의 자료에는 분·시간을 쓰지 않는다. 콘텐츠 분량을 재는 내부
> 저작 기준은 `.claude/skills/curriculum-spec/SKILL.md`에만 있다. v1 → v2 → v3 변경 배경은
> [`docs/restructure-plan.md`](restructure-plan.md)를 본다.
>
> 차시 제목과 10차시 구성은 v2와 같다. 차시별 실제 구현 스펙은 작업 중 `_workspace/01_architect_spec.md`에 있다.

## 공통 수업 구조

| | 1~8차시 | 9·10차시 |
|---|---|---|
| PART 1 | **파이썬** — 생활 예제로 개념 → 반도체 데이터로 확인하기(같은 코드에서 열 이름만 바꾸기) | **Orange3** — 모델을 먼저 눈으로 본다 |
| PART 2 | **Orange3** — 워밍업 데이터 → 반도체 데이터 → 파이썬 결과와 비교 한 문장 | **파이썬 최소 + ChatGPT 체험** — 같은 결과를 코드 몇 줄로 확인하고, AI가 준 코드·문장을 실제 숫자로 검증 |
| PART 3 | **실습지** — 노트북 반도체 TODO 3문제 + Orange 1문제 + 해석 문장 1 | **실습지** — 노트북 반도체 TODO 2문제 + Orange 2문제(워밍업 1 + 반도체 1) + 해석 문장 1 |

- 강의 HTML은 PART마다 앵커(`#part1`, `#part2`, `#part3`)를 두고, "오늘 수업 구성" 표에서 이동한다. 시간은 쓰지 않는다.
- 노트북(학생용·정답)은 **파이썬 PART만** 담는다. 맨 위 "막혔을 때" 안내 셀 → 생활 예제(완성 코드) → 반도체 확인(완성 코드) →
  반도체 실습(TODO, 실습지 문제 1~3과 같은 번호) → AI 단계.
- Orange3 워크플로는 차시마다 4개 — 워밍업·반도체 각각 `_start.ows`(데이터가 연결된 File 위젯 하나 + 한국어 안내 주석)와
  `_done.ows`(완성본). Orange는 `data/weekly/weekXX/orange/*.tab`(생성 스크립트가 CSV에서 파생)만 연다. **Orange 내장 데이터(zoo·iris·titanic 등)는
  쓰지 않는다.**
- **Orange 워밍업 데이터**(모두 시드 고정 가상 데이터, `weekXX_orange_<주제>.csv`): 1~3차시는 생활 공공데이터처럼 생긴 데이터(동네 인구·
  지하철 승하차·대기환경)로 그날 파이썬 개념에 맞는 위젯을 익히고, 4~10차시는 반도체·공정 이해를 쌓는 데이터(8대 공정 흐름표·클린룸 환경·
  웨이퍼 맵·챔버 센서·웨이퍼 패턴)로 Orange에서 깨달음 한 가지를 얻은 뒤 그날 반도체 데이터로 넘어간다.
- **열 이름은 한국어 이름 + 영문/SI 단위**(`기온_C`, `PM10_ug_m3`, `승차인원_count`, `가격_KRW`, `풀이시간_sec`). 기존 CSV의 한국어 단위 열
  (`온도_섭씨` 등)은 그 차시를 다시 만들 때 이름만 바꾼다(값은 그대로).
- **이해용 그림**(공정 흐름도, 웨이퍼 맵 등)은 `scripts/generate_figures.py`가 데이터에서 그려 `assets/images/generated/`에 둔다.
  Orange 화면은 캡처 자리로 남긴다.
- 운영안 "수업 흐름"은 순서와 "여기서 쉬기" 표시만 쓴다.

## Phase 1 · 첫걸음 — 개념과 파이썬 기초 (1~3차시)

### 1차시. 반도체 공정과 데이터 처음 만나기 + 변수·출력

- **선수 지식**: 없음(첫 차시). PART 1 첫 단계는 "환경 확인"(Jupyter에서 첫 셀 실행).
- **학습 목표**: 웨이퍼·칩·공정 흐름과 공장이 기록을 남기는 이유를 내 말로 설명한다. 변수에 값을 저장하고 `print()`·f-string으로
  문장을 출력한다. `type()`으로 숫자와 글자를 구분한다. Orange3에서 표를 열고 합격·불합격 막대를 읽는다.
- **오늘의 질문**: "반도체는 어떻게 만들어지고, 그 과정은 어떤 기록을 남길까?"
- **오늘의 미션**: 입사 첫날, 공장 기록표 40건을 받았다 — 합격·불합격이 몇 건인지 한 문장으로 보고하자.
- **다룰 내용**: 반도체와 공장 데이터 한눈에 보기(웨이퍼 → 칩, 공정, 로트·설비·센서, 표의 행과 열) → 변수와 대입, 자료형, `print()`,
  f-string → Orange3 첫 만남(우리 동네 인구 → 1차시 공정 기록, Distributions로 가장 흔한 연령대·합격·불합격 막대).
  반도체 개요는 생활 비유(웨이퍼 = 피자 도우, 칩 = 피자 조각 등)와 공정 흐름 그림으로 짧게 하고, 공정 이해는 4차시 공정 흐름표에서 다시 연다.
- **새 개념 예산**: 활성 4개 — `=`(계산 결과 저장 포함), `print()`, f-string, `type()`.
  **노출 전용**: `input()`(한 줄 시연, 평가 안 함), "AI로 한 걸음 더" 예시 코드의 `if`/`else`.
- **실습 흐름**: 첫 셀 실행 → 변수 만들기 → 자료형 → 문장 출력 → 계산한 값을 문장에 넣기 → 반도체 확인(합격 32·불합격 8, 불합격률)
  → Orange(동네 인구 → 공정 기록) → 실습지
- **데이터**: `week01_semiconductor_process_overview.csv`(Orange: `orange/week01_semiconductor_process_overview.tab`), Orange 워밍업 `week01_orange_town_population.csv`
- **핵심 질문 → 데이터 연결**: 합격과 불합격은 각각 몇 건이며, 변수에 담아 문장으로 출력하면 어떻게 되는가?

### 2차시. 리스트와 딕셔너리

- **선수 지식**: 1차시 — 변수·`print()`·f-string, Orange File·Data Table
- **학습 목표**: 리스트에 여러 값을 담고 인덱스로 꺼낸다. `len()`·`append()`로 세고 더한다. `max()`·`min()`·`sum()`으로 최고·최저·평균을
  구한다. 딕셔너리로 값에 이름표를 붙이고 키로 꺼낸다.
- **오늘의 질문**: "여러 개의 측정값을 한 번에 담고, 각 값에 이름표까지 붙이려면 어떻게 해야 할까?"
- **오늘의 미션**: 팀장이 EQ-03 설비 온도 7개를 메모로 줬다 — 최고·최저·평균을 정리해 보고하자.
- **다룰 내용**: 리스트·인덱스, `len`·`append`, `max`·`min`·`sum`과 평균, 딕셔너리 만들기·키로 꺼내기, (구경) 딕셔너리의 리스트 = 표 →
  Orange(지하철 역별 승하차 — 평균만 보면 안 보이는 붐비는 역 → 설비 온도, Feature Statistics로 최고·최저·평균을 파이썬 결과와 대조)
- **새 개념 예산**: 활성 4개 — 리스트·인덱스, `len`/`append`, `max`/`min`/`sum`, 딕셔너리.
  **노출 전용**: 슬라이싱, 딕셔너리의 리스트(완성 코드로 "표의 한 행 = 딕셔너리 하나"만 보여 준다).
- **실습 흐름**: 리스트 → `len`·`append` → 최고·최저·평균 → 딕셔너리 → 반도체 확인(EQ-03 온도 7개) → Orange → 실습지
- **데이터**: `week02_python_basics_1.csv`(리스트 값으로 옮겨 사용), Orange 워밍업 `week02_orange_subway_ridership.csv`
- **핵심 질문 → 데이터 연결**: EQ-03 온도 7개 중 최고·최저는 몇 도이고, 평균은 표 전체 평균과 어떻게 다른가?

### 3차시. 리스트·딕셔너리로 배우는 조건문·반복문·함수

- **선수 지식**: 2차시 — 리스트·인덱스·딕셔너리 키 / 1차시 — f-string
- **학습 목표**: 비교 연산자와 `if`/`else`로 정상 범위를 판정한다. `for`로 하나씩 꺼내며 개수를 센다. `def`로 판정 함수 하나를 만들어
  여러 값에 쓴다. Orange Select Rows로 같은 조건을 골라내 개수를 비교한다.
- **오늘의 질문**: "리스트에 담긴 여러 설비 정보를 하나씩 살펴보며, 조건에 맞는 것만 컴퓨터가 골라내게 할 수 있을까?"
- **오늘의 미션**: 기록 30건을 하나씩 보는 대신, 온도 규칙으로 자동 판정해 주는 작은 도우미를 만들자.
- **다룰 내용**: 비교 연산자, `if`/`else`, `for`로 개수 세기, 함수 하나(`check_range` — "범위 안/밖"을 돌려줌, 합격 판정과 구분) → Orange(우리 동네 대기환경 — 미세먼지 등급도 기준 범위로 붙인
  판정이다 → 기록 30건, Select Rows)
- **새 개념 예산**: 활성 3개 — 비교 연산자+`if`/`else`, `for` 개수 세기, `def`/`return` 함수 하나.
  **노출 전용**: `elif`, `+=`.
- **실습 흐름**: 비교와 if → if/else 범위 판정 → for로 세기 → 함수 → 함수와 for 함께 → 반도체 확인(범위 밖 12건, 그중 실제 불합격 3건) →
  Orange → 실습지
- **데이터**: `week03_python_basics_2.csv`(2차시와 같은 계열), Orange 워밍업 `week03_orange_air_quality.csv`
- **핵심 질문 → 데이터 연결**: 내가 만든 판정 함수로 걸러낸 기록은 몇 건이고, 그중 실제로 불합격한 기록은 몇 건인가?

## Phase 2 · 데이터 다루기 (4~6차시)
