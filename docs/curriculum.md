# 10차시 교육과정 설계 (Curriculum) — v2

대상: 프로그래밍 경험이 **전혀 없는** 일반인. 총 10차시.
목표: 전문 데이터 과학자 양성이 아니라, 반도체 공정 데이터를 스스로 열어보고
"어떤 설비에서 문제가 있었는가"를 데이터로 설명하고, 간단한 합격/불합격 예측 모델까지
직접 만들어 볼 수 있게 하는 것.

공통 색상 의미: 🔵 개념 · 🟢 정상/합격/성공 · 🟠 주의/확인 필요 · 🔴 이상/불량/오류 · 🟣 실습/도전.

> **v2 변경 이유**: 최초 설계(v1)는 프로그래밍 완전 초보자에게 파이썬 기초 없이 바로 Pandas부터
> 시작해 진입장벽이 높았고, 9차시의 `fab.csv`(590개 센서)는 난이도가 급격히 높아지는 구간이었다.
> v2는 ①앞부분에 파이썬 기초를 배치하고, ②마지막 예측 실습은 `fab.csv` 대신
> `반도체_공정_샘플.csv` 계열 데이터로 단순화한다. `fab.csv`는 핵심 커리큘럼에서 제외하고,
> 희망하는 반에 한해 강사가 선택적으로 다루는 심화/부록 자료로만 남긴다.
>
> **후속 조정(같은 v2 안에서의 개편)**: 아래 세 가지를 반영해 차시별 구성을 다시 배치했다.
> 1. **용어**: "주/주차" 대신 **"차시"**로 통일한다(예: "1주차" → "1차시", "10주 과정" → "10차시 과정").
>    폴더/파일 이름(`lectures/week01/`, `data/weekly/week01/` 등)은 내부 관리용 영어 표기라 그대로
>    두고, 화면에 보이는 한글 설명만 바꾼다.
> 2. **Orange3 순서**: 기존에는 "코드로 먼저 해본 것을 Orange3로 재확인"하는 순서였지만, 이제는
>    반대로 **Orange3로 먼저 데이터를 훑어보고 나서 파이썬 코드로 분석하는 순서**로 바꾼다. 초보자가
>    코드를 쓰기 전에 "이 데이터가 어떤 모습인지" 눈으로 먼저 확인하면, 이어지는 코드가 왜 필요한지
>    더 쉽게 이해할 수 있다는 목적이다.
> 3. **차시별 내용 재배분**: 1~3차시(파이썬 기초)를 변수/출력 → 리스트/딕셔너리 → 조건문/반복문/함수
>    순서로 다시 나누고, 7차시에도 Orange3를 새로 추가하며, 9~10차시는 미니 프로젝트 대신
>    **머신러닝 예측 실습을 두 차시로 확장**해 Orange3 확인까지 충분히 다룬다. 자세한 배경은
>    [`docs/restructure-plan.md`](restructure-plan.md)를 참고.
>
> 이 문서는 **설계(구성) 문서**이며, 각 차시의 실제 HTML/노트북/데이터는 이후 세션에서 순서대로
> 구체화한다(현재는 제목·학습 목표·다룰 내용 정도의 개요만 있는 차시가 많다).

## Phase 1 · 첫걸음 — 개념과 파이썬 기초 (1~3차시)

### 1차시. 반도체 공정과 데이터 처음 만나기 + 변수·출력

- **선수 지식**: 없음(첫 차시)
- **학습 목표**:
  - 반도체/웨이퍼/칩의 차이, 공정 흐름, 데이터가 왜 생기는지 이해한다.
  - Jupyter Notebook 화면에 익숙해지고, 이미 만들어진 코드를 실행해 결과를 관찰한다.
  - **파이썬 변수**에 값을 저장하고, **`print()`로 출력**하는 방법을 익힌다(숫자형/문자열형 구분 포함).
- **오늘의 질문**: "반도체는 어떻게 만들어지고, 그 기록을 파이썬으로 어떻게 담고 출력할 수 있을까?"
- **다룰 내용**: 반도체란 무엇인가, 웨이퍼→칩 제작 흐름, FAB의 의미, 공정 설비와 센서, 데이터의 행과
  열, 합격/불합격 표기 → (신규) 변수와 대입, 숫자형/문자열형/불리언, `print()`로 값 확인하기
- **실습 흐름**: Jupyter Notebook 열기 → CSV 열기 → `head()`/`value_counts()` 관찰(강사 시연 중심) → 오늘 관찰한
  숫자(예: 합격 건수)를 변수에 직접 저장하고 `print()`로 출력해보기
- **데이터**: 1차시 개요용 데이터(`week01_semiconductor_process_overview.csv`)
- **핵심 질문 → 데이터 연결**: 합격과 불합격은 각각 몇 건이며, 그 값을 변수에 담아 문장으로
  출력하면 어떻게 되는가?

### 2차시. 리스트와 딕셔너리

- **선수 지식**: 1차시 — 변수·자료형·출력
- **학습 목표**: 리스트에 여러 값을 담고 인덱싱·슬라이싱·추가로 다룰 수 있다. 딕셔너리로 값에
  이름표를 붙여 관리할 수 있다. 리스트와 딕셔너리를 충분한 예제로 반복 연습한다.
- **오늘의 질문**: "여러 개의 측정값을 한 번에 담고, 각 값에 이름표까지 붙이려면 어떻게 해야 할까?"
- **다룰 내용**: 리스트 생성·인덱싱·슬라이싱·추가(append)·길이(len), 딕셔너리 생성·키로 값 접근·값
  수정, 리스트 안에 딕셔너리 담기(여러 설비를 한 번에 표현)
- **실습 흐름**: 온도 여러 개를 리스트에 담고 최댓값/최솟값/평균 직접 계산 → 설비 1대 정보를
  딕셔너리로 표현 → 여러 설비를 "딕셔너리의 리스트"로 표현하고 특정 값 꺼내기
- **데이터**: `week02_python_basics_1.csv`(리스트/딕셔너리 리터럴로 변환해 사용)
- **핵심 질문 → 데이터 연결**: 이 리스트에서 가장 높은 온도와 가장 낮은 온도를 가진 값은 몇 번째인가?

### 3차시. 리스트·딕셔너리로 배우는 조건문·반복문·함수

- **선수 지식**: 2차시 — 리스트·딕셔너리
- **학습 목표**: `if`로 조건 판정, `for`로 리스트/딕셔너리 순회, `def`로 함수를 만들어 재사용한다.
  2차시에서 만든 리스트·딕셔너리 예제를 그대로 활용해 "합격/불합격을 코드로 직접 판정"해본다.
- **오늘의 질문**: "리스트에 담긴 여러 설비 정보를 하나씩 살펴보며, 조건에 맞는 것만 컴퓨터가 골라내게
  할 수 있을까?"
- **다룰 내용**: 비교 연산자, `if`/`elif`/`else`, `for`로 리스트·딕셔너리 순회, 누적 합/개수 세기,
  함수 정의·매개변수·반환값
- **실습 흐름**: 온도 하나를 조건문으로 판정 → `for`로 리스트 전체를 순회하며 정상 개수 세기 →
  "딕셔너리의 리스트"를 순회하며 조건에 맞는 설비만 골라내기 → 평균 계산 함수, 합격/불합격 판정
  함수를 만들어 여러 로트에 반복 적용
- **데이터**: `week03_python_basics_2.csv`(2차시와 동일 계열)
- **핵심 질문 → 데이터 연결**: 내가 만든 판정 함수로 걸러낸 불합격 로트 수는 몇 개인가?

## Phase 2 · 데이터 다루기 (4~6차시)

### 4차시. Pandas 가장 기본적인 부분

- **선수 지식**: 3차시 — 반복문·함수로 직접 했던 일을 Pandas가 어떻게 한 번에 처리하는지 연결
- **학습 목표**: `read_csv`로 CSV를 읽고, 열 선택·간단한 조건 검색·정렬 같은 **가장 기본적인** Pandas
  사용법을 익힌다(고급 기능은 다루지 않는다).
- **오늘의 질문**: "3차시에 반복문으로 한 줄씩 처리했던 일을, Pandas는 어떻게 한 번에 처리할까?"
- **다룰 내용**: CSV와 DataFrame, 열 선택, 조건 검색(불리언 인덱싱), 정렬, `head`/`shape`/`columns`,
  `loc`/`iloc`(이름·위치 기반 접근)
- **실습 흐름**: `read_csv()` → 열 선택 → 특정 설비만 조건 검색 → 정렬 → `loc`/`iloc` 연습 →
  3차시 함수 결과와 Pandas 조건 검색 결과 개수 맞춰보기
- **데이터**: `week04_process_filtering.csv`
- **핵심 질문 → 데이터 연결**: EQ-02에서 발생한 불합격은 몇 건인가?

### 5차시. 데이터 훑어보기와 정리(EDA) — Orange3로 먼저 확인

- **선수 지식**: 4차시 — 조건 검색
- **학습 목표**: **Orange3로 먼저** 데이터를 열어 결측값·이상값이 있어 보이는 곳을 눈으로 확인한 뒤,
  Pandas 코드로 실제 결측값·중복값·이상값을 찾아 정제한다.
- **오늘의 질문**: "코드를 한 줄도 쓰기 전에, 이 데이터에 어떤 문제가 있어 보이는지 먼저 확인할 수
  있을까?"
- **다룰 내용(순서대로)**:

     음수 압력·비정상 온도 등을 찾아 정리하고, 정제 전후를 비교한다.
- **데이터**: `week05_dirty_process_data.csv`(Orange3·Pandas 동일 CSV 사용)
- **핵심 질문 → 데이터 연결**: Orange3에서 눈으로 확인한 문제와 Pandas로 찾은 문제가 같은가? 정제
  전후 평균 온도는 얼마나 달라지는가?

## Phase 3 · 비교와 원인 탐색 (7~8차시)

### 7차시. 설비·공정 비교와 수율·불량 분석 — Orange3로 먼저 확인(신규)

- **선수 지식**: 6차시 — 그래프로 관찰한 차이
- **학습 목표**: **Orange3로 먼저** 설비별 분포·수율 차이가 있어 보이는지 훑어본 뒤, `groupby` 집계로
  직접 수치를 계산해 확인한다. 수율·불량률을 계산하고 파레토 관점에서 원인을 찾는다.
- **오늘의 질문**: "설비마다 차이가 있어 보이는데, 숫자로 계산해도 정말 그럴까?"
- **다룰 내용(순서대로)**:

  2. **파이썬으로 확인** — `groupby`로 설비별 평균값·합격률 계산, 로트 단위 수율 계산, 불량 유형
     집계와 파레토 차트로 실제 수치를 확인한다.
- **데이터**: `week07_equipment_yield.csv`
- **핵심 질문 → 데이터 연결**: Orange3에서 받은 인상과 `groupby`로 계산한 수치가 일치하는가? 불량률이
  가장 높은 설비와 수율이 가장 낮은 로트는 같은 설비에서 나왔는가?

### 8차시. 공정 이상과 원인 후보 찾기 — Orange3로 먼저 확인

- **선수 지식**: 5차시(이상값) + 7차시(수율) — 이상값과 불량의 관계 탐색으로 종합
- **학습 목표**: **Orange3 Correlations 위젯으로 먼저** 변수 간 관계를 훑어본 뒤, Pandas `corr()`와
  조건 검색으로 직접 확인한다. "원인 후보"라는 표현을 사용하는 이유를 이해한다.
- **오늘의 질문**: "여러 변수 중 관련 있어 보이는 쌍을 미리 찾아보고, 정말 그런지 계산으로 확인할 수
  있을까?"
- **다룰 내용(순서대로)**:
  1. **Orange3 먼저 훑어보기** — Correlations 위젯으로 모든 숫자 변수 쌍의 상관관계를 자동 정렬해
     확인하고, 관계 있어 보이는 쌍과 없어 보이는 쌍을 미리 짐작해본다.
  2. **파이썬으로 확인** — 정상 범위 이탈 데이터 찾기, `corr()`로 온도-두께 상관계수 계산, 습도(무관
     변수)와 비교하며 "상관관계 ≠ 인과관계", "원인 후보" 표현을 익힌다.
- **데이터**: `week08_anomaly_root_cause.csv`
- **핵심 질문 → 데이터 연결**: Orange3가 보여준 관계와 직접 계산한 상관계수가 같은가? 원인 후보로
  삼을 만한 변수는 무엇인가?

## 차시 간 연결 원칙

- 1~3차시의 파이썬 기초(변수·출력·리스트·딕셔너리·조건문·반복문·함수)는 이후 모든 차시에서 "Pandas가
  대신 해주는 일"로 반복 연결한다(예: 4차시 "3차시에 `for`+`if`로 했던 걸 한 줄로").
- 이론은 매 차시 새로 반복하지 않고 이전 차시 개념 위에 한 단계씩만 추가한다.
- 코드는 이전 차시에서 배운 함수를 재사용하고, 매 차시 새 함수는 3~5개 이내로 제한한다.
- **Orange3는 5~10차시에서 항상 "먼저 Orange3로 훑어보고 → 이어서 파이썬 코드로 확인"하는 순서로
  사용한다.** Orange3가 새 개념을 먼저 가르치지 않고, 코드로 확인할 내용의 "예고편" 역할을 한다.
- "결과 해석 문장 쓰기"는 1차시부터 10차시까지 매 차시 포함되는 고정 활동이다.
- 8차시부터는 "상관관계 ≠ 원인"이라는 문구를 반복 강조해 9~10차시의 "예측이 맞았다고 원인을 안다는
  뜻은 아니다"라는 메시지로 연결한다.
- `fab.csv`는 핵심 10차시 과정에서 제외한다. 다루고 싶은 반은 9차시 이후 선택 부록으로만 진행하고,
  그 경우에도 Sensor0~589의 실제 물리적 의미는 절대 단정하지 않는다(`CLAUDE.md` 규칙 유지).
