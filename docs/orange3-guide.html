Orange3 시작하기

이 부록으로 확인할 질문: "코드 없이 마우스만으로 데이터를 살펴보려면 Orange3를 어떻게 쓰면 될까?"

이 부록으로 할 수 있는 것

  • Orange3가 무엇이고 이 과정에서 왜 쓰는지 한 문장으로 설명할 수 있다.
  • Orange 파일(.ows)을 열고, _start와 _done의 차이를 안다.
  • 위젯을 캔버스에 놓고 서로 연결해 워크플로를 만들 수 있다.
  • File 위젯이 데이터 파일을 못 찾을 때 스스로 해결할 수 있다.
  • 1~10차시에서 쓰는 위젯이 위젯 목록의 어느 묶음에 있고, 각각 무엇을 보여 주는지 찾아볼 수 있다.

언제 보면 좋은가: 1차시 PART 2(Orange3)를 시작하기 전에 한 번 훑어보고, 이후 차시에서 새 위젯이 나올 때마다 그 위젯 설명만 다시 찾아보면 된다.

Orange3란 무엇인가

한 줄 정의 Orange3는 코드를 한 줄도 쓰지 않고, 위젯(widget)이라는 상자를 마우스로 끌어다 놓고 선으로 연결하는 것만으로 데이터를 열고·그래프를 그리고·모델을 만들 수 있는 무료 데스크톱 프로그램이다.

이 과정에서 Orange3는 1차시부터 매 차시 쓰는 본 활동이다. 1~8차시는 PART 1에서 파이썬으로 배운 것을 PART 2 Orange3에서 다른 데이터와 더 넓은 화면으로 넓혀 보고, 9·10차시는 순서를 바꿔 PART 1에서 Orange3로 모델을 먼저 눈으로 본 뒤 PART 2에서 파이썬 몇 줄로 확인한다. Orange 실습은 언제나 워밍업 데이터 → 반도체 데이터 순서다.

쉬운 비유 — 레고 블록으로 만드는 분석 공장 위젯 하나하나는 "파일 열기", "표로 보기", "그래프 그리기", "모델 만들기"처럼 한 가지 일만 하는 레고 블록이다. 블록을 순서대로 놓고 선으로 이으면 데이터가 컨베이어 벨트를 타듯 앞 블록에서 뒤 블록으로 흘러가며 처리된다. 이렇게 이어 붙인 전체 모양을 워크플로(workflow)라고 부른다.

엑셀·Orange3·파이썬은 모두 데이터를 다루는 도구지만, 잘하는 일이 조금씩 다르다.

도구사용 방법잘하는 일이 과정에서의 역할
엑셀셀에 직접 입력·수식작은 표 정리, 간단한 합계익숙한 비교 대상
Orange3위젯을 마우스로 연결코드 없이 빠르게 그래프·모델 확인파이썬에서 배운 것을 넓혀 보기, 파이썬 결과와 비교하기
파이썬코드 작성정확한 계산, 반복 작업 자동화숫자로 직접 계산하기
체크포인트 — Orange3는 따로 실행하는 프로그램이다 Orange3는 Jupyter Notebook 안에서 쓰는 파이썬 패키지가 아니라, 시작 메뉴에서 따로 실행하는 별도의 데스크톱 프로그램이다.

실행하기

1
Orange3 실행 — Windows는 시작 메뉴에서 Orange를 검색해 실행하고, Mac은 응용 프로그램 폴더에서 Orange를 실행한다. 바탕화면에 바로가기 아이콘이 있다면 더블클릭해도 된다.
2
시작 안내 창 — 시작 안내 창(Welcome)이 뜨면 수업에서는 보통 Open으로 실습 파일을 연다(아래 절). 빈 캔버스에서 직접 만들어 보려면 New를 누른다.
체크포인트 — 처음 실행은 오래 걸릴 수 있다 Orange3를 처음 실행하면 위젯 목록을 준비하느라 창이 한동안 하얗게 떠 있거나 아무 반응이 없을 수 있다. 오류가 아니니 기다리면 된다. 아이콘을 여러 번 누르면 창이 여러 개 열리니 한 번만 누르고 기다리자.

실습 파일(.ows) 열기

Orange에서 만든 워크플로는 .ows 파일로 저장된다. 차시마다 이 파일이 4개 있다.

파일 이름 예(1차시)무엇인가언제 여는가
week01_1_town_start.ows① 워밍업 데이터 시작 파일 — 데이터가 연결된 File 위젯 하나와 한국어 안내 메모PART 2(9·10차시는 PART 1) Orange 실습을 시작할 때
week01_1_town_done.ows① 워밍업 완성본 — 위젯이 모두 연결된 상태막혔을 때 따라잡기, 끝난 뒤 내 것과 비교
week01_2_process_start.ows② 반도체 데이터 시작 파일워밍업이 끝난 뒤
week01_2_process_done.ows② 반도체 데이터 완성본막혔을 때 따라잡기
1
더블클릭으로 열기 — week01_1_town_start.ows를 더블클릭한다. Orange가 열리며 캔버스에 File 위젯 하나와 안내 메모가 보인다.
2
더블클릭으로 안 열리면 메뉴로 열기 — Orange를 먼저 실행하고 맨 위 메뉴 File → Open을 눌러 그 파일을 고른다(시작 안내 창의 Open도 같다).
3
데이터가 들어왔는지 확인 — 캔버스의 File 위젯을 더블클릭한다. 위쪽에 파일 이름 (week01_orange_town_population.tab)이 보이고, 아래 Info 칸에 행 수(instances)가 나오면 성공이다.
알아두기 — Orange는 CSV가 아니라 .tab을 연다 Orange 파일이 여는 데이터는 orange 폴더의 .tab 파일이다. 같은 차시 CSV와 값은 같고, 열마다 Orange가 쓸 종류(숫자·범주·결과 열·참고용 meta)가 미리 정해져 있다. 예를 들어 합격여부는 결과 열(target)로 정해져 있어 Orange가 합격·불합격 막대를 바로 그리고, 9·10차시 모델도 따로 설정하지 않고 바로 만든다.

File 위젯이 파일을 못 찾을 때

File 위젯 창에 빨간 글씨(File not found 등)가 보이거나 파일 이름이 빨간색이면, Orange가 데이터 파일을 찾지 못한 것이다. .ows는 자기가 있는 폴더를 기준으로 데이터를 찾아가므로, 파일을 다른 곳으로 옮기면 길을 잃는다. 아래 순서로 확인한다.

1
원래 자리의 파일을 열었는가? — .ows를 바탕화면 등 다른 곳으로 옮기거나 복사했다면, 원래 폴더에 있는 .ows를 다시 연다.
2
그래도 안 되면 .tab을 직접 고른다 — File 위젯 창의 폴더 아이콘을 눌러 orange 폴더의 .tab 파일을 고른다. 같은 이름의 CSV가 아니라 orange 폴더 안의 .tab을 고른다. 고르면 뒤에 연결된 위젯에 바로 데이터가 흐른다.
3
그래도 안 되면 — 강사에게 알린다.
저장할 때 주의 실습한 워크플로를 Ctrl+S(Mac은 Cmd+S)로 저장하면 Orange가 데이터 위치를 내 컴퓨터 기준으로 바꿔 저장할 수 있다. 그 컴퓨터에서는 계속 열리지만, 폴더를 옮기면 다시 이 오류가 난다. 막히면 _start.ows나 _done.ows를 다시 열면 된다.

실습: 첫 워크플로 직접 만들어 보기

수업에서는 _start.ows에 File 위젯이 이미 들어 있지만, 빈 캔버스에서 한 번 직접 만들어 보면 File 위젯이 파일을 못 찾을 때도 당황하지 않는다. 5차시 데이터로 연습해 보자.

1
File 위젯 놓기 — 시작 안내 창에서 New를 누른 뒤, 왼쪽 위젯 목록의 Data 묶음에서 File 아이콘을 캔버스로 끌어다 놓는다.
2
.tab 불러오기 — File 위젯을 더블클릭해 창을 열고, 폴더 아이콘을 눌러 week05_dirty_process_data.tab을 선택한다.
알아두기 — File 창 아래의 열 목록(Type·Role) File 창 아래 표에는 열마다 Type(숫자 numeric / 범주 categorical / 글자 text 등)과 Role(feature: 재료로 쓰는 열, target: 맞힐 정답 열, meta: 참고용 열)이 표시된다. 과정의 .tab 파일은 이 값이 미리 정해져 있으니 바꾸지 않고 그대로 둔다. 합격여부는 이미 target·categorical이다.
3
Data Table 위젯 추가 — Data 묶음에서 Data Table 위젯을 캔버스로 끌어다 놓는다.
4
두 위젯 연결하기 — File 위젯의 오른쪽 가장자리에서 마우스 버튼을 누른 채로 Data Table 위젯의 왼쪽 가장자리까지 끌고 가서 놓는다. 화살표가 있는 선이 생기면 연결 성공이다.
5
결과 확인 — Data Table 위젯을 더블클릭하면 데이터가 표로 나타난다. 빈 칸(결측값)이 그대로 보이는지 확인해 보자.
자주 하는 실수 — 위젯이 연결되지 않는다 가장자리가 아니라 위젯 가운데를 클릭하면 위젯이 움직이기만 하고 연결선이 생기지 않는다. 반드시 위젯 테두리(오른쪽 끝)에 마우스를 올려 커서 모양이 바뀌는 지점에서 드래그를 시작해야 한다.
자주 하는 실수 — Data Table 뒤에 위젯을 잇는다 Data Table은 표에서 행을 고르기 전에는 뒤로 아무것도 내보내지 않을 수 있다. 그래프나 다른 위젯은 Data Table 뒤가 아니라 File(또는 앞 위젯)에서 부채꼴처럼 따로 잇는다.

위젯은 어느 묶음에 있나

위젯 목록은 묶음별로 접혀 있다. 아래 표에서 묶음 이름을 찾아 펼친 뒤 위젯을 끌어다 놓는다. 위젯 이름은 Orange 화면에 나오는 영어 이름 그대로다.

묶음이 과정에서 쓰는 위젯쓰는 차시
DataFile · Data Table · Column Statistics1~10 · 1~10 · 2·5
TransformSelect Rows · Select Columns · Impute · Pivot Table3·4·5 · 4 · 5 · 7
VisualizeDistributions · Scatter Plot · Box Plot · Tree Viewer1·6·7·9 · 6·8 · 6·7 · 9
UnsupervisedCorrelations8
ModelTree · kNN · Logistic Regression9·10 · 10 · 10
EvaluateTest and Score · Confusion Matrix · Predictions9·10 · 9 · 10
헷갈리기 쉬운 묶음 Select Rows·Select Columns·Impute·Pivot Table은 이름과 달리 Data가 아니라 Transform 묶음에 있고, Correlations는 Unsupervised 묶음에 있다. 묶음을 못 찾겠으면 아래 "문제 해결"의 위젯 검색을 쓴다.

위젯 사전 — 이 과정에서 쓰는 위젯

아래 위젯은 처음 쓰는 차시 순서대로 정리했다. 그 차시에 도착하면 이 절을 다시 펼쳐 찾아봐도 좋다.

File — 1~10차시 (Data)

데이터 파일을 Orange3 안으로 불러오는 시작점 위젯. 모든 워크플로는 File 위젯에서 시작한다. _start.ows에는 이미 데이터가 연결되어 있다. 직접 고를 때는 더블클릭 → 폴더 아이콘 → orange 폴더의 .tab.

Data Table — 1차시 (Data)

불러온 데이터를 표 형태 그대로 보여준다. 빈 칸(결측값)이 그대로 빈칸으로 보이므로, 어느 열에 결측이 많은지 눈으로 훑어보기 좋다. 열 머리글을 클릭하면 정렬도 된다(4차시).

Distributions — 1차시 (Visualize)

한 변수의 값이 어떤 모양으로 퍼져 있는지 보여준다. 숫자 열(예: 온도)을 고르면 히스토그램이 되고, 범주형 열(예: 합격여부, 설비번호)을 고르면 값별 개수를 막대로 보여준다. Split by는 기본값이 결과 열(합격여부)이라 막대가 색으로 나뉘어 보인다. 한 열만 보고 싶으면 Split by를 None으로 바꾼다. 설비별 합격/불합격을 비교할 때는 반대로 Split by를 그대로 쓴다(7차시).
헷갈리기 쉬운 위젯 — Bar Plot 위젯 목록에는 Bar Plot이라는 위젯도 있는데, 이것은 개수를 세는 위젯이 아니라 데이터 한 행마다 숫자 값 하나를 막대로 그린다. 범주별 개수를 비교할 때는 Distributions를 쓴다.

Column Statistics — 2·5차시 (Data)

각 열의 평균(Mean)·최솟값(Min)·최댓값(Max)·퍼짐 정도와 빈칸 비율(Missing)을 한 표로 보여준다. 파이썬으로 계산한 최고·최저·평균과 나란히 대조하기 좋다. Max/Min이 그 기록의 평소 범위에서 크게 벗어나 있으면 튀는 값 후보를 빠르게 찾을 수 있다.

Select Rows — 3·4·5차시 (Transform)

조건(예: 온도_C가 어느 값보다 크다)에 맞는 행만 골라 내보낸다. 파이썬의 if나 Pandas 조건 검색과 같은 일을 한다. 조건 열이 빈칸인 행은 조건과 상관없이 버려진다는 점에 주의한다.

Select Columns — 4차시 (Transform)

보고 싶은 열만 남긴다. 파이썬의 열 선택(df[["열1", "열2"]])과 같은 일이다.

Impute — 5차시 (Transform)

빈칸을 지우지 않고 채운다. 숫자 열은 평균(Average) 등으로 채울 수 있다(중앙값 선택은 없다). 파이썬에서 dropna()로 지운 결과와 평균이 어떻게 달라지는지 비교한다.

Scatter Plot — 6·8차시 (Visualize)

두 숫자 변수를 X축·Y축으로 놓고 점으로 흩뿌려 관계를 보여준다. 점들이 대각선 방향으로 모여 있으면 두 변수가 함께 움직인다는 뜻이다. 위젯 왼쪽 옵션에서 X축· Y축 변수를 바꿔 고를 수 있다. 6차시에는 웨이퍼 맵의 X·Y 좌표를 찍어 둥근 웨이퍼 모양을 본다.

Box Plot — 6·7차시 (Visualize)

그룹(예: 설비번호)별로 값이 어디에 몰려 있고 얼마나 퍼져 있는지 상자 모양으로 보여준다. 상자가 넓을수록 그 그룹의 값이 들쭉날쭉하다는 뜻이다. Subgroups 칸에 설비번호 같은 범주형 열을 지정하면 그룹별로 나눠 보여준다.

Pivot Table — 7차시 (Transform)

행과 열에 범주를 놓고 칸마다 개수를 세어 준다. 설비별 합격·불합격 개수를 표로 보고, 칸의 개수로 합격률을 계산해 파이썬 groupby 결과와 같은지 비교한다.

Correlations — 8차시 (Unsupervised)

데이터의 모든 숫자 변수 쌍의 상관계수를 계산해 관계가 강한 순서대로 줄 세워 보여준다. 음수(한쪽이 커지면 다른 쪽이 작아지는 관계)도 함께 읽는다. 상관이 크다고 원인이라고 말할 수는 없다 — 결과는 "원인 후보"로만 말한다.

Tree · Tree Viewer — 9차시 (Model · Visualize)

Tree는 클릭만으로 결정 트리 분류 모델을 학습시키는 위젯이다. 결과 열(합격여부)이 이미 target으로 정해진 .tab을 연결하면 나머지 feature 열로 모델을 만든다. 파이썬의 DecisionTreeClassifier와 같은 원리다. Tree Viewer에 연결하면 모델이 어떤 질문으로 나눴는지 나무 그림으로 보여준다.

Test and Score · Confusion Matrix — 9·10차시 (Evaluate)

Test and Score는 File과 모델 위젯을 함께 연결하면 정확도(CA) 등 성능 지표를 표로 보여준다. 기본 설정은 데이터를 5조각으로 나눠 번갈아 시험하는 방식(5-fold)이다. Confusion Matrix를 Test and Score 뒤에 이으면 실제 합격/불합격과 예측이 몇 건씩 맞고 틀렸는지 칸으로 보여준다.

kNN · Logistic Regression — 10차시 (Model)

Tree와 다른 방식의 분류 모델이다. kNN은 "가장 비슷한 이웃 몇 개가 무엇이었나"로, Logistic Regression은 열 값에 가중치를 곱해 더한 점수로 맞힌다. 세 모델을 한 Test and Score에 함께 연결해 점수를 비교한다.

Predictions — 10차시 (Evaluate)

학습된 모델과 정답을 모르는 새 데이터를 함께 연결하면, 각 행에 대한 예측 결과(합격/불합격)와 확률을 표로 보여준다. 파이썬의 model.predict()와 같은 역할이고, 확률은 이 표에서만 본다.

문제 해결 (Troubleshooting)

Orange3 창이 안 떠요 처음 실행은 오래 걸릴 수 있으니 먼저 기다려 본다. 그래도 안 뜨면 작업 표시줄에 Orange 창이 숨어 있지 않은지 확인하고, 해결되지 않으면 강사에게 알린다.
File 위젯에 빨간 글씨가 보여요 데이터 파일을 못 찾은 것이다. 위 "File 위젯이 파일을 못 찾을 때" 절의 순서대로 확인한다.
위젯 목록에 원하는 위젯이 안 보여요 먼저 위 "위젯은 어느 묶음에 있나" 표에서 묶음을 확인한다. 그래도 못 찾으면 캔버스 빈 곳을 마우스 오른쪽 클릭해 위젯 검색 창을 띄우고, 위젯 이름(예: Box Plot)을 입력한 뒤 Enter를 누르면 그 자리에 위젯이 놓인다.
위젯 창이 안 열려요 더블클릭이 아니라 한 번만 클릭했을 가능성이 크다. 위젯 아이콘을 정확히 두 번 빠르게 클릭한다.
위젯 창이 비어 있어요 앞 위젯과 연결선이 제대로 이어져 있는지 먼저 확인한다. 연결선이 없거나 Data Table 뒤에 이어져 있으면 데이터가 전달되지 않는다. File(또는 앞 위젯)에서 바로 잇는다.
Tree/Test and Score에서 오류가 나요 File 위젯 창에서 합격여부의 Role이 target, Type이 categorical인지 확인한다. 과정의 .tab은 처음부터 그렇게 정해져 있으므로, 바뀌어 있다면 누군가 직접 고친 것이다. _start.ows를 다시 열면 된다. Type이 numeric이면 Orange3는 합격/불합격 분류가 아니라 숫자 맞히기(회귀)로 처리한다.
완성본과 내 결과가 달라요 Orange는 위젯 설정을 기억해 두었다가 새 위젯에 다시 적용하기도 한다. 강의에 적힌 설정(예: Split by, 조건 값)과 내 위젯 창의 설정이 같은지 확인하고, 그래도 다르면 같은 차시의 _done.ows를 열어 비교한다.
