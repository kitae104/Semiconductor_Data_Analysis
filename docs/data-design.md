# 차시별 실습 데이터 설계 (Data Design) — v2

> 이 문서는 [`docs/curriculum.md`](curriculum.md) v2 차시 구성을 기준으로 한다. `scripts/generate_weekly_data.py`가
> 그대로 구현해야 하는 스펙이며, 모든 생성 데이터는 **교육용 가상 데이터**로 실제 기업 생산 데이터가 아니다.
> **주의**: 0절 시드 규칙, 9절, 10절은 v3.1(2026-11-24, 9·10차시 개편) 기준이다. 1~8절은 v2 스펙 그대로라 열 이름이
> 실제 파일과 다를 수 있다(v3에서 `온도_섭씨` → `온도_C`처럼 단위 접미사만 바뀌고 값은 같다). 실제 열은 `generate_weekly_data.py`와
> `data/data_dictionary/`를 기준으로 한다.

## 0. 공통 규칙

- 난수 생성기: `numpy.random.default_rng(seed)` — 생성 함수마다 자기 Generator를 쓴다(호출 순서가 바뀌어도 다른 파일 값이 그대로다).
  시드 계열:

| 계열 | 시드 | 예 |
| --- | --- | --- |
| 차시 본 데이터(1~9차시) | `100 + 차시번호` | 1차시 101 … 9차시 109 |
| 생활 예제 `weekXX_easy_*.csv` | 1000번대 | 6차시 1006, 8차시 1008 |
| Orange 워밍업 `weekXX_orange_*.csv` | 200번대 | 9차시 웨이퍼 패턴 209, 새 웨이퍼 210(옛 10차시에서 이관, 시드 그대로) |
| **10차시 캡스톤**(v3.1) | **300번대 — `CAPSTONE_SEED = 330`** | `week10_capstone_lots.csv`·`week10_capstone_new_lots.csv`가 같은 Generator에서 나온다 |

  옛 10차시 시드 110(`week10_mini_project_dataset.csv`)은 v3.1에서 함수와 함께 삭제했다.
- 저장 인코딩: `utf-8-sig` (UTF-8 with BOM), CSV 저장 경로: `data/weekly/weekXX/`
- 합격/불합격 통일 표기: **1~10차시 모든 실습 데이터가 `합격여부`(1=합격/-1=불합격)를 쓴다.**
  (2026-10-02: 9·10차시의 `검사결과`(0/1) 열을 초보자 혼동 방지를 위해 `합격여부`(1/-1)로 바꿨다.
  생성 난수 순서는 그대로라 다른 열 값은 같고, scikit-learn은 1/-1 레이블도 그대로 학습한다.)
- 설비 목록: `EQ-01`(대체로 정상), `EQ-02`(온도 변동 큼), `EQ-03`(압력 다소 높음), `EQ-04`(불량률 높음)
- 공정 목록: `증착`, `식각`, `포토`, `세정`, `산화`
- 작업조: `A조`(주간), `B조`(오후), `C조`(야간, 결측·불량이 약간 더 많음)
- 제품유형: `TYPE-A`(목표두께 100nm), `TYPE-B`(목표두께 150nm)
- 불량유형: 두께 불량, 파티클, 패턴 불량, 식각 과다, 식각 부족, 오염, 정렬 불량, 전기적 특성 불량
- 기본 정상 범위(교육용 예시, 첨부 샘플 통계를 참고해 설정, 실제 공정 절대 기준 아님):

| 변수 | 정상 범위 |

## 2. Week02 — 파이썬 기초 Ⅰ: 변수·리스트·딕셔너리 (`week02_python_basics_1.csv`, 신규)

- 행/열: 약 20행 × 5열 — `로트번호, 공정명, 설비번호, 온도_섭씨, 합격여부`
- 패턴: 결측 없음, Pandas 없이도 눈으로 훑어볼 수 있을 만큼 작게 구성. 온도 값 중 정상범위(295~305)를
  벗어나는 값 2~3개를 포함해 "리스트에서 최댓값/최솟값 찾기" 소재로 제공.
- 사용 방식: CSV를 그대로 Pandas로 읽지 않고, 강의 중 리스트/딕셔너리 리터럴(`온도_리스트 = [...]`,
  `설비정보 = {"설비번호": "EQ-01", ...}`)로 변환해 제시한다. CSV 자체는 "이 값들이 원래 어디서 왔는가"를
  보여주는 참고 자료로만 쓴다.
- 목적: 변수 대입, 리스트에 값 담기·인덱싱·길이, 딕셔너리로 레코드 1건 표현, 리스트의 딕셔너리로
  여러 설비 표현.

## 3. Week03 — 파이썬 기초 Ⅱ: 조건문·반복문·함수 (`week03_python_basics_2.csv`, 신규)

- 행/열: 약 30행 × 5열 — `로트번호, 공정명, 설비번호, 온도_섭씨, 합격여부` (2차시와 동일 열 구성,
  다른 행으로 별도 생성 — "동일 계열" 데이터)
- 패턴: 정상범위 이탈 온도 4~5개(2차시보다 조금 더 많이) 포함해 `for`+`if`로 걸러내는 연습량 확보.
- 목적: `if`/`elif`/`else`로 온도 1건 판정 → `for`로 전체 순회하며 정상/비정상 개수 세기 → 평균 계산
  함수, 합격/불합격 판정 함수 작성 → 직접 만든 함수 결과를 4차시 Pandas 결과와 비교할 수 있도록 열
  구성을 4차시 데이터와 맞춘다.

  몰리도록 구성해 "설비 비교"와 "수율/파레토"가 같은 결론으로 이어지게 한다.
- 목적: `groupby`로 설비별 평균값·합격률 비교, 로트 단위 수율 계산, 불량유형 파레토, 저수율 로트 탐색을
  하나의 데이터셋으로 연결.

## 8. Week08 — 이상탐지 + 원인 후보 + Orange3 Correlations (`week08_anomaly_root_cause.csv`, = v1 week08)

- v1 week08과 동일 스펙(파일명 변경 없음). Orange3 Correlations도 동일 CSV 사용.
- 행/열: 약 450행 × 12열 —
  `측정시간, 로트번호, 설비번호, 공정명, 온도_섭씨, 압력_Pa, 진공도_mTorr, 두께_nm, 진동_mm_s, 냉각수온도_섭씨, 습도_pct, 합격여부`
- 삽입 패턴:
  1. 온도가 높을수록 두께가 비례해서 증가(약한 양의 상관, 노이즈 포함)
  2. 진공도가 정상범위(4.5~5.5)를 벗어나면 불합격 확률 상승
  3. `EQ-02`에서만 진동 값이 전반적으로 높게 설정
  4. 냉각수온도가 오른 지점 이후 8~12행 동안 공정 온도가 서서히 상승(시차 인과처럼 보이는 패턴)
  5. 습도처럼 불량과 무관한 변수도 포함해 "상관관계 없음"을 확인하는 대조군으로 사용
- 목적: 임계값 이상탐지, 상관관계 읽기(`corr()`) → Orange3 Correlations 위젯으로 모든 변수 쌍을 자동
  정렬해 재확인, 원인 후보 vs 무관 변수 구분.

### 9-1. `week09_pass_fail_train.csv` (학습용)

- `반도체_공정_샘플.csv`의 열 구조(공정명, 설비번호, 온도_섭씨, 압력_Pa, 가스유량_slm, 두께_nm,

  행이 적고 결측이 많아 그대로 쓰지 않는다).
- 행/열: 약 700~800행 × 9열 — `공정명, 설비번호, 온도_섭씨, 압력_Pa, 가스유량_slm, 두께_nm, 진공도_mTorr, 습도_pct, 합격여부`
- Feature 설계: 온도·압력·진공도·두께는 합격여부(불량)와 실제로 연관되도록 신호를 넣고(8차시 패턴
  재사용), 가스유량·습도는 약한/무관한 신호로 남겨 "특징을 다 넣는다고 다 도움되는 건 아니다"를
  보여주는 대조군으로 쓴다.
- 결측치를 10~20건 정도만 남겨 4~5차시에서 배운 정제를 짧게 복습하게 한다.
- `합격여부`: 1=합격, -1=불합격 (1~8차시와 같은 표기, scikit-learn 레이블로 그대로 사용).

### 9-2. `week09_new_lots_to_predict.csv` (예측 실습용)

- 학습에 쓰지 않은 새 로트 9건 × 8열 — 9-1과 같은 열에서 `합격여부`만 뺐다. 값은 v3.1에서도 그대로다.
- v3.1(2026-11-24)부터 **9차시 안에서** 쓴다(옛 10차시 몫을 합침). 파이썬은 노트북 4단계에서 학습한 결정 트리로
  `predict()`해 예측 열을 붙이고, Orange는 `week09_2_passfail`의 File(새 로트) → Predictions(← Tree)로 같은 로트를 예측해
  확률을 읽는다. 정답 열이 없으므로 Test and Score로 채점하지 않는다.
- 목적: `train_test_split` → `DecisionTreeClassifier` 학습 → 정확도와 기준선 비교 → 새 로트 예측 → 확률이 애매한 로트를
  "사람이 다시 볼 것"으로 고르기. 파이썬(588행 학습, 빈칸 행 삭제)과 Orange(750행, 10겹)는 학습 행이 달라 가장 의심하는 로트가
  다를 수 있다 — 이 차이 자체가 수업 소재다. 수치는 Orange 3.40 실측을 운영안에 적는다.

### 10-1. `week10_capstone_lots.csv` — 480행 × 13열

| 열 | 형식 | Orange 역할 | 심은 패턴 |
| --- | --- | --- | --- |
| `날짜` | YYYY-MM-DD(2024-06-03 ~ 06-30, 4주) | time · meta | — |
| `로트번호` | LOT-#### | meta | 480개 모두 다름 |
| `설비번호` | EQ-01~04 | 범주 입력 | **EQ-04 합격률이 가장 낮다** |
| `공정명` | 5종 | 범주 입력 | 효과 없음(합격률 차이 ≤ 10%p로 확인) |
| `작업조` | A조·B조·C조 | 범주 입력 | **효과 없음(대조군)** — AI 초안의 "작업조 탓" 단정을 확인하는 함정 |
| `온도_C` | 소수 1자리 | 연속 | N(300, 3.5), EQ-02만 sd 6.5. **빈칸 5**, **입력 실수 3건**(소수점이 빠진 값, 예: 3028.0) |
| `두께_nm` | 소수 2자리 | 연속 | 100 + 0.5·(온도 − 300) + N(0, 2) → 온도와 강한 양의 상관 |
| `진공도_mTorr` | 소수 2자리 | 연속 | N(5.0, 0.35). 연습용 기준 4.5~5.5 밖이면 불합격 위험이 크다(상관은 약하지만 범위 밖 합격률이 낮은 8차시 패턴). **빈칸 5** |
| `진동_mm_s` | 소수 3자리 | 연속 | EQ-04 N(0.63, 0.06), 나머지 N(0.50, 0.05). 연습용 기준 0.64 초과면 불합격 위험 → 설비 차이와 센서가 함께 나타나는 원인 후보 |
| `가스유량_slm` | 소수 2자리 | 연속 | 효과 없음 |
| `습도_pct` | 소수 1자리 | 연속 | 효과 없음(대조군). **빈칸 4** |
| `불량유형` | 불합격 행에만 값 | 범주 · meta | 정답 누설 방지 |
| `합격여부` | 1 / -1 | class | 불합격 확률 = 0.04 + 0.75·[진공도 기준 밖] + 0.60·[진동 > 0.64] + 0.30·[\|온도 − 300\| > 9], 상한 0.9 |

- 빈칸·입력 실수는 `합격여부`를 추첨한 **뒤에** 넣는다. 중복 행은 넣지 않는다(Orange에서 지우려면 배우지 않은 위젯이 필요하다).
- 설비↔공정 짝은 교육용 단순화다(설비 4대가 여러 공정 기록을 함께 남겼다). 데이터 설명서·강의에 고지 문장을 둔다(10차시는 실습지 없음).
- **목표 수치와 실측(시드 330, `validate_datasets.py`가 확인)**:

| 목표 | 실측 |
| --- | --- |
| 전체 합격률 74~82% | 75.8%(364/480) |
| EQ-04 최저, 다음 설비보다 10%p 이상 낮음 | EQ-04 58.9% · EQ-02 78.9% · EQ-03 80.3% · EQ-01 83.9% |
| 작업조 차이 ≤ 5%p | A조 78.1% · **B조 73.7%(최저)** · C조 75.9% → 4.4%p |
| 공정명 차이 ≤ 10%p | 8.6%p |
| 온도–두께 상관 0.65~0.85(입력 실수 제외) | 0.725(입력 실수를 남기면 0.033) |
| 진공도–합격여부 \|r\| < 0.2, 기준 밖 합격률 ≤ 30%, 안 ≥ 85% | +0.010, 기준 밖 76행 11.8%, 안 87.7% |
