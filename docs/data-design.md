# 차시별 실습 데이터 설계 (Data Design) — v2

> 이 문서는 [`docs/curriculum.md`](curriculum.md) v2 차시 구성을 기준으로 한다. `scripts/generate_weekly_data.py`가
> 그대로 구현해야 하는 스펙이며, 모든 생성 데이터는 **교육용 가상 데이터**로 실제 기업 생산 데이터가 아니다.
> **주의**: 이 문서는 스펙만 개정된 상태이며, `scripts/generate_weekly_data.py`와 `data/weekly/`는 아직
> 이 스펙대로 재생성되지 않았다(다음 단계는 [`docs/restructure-plan.md`](restructure-plan.md)의
> "각 항목별 TODO" 2번 참고).

## 0. 공통 규칙

- 난수 생성기: `numpy.random.default_rng(seed)` — 차시마다 `seed = 100 + 차시번호` 고정
  (예: 1차시 101, 2차시 102 … 10차시 110)
- 저장 인코딩: `utf-8-sig` (UTF-8 with BOM), CSV 저장 경로: `data/weekly/weekXX/`
- 합격/불합격 통일 표기: **원천 실습 열은 기존 스타일(`합격여부`: 1=합격/-1=불합격)을 유지**하되,
  9차시부터는 `검사결과`(0=정상/합격, 1=이상/불합격) 열을 병행 제공해 scikit-learn 등에서 바로 쓰는
  0/1 이진 레이블과 맞춘다. 이 차이는 1차시·9차시 강의에서 명시적으로 설명한다.
- 설비 목록: `EQ-01`(대체로 정상), `EQ-02`(온도 변동 큼), `EQ-03`(압력 다소 높음), `EQ-04`(불량률 높음)
- 공정 목록: `증착`, `식각`, `포토`, `세정`, `산화`
- 작업조: `A조`(주간), `B조`(오후), `C조`(야간, 결측·불량이 약간 더 많음)
- 제품유형: `TYPE-A`(목표두께 100nm), `TYPE-B`(목표두께 150nm)
- 불량유형: 두께 불량, 파티클, 패턴 불량, 식각 과다, 식각 부족, 오염, 정렬 불량, 전기적 특성 불량
- 기본 정상 범위(교육용 예시, 첨부 샘플 통계를 참고해 설정, 실제 공정 절대 기준 아님):

| 변수 | 정상 범위 |
| --- | --- |
| 온도_섭씨 | 295 ~ 305 |
| 압력_Pa | 995 ~ 1025 |
| 가스유량_slm | 47 ~ 53 |
| 전력_W | 1950 ~ 2050 |
| 진공도_mTorr | 4.5 ~ 5.5 |
| 두께_nm | 97 ~ 103 (TYPE-A 기준) |
| 습도_pct | 40 ~ 50 |
| 진동_mm_s | 0.40 ~ 0.60 |
| 처리시간_sec | 110 ~ 130 |
| 냉각수온도_섭씨 | 18 ~ 22 |

## 2. Week02 — 파이썬 기초 Ⅰ: 변수·리스트·딕셔너리 (`week02_python_basics_1.csv`, 신규)

- 행/열: 약 20행 × 5열 — `로트번호, 공정명, 설비번호, 온도_섭씨, 합격여부`
- 패턴: 결측 없음, Pandas 없이도 눈으로 훑어볼 수 있을 만큼 작게 구성. 온도 값 중 정상범위(295~305)를
  벗어나는 값 2~3개를 포함해 "리스트에서 최댓값/최솟값 찾기" 소재로 제공.
- 사용 방식: CSV를 그대로 Pandas로 읽지 않고, 강의 중 리스트/딕셔너리 리터럴(`온도_리스트 = [...]`,
  `설비정보 = {"설비번호": "EQ-01", ...}`)로 변환해 제시한다. CSV 자체는 "이 값들이 원래 어디서 왔는가"를
  보여주는 참고 자료로만 쓴다.
- 목적: 변수 대입, 리스트에 값 담기·인덱싱·길이, 딕셔너리로 레코드 1건 표현, 리스트의 딕셔너리로
  여러 설비 표현.

## 3. Week03 — 파이썬 기초 Ⅱ: 조건문·반복문·함수 (`week03_python_basics_2.csv`, 신규)

- 행/열: 약 30행 × 5열 — `로트번호, 공정명, 설비번호, 온도_섭씨, 합격여부` (2차시와 동일 열 구성,
  다른 행으로 별도 생성 — "동일 계열" 데이터)
- 패턴: 정상범위 이탈 온도 4~5개(2차시보다 조금 더 많이) 포함해 `for`+`if`로 걸러내는 연습량 확보.
- 목적: `if`/`elif`/`else`로 온도 1건 판정 → `for`로 전체 순회하며 정상/비정상 개수 세기 → 평균 계산
  함수, 합격/불합격 판정 함수 작성 → 직접 만든 함수 결과를 4차시 Pandas 결과와 비교할 수 있도록 열
  구성을 4차시 데이터와 맞춘다.

## 7. Week07 — 설비·공정 비교 + 수율·불량 분석 (`week07_equipment_yield.csv`, 신규 병합, = v1 week06+week07 압축)

- 행/열: 약 75개 로트 × 4웨이퍼 = 약 300행 × 11열 —
  `로트번호, 웨이퍼번호, 설비번호, 공정명, 작업조, 온도_섭씨, 압력_Pa, 진공도_mTorr, 처리시간_sec, 불량유형, 합격여부`
- 설비별 특성(v1 week06 그대로 계승):
  - `EQ-01`: 평균 근처로 안정, 불량률 ~5%
  - `EQ-02`: 온도 표준편차를 2~3배로 확대(변동 큼), 불량률 ~10%
  - `EQ-03`: 압력 평균을 +15~20 Pa 상향(다소 높음), 불량률 ~8%
  - `EQ-04`: 불량률 ~20%로 상향(원인은 특정하지 않고 "확인이 필요한 설비"로만 제시)
- 파레토용 열: `불량유형`은 불합격 행에만 채우고(합격 행은 빈 값), 8종 불량유형 중 EQ-04에서는 특정
  2~3종이 더 자주 나오도록 편향 배치.
- 로트 5개 정도를 의도적으로 저수율(웨이퍼 단위 합격률 80% 미만)로 설계하고, 이 로트들이 EQ-04에
  몰리도록 구성해 "설비 비교"와 "수율/파레토"가 같은 결론으로 이어지게 한다.
- 목적: `groupby`로 설비별 평균값·합격률 비교, 로트 단위 수율 계산, 불량유형 파레토, 저수율 로트 탐색을
  하나의 데이터셋으로 연결.

## 8. Week08 — 이상탐지 + 원인 후보 + Orange3 Correlations (`week08_anomaly_root_cause.csv`, = v1 week08)

- v1 week08과 동일 스펙(파일명 변경 없음). Orange3 Correlations도 동일 CSV 사용.
- 행/열: 약 450행 × 12열 —
  `측정시간, 로트번호, 설비번호, 공정명, 온도_섭씨, 압력_Pa, 진공도_mTorr, 두께_nm, 진동_mm_s, 냉각수온도_섭씨, 습도_pct, 합격여부`
- 삽입 패턴:
  1. 온도가 높을수록 두께가 비례해서 증가(약한 양의 상관, 노이즈 포함)
  2. 진공도가 정상범위(4.5~5.5)를 벗어나면 불합격 확률 상승
  3. `EQ-02`에서만 진동 값이 전반적으로 높게 설정
  4. 냉각수온도가 오른 지점 이후 8~12행 동안 공정 온도가 서서히 상승(시차 인과처럼 보이는 패턴)
  5. 습도처럼 불량과 무관한 변수도 포함해 "상관관계 없음"을 확인하는 대조군으로 사용
- 목적: 임계값 이상탐지, 상관관계 읽기(`corr()`) → Orange3 Correlations 위젯으로 모든 변수 쌍을 자동
  정렬해 재확인, 원인 후보 vs 무관 변수 구분.

## 9. Week09 — 머신러닝 예측 + Orange3 (신규, `반도체_공정_샘플.csv` 기반, fab.csv 미사용)

### 9-1. `week09_pass_fail_train.csv` (학습용)

- `반도체_공정_샘플.csv`의 열 구조(공정명, 설비번호, 온도_섭씨, 압력_Pa, 가스유량_slm, 두께_nm,
  진공도_mTorr 등)와 값 범위를 참고해 **완전히 새로 생성**한 가상 데이터(원본 200행은 학습에 쓰기엔
  행이 적고 결측이 많아 그대로 쓰지 않는다).
- 행/열: 약 700~800행 × 9열 — `공정명, 설비번호, 온도_섭씨, 압력_Pa, 가스유량_slm, 두께_nm, 진공도_mTorr, 습도_pct, 검사결과`
- Feature 설계: 온도·압력·진공도·두께는 검사결과(불량)와 실제로 연관되도록 신호를 넣고(8차시 패턴
  재사용), 가스유량·습도는 약한/무관한 신호로 남겨 "특징을 다 넣는다고 다 도움되는 건 아니다"를
  보여주는 대조군으로 쓴다.
- 결측치를 10~20건 정도만 남겨 4~5차시에서 배운 정제를 짧게 복습하게 한다.
- `검사결과`: 0=합격, 1=불합격 (scikit-learn 레이블로 바로 사용).

### 9-2. `week09_new_lots_to_predict.csv` (예측 실습용)

- 학습에 쓰지 않은 새 로트 8~10건, 위와 동일한 Feature 열만 포함(`검사결과` 없음).
- 학습자가 직접 `predict()`를 돌려본 뒤, 강사가 정답(별도 안내 자료)을 공개해 맞춰보는 방식으로 사용.
- 목적: `train_test_split` → `DecisionTreeClassifier`(또는 `LogisticRegression`) 학습 → 정확도·혼동행렬
  확인 → 새 로트 예측 → Orange3 Tree/Test and Score/Predictions 위젯으로 동일 데이터에 대해 코드 없이
  모델을 만들어 정확도 비교.

## 11. 데이터 설명서 규칙

각 CSV는 `data/data_dictionary/weekXX_dictionary.md`에 다음을 포함한다.

- 열 이름 / 쉬운 설명 / 데이터 형식 / 단위 / 예시 / 결측값 가능 여부 (표)
- 데이터의 목적, 가상 상황, 행 1개의 의미
- 합격/불합격 값의 의미
- 정상 범위
- 의도적으로 포함된 이상 현상
- 이번 차시 분석 질문
- 실제 현업 데이터와 다른 점(교육용 가상 데이터임을 재확인)
