# 구현 계획 (Implementation Plan)

## 1. 프로젝트 개요

「반도체 및 반도체 공정 데이터 분석 10주 과정」은 프로그래밍 경험이 거의 없는 일반인을 대상으로,
반도체 공정의 기본 개념과 Python/Pandas 기반 데이터 분석 실습을 결합한 10주 교육 콘텐츠이다.

산출물은 브라우저에서 바로 열리는 HTML 강의 자료, Google Colab/Jupyter에서 실행 가능한
Notebook(학생용/강사용/정답), 주차별 실습 데이터와 데이터 설명서, 실습지·퀴즈·강의 운영안이다.

## 2. 원본 데이터 분석 요약 (2026-07-31 실행)

### 2.1 `반도체_공정_샘플.csv`

- 크기: 200행 × 12열
- 열: 측정시간, 온도_섭씨, 압력_Pa, 가스유량_slm, 전력_W, 진공도_mTorr, 두께_nm, 습도_pct,
  진동_mm_s, 처리시간_sec, 냉각수온도_섭씨, 합격여부
- `합격여부`: `1`=합격 180건(90%), `-1`=불합격 20건(10%)
- 결측값: 대부분의 숫자 열에 6~13개(3~6.5%) 존재 (완전 무작위성 결측으로 보임)
- 이상값: 온도 최대 332.5℃(정상대 약 295~305℃ 대비 이상 고온), 압력 최소 963 Pa 등
  정상 범위를 벗어나는 값이 소수 존재
- 측정시간은 문자열(object) 형식이며 순서가 일정하지 않음(랜덤 샘플링된 타임스탬프로 추정)

이 파일을 1~8주차 기본 데이터의 "원형"으로 삼되, 그대로 쓰지 않고 로트번호·설비번호·
공정명 등 교육용 열을 추가하거나 주차별 목적에 맞게 행/열을 축소·재구성한 새 데이터를 생성한다.

### 2.2 `fab.csv`

- 크기: 1,567행 × 592열 (SensorTime 1개 + Sensor0~Sensor589 590개 + Pass_Fail 1개)
- `Pass_Fail`: `-1`=정상/합격 1,463건(93.4%), `1`=이상/불합격 104건(6.6%) → 전형적인 불균형 데이터
- 센서 결측 비율: 평균 4.5%, 최대 91.2%. 결측 50% 초과 센서 28개, 90% 초과 센서 4개
- 거의 변하지 않는 센서(표준편차 0 또는 고유값 1개): 116개 → 정보량이 없어 교육에 부적합
- 결측률 5% 미만이면서 표준편차>0, 고유값 10개 초과인 "정상 후보" 센서: 415개
- `Pass_Fail`과의 단순 상관계수 절댓값 기준 상위 센서(예: Sensor59, Sensor103, Sensor510,
  Sensor348, Sensor431 등)도 상관계수가 최대 약 0.16 수준으로 **어느 센서도 단독으로
  합격/불합격을 명확히 구분하지 못함** → "하나의 센서로 불량을 완벽히 예측할 수 없다"는
  9주차 교훈을 뒷받침하는 실제 근거로 사용한다.
- 센서 이름(Sensor0~Sensor589)의 실제 물리적 의미는 원본 데이터에 없으므로,
  교육 자료에서는 절대 단정하지 않고 "교육용 가상 별칭"만 부여한다.

## 3. 설계 원칙 → 실행 방식 매핑

| 요구사항 | 실행 방식 |
| --- | --- |
| 원본 데이터 보존 | `data/raw/`에 원본 그대로 복사, 이후 어떤 스크립트도 이 파일을 쓰기 모드로 열지 않음 |
| 재현 가능한 난수 | `scripts/generate_weekly_data.py`에서 `numpy.random.default_rng(seed=42)` 등 주차별 고정 시드 사용 |
| UTF-8 with BOM | 모든 생성 CSV는 `encoding="utf-8-sig"`로 저장 |
| 초보자 난이도 곡선 | 1~2주차 5~8열·20~50행 → 9~10주차 15~25열·500~1,500행으로 점증 |
| fab.csv 직접 노출 금지 | 9주차에서만, 그것도 선별된 10~20개 센서로 축소한 파생 파일만 사용 |
| 개념-실습 일체화 | 모든 코드 블록에 목적/한줄설명/실행결과/해석/자주 하는 실수를 함께 제공 |

## 4. 작업 단계 (본 세션 실행 순서)

1. 원본 데이터 분석 (완료)
2. `docs/implementation-plan.md` (본 문서)
3. `reports/raw-data-profile.html`
4. `docs/curriculum.md`
5. `docs/data-design.md`
6. 폴더 구조 생성 (완료)
7. 공통 CSS/JS, `requirements.txt`, `index.html` 뼈대
8. `scripts/generate_weekly_data.py` 등 데이터 생성 스크립트 실행 → `data/weekly/week01~10` 생성
9. `scripts/validate_datasets.py`, `scripts/validate_notebooks.py`
10. 1주차 전체 산출물(HTML 강의자료 3종, Notebook 3종, 데이터·설명서, 실습지, 퀴즈, 운영안) 완성 → 형식 기준 확정
11. 2~10주차를 1주차와 동일한 형식으로 제작 (독립적인 하위 작업이므로 병렬 서브에이전트로 진행)
12. `index.html`, `docs/glossary.md` 완성
13. 전체 검증 실행 및 오류 수정 → `reports/validation-report.html`
14. `README.md`, `docs/instructor-operation-guide.md` 작성

## 5. 품질 기준

- 모든 코드는 실제로 실행 가능해야 한다(가짜 출력 금지).
- 모든 HTML 내부 링크는 실제로 존재하는 파일을 가리켜야 한다.
- 교육용 생성 데이터는 실제 기업 데이터가 아님을 각 데이터 설명서에 명시한다.
- 상관관계와 인과관계를 구분하는 문구를 8주차·10주차 자료에 반드시 포함한다.
